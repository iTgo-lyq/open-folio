# 开发后的原型还原验收

用于有用户确认原型的 UI 实现，在任务验证及关闭整体验证时按改动范围读取。沿用项目现有组件库、工程、工具及验收流程，不强制新增 UI 工程、指定产物目录或重复审批；证据写入现有验证记录，较长内容按需放 Execution / Review。

## 验收基准

- 以用户确认的固定版本原型及其源码为基准，从 Change 固定引用定位产物与 `sourceCommit`，不以会变化的当前原型清单替代。
- 用户后续明确决策优先；记录有意调整及其决策依据，已批准的差异不作为缺陷。基准产物或源码无法取得时，说明受影响的核查项与限制。

## 对照范围

对齐原型和实现的视口、主题、数据及交互状态，再逐项比较：

- 布局、间距、字体、字重、行高及对齐。
- 背景渐变的颜色、位置和方向，玻璃材质的透明度与模糊，边框、阴影和圆角。
- Logo、图标等资源的版本、尺寸、比例和颜色，以及动效的时长、延迟、缓动和变化幅度。

按实际差异核对样式值与资源；页面结构相似不足以判定还原完成。

## 交互与状态

- 按改动范围检查明暗主题、悬浮、按压、鼠标跟随、弹层、滚动，以及切换、加载、空态和错误态。
- 实际触发并观察进入、变化和退出过程，关注闪烁、数字短暂消失、布局跳动及状态重置；稳定截图不能替代过程验证。按需保留录屏、连续截图或复现步骤，修复后复验相关状态与过渡。

## 证据与环境

- 结合浏览器表现与原型、实现两侧的源码核对，将视觉或交互效果追溯到样式层、资源、事件绑定及运行逻辑；按需记录计算样式、关键参数和源码位置。
- 缺少 GPU 等环境条件时，以代码逻辑、参数及计算样式核查实现；实际渲染无法确认的项目明确标为未验证，不计为通过，也不据此删减效果或添加降级逻辑。继续验证不受该限制影响的项目。

## 差异闭环

对每项差异简要记录原型表现、实际表现、根因及处理结果，关联复现状态、证据和修复后的复验结论；根因未查明时如实注明。已有证据仍适用于当前实现时直接复用。

完成报告简要列出：

- **已通过项**：具体检查范围及证据。
- **已批准差异**：有意调整及用户决策依据。
- **未解决项**：尚存差异、影响及待处理事项。
- **未验证项**：未能确认的表现、环境或证据限制及待补验证。

没有对应事项时注明“无”；不用“整体一致”代替具体结论。验收通过与后续关闭仍遵循主流程，不将未解决或未验证项写成通过。
