# 需求范围变化时同步复核任务标题、规模与优先级

## 目标

需求在讨论、澄清或返工中调整后，Change 的标题、规模和优先级应继续反映当前交付，便于用户一眼识别任务。

## 范围与方案

- 补充单个 Change 的标题写法：用简洁、具体的单行文字说明交付对象与变化或结果，避免泛称、过程词和实现细节堆砌。
- 需求目标或范围变化时，同时复核 `title`、`size`、`urgency`，不合适时按最新已明确的范围和用户安排调整；元数据调整本身无需额外审批，新增需求取舍仍遵循现有确认规则。
- 标题可优化但 id 保持不变；规模按现有标准可升可降，并对齐文档、阶段和有效确认；优先级不因规模或类型自动改变，依据不足时保留当前值并只澄清影响安排的取舍。
- 沿用现有字段与命令，不改工作台 UI 或状态契约；同步 skill 补丁版本与应用版本。

## 验收

- 初始化指引可直接找到标题命名规则，并有能说明具体程度的例子。
- 范围扩大、缩小或目标调整均触发三项复核；现有规模调整、需求讨论和返工入口能找到该规则。
- 指引区分元数据优化与需求重新确认，不引入逐次改名审批，也不把规模增长当作提高优先级的依据。
- 技能结构校验通过，三个版本号一致，差异无格式错误。
