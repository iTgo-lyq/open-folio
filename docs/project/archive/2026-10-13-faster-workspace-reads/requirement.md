# 缩短工作台缓存读取等待

## 背景与目标

2026-10-13 使用本地环境配置中的真实 token 登录已有工作台，单仓库列表耗时 7.6–8.8 秒，已有快照的工作台目录耗时 9.2–11.2 秒，8.6 KiB 正文耗时 8.5–9.3 秒；点击仓库至正文可阅读约 18.2 秒。一次缓存读取包含 12 次 GitHub API 请求和两次 Git refs 探测，同样的授权链独立重放耗时 8.9 秒。

用户明确要求：“减少重复鉴权和串行等待，不要设置太过分的权限校验，大胆删除。改完更新本地服务，再用同一个工作台复测一下。”此指令作为本次启动与精简校验方向的授权。

## 范围与行为变化

- MODIFIED：普通目录、正文、搜索、图片和历史快照读取，在有效设备会话内使用当前 token 解析仓库并检查内容读取权限一次。目录条目检查受限并发，保持原有顺序与部分不可用结果。
- REMOVED：普通缓存读取中的重复平台身份查询、Git refs 探测、读取结束后再次执行整套远端检查；读取发现进度和恢复已有发现记录时的额外身份查询。
- MODIFIED：token 或仓库权限的变化由下一次远端读取检查发现；已完成本次权限检查后发生的远端撤权不追溯本次短请求。设备退出、切换和会话撤销仍通过本地会话检查立即阻止在途交付。
- 保留登录时的平台身份验证、每次读取的仓库与内容权限检查、不同 token 的工作台隔离；实际 Git 采集继续使用当前 token。刷新快照与公开原型发布在完成长操作时复验内容权限。

## 方案要点

复用现有仓库解析与内容权限接口，将 GitHub 内容检查精简为提交读取；普通读取只执行一次授权。删除普通读取的 Git 探测依赖与多余的交付检查，长操作通过显式回调复验权限。目录统一使用现有 8 并发上限，完成一轮后仅检查设备会话。

改动集中在服务端授权及发现路径，预计有效实现不足 300 行；API、Provider 方法签名、存储格式和 UI 不变，无迁移，按 small 管理。旧测试中过度复查的预期随本次明确取舍调整，保留真实 token 失效、权限撤销、跨工作台访问与设备撤销覆盖。

## 验收标准

1. 普通缓存读取不重复查询平台身份、不执行 Git 探测；仓库解析与内容权限检查各一次。目录检查并发且不超过现有上限，顺序、分页与不可用条目处理正确。
2. 未登录、错误工作台、失效 token、请求开始前已失去仓库权限及请求中撤销设备的访问被拒绝；真实 Git 刷新继续使用当前 token，并在撤权时失败且保留旧快照。
3. 类型检查、相关自动测试和生产构建通过；按停止、构建、启动、验证顺序更新本地长期服务。
4. 使用同一个真实 token、同一个仓库与已有快照复测登录、目录、工作台和正文，记录与基线的实际耗时对比。保留原运行数据，测试结束只撤销本次设备会话。
