# 原型发布配置统一到根目录环境文件

## 背景与目标

用户明确要求将原型发布所需的 R2 环境变量统一放入仓库根目录 `.env`，发布脚本自动加载，变量模板合并到根目录 `.env.example`。当前配置位于发布机器的 `~/.config/open-folio/r2.env`，上传命令需要显式指定 `--env-file`。

## 范围与行为变化

- MODIFIED：本仓库原型发布配置沿用开发服务的根目录环境文件与加载优先级；从任意工作目录调用发布脚本均可自动读取配置，进程环境变量优先于 `.env.local` 和 `.env`。
- MODIFIED：根目录 `.env.example` 收录五项 R2 配置，发布文档使用无需 `--env-file` 的命令。本机已有 R2 配置迁入 Git 忽略的根目录 `.env`，保留其他本地配置与文件私有权限。
- REMOVED：原型包独立的 `r2.env.example` 与仓库外旧配置，不再维护两套配置入口。

## 方案要点

small：仅调整项目级发布脚本的配置入口，复用现有 `@next/env` 加载方式；不修改上传协议、对象版本、原型清单或服务实现。有效实现改动不足 300 行，仅涉及一个发布职责模块。用户本次指令已明确目标和实施方向。

环境加载仅在 CLI 入口执行；通过函数显式传入的环境保持可测试。测试在临时仓库中使用示例值，覆盖根目录定位、覆盖优先级、缺失配置和失败结果，不读取真实凭据或上传测试产物。本机迁移校验只输出是否一致，不打印凭据；确认迁移完整后删除旧文件。

## 验收标准

1. 发布 CLI 自动加载根目录配置，从仓库根目录、包目录或仓库外调用均可定位同一配置。
2. `.env.local` 覆盖 `.env`，调用进程已有变量保留最高优先级；配置缺失仍以明确失败结束，不上传产物。
3. 五项变量模板只保留在根目录 `.env.example`，README 发布命令不再依赖旧配置路径。
4. 本机五项真实配置完整迁入 `.env`，其他配置保持原样，文件权限为 600 且被 Git 忽略；旧配置删除，凭据不出现在提交中。
5. 原型包既有发布与构建验证通过，上传和固定引用行为保持既有约定。
