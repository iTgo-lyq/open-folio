# 执行与验证

## T1：统一配置入口、迁移本机 R2 环境并验证发布加载

发布 CLI 在校验请求后、调用上传适配器前，依据自身路径定位仓库根目录，通过已有 `@next/env` 自动加载配置。显式传入函数的环境不触发文件加载，上传协议与固定引用未修改。五项 R2 模板并入根目录 `.env.example`，删除独立模板，根目录及原型包 README 使用新入口与命令。

本机将旧 `~/.config/open-folio/r2.env` 中的五项配置迁入根目录 `.env`，追加前逐项核对冲突，原子写入后验证值一致、其他配置保持原样及实际加载结果，再删除旧文件。`.env` 权限为 600，已被 Git 忽略；迁移过程只输出验证结果。差异检查确认不含实际 R2 Access Key ID 或 Secret Access Key。

验证证据：

- `npm run test --workspace prototype`：13 项通过，包括既有固定版本、冲突拒绝、部分失败重试、公开读取校验、截图以及新增 CLI 自动加载验证。
- CLI 测试在临时仓库运行，使用示例配置，分别从仓库根目录、包目录、仓库外目录调用；验证 `.env.local` 覆盖 `.env`、已有进程变量覆盖文件以及无配置时替换旧成功结果为失败。无真实 R2 上传。
- `npm run build --workspace prototype`：导出 3 个自包含原型成功。
- 对修改的脚本和 README 运行 Prettier 检查通过；`git diff --check` 通过。
- 本机检查：五项 R2 变量均已配置，`.env` 权限 600，旧文件与独立模板均不存在，实际凭据未出现在 Git 差异中。

本次仅调整独立发布工具与本地配置，未修改 OpenFolio 服务实现，无需重建运行服务或重新发布已有原型。产品 Specs 的“凭据由发布机器环境提供”仍准确；环境文件位置与加载细节保留在发布 README，不新增产品能力约束。
