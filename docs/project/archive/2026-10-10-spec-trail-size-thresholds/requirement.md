# 明确 Change 实现规模的默认阈值

## 背景与目标

用户要求进一步明确“预期实现规模较大”的具体尺度。基于同分支已完成的 `spec-trail-size-guidance`，给出可用于事前估算的默认参考线，避免只换成另一种模糊描述。

## 行为与方案

`change-workflow`：MODIFIED 以约 300 行有效实现代码或至少 3 个需联动改写的职责模块作为 medium 的默认规模参考；约 1000 行或至少 5 项需要分阶段集成的独立交付任务作为 large 的参考。核心契约实质变化仍至少为 medium，xlarge 仍按独立子 Change 划分。

有效实现量按新增、实质改写后的手写生产代码估算，排除纯删除、机械调整、生成代码、文档和测试；模块按职责和行为边界计数。阈值用于预估，偏离默认档位时说明具体依据，不把行数变为逐行审计或结构校验门禁。

局部调整 skill 与工作流 Spec，采用 small；前置规则已在同分支归档、推送，实际内容可用。

## 验收标准

- 250 行、2 个职责模块且没有核心契约变化的局部修改，默认 small。
- 约 300 行有效实现，或 120 行分布于 3 个需实质联动修改的职责模块，默认 medium。
- 约 1000 行有效实现，或 5 项需要分阶段集成的独立交付任务，默认 large。
- 核心协议关键字段变化即使只改少量代码，至少为 medium；机械清理及辅助文件数量不单独升级。
- skill 校验、文档格式与差异检查通过，判断定义和长期 Spec 一致。
