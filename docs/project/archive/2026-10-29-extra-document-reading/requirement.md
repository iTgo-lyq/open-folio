# 修复 Change 附加 Markdown 文档误报缺失

## 目标与范围

Change 已存在 `research.md` 等附加 Markdown 文档时，打开 `ct=file:research.md` 应显示对应正文。当前阅读材料解析在匹配已有材料前进入 `file:` 缺失兜底，导致误报“文件缺失”。本次恢复已有文档的正常阅读行为，不改变材料结构或链接格式。

## 方案要点

保留旧 `doc`、`document` 参数的既有匹配优先级与 `ct=documents`、`ct=previews` 别名；优先返回匹配到的已有材料，确实找不到目标文件时才构造缺失材料，未知非文件目标仍回到概览。

## 验收

- 根目录及嵌套目录的附加 Markdown 文档通过 `ct=file:...` 打开时返回对应可读材料，不标记缺失。
- 旧 `doc`、`document` 文档链接与旧 `ct` 别名继续定位到原材料。
- 文件删除后，新旧文件链接仍明确指向原文件并显示缺失，不误开其他材料。
- 补充正常打开与已删除文件的回归测试，并验证工作台和匿名阅读共用的解析路径。
- 按 small Change 自查、自验收、归档，交付目标为 `develop` 的可审阅 PR。
