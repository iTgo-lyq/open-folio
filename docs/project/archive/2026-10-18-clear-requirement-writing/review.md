# 需求写作规则评审

iclaude 在独立会话中阅读完整 skill、差异和本次需求，并用刷新性能、多身份切换两个案例做纸面检验。首轮无阻断问题，提出以下两项改进；修正后另轮复验，结论为“两项均已解决，未引入实质问题”。

- **R1：迁移影响的适用范围。** 规则覆盖兼容或迁移对既有使用和数据的影响；旧登录失效、工作台数据保留等变更在需求阶段即可判断，small 同样适用。复验确认覆盖完整。
- **R2：外部产物的登记位置。** 生成的外部文档在 Requirement 相关内容处登记，保留来源、用途、读者、同步和授权职责。复验确认位置明确且职责完整。

Agent 补充检查：skill-creator 的 `quick_validate.py`、`git diff --check`、相对链接目标检查均通过；核对主 skill、子 skill、references 和实现中的相关表述，未发现冲突或固定章节解析依赖。本次验证针对文档规则与纸面案例。
