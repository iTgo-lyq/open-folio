# 简明且可判断的需求写作

让需求作者用足够简洁的文字说明问题、交付边界和完成条件，帮助 reviewer 作出判断。文档按阅读需要组织，行为本身可判定时直接作为验收依据。

本次交付以下写作指引：

- 目标描述用户、调用方获得的结果或明确的技术结果；行为说明新增、当前与目标差异、删除后的影响，容易误解的边界说明取舍。
- 验收覆盖全部已确认交付，按需要补充条件、动作、结果及异常边界；已承诺的性能或效果有交付证据，额外观察按需安排。
- 影响判断的来源与不确定性就地说明，较长证据放 Research；章节和摘要服务阅读，内容避免反复铺陈。
- Specs 依据最终验收实现，结合需求中的行为变化与长期核心方案更新。技能正文直接陈述当前规则，保持措辞简洁。

## 方案与验证

集中修改主 skill 的写作、调查引用及同步表述。分轮澄清、状态契约、确认与关闭流程沿用现行约定。

以短需求和涉及迁移、权限边界的复杂需求检验规则；检查正文及引用的一致性，运行技能校验，再由 iclaude 独立 review。评审问题处理完成且上述指引可用于判断实际交付后验收。
