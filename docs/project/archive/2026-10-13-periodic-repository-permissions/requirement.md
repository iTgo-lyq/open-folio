# 按周期复用仓库权限检查

## 背景与目标

用户明确要求不再每个动作都鉴权，可定时检查权限，并在接口出错时确认是否失权。当前目录、正文、搜索、图片及原型的每个请求均串行调用仓库解析与内容权限两个远端接口，约 1 秒；目录列表也逐次复验每个条目。

本次沿用已归档推送的 faster-unchanged-refresh（尚未合入 main），继续减少交互时远端往返。按 small 执行：预计不足 300 行有效实现，职责为共享权限检查与既有读取/错误处理接入；不改变 API、持久化格式或凭据归属。

## 范围与行为

MODIFIED：同一凭据工作台、同一稳定仓库身份的成功权限检查复用 5 分钟，列表及仓库读取共用结果，并发合并。首次、过期、服务重启后的请求先检查；活跃工作台通过既有每分钟后台检查在到期时复验，关闭页面不常驻请求。单设备本地会话、归属和撤销仍逐次检查。

MODIFIED：远端明确拒绝立即使相应权限结果失效；token 失效影响该凭据全部仓库。Git 读取失败触发一次强制权限复验，区分失权与网络/采集错误。临时网络和限流不冒充权限撤销，不清除仍在显示的正文；过期后的权限检查失败不延长成功状态。

私有新快照和已发布原型读取沿用周期权限结果，真正发布新的公开原型前保留一次即时检查。不同凭据不共用状态，已确认失权不能被较早的在途检查覆盖。本地退出或切换仍立即阻止在途结果交付。

## 方案要点

在进程内按凭据工作台与仓库保存检查时间、规范仓库信息和同一在途请求，不保存 token，不落盘。请求通过本地会话后复用检查；检查任务属于工作台，单台设备退出不取消其他设备的共用检查。错误分类集中处理，保留明确拒绝状态以阻止已在途交付。复验成功后恢复读取。

## 验收标准

- 同一仓库连续读取、列表到正文跳转及并发读取在有效期内不再访问平台鉴权接口；到期后合并成一轮复验。
- 不同凭据隔离；已撤销本地设备即时拒绝，远端失权在下一次周期复验或实际远端错误时生效。
- Git 失败复验能区分权限与临时故障；明确撤权阻止同工作台已在途结果，较早请求不能回填失效权限。
- 后台检查能够在到期后识别失权，UI 只对明确失权清理正文，临时故障可恢复。
- 更新本地服务，用同一真实工作台复测目录/正文、无变化刷新和原型读取耗时。
