# 历史归档发布状态补记

## 目标与范围

延续 pr-release-delivery，为缺少 PR 或规范合入记录的历史交付提供显式补记。新增可选字段 `deliveryOverride: "releaseMerged"`；仅集成分支上的有效归档具有覆盖效力。保持现有分支路由、自动交付判定和 CI 规则。

用户已确认：以集成分支归档为准，按已讨论方案推进，skill 和升级文档保持精炼，不扩展需求。本次为 small：一处交付判定及字段校验适配，预计不足 100 行生产实现，不改变既有状态结构或权限边界。

## 行为与方案要点

- 以集中路由选中的归档为准；候选必须有效完成、位于集成分支且包含精确字段值，覆盖为“已合入发布分支”。归档内 branch 保留历史归属。
- 工作分支、发布分支、活动或无效记录中的字段不触发覆盖；缺省时沿用自动计算，删除字段后恢复自动计算。
- 覆盖优先于缺失或异常的 Git 合入记录、PR 查询失败及关联歧义；保留可读 PR 和诊断，不制造 Git/PR 事实，不绕过仓库读取权限或 CI。
- JS 校验器、服务端类型与校验同步支持单一字段值；无效值不产生覆盖。更新索引缓存指纹，使现有缓存重新索引。
- 主 skill 只补字段定义和升级文档入口；独立 upgrade.md 简述 skill/配置更新、集成分支历史归档补记和刷新验证。只允许补记该字段，保留其他归档证据与 Git 历史。
- 不批量标记本仓库历史、不增加其他覆盖状态、UI 配置入口或自动升级机制。

## 验收

1. 集成分支有效归档中的覆盖生效，原工作分支删除、缺少 PR/M、PR 缺权或歧义不改变覆盖标签。
2. 只有工作分支或发布分支存在覆盖时不采用；未归档或无效记录不被提升为已发布。
3. 缺省和移除覆盖恢复现有计算；PR 链接与相关诊断仍可读取。
4. 提交校验拒绝非法字段值，CI 仍拒绝未归档或无有效集成历史的交付。
5. Skill 和独立升级说明简短、单一事实来源明确，无额外流程或需求。
