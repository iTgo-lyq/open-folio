# 取消 Change 时可选择删除或归档留存

取消前确认用户是否需要保留记录。确认删除后，清除协作分支的 Change 入口，以及经核实专属该 Change 的工作分支与工作区。确认留存后，保存取消原因和当时的阶段、任务与材料。已移交的 Change 在工作分支归档并推送，协作分支只标记取消，完整材料与实际工作仍以工作分支为准。尚未移交的 Change 在协作分支归档。

## 方案与验收

- 取消命令要求显式选择留存或删除。留存记录包含取消时间和原因，完整材料归入 archive。正常交付继续执行验证、验收、Specs 同步与归档。
- 已移交的 Change 先推送工作分支归档，协作分支再记录同一取消信息。工作台读取工作分支的任务与正文，按已取消展示。删除时不产生归档。
- 移交脚本拒绝复用已取消 Change 的分支名。
- 将本仓库已取消的 Change 整理到规范位置，保留原始取消时间、原因与工作记录。
- 用临时 Git 仓库验证取消的两条路径、工作分支归档、协作分支标记、移交冲突及对正常归档的影响。此次交付由用户验收。
