# Changes 动态视图与已发布归档：实施计划

依据 [需求](requirement.md)、[技术方案](technical.md) 和已通过用户评审的固定原型实施。目标是让用户在现有 Changes 页面切换、保存和管理关注范围，默认进入“我的”，并将确认发布的记录归入已归档。

## 交付边界

界面仅调整 tab、视图管理弹层及必要筛选/显示联动。系统状态 tab 固定在前，个人视图在右侧；管理排序使用拖拽柄，不展示上下按钮；系统默认条件不重复显示为标签。整页原型中的侧栏、顶栏、表格/卡片和详情样式只是上下文，继续复用正式产品现有组件，不整体替换页面或调整全局主题。

数据改动仅包括视图持久化、当前查询恢复、本人识别和已发布分类所需支持。复用现有账号、仓库身份、读取缓存和发布证据，不重写 GitHub 请求算法，不新增业务依赖、数据库、轮询或全量缓存重建。

## T1：统一状态范围与本人筛选

交付：共享目录投影支持进行中、已完成、已归档、已取消及多状态并集，驱动系统 tab、计数、分组、延续组和详情相邻顺序。已确认发布才进入已归档，取消总数为零隐藏对应系统 tab。增强可识别作者的数字身份，以当前 GitHub 身份计算本人条件；保持固定作者筛选和历史链接可用。

验收：已完成与已归档互斥，PR 临时失败不凭空生成发布事实；取消入口隐藏不删除历史详情；状态组内 OR、不同筛选组间 AND，关联记录不绕过筛选；只含 login、普通姓名或数字身份冲突的作者不误判为本人。新增状态与本人参数可往返解析，旧 scope 和详情链接保持有效。

验证：补充目录查询、作者解析、发布分类与路由的单元用例；用现有浏览器目录场景验证系统 tab、空态、分组及详情返回。比较修改前后范围外页面的样式和 DOM 结构，避免修改表格、侧栏和阅读器布局。

## T2：保存并恢复账号级视图

交付：在已有账号存储中按稳定仓库身份保存视图定义、顺序和最近选择，提供读取、首次初始化、整批保存及选择接口；接入客户端会话缓存、默认“我的”、tab 切换与 URL 查询恢复。无配置时初始化一次，用户删除“我的”后不重建。

验收：同账号同仓库在不同浏览器和 Token 下共享定义，不同账号/仓库隔离；初始选中我的，之后恢复最近视图；显式查询、刷新、前进后退及详情深链接优先于默认选择。切换仅过滤已加载数据，不触发 Git 刷新；后台配置和晚响应不覆盖当前查询或跨身份写入。定义并发冲突返回明确错误，最近选择保存不制造定义冲突；旧账号数据可读且不需要重绑 Token。

验证：存储/API 测试覆盖并发初始化、权限/来源校验、大小及枚举限制、CAS 冲突、选择与管理并发、原子写入失败和身份切换；双浏览器端到端覆盖恢复、URL 优先级和缓存复用，记录请求次数以确认切 tab 无额外仓库刷新。

## T3：交付视图管理与完整交互

交付：在现有 tab 右侧加入设置入口。新增完整继承当前筛选与显示选项，编辑载入已保存定义，状态四选项始终可选；支持显隐、编辑、删除和桌面/触屏拖动。管理草稿通过取消/确认统一处理，主列表临时条件支持恢复、保存和另存；失败及并发冲突保留本地草稿并提供可见处理方式。

验收：系统 tab 固定在前且不可被个人排序穿插，个人 tab 在右侧按保存顺序展示；没有上下按钮。隐藏/删除当前视图正确回退，默认自带条件不重复展示、额外条件可移除；自定义视图保留完整条件展示。新增、编辑、取消、失败重试和确认均符合原型；多状态或窄屏的列表降级不覆盖看板偏好。范围外页面保持现有行为和视觉。

验证：浏览器覆盖管理草稿、桌面及触屏拖动、键盘、显隐删除、名称校验、冲突/失败、默认条件展示及详情返回；浅深色和 1440/834/390/320 宽度检查溢出、焦点和滚动。复用现有基础组件，仅新增业务组合。按整体差异执行独立评审，修复后定向复验，再交用户验收。

## 整体验证与交付

默认串行 T1 → T2 → T3，每项包含实现、对应验证和提交推送，不拆成额外的“写测试”任务。每个阶段保持可运行；计划与任务名称一致，执行事实在任务状态和必要的执行记录中维护。

- 单元检查使用现有 `node --conditions=react-server --test`，重点覆盖目录、创建顺序/身份、账号会话、路由与读取缓存；最终执行 `npm test`、`npm run typecheck` 和生产构建。
- 浏览器检查使用现有 `npm run test:e2e` 与 `.next-e2e` 配置，重点回归 Changes 目录、阅读、账号/Token 和跨浏览器视图恢复。生产验证构建只在任务工作区的 `.next` 进行，不覆盖主工作区常驻服务产物。
- 开发验收使用现有专用账号配置与 `withSmokeSession`；需要复用常驻数据时先确认兼容、停止占用实例，确保同一目录只有一个实例。测试结束须退出并复查匿名且无可见绑定，不修改用户数据清理会话。
- 交付前同步 develop，核对同期 GitHub 请求优化在上下文、缓存和分类数据上的交集，保留双方行为；不扩大到该 Change 的请求算法。
- 独立评审检查账号隔离、URL/缓存竞争、分类一致性和 tab 之外的差异。向用户提供实际实现与测试结果，验收后才同步 Specs、归档并按授权合入 develop；集成验证后更新常驻服务。正式发布 main 需本次明确授权。

无新增外部服务或配置前置。计划准备期间不修改生产实现；原型通过不替代正式实现验收。
