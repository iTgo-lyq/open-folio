# 支持无新增 Change 的版本发布

## 目标与范围

发布 PR 没有新增 Change 时，允许正文末尾只保留 `SpecTrail-Version`，不再为满足校验虚填 `SpecTrail-Includes`。已有 Change 清单继续核实归档和实际集成证据，空值、重复或非法标记仍拒绝。

省略清单的发布不得新增、修改或删除 Change 归档；原有规划记录可随发布保留。工作台能读取并持久化空清单发布记录，不使其他 Change 的交付读取失败。

## 方案与验收

沿用现有标记解析和发布校验，允许空清单；空清单时比较发布源、目标的归档目录。放宽缓存中清单数组的非空限制，同步发布指引，保持实现精简。

验证标记解析、无 Change 发布通过、归档变化仍被拒绝、有 Change 的既有校验、工作台缓存往返读取，以及相关类型和接入校验。验证通过后集成至 develop，更新服务并继续已有发布 PR 合入 main。

用户授权：本次对话明确要求“补上无新增 Change 的发布支持，验证通过后继续合入 main，注意精要”。
