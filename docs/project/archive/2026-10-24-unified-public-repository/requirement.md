# 统一公开仓库与 SpecTrail 分发

当前仓库已清理作者和提交者信息，但旧 PR 保留了旧提交。迁移到独立的新仓库，保留清理后的 Git 历史，放弃旧 PR，避免旧邮箱和作者名通过 PR 历史继续出现在新公开仓库。

## 范围与行为

- 新仓库继续使用 `iTgo-lyq/open-folio`；旧库改名为 `open-folio-legacy`，保持私有并在新库验证后归档。新库保留 `main`、`develop` 和已清理的现有标签，不导入旧 PR 引用。需求问题 Q1、Q2 已由用户确认。
- 以当前已验证实现建立新发布基线，历史有效归档使用现有 `deliveryOverride: "releaseMerged"` 明确补记已发布，保留其他关闭记录。此补记不生成旧 PR 或合入差异。
- 当前 `.agents/skills/spec-trail/` 是较新的源码，继续作为唯一技能目录。保留公开分发副本的 MIT 许可证、安装使用说明和介绍站源码，介绍站继续使用原来的静态站实现。
- 移除 OpenFolio 到独立 SpecTrail 仓库的同步工作流、脚本及对应测试。技能版本文件直接随源码提交；安装、更新检查和网站源码链接统一使用新仓库。独立技能仓库在入口迁移后归档。
- 修复新基线中需要读取的原型等固定提交引用，使其指向已清理且内容等价的提交，不引入长期旧新 SHA 兼容表。
- 保留本机账号、Token、工作台数据和服务配置；从主工作区更新长期服务并验证新仓库读取及本人匹配。

## 方案要点

这是一次仓库与分发配置迁移，复用既有发布补记和技能版本格式，不修改 OpenFolio 的 GitHub PR 识别协议。新仓库首次建立 `main` 与 `develop` 的共同发布基线；按用户要求不向旧库新增迁移 PR，不复制旧 PR。之后的开发和发布继续使用现有 SpecTrail PR 流程。

公开前扫描所有拟推送提交及文件，验证旧邮箱、旧作者名和旧 PR 引用未进入新仓库的可达历史。新仓库只接收明确列出的分支和标签。旧仓库保留为私有归档，不执行删除。

## 验收

- 新仓库为独立公开仓库，无旧 PR；仅有 main、develop 与保留标签，提交历史中的作者和提交者信息均已清理。
- 历史有效 Change 记录完整，并因本次发布基线与历史补记正确显示为已发布；没有伪造 PR 或差异证据。
- SpecTrail 能从新仓库完整安装并读取版本，更新检查地址可匿名访问；介绍站静态检查、构建和现有测试通过。
- 跨仓库同步入口已移除，用户说明与实际分发方式一致；旧技能仓库显示迁移入口并归档。
- 长期服务使用新基线运行，新仓库实际读取与本人匹配通过，测试登录正确退出并验证匿名状态。
