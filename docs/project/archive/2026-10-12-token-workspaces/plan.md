# Token 工作台实施计划

按[需求](./requirement.md)和[技术方案](./technical.md)交付完整路径：可选用户名与 token 登录，同一凭据在多设备恢复工作台，不同 token 隔离仓库缓存，用户主动复制当前 token。平台实例与完整 token 决定工作台身份；用户名用于显示，Git 传输使用适配器返回值。

## 前置与执行方式

前置 `personal-workbench` 已归档并推送，交付和归档提交在当前 `codex/personal-workbench` 分支。实施前再次 fetch 并核对依赖记录、工作区及分支；同分支无需先合入 main。

T1–T6 按编号串行推进。每项包含实现、对应验证、README 中适用的使用或运维说明，并记录实际执行证据，验证后提交推送。中间任务采用受控数据验证；完整迁移和集成通过前不更新运行实例。保持单进程、持久磁盘、受信 HTTPS 代理和既有公开原型契约。

## 交付任务

### T1 让同一 token 在多设备恢复同一工作台

建立 `personal-v2` 凭据工作台与独立设备会话，使用私有 HMAC 指纹匹配随机工作台 UUID、AES-GCM 保管不可替换的 token。提供 Git 用户名与 token 登录、Cookie 恢复、失败切换回滚和成功切换当前设备；适配器返回有效 Git 用户名，通用身份模型不依赖 GitHub subjectId。

活动会话采用 30 天闲置期限、90 天绝对期限和每天一次的续期写入。退出当前设备保留工作台；退出全部设备撤销对应会话。普通摘要不包含 token、指纹或密文，旧新增／替换连接接口退出使用。落实总量及单工作台 32 设备上限、私有文件权限、缺失密钥拒绝恢复。

验收与验证：

- 两个独立 Cookie 以相同凭据登录，得到相同工作台，互不轮换；同账号不同 token、不同实例分别隔离，并发首次登录相同 token 收敛。
- 无效切换保留原会话，成功切换只撤销当前设备旧会话；重启、每日续期、闲置与绝对到期行为正确。
- 非 GitHub 测试适配器走通相同身份契约；用户名变化不改变凭据索引，GitHub 用户名不匹配明确失败。
- 用受控时钟及状态夹具检查密文、nonce/AAD、密钥丢失、数量上限和摘要无秘密，运行相称的会话／适配器测试与类型检查。

### T2 按 token 共享发现与仓库缓存，保持逐设备授权

将发现、Git、快照、错误和任务归属改为工作台，写入独立 `discovery-v2` 与 `repositories-v2` 目录。相同 token 的设备复用发现进度和完整快照，写入按工作台串行去重；不同 token 不共享私有数据、锁或任务。ReadContext 同时携带设备会话与工作台身份，旧 connectionId 仅在可证明当前归属时兼容。

单设备退出取消自己的请求，不中止其他设备使用的共享任务；退出全部设备取消工作台任务但保留已提交结果。所有读取继续验证当前 token 身份、仓库 API 与 Git refs，长请求交付前检查远端权限及设备仍有效，禁止失权后的缓存回退。

验收与验证：

- 两设备同 token 读取同一已采集快照，实际缓存目录与写任务复用；同账号不同 token、同仓库同提交仍独立发现和 fetch。
- 用真实 HTTPS Git 测试服务记录传输凭据，验证并发去重不借用另一 token；单设备退出不破坏另一设备读取，已撤销设备在途请求不能交付。
- 覆盖普通读取、HEAD、搜索、图片、历史快照、失败刷新、token 撤销、权限缩小及交付时撤权，无法确认权限时不返回旧正文。
- 仓库分享、Change 来源与公开原型准备／匿名读取通过定向回归，运行发现／仓库集成测试和类型检查。

### T3 升级旧连接并恢复可证明归属的缓存

提供停机升级的幂等迁移：验证旧 schema、密钥与全部密文，按平台实例和完整 token 分组，重建新 AAD 密文及来源映射。通过受控 staging、原状态摘要和稳定映射恢复中断；所有新文件验证后才原子发布新状态。保留完整旧目录，不自动清理备份。

同 token 的同仓库多份缓存只选择完整且最新的一份作为基线，不拼接不同 refs 或快照；无法证明来源的文件仅留备份。单连接旧 Cookie 可兑换新设备会话，多连接旧 Cookie 显式选择自己已有的凭据；兑换重新验证并原子使旧选择凭证失效，不能用 connectionId 单独登录。

验收与验证：

- 覆盖单连接、多连接、重复 token、多个 revision、同账号不同 token 与不同平台实例，只有完全一致的凭据合并。
- 升级后发现与快照可恢复且仍重新授权；新设备使用一个 token 无法枚举旧会话中的其他 token。
- 注入密钥缺失、坏密文、来源不明和发布前中断，确认原数据不变、可重复恢复且工作台 UUID 不漂移；已存在新状态不重复导入。
- 使用临时部署夹具按 README 演练升级、重启和停机回退；回退保留新目录，明确新 Cookie 需重新登录，不宣称旧版本恢复新会话或新快照。

### T4 提供当前凭据复制与设备会话管理

提供只面向当前 Cookie 工作台的 token 复制接口，以及设备列表、单设备撤销与退出全部设备入口。复制接口不接受目标工作台或连接 id，返回前重新检查会话；复用 HTTPS、同源与 `private, no-store` 约束。设备列表只展示安全摘要和当前设备标记。

当前凭据页面沿用现有玻璃导航与组件，展示账号、复制 token、切换入口和设备管理。仅在主动点击时读取 token 并写剪贴板；剪贴板不可用时提供本次操作的短暂手动复制文本，关闭、切换与退出时清除。

验收与验证：

- 复制结果与原 token 完全一致；未登录、跨站、伪造目标、会话撤销及切换竞争不能读回凭据，普通摘要仍无秘密。
- 两浏览器能看见各自独立设备，撤销另一设备使其后续与在途读取失败；退出当前设备和退出全部设备的影响符合约定。
- 浏览器验证主动复制、权限失败、手动复制弹层清理及设备管理反馈；确认 URL、localStorage、sessionStorage 和日志无 token。
- 运行复制／设备管理 HTTP 测试、对应浏览器场景与类型检查，桌面与窄屏可操作且焦点恢复正确。

### T5 贯通登录、切换与跨设备阅读恢复

将登录页、会话恢复、当前凭据选择和仓库阅读统一接入新模型；仅展示受支持平台，旧多连接会话使用一次性选择页。相同 token 恢复已有发现和缓存，不同 token 进入各自工作台；切换、退出和过期清理旧正文、错误及在途前端响应，避免旧请求覆盖新工作台。

以白名单保存当前工作台的最近仓库／模块与侧栏偏好，更新时只原子合并实际修改字段；跨设备恢复目标时重新授权，滚动仍属于当前页面。工程分享保留稳定仓库与阅读参数，协作者以自己的 token 访问；公开原型继续匿名可读。

验收与验证：

- 两个隔离浏览器完成首次登录、同 token 恢复、阅读、刷新、切换、失败切换、复制和退出；同 token 恢复原缓存，不同 token 不显示旧仓库状态。
- 会话过期、远端失权、服务重启和旧 Cookie 选择均提供正确恢复入口；快速切换时旧响应无法写入当前页面。
- 并发修改不同偏好字段不会互相覆盖，偏好或分享链接不能授予读取权限；原有 Specs、Changes、固定原型与管理权限路径保留。
- 桌面 1440、平板 834、手机 390 和 320px 通过真实浏览器交互、键盘、前进后退及无横向溢出检查，实际查看主要截图。

### T6 将用户名改为可选显示名称并自动填充 Git 账号名

按用户明确调整返修 T1、T5 的用户名行为：登录只保留用户名（可选）和 token，省略或留空时首次使用平台账号名；自定义用户名保存为工作台显示名称，恢复时未指定名称保留已有值。取消 GitHub 用户名匹配限制，显示名称不作为鉴权输入，真实 Git 传输仍由适配器决定；不改变 token 身份、缓存目录或设备会话契约。既有 label API 保持兼容。

验收与验证：

- 仅提交 token、空用户名、纯空白均能登录；任意普通显示名称（含中文、内部空格或冒号）可保存并跨设备恢复，控制字符与超长输入仍被拒绝。
- 同 token 不同用户名恢复相同工作台，不同 token 保持隔离；Git 传输始终使用平台返回的真实用户名。
- 定向会话／Provider 测试、登录和切换的真实浏览器回归、类型／格式及生产构建通过；独立评审新增差异并沿用已验证的原交付证据。

## 整体交付与验证

完成任务后逐项核对 Requirement 的十条验收标准，执行完整单元／集成、类型、格式、既有及新增浏览器回归与生产构建。构建沿用仓库产物约定，保留运行服务时才使用 `.next-verify`，同目录串行并清理临时产物与类型引用。

以不继承实现会话的独立评审覆盖完整差异、迁移与凭据复制边界，记录问题及复验，修正后再次运行受影响检查。README 说明存储／密钥配套备份、会话期限、token 工作台隔离、设备退出、主动复制和迁移回退。通过整体验证后进入人工验收；按实际交付同步 Specs、归档并保留原型引用。

本次不引入 OAuth、邮箱密码注册、跨 token 合并、额外平台实现或自动清理旧备份。真实凭据不进入测试与日志；自动化使用虚构适配器及真实 HTTPS Git 夹具，不以原型演示代替产品验收。
