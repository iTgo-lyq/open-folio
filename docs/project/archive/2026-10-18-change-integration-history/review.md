## R1 · P2 · 共享 Git 原型未固定到归档

**问题**：共享目录 HTML 未纳入归档子树一致性校验，协作分支并发修改共享 HTML 后，历史预览可能展示其他交付的内容。

**修复**：归档命令将共享 HTML 复制到本 Change 的 previews 目录，保留 sourceCommit；目标不同则停止，dry-run 不写入。共享合入校验要求 Git 引用精确指向该归档的 previews/<id>，集成预检拒绝共享路径。

**证据**：真实临时仓库中，源交付为 ACCEPTED、协作共享 HTML 改为 CONCURRENT OTHER DELIVERY；合入后归档预览仍为 ACCEPTED。手工构造不安全归档被拒绝。独立复验通过，相关用例 17/17 通过。

## R2 · P1 · 索引标记隐藏修改造成误删

**问题**：assume-unchanged / skip-worktree 会让普通 git status 和非强制 worktree remove 漏过未保存内容。

**修复**：来源预检、清理预检及实际移除前均检查 ls-files 索引标记；发现任一种即保留来源，提示解除标记后检查文件。

**证据**：两种标记分别隐藏 UNSAVED USER WORK，清理均返回 retained；远端分支、本地分支、worktree 及原文件内容完整保留。独立复验通过。

## R3 · P2 · 原型复制部分失败缺少回滚

**问题**：复制完成后才登记目标，ENOSPC 导致部分写入时残留不完整文件，阻止重试归档。

**修复**：以 wx 独占创建成功后立即登记本次拥有的目标，再写入并关闭；失败时删除本次创建的文件和空目录，不删除未成功独占创建的目标。

**证据**：通过 --import shim 注入写入前 8 字节后抛出 ENOSPC，原 change.json 不变，部分文件被清理；正常重试完成归档。独立复验进一步在第二个原型文件注入部分写入，确认此前已复制文件一并回滚、预存用户文件保留、原始 ENOSPC 未被覆盖，直接重试成功。
