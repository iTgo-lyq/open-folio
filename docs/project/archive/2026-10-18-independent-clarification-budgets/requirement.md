# 需求与技术问询分别计算额度

用户要求技术问询额度单独计算，避免需求澄清用满后无法继续技术问询。本次为 small 规则文档变更：需求与技术分别使用既有规模上限，取消共用 Change 总额度；保留技术问询中的实现重点说明及精简问题原则。

## 方案与验收

- 需求额度保持 small 1 轮 / 每轮 3 题 / 共 3 题、medium 2 / 3 / 6、large 3 / 4 / 12、xlarge 4 / 4 / 16；技术额度保持 small 1 / 1 / 1、medium 1 / 2 / 2、large 与 xlarge 2 / 2 / 4。两类互不扣减，需求用满不阻止技术额度内的问询。
- Q 编号和 round 仍在整个 Change 中递增。按首次提问的决策内容区分需求与技术，分别统计该类题数、每轮题数及不同 round 的数量，不以 round 最大值当作已用轮数。同轮混合问题分别计数，不重复计题；small 在需求阶段完成技术问询，也使用独立额度。
- 问题归属和 Q 引用随正文保留，跨会话与返工不重置，撤回不退额度，跨文档引用或阶段变化不改归属。技术答案导致需求变化时按返工处理，不重复计数原问题。
- 某类到限只停止该类扩展；关键缺口仍阻塞依赖它的推进，另一类仅可继续前置已明确的问题。
- 同步主 skill、命令参考和当前 Specs；不修改已归档交付，不扩展 JSON 或工作台接口。
- 验证 skill、文档链接和差异；情景自查覆盖需求已满后继续技术、混合轮次、small、撤回续接及需求返工。
