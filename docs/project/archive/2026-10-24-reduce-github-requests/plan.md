# 实施计划

## T1：批量读取与复用 PR 页面

将交付采集改为按集成、发布目标分支读取完整目录；相同查询只执行一次，从目录建立内存关联索引。新增来源隔离的条件请求页面缓存，保存完整分页、ETag、原始条目数和规范化标记；成功查询原子替换，失败保留上一完整集合。

验收覆盖两分支单页仅两次请求、无新增 PR 的页面复用、旧 PR 元数据更新、超过十页、满页尾部增长、目标分支变更、缓存损坏和资源上限。现有交付判定与权限检查保持有效；冷缓存与热缓存均不逐 Change 查询。

## T2：统一冷却与限流错误传递

所有具有已知身份的 GitHub 请求共享按实例和账号划分的冷却状态。实际 403/429 限流记录服务端等待信息；冷却期间直接返回限流错误，过期后由正常调用恢复，不增加重试或兜底。补齐二级限流识别、刷新失败传递与浏览器等待信息。

验收覆盖同身份跨工作台阻止后续 HTTP、其他身份不受影响、冷却过期、正常权限错误、首个限流立即停止 PR 采集、失败不更新成功时间，以及客户端错误信息。完成后运行相关回归、类型检查、构建与独立评审，提供可核对的请求量对比和交付证据。

## 执行顺序

按 T1 → T2 串行交付，每项包含实现、必要回归和证据。用户在技术方案展示后明确要求“开始优化吧”，本计划将已授权方案拆为上述实施顺序，不增加范围或方案决策。
