## R1：重复绑定已有 Token 绕过共享冷却

证据：原绑定入口始终调用无已知身份的 authenticate。已有绑定被限流后再次提交相同 Token，会额外发送 `/user`，与“所有已知身份入口共享冷却”的要求不一致。

修复：在现有账号状态锁内复用已有凭据指纹，查找该账号的已有绑定，把已知身份传给 authenticate；未识别的首次绑定仍执行必要的身份查询。没有增加 Token 指纹登记表或跨账号缓存。

复验：真实 PersonalSessions.bind、switchConnection 与 Discovery.start 调用链的模拟测试证明，请求序列只有首次 `/user` 和触发限流的 `/user/repos`；冷却中重复绑定、切换和发现均不发 HTTP、不改变设备版本。独立评审复跑 17 项身份/冷却相关测试通过，R1 已解决，未发现其他可行动问题。

附加检查：Retry-After 限制为整数秒或 HTTP 日期，畸形数字 `1.5` 不被当成过去日期；二级限流未知恢复时间保留至少一分钟的等待提示。浏览器用例验证错误等待信息与旧交付内容保留。
