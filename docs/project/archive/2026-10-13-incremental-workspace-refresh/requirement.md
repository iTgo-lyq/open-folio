# 分支增量采集与工作台后台自动刷新

## 背景与目标

工作台曾长期显示 personal-workbench 归档前的旧快照；手动刷新又会串行重扫所有分支。用户明确要求加入分支增量缓存与后台自动刷新，完成后更新开发机服务，并使用同一真实工作台复测。

## 范围与行为变化

- MODIFIED：采集仍覆盖全部已推送分支与归档保留标签，按来源名称、固定提交和扫描规则复用上次成功快照；未变化来源不重新扫描文档树。新增、改写、删除分支及默认分支变化在新快照中准确反映。
- MODIFIED：用户追加明确 Specs 和项目当前原型仅看默认保护分支。其他分支只采集 Change 与归档目录，不扫描其 Specs；Specs 移除分支选择，旧链接的分支参数不改变默认保护分支来源。Change 到 Spec 的引用指向当前保护分支能力；Change 内部文档和固定历史原型维持自身提交来源。
- MODIFIED：Specs 正文、目录和项目原型清单沿用快照读取缓存，默认保护分支未变化时复用原型清单，不因其他 Change 更新重复扫描清单。固定原型产物继续复用已有不可变发布缓存。
- ADDED：打开仓库、页面回到前台及可见页面每分钟自动检查远端；同工作台同仓库共享刷新并合并请求，一分钟内成功检查可复用。页面隐藏时暂停，返回后补查。
- MODIFIED：检查期间保留可读内容，有新快照才替换页面数据；无变化不制造新快照。普通刷新失败保留内容并提示，失权仍按现有边界清除内容。手动刷新保持可用。

## 方案要点

small：内部采集缓存与页面刷新调度两个职责，预计少于 300 行有效实现代码；复用现有快照、blob、刷新接口及工作台任务锁，不增加新的业务数据模型或后台常驻进程。前置 faster-workspace-reads 已归档推送，当前分支直接包含其完整实现。

在快照内保存可选扫描规则指纹，以现有分支提交和文档元数据作为增量缓存；旧快照或规则变化时完整扫描，正常容量限制继续生效。所有 refs 不变时复用快照及索引；成功检查时间单独持久化，用于跨请求节流。沿用当前 token 的请求授权和刷新完成复验。

客户端后台使用现有空体 POST refresh 的自动模式；返回快照 ID 变化时重新读取工作台，不清空当前页面。切仓库、凭据、分支或手动刷新时取消旧页面的自动交付，服务端共享任务仍沿用已有生命周期。

## 验收标准

- 连续刷新未变化仓库及重启后刷新，均不执行分支文档树扫描、不生成重复快照。
- 单个分支更新只扫描该分支；新增、删除、强推、默认分支变化及归档标签保持正确聚合；扫描规则变化不能绕过限额。
- 后台刷新不阻塞旧内容阅读，可见页面自动获得新版本；隐藏页面不轮询，回到前台补查；失败及凭据切换不交付错误来源。
- 适当自动测试通过，更新开发机服务，以配置的真实 token 登录原工作台验证无变化复用及远端更新自动显示，并记录实际耗时和限制。
