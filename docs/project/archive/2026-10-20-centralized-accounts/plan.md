# 实施计划

按 [Requirement](requirement.md) 和 [Technical](technical.md) 交付账号登录、账号绑定 Token 及跨浏览器恢复。任务按 T1 → T2 → T3 串行推进；实施前移交独立工作分支，并完成注册、登录、绑定列表和设备管理原型验收。

## T1 注册登录并绑定首个 Token 读取仓库

交付新账号、绑定及设备状态模型；用户自行设置账号密码，注册或登录后添加首个有效 Token，进入自己的工作台。接入现有发现与仓库读取，替换旧 Token 登录和测试身份准备方式。

验收：空账号能登录；重名、错密、限流和无效 Token 均有明确反馈；有效 Token 可读取本人仓库；他人工作台 id 与旧 Cookie／登录请求不能获得授权。

验证：会话与 API 测试覆盖唯一性、密码校验、Cookie、加密、账号归属和首个绑定；浏览器走通注册 → 绑定 → 阅读，并验证重启恢复。

## T2 跨浏览器管理多个 Token 与账号设备

交付绑定列表、命名、选择、去重、解绑，以及账号级设备退出。各浏览器独立选择，同浏览器标签页同步；接入读取代次和任务撤销。

验收：另一浏览器登录后直接使用已绑定 Token；两个账号绑定相同 Token 仍隔离；退出不解绑；解绑对全部设备生效；失效 Token 和临时平台故障不导致账号退出。

验证：两个账号、两个浏览器及同浏览器多标签页覆盖管理和越权；以受控延迟检查 A → B → A、解绑、单台／全台退出后的晚到响应及在途绑定，确认不恢复旧内容或授权。

## T3 新模型运维与完整验收

交付新格式密钥轮换、账号登录冒烟包装器、本地环境模板及使用说明，清除失效的旧模型说明和工具分支。隔离验证实例使用独立端口及数据目录；真实平台验证通过专用账号和 `withSmokeSession` 完成。

验收：服务重启和新格式密钥轮换保留账号绑定；冒烟成功或失败均撤销测试设备，清理失败明确报错；新模型不读旧数据，运行数据和秘密不进入 Git。

验证：运行 `npm test`、`npm run typecheck`、受影响文件格式检查、生产构建和 `npm run test:e2e`。构建 `.next` 前停止使用它的服务，同目录串行构建；浏览器测试使用 `.next-e2e`。复用已有成功检查，仅对新改动或未解决问题补测。

## 整体验证与交付

以需求八项验收逐项核对，安排与实现上下文隔离的独立评审。用户验收通过后同步访问能力 Spec，归档并合入 `develop`；再在主工作区执行 `service:update`，验证跨浏览器恢复、仓库读取及冒烟退出。更新时按技术方案清理旧个人身份数据，不重置新账号数据。
