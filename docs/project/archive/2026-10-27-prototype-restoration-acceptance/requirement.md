## 目标与范围

原型协作已有开发前设计确认，但缺少开发完成后核对实现还原的要求。补充通用于不同项目的验收指引，覆盖固定基准、视觉细节、动态状态、证据与环境限制及差异闭环。

本次技能内容已在 `a0939c8` 直接提交至 develop，当时遗漏 Change 记录。本 Change 如实补齐该交付的范围、验证及验收依据；创建与关闭时间采用实际补录时间，不改写原提交历史。

用户已确认补充方案：“可以，就按照之前说的，补充一下验收相关的内容吧”；交付后明确要求：“合入到 main 吧”。沿用上述范围、验收与合入授权。

## 方案要点

- Prototype 子技能保留触发条件、核心要求和详细参考入口；主流程在任务验证和关闭整体验证时引用它。
- 详细检查项放在按需读取的参考文件，沿用现有组件库、工具和验收记录，不新增强制工程、目录或审批。
- 技能版本为 `0.1.1`；仅补齐记录不再次增加版本，不改变 OpenFolio 运行实现。

## 验收

- 以用户确认的固定版本原型及源码为基准，后续明确决策优先，已批准差异有依据。
- 同视口、主题、数据和交互状态对照视觉细节，覆盖相关动态过程和异常状态。
- 浏览器表现与源码共同核查；环境受限的实际渲染标记未验证，不计通过，不据此删减效果或添加降级。
- 差异记录原型表现、实际表现、根因、处理及复验；报告区分通过、批准差异、未解决和未验证。
- 技能格式、相对引用和既有接入检查通过；经 Change PR 补齐集成记录，再以发布 PR 合入 main。
