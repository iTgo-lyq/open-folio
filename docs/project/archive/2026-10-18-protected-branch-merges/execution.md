# T1：保护分支正常合并

主 skill 与 Setup 指引统一为协作分支持续交付、保护分支决定正式上线。发布保留规划文档和提交历史，合并完成须核实远端祖先关系；保护分支修复回流使用 --no-ff，保留协作 first-parent 上的 Change 合入记录。

Agent 自查确认取消分支冻结、用户主动授权发布、项目开发验证服务和归档只读约束仍适用。本次没有修改应用、命令实现或状态协议，不新增发布引擎。

临时真实 Git 仓库验证通过：从旧单父快照恢复双亲合并、保留修改中的规划、连续发布、保护分支独立修复回流、原 Change 的合并提交继续位于协作 first-parent。旧快照造成规划文件 add/add 冲突时，先确认 main 与上一交付树一致，再采用 develop 后续修改；新 merge 同时保留源与目标父提交。临时仓库验证后删除。

主 skill、Setup 的 quick_validate 与 git diff --check 通过。工作流与文档调整不影响已验证的应用产物，不重复应用构建或浏览器测试。

归档后将规则集成到 develop，再从隔离 worktree 对 main 执行普通 merge，按固定提交核实历史和内容。真实发布、自动同步和清理结果留在 Git / CI，不回填本归档。
