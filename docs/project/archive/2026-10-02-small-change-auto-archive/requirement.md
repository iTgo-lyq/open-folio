# small Change 自验收后直接归档

## 背景与目标

用户明确要求：“这种小型 change 做完直接归档就行了。优化一下 skill。”取消 small Change 在整体验证后默认等待人工验收的停顿，由 Agent 按已确定的验收标准自验收并完成关闭。

## 范围与行为变化

- 调整 SpecTrail 的阶段推进与关闭规则：small 任务全部验证、提交推送且整体验证通过后，由 Agent 自验收，继续同步 Specs 并归档；用户明确要求人工验收时仍遵循该要求。
- medium、large、xlarge 保持人工验收要求；规模升级、失败返工和合入守护分支的授权规则保持有效。
- 验收结果沿用 `acceptance.result: accepted`，摘要必须区分 Agent 自验收和人工验收，记录实际依据，不增加字段或变更 JSON schema。
- `project-knowledge/change-tracking`：MODIFIED，工作台关闭步骤使用“验收”标签，具体方式由真实记录说明，兼容既有人工验收历史。

## 方案要点

这是单一规则调整及对应标签修正，按 small 执行。同步修改主 skill 中相关阶段表、整体验证和验收说明；复用现有状态字段、校验和四步关闭顺序。小型交付的自验收记录由本次用户授权的新规则支持。

分支 `codex/small-change-auto-archive` 从守护分支建立并纳入已归档的 `9ba0388` 交付。依赖 `impeccable-submodule`，保留当前工程源码基线和完整归档历史。

## 验收标准

1. small 的默认成功路径没有等待人工验收步骤；记录自验收依据后同步 Specs、移动完整目录并提交推送。
2. 需要人工验收的其余规模，以及用户明确要求人工验收的 small，仍保留原等待与确认条件。
3. 自验收和人工验收均使用现有 schema 可读取的记录，工作台标签不把 Agent 自验收标成人工验收。
4. skill 校验、现有状态校验兼容检查及与标签修改相称的检查通过；当前规则调整本身按新 small 规则完成归档。
