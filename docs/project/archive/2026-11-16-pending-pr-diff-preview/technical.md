# 待合入 PR 的 diff 预览

[需求与验收](requirement.md)

## 差异来源

登录工作台的差异读取在指定仓库快照中优先使用有效的合入记录。只有合入索引为 `missing`，且该 Change 的 PR 信息读取成功时，才从同一快照已精确关联的 Change PR 中选取唯一开放项，包含 Draft。索引异常、平台读取失败或存在多个开放项时提供对应提示。

正式差异继续比较合并提交的第一父提交与合并提交。PR 预览使用快照记录的 PR base 和 head SHA，在现有仓库 Git 缓存中求共同祖先，再比较共同祖先与 head。这会排除仅出现在目标分支上的修改。GitHub 原生 PR 页面在目标分支变动后可能采用不同的比较基点，页首提供 PR 链接，便于直接查看平台上的评审内容。[GitHub 比较规则](https://docs.github.com/en/pull-requests/reference/pull-requests#differences-between-commits-on-compare-and-pull-request-pages)

复用现有差异读取器的文件清单、分页、增删统计、逐文件读取及展示上限。摘要返回明确的 PR 预览状态与链接，文件、分页游标和 diff 始终使用同一快照所确定的提交对。仓库刷新已有同仓库来源及目标分支的 Git 对象，也会在 PR 信息变化时更新快照。所需对象因刷新竞态等原因缺失时，页内提示重新刷新。合入索引继续表示正式交付。

## 访问与页面

登录仓库 API 通过现有仓库授权开启 PR 预览，服务端根据快照决定读取范围。公开分享 API 使用仅正式合入的读取路径。PR 预览直接读取工作台已有的 PR 数据和 Git 缓存。

「合入变更」页复用现有列表和正文布局，预览时显示「待合入」或「Draft PR」与 PR 链接。现有自动刷新更新快照后，同页重新读取，合入记录可用时自动显示正式差异。沿用请求取消和文件失效回退，避免上一版本的文件或响应留在当前页面。用户已选择在功能验收时查看界面。

## 验证

使用受控 Git 仓库及 PR 夹具覆盖目标分支和 PR 分叉、PR 新提交、关闭、合入与记录不可读。验证公开分享的摘要、分页及逐文件请求均只允许正式合入来源。浏览器回归覆盖两个主要状态以及同一页随工作台快照更新自动切换。
