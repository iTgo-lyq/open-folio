# 阻止在集成分支提交已移交 Change 的文档修改

## 目标与范围

任务移交到独立 worktree 后，Agent 仍可能误改主工作区，并把实现与 Change 文档一并提交。现有提交校验只检查状态结构与原型引用，不能拒绝这种提交。

在现有 SpecTrail pre-commit 中增加本地归属检查：当前分支是 workflow 配置的集成分支，本次实际提交涉及 `docs/project/changes/<id>/` 下任意文件，且 HEAD 中该 Change 为 active、branch 已登记到独立工作分支时，拒绝整个提交并提示 Change、登记分支和本地可用的 worktree。不依赖集中副本的 stage；移交后集中副本可以保留规划阶段。

继续允许未移交 Change 的规划提交、首次分支移交登记，以及不涉及 Change 文档的极小变更。暂不识别只改实现而未同步 Change 文档的情况，不增加源码范围推断、网络查询或写入时隔离。

## 方案要点

复用现有 hook 和 Git 暂存区读取，以 HEAD 保存的归属判断是否已移交，避免本次修改 branch 字段绕过校验。按本次实际提交的路径收集 Change，覆盖新增、修改、删除和重命名来源；保留 `GIT_INDEX_FILE`，兼容 `git commit --only`，不受未暂存文档影响。

只约束集成分支的普通提交；登记工作分支及其任务分支继续正常提交。Git 正常合并仍沿现有 PR、归档与合码校验交付，不把交付带来的集中文档移除误判为手工修改。校验失败保留文件与暂存区，错误消息提供迁往正确工作区的操作线索。

同步技能说明及当前能力 Spec，技能与应用版本按仓库约定统一递增补丁号。

## 验收

- 在集成分支提交已移交 active Change 目录的正文、状态、增删或重命名，提交失败且 HEAD 不前进；集中 stage 仍为 requirement 时同样生效。
- 同次把 Change 的 branch 改回集成分支仍被拒绝，归属以 HEAD 为准。
- 错误消息包含 Change、登记分支，并在本地 Git 已登记对应 worktree 时输出路径。
- 未移交规划、首次普通与子 Change 分支登记、登记工作分支提交、正常合并以及不涉及 Change 文档的提交正常放行。
- 部分提交只检查其真实提交的暂存区，其他暂存或未暂存的 Change 修改不误拦截。
- 使用隔离测试仓库验证真实 Git hook 的通过和失败路径；不污染现有工作区与暂存区。
