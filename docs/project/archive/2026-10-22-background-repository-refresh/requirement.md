# 后台常驻刷新工程记录

## 目标与范围

当前远端检查由可见页面触发，关闭页面后缓存不再更新。改为服务启动后持续扫描各账号 Token 工作台中已接入的仓库，更新最新已推送的 Specs、Changes、交付信息和原型清单；保留现有定向分支读取及凭据隔离。

用户要求无人打开页面时降低轮询频率。本轮采用：页面活跃时沿用约一分钟检查；连续两分钟没有该仓库的页面刷新请求后，后台按每次扫描结束至少五分钟的间隔检查。服务重启后从现有绑定和发现记录恢复目标，不依赖用户再次打开页面。

只刷新已发现或通过仓库地址检查成功接入的仓库，不额外枚举新仓库、不编辑或推进仓库中的 Change / Spec。解绑、失权、网络故障和单实例数据目录沿用现有约束；服务停止期间不扫描。

## 方案要点

通过当前 Next.js 的 Node 服务启动入口启动单个后台调度器，开发服务与生产服务均可运行，构建阶段不启动。复用现有工作台凭据 lease、无浏览器读取入口、增量快照及并发刷新合并。页面刷新请求只登记该工作台、仓库和集成分支的近期活跃时间；活跃记录留在内存。

每分钟检查待执行目标，限制全局并发，同一轮不重叠。扫描完成后计算下次到期时间；单仓库或单工作台失败不阻断其他目标，失败保留最近成功快照并在后续周期重试。服务关闭时停止调度，不新增外部队列或独立常驻进程。

## 验收

- 无任何页面请求时，服务启动后能采集已接入仓库，且后续已推送的 Change / Spec 变化会在后台刷新中反映；重启后继续识别已有绑定和仓库。
- 页面活跃期间约一分钟检查，连续两分钟无刷新请求后使用五分钟间隔；手动刷新仍立即执行，后台与页面的同来源刷新复用现有合并机制。
- 多账号、Token、仓库与集成分支的活动时间和缓存相互隔离；全局并发受限、循环不重叠，解绑目标不再调度，失权不得发布新内容。
- 一个目标失败不影响其他目标；失败保留快照且会重试。停止后不再启动新扫描，构建期间不访问运行数据。
- 在独立工作区和独立数据目录验证，不启动、停止或重建当前前端测试分支服务；未获合入授权前不部署主服务。
