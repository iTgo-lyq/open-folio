# 技术方案

## 读取与更新分开

私有 workbench 继续使用已有本地快照路径。阅读模块是否活跃作为加载触发条件，Specs/Changes/原型之间的切换不重启相同仓库的数据请求。手动刷新、恢复到阅读区、仓库/分支/绑定变化仍触发必要读取。自动刷新保留已有单任务和一分钟复用机制。

分享详情默认先读取本地快照；仅快照缺失或可重建缓存无效时等待首次采集。详情读取增加明确的更新请求参数，客户端在缓存详情完成后请求更新，更新请求等待共享 refresh 完成并直接返回完整新详情。这样服务端无需新增后台调度、任务状态接口或丢失错误的后台 Promise。焦点恢复、周期检查与手动刷新使用更新请求，并合并当前页面在途更新。

分享详情可以返回构造时读到的完整、仍获授权的快照，不要求它在响应末尾仍是最新版；正文、图片、原型等资源继续按请求快照检查，版本变化时触发详情重读。初次读取与后台发布竞争时必须自动恢复，不能把 SHARE_VERSION_CHANGED 变成永久空白。发现目标在缓存中不存在时允许刷新后再判断一次，避免新 Change 因旧缓存误报不存在。来源切换后只使用对应来源的快照。

## 客户端缓存与连续阅读

使用有界内存缓存复用当前页面会话中的已读快照、正文及原型目录，避免引入新数据层依赖。缓存身份包括读取作用域、仓库/分支、材料身份和内容版本；正文按稳定内容标识复用，不能只按文档 id。私有读取作用域必须包含设备会话和当前绑定的恢复代次，分享作用域为规范化目标和来源快照。不要将私有正文或 Token 保存到 localStorage、浏览器持久缓存或公共 HTTP 缓存。

返回已访问仓库/材料时先使用仍属于有效作用域的缓存，再按现有入口检查更新。缓存限额按条目和总字节约束，淘汰只影响性能，不影响正确性。先以少量仓库与常用材料的容量实现，无长期持久化和迁移机制。

正文未变化时快照变化不重新请求相同正文。当前材料变化时保留已展示版本，在新正文完整取得后连同版本元数据一起替换；新目录已经移除的材料立即停止展示。对仍在更新的旧正文，链接和资源必须使用其实际版本或暂停可能混用版本的交互，不能用新快照解析旧正文。实现时优先原子提交阅读版本，避免新增普遍的双版本状态协议。

目录发现状态和列表首次读取相互独立，已有列表在更新期间保留。原型目录依赖稳定快照 key，避免 data 对象变化引发重复读取。所有异步结果以作用域/代次核对，旧请求不能覆盖新账号、绑定、仓库或材料。

## 临时失败与明确失效

会话后台检查的网络错误、限流和服务暂不可用保留最近一次确认的页面状态，并展示可重试提示；不能据此视为新一次授权成功或延长服务端权限期限。初次没有成功会话时仍显示加载失败。

显式登录、退出、切换 Token，或服务端确认会话失效/读取拒绝时，清空对应缓存并取消在途页面交付。继续遵守服务端五分钟固定授权有效期，权限到期复验失败不返回新的私有数据。普通目录更新失败保留原列表，明确失效移除不再可读的项。

## 登录恢复

登录后恢复会话时，若尚未选择且恰好有一个绑定，客户端自动调用现有选用接口，复用服务端 switchConnection 的远端身份验证和提交前归属检查；零个或多个时保持未选择。密码登录与选用分开，登录 Cookie 先正常交付，避免 GitHub 暂时故障把已成功登录变成失败。自动选用期间展示恢复状态，失败后保留已登录账号与绑定列表，明确显示错误及手动重试入口，不循环自动重试。

恢复尝试按设备、绑定和选择代次管理，结果交付前核对当前上下文；用户手动选择、解绑、退出后晚到恢复不得覆盖。直接复用已保存的加密绑定及偏好，不创建新绑定、不传回 Token。实际仓库读取继续走既有归属和权限检查；失效 Token 显示凭据问题，不降级成另一个账号或自动新增绑定。服务端账号与会话持久化格式、现有选用协议均保持不变。

已有设备选择不受其他浏览器登录影响。未选择但已有绑定的首页以「选择已有 Token」为主要动作，并显示当前账号；零绑定才以新增为主要动作。沿用当前布局和组件，仅调整状态文案及动作优先级，不新增设计系统组件。

## 验证与取舍

- 保留：服务端快照/Git/blob 缓存、权限有效期、刷新去重、固定版本资源和失败后会话清理，均有现有契约与真实失败场景支撑。
- 合并：阅读模块重复请求合并为仓库级数据读取；同版本材料复用有界客户端内存。
- 延后：目录分批返回、权限结果持久化、跨账号共享缓存及通用查询库迁移，均非本次体验修复必需。
- 不引入：额外后台任务系统、持久化浏览器内容缓存、数据格式迁移、例行备份或新的远端权限放宽。

测试通过挂起远端刷新验证缓存先返回，通过材料往返和模块切换统计请求，通过临时失败/退出/解绑/多账号/版本竞争验证连续显示和隔离；完整执行相关服务端与浏览器测试、类型检查及生产构建。medium 完成后独立评审，并交用户验收。开发验证使用隔离实例；合入后主工作区串行 service:update，使用 withSmokeSession 运行实际登录与缓存读取冒烟并核实清理。
