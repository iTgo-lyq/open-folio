# 直接读取协作分支并收敛工作流约束

当前后台仍用托管默认分支发现协作分支，发现阶段还校验保护分支存在；Skill 命令保留无协作分支的旧工作流。这使已配置的协作分支被无关分支阻挡，与集中协作的约定不符。

用户已明确要求本轮实现、验证后合入 develop，并更新主工作区长期服务。

## 行为与范围

- 仓库接入直接指定协作分支。自动发现以 develop 为推荐初值，手动接入可填写其他合法名称并保存；已选名称在重新发现、刷新、跨设备恢复和阅读链接中保持。
- 后台直接读取该分支的 workflow v2、Specs、当前原型和 Change 入口；Change 最新记录继续按 branch 定向读取。默认分支不参与配置发现、权限内容探测或刷新一致性判定，保护分支不参与内容来源判断和存在性校验。
- 保护分支保留发布约束：只有用户主动要求才合入或创建 PR，普通工作不能绕过该约束写入保护分支。
- 删除工作流 v1 的运行、校验和接入兼容；缺少有效协作配置时明确要求 Setup，不扫描全部分支。Change 记录本身的 schemaVersion 1 不变；与本次无关的登录数据格式不变。
- 通用 Skill 使用项目配置的协作分支；develop 只是推荐名。OpenFolio 本项目继续固定 develop 和主工作区 .next，任务路径沿用项目名-worktrees/工作区名。

## 验收

默认分支无配置、配置过旧或不可用、保护分支不存在时，合法协作分支仍可接入读取；自定义名称得到相同行为。错误名称、配置不匹配和旧版配置明确报错，不回退到其他分支。更换协作分支不复用旧来源快照或错误原型策略；当前身份权限与隔离保持有效。CLI 和 hook 拒绝旧 workflow，当前工作流的规划、移交、执行、归档及发布约束继续通过验证。Skill、当前 Specs 和用户文档与实现一致，长期服务来自已合入 develop 的提交。
