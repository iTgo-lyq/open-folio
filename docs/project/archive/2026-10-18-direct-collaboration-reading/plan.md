# 实现计划

## T1 接入与读取直接使用指定协作分支

交付：协作分支选择贯穿发现、项目读取、偏好和链接；定向 Git 采集及缓存只依赖该入口，取消默认和保护分支的读取依赖，同步相关产品文档。

验证：后端权限/采集/发现测试，来源变化与错误分支用例，浏览器接入与刷新验证，类型检查和构建。

## T2 移除旧版工作流兼容并统一 Skill 规则

交付：当前 workflow v2 成为共享校验、状态命令、hook 与 Setup 的唯一协议；保护分支只保留发布约束；Skill 使用配置的协作分支，develop 为推荐名称，保留项目自身的固定约定。

验证：共享脚本和 Setup 集成测试、旧版明确拒绝、新版规划/移交/执行/关闭流程回归、Skill 校验和文档核对。

## 执行顺序

| 任务 | 前置任务 |
| --- | --- |
| T1 | 无 |
| T2 | 无 |

两项接口边界明确，可由隔离上下文分工，所有写入协调在同一 Change 工作区；提交逐项限定文件。完整差异经独立 Codex 评审和回归后，按用户授权同步 Specs、归档合入 develop，再在主工作区更新长期服务。
