# 父子 Change 集成计划

依据 [Requirement](./requirement.md) 与 [Technical](./technical.md)，按 T1 → T2 → T3 串行推进。每项包含对应规则、实现与回归，复用同一父子 Git 场景验证各阶段，不为测试或文档单独拆任务。

## T1 子项从父分支移交并可靠读取交付材料

交付：统一父子关系、实际合入目标和材料来源解析；支持子项基于父分支建立工作区，集中登记仅包含规划变更；CLI 与工作台在子项自身、父分支归档和集中归档之间按权威来源读取。

验收：父分支已有实现时移交子项，子项包含该实现而项目集成分支不包含；重复或中断移交可安全恢复；父项未移交、已取消、关系不一致或来源不可读时明确失败。子项归档进入父分支后，即使子分支删除仍可读取材料；取消项仍使用保留来源。

验证：扩展 `workspace-routing`、`routing` 和 Git 读取用例，以临时 bare remote、worktree 和自定义分支名覆盖父子基线、来源切换与失败恢复；普通独立 Change 的移交行为回归通过。

## T2 贯通父子 PR 合入、依赖关闭与安全清理

交付：子项 PR 指向父分支；父项关闭及兄弟依赖基于真实子项交付；父项 PR 接收完整父子归档集合；合入、返修与清理按实际目标执行。Setup 和本仓库 CI 覆盖父目标，不增加审批流程。

验收：两个相互依赖的子项先后合入父分支，后项无需等待项目集成即可执行；错误 PR 目标、无关归档、缺失子项和未核实交付被拒绝。子项合入后禁止原归档返修，安全清理不破坏集中发现；父项整体验证后可整体交付，旧规则的真实历史仍可核实。

验证：扩展 `state-commands`、`archive-rework`、`pr-archive-check`、`integration-delivery` 与 `integration-prs`，用 PR 读取替身核实父子证据、重复候选、取消项及删除保护。运行同一隔离仓库从移交到父项整体合入的完整场景。

## T3 对齐工作台与发布核实并完成流程回归

交付：批量读取已知父目标 PR，区分子项进入父分支与进入项目集成历史；父子各自 diff、历史分支删除后读取及发布清单核实保持一致。精简 skill 主文和现有 references，递增技能补丁版本。

验收：仅合入父分支的子项显示待集成及父目标说明；父项整体合入后子项进入待发布判定。发布清单列出的父子项都能核实真实交付，父子 diff 不混淆。单个父目标查询失败不阻断无关 Change，普通和旧规则交付通过回归。

验证：扩展 `delivery`、`integration-records`、`integration-diff` 与相关发布校验；通过现有浏览器交付场景检查真实目标、说明和差异。运行 `npm test`、`npm run typecheck`、`npm run build` 与技能 `quick_validate.py`，对整体差异进行独立评审；检查 skill 无矛盾旧规则、重复说明及失效引用。

## 整体交付

向用户展示父子链路的测试证据和实际页面结果，人工验收后同步 Specs、归档并更新同一个 Draft PR。按授权合入 develop 后，在主工作区构建更新长期服务；登录冒烟使用 `withSmokeSession` 并核实清理。来源清理与发布沿用现有项目规则。

浏览器复用常驻 Chrome CDP，为本任务创建并关闭自己的标签页。工作区构建使用自身 `.next`；长期服务使用主工作区 `.next`，更新前停止占用服务。临时 Git 测试数据使用隔离目录，失败时保留必要诊断，不操作其他 Change 的真实分支或 PR。
