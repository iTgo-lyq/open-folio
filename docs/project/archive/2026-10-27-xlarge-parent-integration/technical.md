# 父子 Change 分支集成方案

需求见 [Requirement](./requirement.md)。核心改动是将项目集成分支、Change 合入目标和材料读取来源分开处理，复用现有父子关系、PR 标记与 Git 历史，不新增持久化交付状态。

## 依据与共享规则

代码调查确认：`workspace.mjs` 当前将同一个登记提交推送到工作分支和项目集成分支；`repository.mjs` 只在集中归档与登记工作分支间路由；`integration.mjs` 和 `github-prs.mjs` 固定核实项目集成目标；`check-pr.mjs` 只允许一个新归档；OpenFolio 的 `git.ts` 和 `delivery.ts` 使用相同的单层假设。现有 Git 隔离仓库测试、PR 读取替身及按目标分支分页缓存可复用。

在现有无文件系统依赖的路由与 PR 关联模块中集中表达以下规则，CLI、CI 和工作台分别提供 Git/平台读取适配：

| 对象 | 工作分支基线 | 交付 PR 目标 | 合入后的材料来源 |
| --- | --- | --- | --- |
| 独立 Change | 项目集成分支 | 项目集成分支 | 集中归档 |
| xlarge 父项 | 项目集成分支 | 项目集成分支 | 集中归档 |
| 子项 | 父工作分支，并纳入集中规划登记 | 父工作分支 | 父分支归档；整体集成后为集中归档 |

`change.json.branch` 始终保留所属工作分支；读取来源可随交付变化，不能把读取分支误当成原始所属分支。目标由有效的 `parent` 与父项所属分支推导，父子关系必须双向一致、父项为无 parent 的 xlarge，子项不得嵌套。父项未移交、已取消或已完成时，不建立新的子项执行分支。项目的 workflow v3 与 Change schemaVersion 1 保持不变。

## 移交与材料读取

普通 Change 继续使用现有移交路径。子项移交先从项目集成基线准备仅修改该子项 branch 的登记提交，再从父分支固定的已推送提交建立子分支并合入该登记提交。先推送子分支，再推送独立的集中登记提交；绝不将带有父项实现的子分支 tip 推向项目集成分支。合并冲突保留在子工作区解决，不覆盖父项当前文档。

沿用有限重试、普通非快进保护和仓库锁。重试以现有规划目录、登记和提交关系判断是否可复用；父基线、规划内容或目标归属变化时报告现场供核对，不增加操作日志或另一套登记文件。`--dry-run` 输出父基线、合入目标及两次推送的区别，不写入。

集中入口仍是发现起点。读取子项时，优先采用项目集成分支的有效归档；尚未整体集成时定向读取父项所属来源，若已有关系一致的子项有效归档则以此为准，否则读取子项自身登记分支。这里是按交付层次选择权威来源，不是因某个来源读取失败而使用旧副本；父项不可读或目标归档异常须明确报错。取消子项仍从保留的所属分支读取。

OpenFolio 先读取已登记父项，再解析其子项来源；同一父分支只读取一次。使用现有快照、分支上限和刷新一致性机制，原型与归档文档随权威材料来源读取。缓存版本按实际结构变化递增，旧可重建快照刷新后重算，不迁移账号数据或工程文档。

## 合入、关闭与清理

`preflight / verify / cleanup` 共用实际目标解析。对每个 PR 继续以同仓库、源分支、实际目标和唯一 Change 标记关联，普通 merge 的合并提交作为该项证据。子项的成功核实仅表示已进入父分支，不把项目集成分支名称用于这一结果。

父项关闭核对每个子项已取消，或有效归档且其 PR 合并提交已进入父分支。兄弟依赖使用所需子项交付提交与当前 HEAD 的祖先关系，不要求下游包含父分支在该交付之后新增的无关提交。人工可用性说明继续用于原有代码可用性核对，不能替代父子关系、归档或 PR 合入事实。

子项归档已进入父分支后不能 rework；后续修正走后继 Change。清理检查实际目标中可读取的有效归档、已验证提交及来源 tip 包含关系，保留现有脏文件、占用和其他入口引用保护。子项自己的集中入口仍保留历史 branch，但该子项已由父归档承接时不再要求保留其工作分支；父分支只有整体交付完成、所有子项材料可从集中入口恢复后才可清理。

旧规则下已直接合入项目集成分支的子项，沿实际的已合并 PR 和提交证据识别，并在父分支同步其交付后作为已有子项纳入整体核对。新建或未合入的子项 PR 必须采用父目标；不批量改旧 PR、不修改历史归档。如果同一子项存在多个已合并的候选交付，沿用歧义诊断，不自动挑选。

## PR 校验与发布

子项 PR 的来源登记从项目集中入口核对，父目标身份从该入口指向的父记录及 PR 固定基线核对；无需要求父分支已提前镜像每个子项的集中规划。子项合入只允许新增自己的有效归档。

父项 PR 的新增归档集合为父项加上本次首次进入项目集成分支的已完成所属子项。子项关系、已合入父分支的 PR 证据和归档必须一致，取消项不要求归档；已有集中归档继续只读。任意无关新增归档或缺失交付均拒绝。校验以固定 PR 对象与集中基线读取，归属判断不运行项目 hook 或业务脚本。

Setup 模板和本仓库 PR workflow 覆盖动态父分支目标；不通过固定 `change/*` 前缀猜父项，也不修改平台权限或保护配置。非交付目标的普通任务 PR可明确标为不适用，带 Change 交付标记但目标错误的 PR 必须失败。

发布清单继续显式列出实际包含的 Change。子项可通过自己的合并提交已进入项目集成历史来证明集成，即使其 PR 原目标是已删除的父分支；随后核实发布提交包含它。子项 diff 始终为自己的 `M^1 → M`，父项 diff 为整体合入边界。

## 工作台交付语义

PR 查询按项目集成、发布和已知父工作分支去重批量读取，继续复用分页、ETag 与失败隔离；历史父分支名称从父归档的 branch 获取，不要求远端 ref 仍存在。父分支 PR 查询失败只影响相关父子项，不能让其他 Change 全部变为不可读。

子项已合入父分支但未进入项目集成历史时，沿用“待集成”标签并说明“已合入父分支，等待父项整体集成”。差异摘要显示真实合入目标。父项整体合入后，子项自己的 M 已属于项目集成历史，进入现有待发布/已发布判定；合入事实和差异可用性仍分别处理。仅修改现有区域的数据与说明，不新增视图或交互流程。

## 精简取舍与验证

- 保留：PR 关联、归档完整性和删除前来源包含检查，分别防止错认交付、提前合入及丢失成果；沿用现有检查入口。
- 合并：目标选择、父子关系和材料来源的重复判断放入共享规则；skill 主文仅写分支路径与关闭条件，命令细节各自放在现有 references。
- 延后：任意多层父项、可配置的多套合入策略和批量迁移，当前需求不需要。
- 建议删除：被替代的“所有 Change 直接合回项目集成分支”和“父 PR 只能引入一个归档”的无条件表述，不增加新的审批阶段或哈希清单。

用本地 bare remote 与 worktree 覆盖完整父子链、推送中断重试、错误目标、取消、清理后读取和历史直接交付；PR 查询使用现有替身，不创建真实测试 PR。工作台通过读取/交付单测和已有浏览器入口验证目标说明、差异及待集成判定。执行时运行相关单测、全量测试、类型检查和生产构建，最后独立评审。整体验收后合入 develop，按项目约定更新长期服务并以 `withSmokeSession` 冒烟；本次规划阶段不更新服务。
