# 交付计划

依据 [Requirement](requirement.md) 与 [Technical](technical.md)。

## T1：以静态业务片段替代七组手写原型

交付七个直接引用业务组件的 TSX 入口、类型化内存 mock、静态构建与匹配现有产品的评审场景；清除不再引用的旧实现与验证脚本，更新包内约定和使用说明，保留历史固定引用。

验收：不启动真实应用即可浏览各片段，主题与关键局部交互工作正常；无真实后端或持久存储副作用；清单、截图与发布协议保持兼容。

验证：原型单元测试、类型检查、自包含构建、七入口 × 明暗 × 声明设备及窄屏浏览器验证，关键表单/列表/目录/画布操作，prepare 协议检查及独立评审。证据写入 Execution；如环境限制无法核实，记录具体限制与复现步骤，不把未通过项记为成功。

## T2：发布七组静态片段并替换旧原型引用

沿用 T1 已验证实现，从干净提交构建并生成标准缩略图，上传公共 R2，登记七项当前 artifact 与本 Change previews，清除“仍是旧发布”的过时说明。核对远端分支、标签和 Change 引用后，清理已无引用的旧原型对象，不备份、不删除仍被未切换入口使用的对象。

验收：七个页面与 21 张标准图公开可读，固定 URL、摘要和源码提交匹配；真实工作台展示本 Change 的新原型及缩略图，关键交互可用。旧架构与专属数据不进入新产物，无真实账号或工作台数据改动。

验证：重新构建与截图、prepare/upload/register、公开字节检查、浏览器检查和真实工作台独立 smoke session；核对清理范围与删除结果，证据追加到 Execution，不覆盖 T1 记录。

## T3：按业务状态还原片段并重新发布七组原型

评审返修 T1、T2。Specs、Changes 与分享片段的加载、失败、空态改为与业务页一致：工作台片段按 `Workspace` 的读取占位和同步失败横幅呈现，分享片段按分享页的读取、失败和不可读状态呈现，空态直接由业务组件按空数据渲染；两处业务状态未导出，在原型包内按原文案和样式轻量还原。修正清理记录：已删版本只是当前分支无引用，历史提交与旧公开预览中的引用按不兼容历史数据处理。

验收：七组片段的所有声明场景都显示对应业务状态，不再出现包内自拟的“只读材料”占位；重新发布的七页与 21 张标准图公开可读，当前清单与本 Change previews 指向新版本。

验证：类型检查、构建、包内与协议测试、浏览器矩阵与交互检查，重新截图、发布、公开字节核对和真实工作台 Change 预览检查；独立评审覆盖 T3 差异。

用户已授权完成优化后归档并合入 develop，并明确不考虑历史数据兼容。合入后检查默认原型总览与新 Change 的原型页正常；仍被 develop 归档引用的旧版本不再另行清理。
