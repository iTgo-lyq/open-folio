# 独立评审

## R1：来源丢失保护只维持一次刷新（P1）

独立只读评审在临时仓库中复现：实际 requirement 分支删除后，第一次刷新清空 primary 并提示不存在，第二次刷新不再识别旧来源，回退到旧集中标题且诊断消失。原因是仅依赖上一快照的 primary 判断曾有归属。T3 已复用既有 Git 跟踪元数据作为历史归属证据，不将其收集或提供为当前来源。回归覆盖连续刷新和 SnapshotStore 重启。原独立评审者在临时仓库连续四次刷新（含两次重建 Store），均确认 primary=null、保留不存在诊断且不返回旧目标正文，问题关闭。

## R2：父子都预填时 CLI 无法继续澄清（P2）

父项与子项的目标都尚未建立时，后台能从集中分支读取，但 CLI 的 locate/show/retitle 子项会报父项未移交。原因是仅按父项文本 branch 判断是否尚未启动，未看解析后的实际来源。T3 已按解析后的父项实际来源判断规划。原独立评审者复验 locate/show/retitle 均成功且保留 pause，补查子项目标存在时的继承记录与真实归属两种变体，CLI 与后台均一致；回归同时确认创建子项工作区仍拒绝未实际移交的父项，问题关闭。

## R3：暂缓摘要缺少原型暂停图标（P3）

Astra 只读对照发现列表和看板只有暂缓文字，未还原已确认原型的中性暂停图标。T2 已补充 aria-hidden 的 CirclePause，并保持详情同款图标；浏览器验收通过。Astra 复查正式列表和阶段看板截图，确认此问题修复、无新增问题。

## R4：循环父引用触发栈溢出（P3）

复验发现新增递归在拒绝嵌套父项之前调用自身，非法循环 parent 会丢失原有明确诊断。T3 在递归前复用既有父项存在和非嵌套校验，并增加 show/locate 的循环父链回归。原评审者复跑原临时仓库场景，两个入口均明确返回 parent is missing or nested，不再栈溢出，问题关闭；本次复验无新增问题。

正式实现评审由独立子 agent 完成，原型还原对照由 Astra 完成。GLM 评审在用户要求后已终止，未采用其输出。
