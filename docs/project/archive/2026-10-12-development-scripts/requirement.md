# 开发服务与原型工具

## 背景与目标

当前是开发机环境，长期经 Merlin 暴露的 OpenFolio 服务随开发任务保持最新。将临时启动、截图逻辑沉淀为项目脚本，清理已完成任务的临时产物，保留当前工作台运行数据。

用户已确认服务更新允许短暂停机、不创建例行备份或回滚快照；冒烟检查由当次任务 Agent 自主选择。真实工作台 Token 存放在未提交的本地环境配置，模板仅定义配置项。

## 范围与行为

- ADDED：项目提供长期服务的启动、停止、状态、更新命令。沿用 Node.js 24、tmux 和默认 10680 端口，目录由项目位置推导，配置从本地环境读取；更新先停止服务再构建 `.next`，随后启动，不备份、不重置工作台数据。
- ADDED：原型包提供通用截图命令，接受自包含 HTML 入口、输出目录、标准设备或自定义视口，默认生成 PC Web、iPad、Mobile 三张 PNG，复用已有沙箱与发布约定。
- ADDED：根目录 `.env.example` 定义服务配置、验证地址和 Token 占位值，真实值放 Git 忽略的 `.env.local`；不增加固定冒烟流程。
- REMOVED：已替代或失效的临时脚本、截图、日志、闲置测试构建和失效测试现场。运行中的 `.next`、当前数据目录及已发布原型版本继续保留。

## 方案要点

新增两个本地工具职责：服务生命周期管理和原型截图，预计不足 300 行有效实现代码，不改变产品 API、权限或持久化契约，按 small 推进。服务管理复用 tmux 保持脱离终端运行，并防止并发更新、覆盖运行中构建或占用其他进程端口；截图复用既有 HTML 检查和 CSP，在启用 OS 沙箱的 Chromium 中通过不透明 iframe 渲染。现有 R2 发布器继续收集标准命名的截图。

## 验收标准

- 命令可以在项目外调用并正确定位仓库；服务重复启动不会产生第二个实例，停止释放监听端口，更新失败不会覆盖运行数据或创建备份。
- 服务从新脚本成功更新并继续在 Merlin 原端口提供页面；状态能区分停止、启动和运行中的服务，保留构建来源信息。
- 实际原型可生成三种标准视口及自定义视口截图；无效参数、外部资源及渲染失败明确报错并释放浏览器和本地服务器。
- 配置模板不含真实凭据，项目指南说明脚本入口；临时目录不再承载正式脚本，也不参与类型检查。
- 清理完成后保留当前工作台状态、密钥和公开版本，不留下本次验证产物或测试构建的失效类型引用。
