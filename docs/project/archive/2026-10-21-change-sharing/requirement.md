# 单个 Change 的公开只读分享

## 目标

协作者需要把一个 Change 的需求、方案、原型及推进详情发给其他人，对方拿到链接即可阅读，无需登录 OpenFolio 或配置 GitHub Token。用户要求内容自动跟随最新已推送版本、包含全部详情，并在技术文档或原型就绪后由 Agent 主动给出链接。

用户进一步明确：“分享链接设计上不该和账号挂钩，任何人都可以分享。只要那个 change 实际存在。”链接应直接指定仓库与 Change；不需要先创建分享记录、指定分享账号或开启分享。

## 范围与行为

分享地址由 OpenFolio 服务地址、仓库地址及 Change ID 组成，可直接构造和转发。工作台中的“分享”提供复制及打开阅读页的便利入口，不创建授权记录。原有“复制页面链接”仍用于恢复个人工作台的阅读位置。

匿名请求以链接中的仓库和 Change 为目标。服务能够读取且目标实际存在时，展示完整详情；接收者和分享者均无需提供账号、Token 或连接 ID。没有可用读取来源时显示“内容不存在或暂不可读”，一个 URL 不会赋予服务本身没有的仓库权限。

不增加逐仓库或逐 Change 的分享开关。服务已接入且可读取的仓库，包括私有仓库，均适用上述行为；链接不依附某个创建者。读取来源退出设备不影响链接；某个来源失效后，同一仓库仍有其他有效来源时继续可读。所有来源失效时停止交付，恢复可读后原链接仍可使用。

分享页包含指定 Change 当前可展示的全部详情：概览、任务、需求、技术方案、计划、执行与评审记录、澄清问答、阶段确认与关闭依据、图片和图表、原型，以及代码合入记录、文件列表与差异。尚未产生的材料沿用工作台的缺失或未就绪状态。

页面复用已验收的全宽文档阅读布局：材料目录、内联正文、章节导航、专注阅读与字号切换；支持桌面、平板和手机，不提供任务编辑、阶段确认或仓库写入。

每次读取限定在链接指定的 Change 内。其他 Change、Specs 和仓库浏览不混入详情响应；范围外的正文引用提供明确提示。其他 Change 可以使用自己的直接地址读取。地址不是保密凭证，不以随机标识充当访问控制，也不提供匿名全仓库枚举接口。账号、凭据、连接信息和个人工作台数据不进入分享响应。

同一链接跟随中心 Git 最新已推送内容，沿用工作台的刷新节奏与来源解析。规划移交、工作分支变化、归档和合入后仍定位同一个 Change；文档与原型深链继续定位相同材料。本地未提交或未推送的修改不属于最新内容。一次阅读的正文、图片、原型及差异对应明确来源，不混用版本。

临时网络失败或限流显示同步失败，不能冒充已取得最新内容。前端可保留本次已显示的正文并标记未同步；服务端不得在权限失效后继续从旧缓存交付响应。

本次不提供创建、停止、撤销、重新生成分享的状态管理；直接链接随目标内容和服务读取能力可用。也不增加密码、指定收件人、评论、编辑、访问统计或到期设置。

## 服务地址与 Agent 提供链接

复用 `docs/project/workflow.json.openfolioUrl`，保存接收者实际可访问的服务地址。该字段已有 schema 和设置命令支持，本仓库尚未填写；可用原型设置命令的 `--configure --openfolio-url <地址>` 更新并保留原有托管选择，不新增重复字段。

`OPENFOLIO_VERIFY_BASE_URL` 仅供冒烟检查，`prototype.hosting.uploadUrl` 是上传入口，两者均不能代替分享服务地址。部署时核实外部入口的匿名可达性，仅有 localhost 或平台登录后的可达性不足以完成本需求。

Skill 在技术文档推送后，或原型发布、引用登记并推送后，主动给出链接，尽可能定位本次文档或原型。链接工具只需服务地址、本地仓库和 Change 信息，从 Git origin 及 workflow 取得仓库地址和协作分支，不需要分享账号、密码、Token、Cookie 或绑定 ID。

工具匿名核实目标存在、材料可访问，并返回读取来源。Agent 核对服务已读到本次推送后再称为最新交付。地址未配置、服务不可读或材料尚未同步时如实说明，并提供仓库文档或已发布原型入口，不把未验证 URL 当作可用结果。

Skill 改动保持精简：主流程说明触发时机，具体命令集中在一份参考，原型子 skill 引用同一说明；不新增审批、状态字段或重复配置，不将地址写入每个 Change。

## 产品取舍

- **Q1（需求：更新方式）**：自动跟随最新已推送内容，不固定在创建链接时的版本。
- **Q2（需求：内容范围）**：包含全部详情和合入差异；技术文档与原型就绪后主动提供链接。
- **Q3（技术：原型）**：先制作原型；用户随后确认全宽文档阅读方向。保留布局，按新要求简化分享入口。
- **Q4（需求：分享范围）**：链接直接指定仓库和 Change，目标存在即可分享；去掉账号归属、创建记录和额外开关。服务仍须实际具备源内容读取能力。

## 验收

1. 无需创建分享或登录，直接构造仓库与 Change 链接即可阅读存在且服务可读取的目标。工作台可复制和打开相同地址，没有开启、停止或重新生成操作。
2. 全新匿名浏览器可阅读该 Change 的全部详情、正文、图片、原型与合入差异，不请求个人会话或私有工作台接口，不要求 Token。
3. 同一链接在刷新与自动检查后显示最新已推送内容；移交、换分支、归档、合入及服务重启不改变链接。相对文档路径与原型 ID 深链有效，未推送内容不出现。
4. 子资源接口仅读取指定 Change 的合法内容；修改文档 ID、快照、提交或路径不能越界。修改仓库或 Change 表示新目标，必须重新校验；私有 API 保持原权限要求。
5. 设备退出不影响链接。单一来源失效可切换同仓库其他有效来源；全部失效后不交付旧缓存。目标不存在、服务不可读、同步失败及版本变化均有明确状态。
6. 正文关联引用、外部链接、缺失材料与图表可理解；正文不执行任意 HTML 或脚本，Git 原型保留现有沙箱。
7. 桌面、平板及 390/320px 手机宽度可完成复制、打开和阅读；全宽与专注布局、目录焦点、章节定位及材料切换可用。原有工作台链接和独立原型公开链接继续有效。
8. 配置 `openfolioUrl` 后，Agent 无需分享凭据即可获取并验证文档或原型链接，在本次推送可读后主动提供。错误或未同步不报告成功，真实外部链接通过匿名访问验证。

## 现状依据

- [个人访问与分享](../../specs/project-knowledge/access/spec.md)目前规定工程阅读链接不转让权限；本次新增独立匿名 Change 入口。
- T1、T2 已在工作分支实现初版服务与全文阅读页，尚未集成长期服务，证据见 [Execution](execution.md)。本次替换分享身份及管理机制，保留读取与布局能力。
- `Repositories`、`Discovery`、`PersonalSessions` 分别提供仓库上下文、按绑定发现的仓库和持久绑定；新目标解析不能依赖分享者 Cookie。
- 现有 provider 只支持 GitHub.com，本次沿用该范围；`openfolioUrl` 已获服务端与 Skill 校验器支持，尚无无账号分享 CLI。
