# 方案与原型验证依据

## 无账号直接链接的修订依据

T1/T2 初版提交后，用户否定按账号创建分享的前提，并明确：“链接上指定change和仓库，被分享者拿到链接后，只要目标访问内容真的存在就分享给他。”当前 Requirement、Technical 与 Plan 已据此修订。以下关于随机分享、撤销及账号 CLI 的调查和原型记录属于此前方案历史，不作为新契约依据。

代码核实：持久绑定与设备会话分离，T1 已提取内部 `credentialLease`；Discovery schema 2 按绑定保存仓库、稳定身份和协作分支；Repositories 可用内部 lease 复用权限与刷新能力。因此无需新增分享账号即可从已有来源读取。仍须实现跨来源目标解析，现有方法签名不代表新功能已完成。

配置核实：`workflow.openfolioUrl` 已支持但本仓库未填写；`--configure --openfolio-url` 保留原托管选择。先前拟议的 `OPENFOLIO_SHARE_*` 不再需要。本轮仅只读核对 Merlin 链接：11117 的入口当前非公开，其他端口另有公开服务；未替换、停止或修改它们。后续围绕仓库指定的 11117 服务验证匿名入口。

## 代码调查

已从账号/仓库读取及前端阅读两个方向分别做只读调查，核对结果收敛到 [Technical](technical.md)。关键约束为：现有 workspaceLease 创建仍依赖设备 Cookie；完整 Workbench 含全仓库与原型配置；永久公开原型不能承担可撤回的 Change 分享；文档 id 在换分支和归档路径变化时不稳定。未调用真实分享写接口，当前服务没有本次拟新增接口。

本轮协作分支已集成 `change-labels-urgency`，方案采用标签、紧急程度与 schema 7 的现状，不沿用此前 schema 6 的调查快照。生产账号数据不迁移。

方案复核补齐两个现有契约：CLI 写请求须带 Origin 与当前 revision，并在解析正文前保存响应 Cookie；返回材料须按来源提交或原型固定引用核对本次交付。成功链接只在独立设备会话清理完成后输出，相关失败场景已列入 T3 验证。

## 分享模式原型

按技术澄清 Q3 制作 `packages/prototype/src/pages/change-sharing.html`，默认进入接收者的技术方案阅读页。顶部评审工具切换接收者/分享者、正常/尚未分享/已停止/来源不可用/同步失败/读取中，并可模拟新内容推送。hash 支持定位页签、文档、视角和场景。所有项目、材料、提交和分享链接均为示例；不调用业务接口、不保存浏览器持久状态。

视觉采用正式产品浅蓝白色基线。桌面材料导航与正文并列，手机材料导航横向排列，代码差异在文件列表和正文间往返。分享管理包含公开范围说明、复制、停止、重新生成链接以及接收者预览。

实际执行：

```bash
npm run build --workspace prototype
npm run screenshot --workspace prototype -- --entry dist/change-sharing/index.html
node packages/prototype/verify-change-sharing.mjs
```

构建导出 14 个既有及新增自包含入口，本次仅发布 `change-sharing`。标准截图生成 1440×900、834×1194、390×844 三种设备；已查看桌面及手机截图。浏览器检查在仅有 `allow-scripts` 的不透明 iframe 和既有 CSP 下运行，1440、834、390、320px 四档均通过，无页面异常、外部网络请求或整页横向溢出。

交互覆盖：六页签、材料切换、范围外链接提示、模拟文档更新、原型筛选与设备切换、代码文件选择和手机返回、创建/停止/重新分享、失效后隐藏正文、复制受限时手动兜底、同步失败重试、来源不可用重试及键盘页签导航。停止后重新创建得到不同示例 id。验证结果和分享弹窗截图位于 Git 忽略的 `artifacts/change-sharing-prototype/`；可用上述脚本重现。

该证据证明原型交互与显示，不证明尚未实现的服务端权限、实时 Git 读取或真实分享链接可用性。
