# Change 列表按创建时间倒序

默认按 Change 首次进入 Git 的提交时间从新到旧展示，后续修改和归档不改变创建时间。时间相同按 ID 稳定排序，历史无法追溯的记录放末尾。创建时间仅代表首次提交，不声称是文件实际创建时间。

## 方案

在 Git 读取层追溯集中入口及登记来源可达历史中的 change.json，兼容归档移动与历史合并；时间进入可重建快照，不改变 SpecTrail 状态文件契约。更新快照指纹使既有缓存刷新生效。列表、筛选后的列表沿用同一默认顺序，延续组按最新匹配成员出现的位置排列。

## 验收

- 新记录排在旧记录之前，相同时间按 ID 排列，未知时间置后。
- 后续修改与归档仍保留首次提交时间；分支来源与合并引入记录可追溯。
- 缓存刷新后排序生效，既有筛选和延续分组正常。
- 运行相关自动化测试、类型检查与构建，集成 develop 后更新长期服务并冒烟。

用户已确认上述方向：“没问题，继续吧”。范围为局部读取与排序，不改变持久化工作流契约，按 small 执行。
