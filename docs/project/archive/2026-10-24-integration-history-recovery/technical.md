# 简化合入确认、差异定位与来源清理

落实 [Requirement](./requirement.md) 中已确认的简化取舍。CLI、工作台和 CI 各自使用所需事实，不再把差异索引当作通用交付门禁。

## 三项职责

| 用途 | 最小证据 | 失败影响 |
| --- | --- | --- |
| CLI 确认代码纳入 | 当前来源 tip 是远端集成 tip 的祖先 | 保留尚未纳入的来源 |
| 工作台展示差异 | 目标 Git 历史中唯一带 Change 标记的双亲合并提交及归档位置 | 该差异不可用，保留诊断 |
| 删除来源 | 来源已纳入已验证的交付提交，且不存在新增成果、依赖或占用 | 逐对象保留或失败，可重试 |

## CLI 与清理

读取集中入口确定来源归属，定向读取远端目标和来源引用，以 merge-base --is-ancestor 比较所有仍存在的本地/远端来源 tip。verify 返回目标和来源身份及 sourceIncluded，不再返回一个由格式校验认证的 M。来源引用均不存在时报告 sourceAbsent，sourceIncluded 为 null，不宣称重新证明了已删除来源的代码。

cleanup 不调用差异扫描器。保留 --verified-commit 作为 Agent 已完成交付/服务验证的实际 Git 提交：它须属于当前远端集成历史，当前工作区包含它，所有待删来源 tip 均已纳入它。该提交可以是 PR 合并提交或后续已验证提交，无须具有特定 trailer 或第一父位置。

保留来源归属、主工作区、活动/取消入口依赖、Git 操作和工作区文件/占用检查，以及预期 tip 条件删除。清理不重复比对归档与来源字节，也不重演合入前 CI。来源全部已不存在时返回已清理，可继续部分清理；代码纳入与清理分别报告。

preflight 保留合入前来源归档、推送和归属检查。归档返修仍拒绝恢复已被目标包含的来源，差异定位不作为唯一合入事实。

## 差异与交付状态

差异索引直接使用 git log --merges 查询固定集成 tip 的完整可达历史，不使用 first-parent 限制或自定义路径遍历。唯一合法标记、双亲结构及归档目录定位只用于找到 M、M^1、来源与归档位置。删除合入后的归档状态重验、首次引入检查、第二父归档和子树逐字节比较；归档完整性由合入前 CI 负责。不同合并提交重复标记时差异报歧义，不任选一份；普通非合并提交中的标记不参与。

工作台优先使用可定位的 M；索引不可用时，使用现有 PR 数据中已合并且 mergeCommit 属于集成历史的证据判断已集成，不增加平台请求。发布状态继续核对发布 PR 的包含关系与真实 Git 祖先关系。差异错误作为诊断保留，不否定已证明的 PR 合入。

INTEGRATION_VERSION 递增到 2，使同 tip 的旧索引按新规则刷新；索引结构保持，旧快照不改写。差异仍为 M^1 到 M，原型沿用固定提交及已有路径/授权检查。发布 CI 继续检查候选归档与其交付内容，不把这些检查放回清理路径。

## 验证与交付

回归普通与第二父路径上的合入、标记缺失/歧义下独立清理和 PR 状态、旧缓存重算、固定差异及来源删除后冷读取。删除保护覆盖新提交、文件、依赖、占用、远端 tip 竞争和部分清理重试。运行相关测试、完整项目与自包含测试、类型/格式检查、构建和 medium 独立评审。

人工验收并获合入授权后更新 develop 长期服务，登录冒烟使用 withSmokeSession，确认匿名退出及无可见绑定。再核对 skill-auto-update 现有来源及实际占用，继续已授权清理；不改写历史或归档，不发布 main。

## 取舍核对

保留 Git 实际纳入与防误删检查；移除 first-parent 门禁和合入后归档重复证明；合并使用现有 Git 历史查询及既有 PR 数据；不实现原自定义遍历、同步引擎或额外 API 兜底。接受不再于合入后单独证明归档与来源逐字节一致这一保证收窄。
