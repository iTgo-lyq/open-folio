# 独立评审

独立子 Agent 在无实现对话上下文的会话中检查需求、全部生产差异与测试，执行针对性回归和真实 Git 反例。

## R1 归档自身关系错误被跳过

原实现的归档模式在关系校验前返回，自 dependsOn 或自 parent 会被错误认定为有效发布归档。已保留发布快照内可判断的关系、环与父子形状校验，仅忽略未在归档集合中的外部来源依赖。自引用反例及既有取消子项案例通过。

## R2 异常日期目录中的重复归档被忽略

原实现提前使用合法位置解析器过滤归档路径，导致有效目录旁的 2026-99-99 同 ID 归档被忽略。已保留形似归档路径的候选，由既有目录校验和唯一性校验拒绝。无效日期单记录、同 ID 重复记录回归通过。

## R3 PR 错误仍阻止发布快照

保留原限流和损坏缓存的全局异常会让已读取的新发布归档无法更新。已将 PR 限流/元数据限额转为停止后续 PR 查询并显示诊断，缓存损坏使用有界冷读取；身份失效、仓库权限失败和取消继续中止，发布前权限检查不变。已发布条目继续进入合入时间未知，不推进 PR 成功时间、不覆盖完整缓存的失败页。

最终独立复验：两处校验缺口已关闭；缓存重试、重启复用、发布提交和已知 ID 集合变化失效通过；最终 PR 错误隔离相关 21 项检查通过，无未解决问题。

## R4 版本文件超限被误当作缺失

T2 独立评审发现：超过读取上限的版本文件被跳过，随后错误回退 tag，可能将未读取文件中的真实版本替换为另一版本。已引入确定的 unreadable 结果，超限、符号链接等不可读取文件不被 tag、其他小文件或旧 PR 标记覆盖；按提交缓存，避免重复读取。临时 I/O 失败仍可重试。归档和时间不受版本读取失败影响。

T2 最终独立复验：版本读取、缓存和交付投影 25 项全部通过；另以独立实验核实 tag 正负缓存 TTL、后补、移动和文件缓存复用，git diff --check 通过，无未解决问题。

## R5 去标记后的父子身份

T3 独立评审发现 CI 的 children 循环遮蔽了父项 id，导致正常 xlarge 交付被拒绝。已显式比较父记录 state.id，无标记父项携 completed/cancelled 子项的真实 Git 回归通过。

## R6 提前返回后的后台权限传播

冷列表返回后，后台 PR 读取的凭据拒绝不再经过原 HTTP 调用的外层 catch。已在后台凭据租约内传播权限失效，并保留 Git 获取失败后的强制权限复查。新增测试在首屏返回后拒绝 Token，完全不发起另一个 refresh 等待者，后续工作台读取仍返回 401。最终发布失权保留先前指针，重启可补齐历史。

## R7 空发布范围隐藏重复归档

仅按新增 ID 算范围会忽略旧 ID 的新增日期目录。已在计算范围前拒绝归档 ID 对应多个归档或活动记录；已有归档只读。真实 Git 测试覆盖无新增 Change 的发布加入重复旧归档和同 ID 活动入口，均拒绝。

## R8 首屏历史人工补记

首屏曾只认 releaseBranch 有效归档，遗漏仍受兼容支持的有效集成归档 deliveryOverride。已抽取同一判定供首屏与最终投影复用；首屏回归确认历史补记立即进入已归档，不能因后台失败留错 tab。

T3 最终独立只读评审：上述问题均关闭，批量对象/合入差异、发布 first-parent 追溯、更新时间分页/ETag、文件缓存、权限边界和现有页面补齐链路未发现未解决问题。独立执行的相关测试 99/99 通过；独立评审没有冒称运行全量测试或千级基准，后两项由实现 Agent 执行并另行记录。

最终容量计数优化独立复验：冷两页（重复 PR 替换与新增 ID）、暖增量、多字节与转义的真实序列化字节计数一致；1,429 / 2,263 B 精确上限通过，少 1 B 均明确超限，失败暖更新保留旧缓存。无新增问题。

## R9 T3 后代码评审

Claude Code 会话执行人工走读并另起隔离上下文的 code-review，覆盖 develop...codex/release-archive-detection 全部差异。以下问题经复现或对照代码确认，由 T4 返修：

- 写 Git stdin 未监听 error。批量 blob 输入超过管道缓冲时，取消、超时或 Git 提前退出产生未处理 EPIPE，长期服务进程退出；Node 24.21 以 6000 个 blob、1 ms 后取消复现。
- 合入差异批读以 `\0` 加十六进制切分记录，单亲提交的 `%P` 被误认作新记录并抛 TypeError；任一 squash/rebase 合入的 Change PR 使整批不可用，所有未缓存 Change 显示合入差异暂不可读取。
- 发布快照读取失败把全部已知 ID 记为 unavailable，并把进行中、待集成 Change 一并降为 unknown。
- 最终发布时 PR 缓存先于 beforePublish 写盘，权限复查失败后仍保留本轮读取结果。
- tag 缓存 checkedAt 每 5 分钟变化、版本文件结果键顺序不稳定，均使未变化判断失败；只保留 3 份快照，固定快照页面约 15 分钟后过期。
- PR 读取失败时保留旧 releasePrs 却丢弃 releaseMergedPrNumber，已定批次在限流期间跳回合入时间未知。
- 发布 CI 对每个旧归档启动两次 rev-parse，且删除旧全量差异检查后不再拦截不属于任何记录的归档路径。
- 新登记 Change 改变 ID 集合即丢弃全部首次引入并重遍历发布历史。
- 遗留无效代码：共享目录读取后的 catalogStopped、只含已合并 PR 时不可能成立的 releaseConflict、无用别名及 preflight 不再读取的 associated。

按用户“极端场景不用死磕，目前还碰不到”的要求，以下记录为已知限制，本轮不改：

- 祖先判定一次读取目标完整 rev-list，超过约 40 万提交会触发 16 MB 输出上限，集成核实不可用。
- Change PR 仅按登记分支关联；已归档 Change 的分支名被新 Change 复用时可能误关联。默认分支名含唯一 ID，当前协作不会复用。
- 合入差异批读不复查全树归档唯一性；同 ID 重复归档已由 PR CI 拒绝。
- 版本识别每个发布提交一次 ls-tree，200 批约 200 个进程。
- 归档 ID 提取规则分散在多处，对非日期前缀的处理不一致。

## R10 归档前复核

Codex 复核另一 Agent 的 T4 实现、回归和已知限制，确认 R9 的修正均针对实际缺陷，无需增加极端场景机制。补齐旧发布批次复用的目标分支条件：上次 PR 必须属于当前 releaseBranch，且合并提交仍等于首次引入提交；新增同一提交改配发布分支的回归。清除主 skill 同仓库合码段落残留的 Change 标记要求。

最终定向回归 46/46 通过，包含 Git 管道、合入差异、交付降级、PR/tag 缓存、版本识别、发布 CI 和服务生命周期；上轮受沙箱环境影响的服务生命周期用例本轮直接通过。类型检查、生产构建、修改代码格式检查、skill 校验及 git diff --check 通过。无未解决的归档阻断问题。

Performance 中千级耗时仍明确为 T3 实测；T4 没有重新测量全部千级样本，不将网络估算作为吞吐保证。提交历史保留有效的 T1–T4 任务边界及规划/返工检查点，不合并不同已验证任务的历史。
