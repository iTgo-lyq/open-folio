# 按核心契约和实现规模判断 Change 大小

## 背景与目标

用户要求只有涉及核心契约字段或预计实现改动较大时，才从 small 升为 medium，使规模判断符合一般开发者对局部修改和整体改造的区分。

## 范围与行为变化

`change-workflow`：MODIFIED 规模主要依据核心契约的实质变化和预期实现范围。明确普通配置项、局部校验及其增删不因主题自动升级；文件数、文档和测试同步也不直接代表实现规模。large 与 xlarge 继续依据独立交付数量、协调复杂度和是否需要拆分 Change 判断。

删除信息不足、出现用户取舍时自动升级的要求，改为调查或澄清后按同一标准复核。验证和实际操作授权仍根据具体影响处理。

## 方案要点

集中调整 skill 的规模表、判断依据及规模调整说明，并在工作流 Spec 中记录长期原则。这是局部指引修改，采用 small；流程字段、命令和阶段路线沿用既有实现。

## 验收标准

- 局部配置或校验清理、普通缺陷修复、批量机械修改可判 small。
- 核心协议字段或持久化数据语义发生需要协同适配的变化，应至少为 medium。
- 预计业务逻辑改动较大、模块联动较多的实现，应至少为 medium；大量独立交付或需要拆分子 Change 时采用更大规模。
- 判断依据包含实际契约变化或实现范围，不以主题、一次澄清、代码行数或文件数自动升级。
- skill 基础校验、文档结构与差异检查通过。
