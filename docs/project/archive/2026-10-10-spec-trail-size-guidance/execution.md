# 执行证据

## T1 调整规模判断指引并核对典型场景

规模表以核心契约变化和预期实现范围为依据，补充核心契约与实现规模的定义，并将创建、规模调整和返工中的判断统一到同一标准。移除按主题、信息不足或一次用户取舍自动升级的要求。

Agent 对照需求逐项自查，并用以下场景检查规则含义：

| 场景                                                      | 判断与依据                                                        |
| --------------------------------------------------------- | ----------------------------------------------------------------- |
| 删除局部校验与普通配置项，同步调用和说明                  | small：方案明确、实现集中，没有核心消费协议变化                   |
| 修复局部缺陷，恢复原有接口行为                            | small：沿用既有契约，改动局部                                     |
| 内部符号的全仓机械改名，保持对外与持久化契约              | small：文件多来自机械同步，实际逻辑改动有限                       |
| 调整公共 API 中核心对象标识的字段语义，需要多个调用方适配 | 至少 medium：核心契约实质变化，即使代码量少也需设计兼容与协调适配 |
| 联动改写缓存、采集和查询的业务逻辑，交付数量有限          | medium：实现与验证需要多个模块协调                                |
| 多个独立交付任务，需要分阶段集成                          | large：工程体量与协调复杂度较高                                   |
| 多个能力需要独立推进、验收和合入                          | xlarge：拆分为独立子 Change                                       |

验证：skill-creator 的 `quick_validate.py` 通过；新增正文格式与 `git diff --check` 通过。检索并清理了创建、规模调整和返工三处相互重复的旧升级条件；语义命令和结构校验器没有自动推断规模，无需修改运行时代码。本次为文档指引修改，按场景核对，不新增匹配文案的测试，也不重跑应用构建。
