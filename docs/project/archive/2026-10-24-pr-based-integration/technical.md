# 统一 PR 集成证据

落实 [Requirement](./requirement.md)。在 `integration-history-recovery` 的职责拆分上，删除按 Git 消息发现 Change 的扫描器，所有正式集成判断改用同一 PR 关联规则。实际来源 tip 的祖先关系继续独立负责清理安全。

## PR 关联与合入事实

共用模块接收固定集成 tip、已知 Change 的 id 与登记分支、完整读取的 PR 集合及 Git 读取能力。PR 数据只补充已知 Change，不成为 Change 发现入口。保留现有 `prMarker` 对正文末尾独立元数据段的解析规则，并集中使用以下判断：

| 判断 | 用途 |
| --- | --- |
| 源目标仓库均为当前仓库、目标为 integrationBranch、来源为 Change 登记分支、正文唯一标记匹配 id | 精确关联 PR；来源使用 PR 保存的名称，无需远端源分支仍存在 |
| 匹配 PR 的 state 为 merged，且具有合法 mergeCommit | 获取平台记录的合并提交 M；closed 不等于 merged |
| M 是固定集成 tip 的祖先 | 核实交付属于当前集成历史；不限制 first-parent 位置 |
| 恰有一个匹配的已合并 PR | 得到唯一集成交付；多个已合并候选不按编号或时间任选 |

无匹配已合并 PR 为 missing，关联歧义为 invalid，平台读取未完成、关键字段缺失或 Git 对象不可读为 unavailable。提交明确存在但不属于固定集成 tip 时，报告尚未在该版本核实，下一次刷新可重试。失败不能静默退回消息标记或把上次缓存当作本次成功结果。

PR 合入结果与差异结果分别保存于本次计算中。已经核实 M 后，差异读取只检查 M 的两个父提交并定位归档目录，返回现有 commit/base/source/archivePath 等字段；不再检查消息中的标记，也不重演归档 CI。无法生成差异时返回独立诊断，交付状态仍可使用已经核实的 M。整体差异保持 `git diff M^1 M`，原型继续使用原快照与路径检查。

## OpenFolio 刷新与缓存

将依赖 PR 的集成索引计算放到已读出已知 Change、且批量 PR 集合已就绪之后。GitReader 继续读取固定引用、文档与历史对象；SnapshotStore 协调一次刷新，复用同一 PullRequestCache 查询结果计算集成索引和交付状态。Delivery 不再优先采用标记索引、失败后再用 PR 兜底。

保留现有分页、ETag、请求合并和缓存大小限制，不增加逐 Change PR 查询，不按合并提交逐条反查 PR。每次实际刷新从本次完整 PR 集合重新关联；相同 tip 不再直接复用旧集成索引。可在一次刷新内按 M 复用 Git 元数据读取，但不增加第二份持久 PR 清单。

递增 INTEGRATION_VERSION，使旧消息索引不能作为新结果沿用。新的索引和交付状态共同参加快照内容比较；仅 PR 发生变化也必须能生成新快照。保持现有快照字段布局，旧固定快照仍可读取，刷新时生成新事实；不迁移用户数据或回写归档。平台失败时沿用现有旧 PR 展示与 stale 标记，但正式合入结果标为待核实，不能更新成功时间。

## CLI 与发布检查

CLI 与 Setup 共用一个轻量 GitHub PR 读取适配器，通过现有 `gh` 的认证调用 REST，按集成目标分页获取全部状态，并归一化到共用记录结构。用参数数组调用进程，PR 内容仅当数据读取；完整分页后再交给关联器。无 gh、无权限或网络失败均提供可操作诊断，不改认证配置、不读取 OpenFolio 用户 Token，也不以 Git 消息补认。OpenFolio 保留现有 Provider，不转用 gh。

`preflight`、`verify`、归档返修保护与发布检查复用同一 PR 证据。preflight 不再输出必须写入合并消息的 trailer；PR 正文标记仍是交付协议的一部分。verify 分别报告 PR 正式合入和来源 tip 纳入情况，清理继续独立核对实际来源、已验证提交、远端 tip、文件、依赖与占用；不把差异读取失败当成删除门禁。

发布检查通过完整 PR 记录定位被 includes 引用的 Change 的 M，再核对候选包含 M 及原归档。Change PR 的合入前归档检查仍直接验证该 PR 的固定源目标对象，无须为它额外查询历史 PR。同步仓库 CI 和 Setup 模板的 `pull-requests: read` 权限，在检查步骤向 gh 传递只读 GITHUB_TOKEN；不触发发布或执行 PR 正文。

## 取舍

复用现有 PR 正文协议、批量读取及 Git 祖先关系，删除消息扫描和两条路径的优先/兜底分支。接受正式集成核实需要可读取平台 PR 这一直接成本；来源清理保留既有独立安全证据，不恢复合入后的归档逐字节门禁。不新增后台同步服务、历史消息修补、归档字段、通用多平台框架或旧标记兼容路径。
