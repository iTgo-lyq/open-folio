# 背景与目标

SpecTrail 的安装器会创建 `.githooks/pre-commit` 并在无既有配置时设置 `core.hooksPath`。业务项目已有 Husky 等管理器时，安装器根据 Git 的实际入口查找命令，无法可靠判断委托调用，也可能引导修改会被重新生成的文件。

用户已确认职责边界：SpecTrail 提供校验脚本、调用命令和 setup 检查；用户或业务项目的 Agent 负责接入现有提交流程。

# 范围与行为变化

- MODIFIED：setup 改为只读检查 Git、Node.js、项目守护分支配置以及仓库中的校验脚本和共享模块，输出准备情况及接入命令。
- REMOVED：自动创建 hook 目录、复制或覆盖校验文件、修改 `core.hooksPath`，以及通过入口文件字符串推断接入完成的行为。
- MODIFIED：setup skill 指导业务 Agent 查明项目维护的入口、接入校验并验证失败传播；setup 检查本身将 hook 接入报告为未验证。
- 保持暂存区校验、部分提交、原型关联和 worktree 行为。本仓库已有 `.githooks/pre-commit` 属于项目既有接入，继续使用。

# 验收标准

- 首次及重复 setup 检查均不改变工作区、Git 配置、hook 或暂存区；缺少资源或无效配置时准确失败，不创建文件补救。
- 未配置 hook、原生 hook、自定义目录和委托入口均不被接管；检查就绪不等于 hook 已验证。
- 由业务方显式接入后，真实提交能够接受有效状态、阻止无效状态，保留既有检查，并支持 clone、worktree 和部分提交。
- 接入指引与测试统一使用只读检查入口，不修改业务包配置，不引入第三方运行依赖。
