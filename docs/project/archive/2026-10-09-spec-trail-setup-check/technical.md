# 方案

将自动安装器替换为 `check-setup.mjs`。检查器从指定目录解析 Git 工作树，核对 Node.js 20+、Git、守护分支配置，以及目标仓库内校验脚本和共享模块的存在、语法及模块加载。输出 JSON，包括准备状态、问题、调用命令和 Git 实际入口信息；成功退出仅表示准备就绪，hook 状态始终为 `unverified`。

检查器不执行业务 hook，也不改变项目文件、Git 配置或 index。资源随 skill 交付；缺少资源时由用户或 Agent 完成 skill 文件接入。已有安装器入口删除，接入指引使用新的检查入口。

setup skill 将入口选择和编辑交给业务 Agent，要求保留既有命令、在暂存区修改步骤之后校验，并传播失败。委托入口的生成文件只能用来追踪调用，实际修改项目维护的入口。通过实际执行验收，不增加 Husky 等工具的识别分支。

# 验证路径

在临时仓库中比较检查前后的完整文件及权限快照；覆盖缺失资源、无效配置和脚本错误。业务接入由测试夹具显式完成，使用真实提交覆盖原生入口、委托调用、失败传播、clone/worktree 和部分提交，保持已有字段与原型契约回归。变更完成后进行独立评审。
