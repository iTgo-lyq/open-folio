# 背景与目标

工作台要求 Plan 必须提供执行顺序表，而流程命令只检查 Plan 文件存在，也没有校验任务前置。普通单任务 Plan 因此出现来源警告，任务还可能在前置未完成时启动。

用户已确认执行顺序表可选：未声明时按任务编号数值递增串行；需要并行或特殊安排时显式覆盖；无效的显式声明仍需报错。

# 范围与行为变化

- MODIFIED：普通 Change 默认按编号串行，无需执行顺序表。medium/large 仍需 Plan 正文；无表的执行顺序文字说明不构成覆盖。
- MODIFIED：显式表覆盖默认安排，须唯一、完整、编号有效且无循环。代码示例不算实际声明；无效声明不能退回默认。
- ADDED：流程命令校验有效顺序与未完成的前置，执行、任务开始/完成和关闭步骤使用同一规则。
- MODIFIED：工作台展示顺序来源及依赖；缺少可选表不产生来源警告。small 同样使用任务默认串行，xlarge 仍按子 Change 组织。
- 保持业务 hook 的职责、JSON 状态字段、已完成任务记录及人工验收边界。

# 验收标准

- 单任务及无表 Plan 可正常执行和展示，编号排序不受 JSON 属性顺序影响，T2 位于 T10 之前。
- 后续任务在其串行前置未完成时无法开始或完成；显式独立任务可以分别启动。
- 无效、歧义或变更后不完整的显式安排被流程命令和工作台一致识别，失败操作不改变状态和暂存区。
- 验证和归档前重新检查安排；修复现有来源提示的同时保留真正的错误提示。
