# Change 类型标签与紧急程度

## 目标与范围

项目积累较多 Change 后，仅凭标题、规模和阶段难以快速辨认工作内容及处理先后。增加类型标签和紧急程度，帮助读者筛选同类工作、识别需要优先处理的 Change；规模继续表达改动大小，阶段继续表达推进进度。

本次覆盖 SpecTrail 的元数据约定、语义写入命令与校验，以及 OpenFolio 工作台的读取、展示、筛选和排序。标签相关前端适配由本 Change 一并实现和验收，沿用当前工作台的组件与布局。采用独立 medium Change：需要扩展双方共享的持久化契约，并联动命令写入、服务端解析和前端浏览。现有“前端样式与交互重构”聚焦既有能力的视觉与交互，本次新增元数据能力不并入其范围，也不以其交付为前置依赖。

## 类型标签

每个 Change 可记录多个类型标签，使用能概括本次实际工作的简短文字，不限定在固定枚举或候选池中。标签可以表达工作性质或具体事项，例如“修复”“安全”“数据迁移”；一个 Change 可以同时标注“修复”和“安全”。标签仅用于描述与检索，不改变规模判断、流程路线或验收规则。

提供以下推荐词，帮助 Agent 在创建、整理需求或更新 Change 时保持用词一致：

| 推荐词 | 常见用途 |
| --- | --- |
| 新功能 | 增加此前没有的能力 |
| 修复 | 修正错误、恢复应有行为 |
| 体验 | 改善操作、布局、反馈及可访问性 |
| 性能 | 改善响应速度、资源占用或承载能力 |
| 重构 | 调整内部结构及职责划分 |
| 安全 | 修补安全问题、完善安全机制 |
| 适配 | 适配平台、设备、接口或依赖版本 |
| 文档 | 完善使用说明及知识材料 |
| 测试 | 增加或改善测试能力 |
| 工程 | 改善开发工具、构建及部署 |
| 流程 | 调整协作方式及工作流规则 |
| 数据 | 数据整理、迁移及修正 |

推荐词用于引导，不作为合法值白名单。标注时先看项目已有用词，同义优先复用，例如“Bug 修复”“缺陷修复”通常采用已有的“修复”；已有词不能准确表达目标时可新增简短标签。用户明确指定的名称沿用，不自动批量改名或依赖模糊匹配合并历史标签。不增加标签词库管理、别名系统或项目级强制分类配置。

标签以纯文本处理，去除首尾空白，避免空白标签和完全重复的标签；保留用户可辨认的名称和顺序。没有标签时允许省略，不从标题、提交类型或正文自动推断并补写。

以上类型多选、自由命名及兼容旧记录的决定来自需求澄清 **Q1**。用户随后补充：仍需提供简短、覆盖日常场景的候选词，并尽量避免同义词；该补充落实为推荐用词和复用指引。

## 紧急程度

紧急程度独立于类型和规模，每个 Change 可设置一个值：“紧急”“高”“普通”或“低”。不必填写，未填写或主动清空均按“普通”处理；与显式“普通”采用相同的展示、筛选和排序规则。不从“修复”“安全”等类型或规模推断其他紧急程度。

Agent 根据用户明确安排维护紧急程度；缺少特别安排时省略字段，按普通处理。紧急程度表达处理先后的提示，不自动启动任务、跳过确认或越过执行依赖。

## 工作台浏览与维护

Change 列表、阶段看板卡片和详情展示类型标签与紧急程度，缺失字段不产生来源异常。列表和卡片仅为非普通紧急程度显示徽标；无论字段省略还是显式普通，均不额外标注。详情中的紧急程度统一按有效等级显示，省略时显示普通；没有类型标签可显示“无类型标签”。多个标签或较长名称在窄屏仍能阅读，不遮挡标题及原有状态。

类型筛选提供当前项目实际出现的标签，可多选，命中任一已选标签即匹配，并提供“无类型标签”。紧急程度只按四个等级筛选，选择普通时同时匹配省略字段和显式普通的记录，不提供独立的未设置筛选项。两类条件与已有状态范围、规模、阶段等筛选取交集，筛选与清除沿用现有 URL 和返回位置约定。列表、看板、依赖视图和任务粒度共享 Change 筛选语义；任务不拥有独立标签或紧急程度。

默认保持现有创建时间倒序；增加可选的“紧急程度优先”排序，顺序为紧急、高、普通、低，省略字段的记录归入普通，同级沿用创建时间倒序及既有 ID 兜底。延续交付继续先筛选成员再分组，按匹配成员的排序确定组的位置和组内顺序；不向无标签的成员继承标签，也不改组名。看板保留阶段分栏，仅调整栏内顺序；依赖视图继续表达真实依赖。

维护仍通过 SpecTrail 语义命令完成，支持创建时填写及活动 Change 的更新、移除和清空，并同步 skill 中的标注指引。OpenFolio 继续只读展示，不增加网页端编辑、批量打标或标签管理权限。

skill 修改保持精简：在现有字段定义、创建指引和命令说明中就地补充必要内容，推荐词及同义复用原则集中说明一次；不重复铺陈规则，不新增审批步骤、独立分类流程或配套 skill。

## 数据兼容

新增信息采用可选元数据，继续使用现有 Change schemaVersion；已有 Change 无须迁移或补字段即可读取、校验及继续推进。类型和紧急程度相互独立，允许两者都缺失，也允许只填写其中之一。紧急程度默认普通仅是使用时的语义，不向历史文件补写默认值。

历史归档保持原样，不批量回填标签，不改变原有标题、状态、确认、验收、归档时间或有效完成判定。标签更新也不重置 Change 创建时间和流程记录。新元数据格式错误时，写入端给出明确提示；读取端隔离错误元数据并提示问题，仍保留可正常读取的核心流程事实，与现有可选阅读信息的处理方式一致。

## 验收

1. 可以创建和更新带多个类型标签的 Change；推荐表之外的名称也能保存、读取、展示和筛选。完全重复或空白标签不会产生重复或空白徽标；推荐用词仅提供指引。
2. 四档紧急程度可以分别设置和读取，省略或清空后按普通处理，与显式普通的展示、筛选及排序结果一致；类型为“修复”或规模为 large 都不会自动提升紧急程度。
3. 无新增字段、仅有类型、仅有紧急程度以及两者都有的 Change 均正常读取。既有活动记录可以继续推进，合法历史归档仍为有效完成，原文件无需改写。
4. 标签与紧急程度在列表、阶段看板及详情准确展示；普通不在列表和卡片额外显示徽标，省略紧急程度不会出现“未设置”提示。多标签和长标签在桌面、窄屏可阅读，内容按文本显示。
5. 类型多选按任一命中，和紧急程度及已有筛选共同作用；无类型标签可被单独筛出，普通筛选包含省略紧急程度的记录。刷新、前进后退、打开详情返回及清除筛选保留符合约定的上下文，空结果提示正确。
6. 默认创建顺序保持不变，切换紧急程度优先后等级、空值、同级记录及延续组顺序符合上述规则；依赖关系不受排序影响。
7. 标签或紧急程度的错误值被写入校验拒绝；读取此类记录时有明确元数据提示，合法的其他元数据和核心流程事实仍可阅读。
