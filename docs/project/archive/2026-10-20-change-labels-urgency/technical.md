# Change 类型标签与紧急程度技术方案

依据[已确认需求](requirement.md)，在现有 `change.json → 校验与索引 → 工作台` 链路增加两个可选字段。标签帮助辨认工作内容，紧急程度帮助浏览排序；不引入标签管理服务、网页写入接口或新的流程状态。

技术澄清 **Q2** 已选择不单独制作原型，沿用当前工作台组件，在实现时验证交互与窄屏表现。

## 数据与写入

Change 保持 `schemaVersion: 1`，扩展以下契约：

| 字段 | 取值与空值 | 规则 |
| --- | --- | --- |
| `types?: string[]` | 自由文本数组；省略或 `[]` 均为无标签 | 每项为去除首尾空白后的非空单行字符串，区分大小写，不得完全重复；保留顺序 |
| `urgency?: "urgent" \| "high" \| "normal" \| "low"` | 对应紧急、高、普通、低；省略等同普通 | 不从类型、规模或标题推断；恢复普通时删除字段 |

空值统一通过字段省略表达，不写 `null` 或空字符串。类型允许 `[]` 读取，命令清空后省略字段。紧急程度读取时接受显式 `normal`，命令设置普通时省略该字段；展示、筛选与排序统一使用 `urgency ?? "normal"`，不向源记录或快照状态补写默认值。标签中的逗号、引号、中文和 `none` 等名称均为普通文字；不设置名称白名单，不做大小写折叠、同义替换或历史补写。

沿用状态命令的字符串参数机制，增加以下语义入口：

| 入口 | 行为 |
| --- | --- |
| `create --types '["修复","安全"]' --urgency high` | 创建时可选填写；两个参数均可省略 |
| `labels --types '["体验","适配"]'` | 替换类型集合，未传的紧急程度保持原样 |
| `labels --urgency urgent` | 仅更新紧急程度 |
| `labels --types '[]' --urgency normal` | 清空类型并恢复普通紧急程度，删除对应字段；可分别操作 |

`labels` 至少需要一个参数；紧急程度参数只接受四个等级，不新增第五种空值等级。类型参数先解析 JSON 数组，检查字符串元素，再 trim 并按首次出现顺序去重；空白、换行、错误 JSON 或错误类型均拒绝，不静默丢弃。既有原始 JSON 的重复或非法值仍由校验器拒绝，不在读取时自动改写。

新增字段规则集中放入现有共享校验模块，命令、提交 hook 和服务端 Zod 校验调用同一规则，沿用现有可选字段的组织方式。`labels` 复用所属分支、active 状态、锁、原文检查和原子写入；不提供任意字段 patch，也不放开取消及归档记录。更新保留阶段、任务、确认、等待、关闭记录及 Git 创建时间。

skill 文本仅补两处字段说明、一段创建/维护指引及命令表参数。推荐词只在指引中集中列一次，说明“优先复用项目已有同义词，无法表达时新增，用户指定名称沿用”；不把需求中的解释表和前端规则复制进 skill。

## 读取、兼容与缓存

现有[服务端解析](../../../../src/server/changes.ts)已对 `previews`、`followUpOf` 等可选阅读信息逐项隔离错误；本次将 `types`、`urgency` 纳入同一路径。某一字段非法时，仅从用于解析的副本移除该字段，并产生带字段路径的 warning；另一合法字段继续保留。核心字段错误仍按现有规则诊断，不借元数据容错掩盖真正的流程错误。

读取模型使用上述可选字段，无新增 API。正常读取的元数据随现有工作台快照交付，仍采用同一仓库授权及权威分支记录。无字段的历史记录不产生 warning，合法 completed 的完成事实、依赖满足判定及延续关系保持原样。被隔离字段按缺失处理：类型为空、紧急程度为普通，同时保留可见诊断。

已核实[快照缓存](../../../../src/server/store.ts)在 Git 引用未变时直接复用解析结果。旧版严格校验可能已把带新字段的记录缓存为错误，因此递增既有 `cacheSchemaVersion`（当前为 6），使升级后的下一次读取重建解析快照。使用现有刷新与清理机制，不另建迁移器或兼容版本分支；Change 数据、账号、Token、偏好及公开原型不变。旧快照链接沿用已有过期提示，正常入口重新读取当前版本。

这里保证的是新版读取既有 Change。已有旧版严格校验程序不能识别新增字段，使用新命令前应同步本仓库 skill 与 OpenFolio 读取版本；不要求为旧记录迁移或增加版本标记。

## 前端展示与查询

业务层复用 `@open-folio/ui` 的 Badge、Button 和现有 select。类型多选采用已安装的 Radix Popover 配原生 checkbox，使用 Portal 避免工具栏滚动容器裁剪；不为本次场景扩充公共组件库或新增依赖。

列表、阶段看板及详情共用标签展示组合。类型采用中性色徽标，非普通紧急程度使用明确文字并辅以现有语义色；列表和卡片内部徽标保持只读，避免在整行按钮内嵌套按钮。标签放在标题附近的独立换行区域，允许长词断行；浮层限制在视口内并可滚动。列表/卡片不为无类型或普通紧急程度新增徽标；详情按有效紧急程度显示普通，不区分字段省略与显式 `normal`，类型为空时显示“无类型标签”。

多选触发器提供可访问名称与选中数量；复选框可用 Tab、Space 操作，Escape 关闭并恢复触发器焦点。按桌面和 320px 窄屏检查多标签、长名称及筛选浮层，不改整个 UI 包的徽标样式。

现有 [Query 与导航](../../../../src/components/context.tsx)只保存单个字符串值，URL 使用以下表示：

| 查询参数 | 含义 |
| --- | --- |
| `types` | JSON 字符串数组，通过 `URLSearchParams` 编码；空数组省略 |
| `noTypes=1` | 勾选“无类型标签”；与已选类型按 OR 匹配 |
| `urgency` | 四个等级之一；`normal` 同时匹配省略字段和显式普通的记录；查询参数省略为全部 |
| `sort=urgency` | 紧急程度优先；省略为当前创建时间倒序 |

不使用逗号分割或重复查询键，避免自由标签被拆分或覆盖。非法参数仅清理该筛选/排序条件，通过 replace 更新 URL，不清除具体 Change 深链接；合法但当前没有匹配记录的标签保留在选项中，便于取消。

类型选项来自项目当前快照实际出现的标签，并合并 URL 中已选的合法名称；推荐词不混入筛选候选。类型内部按 OR，紧急程度和现有范围、阶段、规模等条件按 AND。清除筛选同时清除新增条件，保留排序、当前范围及已有导航约定。切换范围保留标签条件；切仓库沿用整体查询清理。打开详情、刷新及前进后退继续使用现有 URL 状态和焦点恢复。

沿用 [Changes 的统一过滤入口](../../../../src/components/changes.tsx)，将筛选后的同一数组交给列表、看板、任务和依赖视图。排序只针对该数组的副本：

1. 默认直接保留服务端已确定的创建时间倒序、未知时间末尾及 ID 兜底。
2. 紧急排序按 urgent、high、normal、low 排列，省略字段与显式 normal 同级；同等级稳定保留输入顺序，不重复计算 Git 创建时间。
3. 再调用既有[延续分组](../../../../src/lib/follow-ups.ts)，其分组和成员自然沿用匹配输入顺序；关系与组名仍从完整快照解析。
4. 看板仅改变栏内顺序；任务按所属 Change 排列，内部任务顺序不变；依赖视图不改变关系及其语义。

## 取舍与验证

方案所需事实已从当前实现核实：语义命令接受字符串参数，共享校验由 hook 复用，服务端已有逐字段 warning 降级，浏览视图共用过滤数组，延续组保留输入顺序。当前 Next.js 随包[导航文档](../../../../node_modules/next/dist/docs/01-app/01-getting-started/04-linking-and-navigating.md#native-history-api)支持现有 History API 路径，无须更换路由机制。没有外部服务或新增环境配置依赖。

按需求中的精简约束，复杂度核对如下：

| 处理 | 机制、依据与最小方案 |
| --- | --- |
| 保留 | 可选字段及逐字段 warning：满足旧数据兼容和元数据错误不抹除流程事实；复用已有解析路径 |
| 保留 | 既有缓存版本递增：避免同一 Git 提交永久复用旧解析错误；复用当前重建方式 |
| 合并 | 写入、hook、读取共用字段规则；四种视图共用筛选排序，避免多套实现 |
| 延后 | 独立标签管理、批量历史标注与网页编辑；当前需求不需要这些能力 |
| 建议删除 | 不采用候选词白名单、同义词自动归并、双版本数据模型或新增审批机制；用一段标注指引和可选字段即可 |

验证对应[需求验收](requirement.md#验收)：命令测试覆盖创建、替换、清空类型、恢复普通、规范化、错误输入及越权状态拒绝；读取测试覆盖新旧字段组合、单字段错误隔离、completed 与依赖，以及旧缓存重建。浏览器覆盖类型多选与无类型筛选、省略紧急程度和显式普通的一致表现、紧急排序及延续组、URL 往返、详情焦点和桌面/窄屏展示。复用已有 fixture 与定向测试，不建立全排列或额外自动化平台；具体交付顺序见[实施计划](plan.md)。

实现验证使用独立 worktree，生产验证构建使用其 `.next`，浏览器 fixture 沿用 `.next-e2e`。验收、归档并集成到 develop 后，在主工作区执行 `service:update` 并冒烟；真实登录统一使用 `withSmokeSession`，检查与会话清理均须完成。若升级有问题，保留运行数据，修复兼容实现后重新构建，不通过删除标签或重置账号回退。
