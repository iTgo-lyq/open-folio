# 实施与验证记录

## T1 · 双分支契约

workflow 升为 v3，集成与发布分支均为必填单值，贯穿共享校验、Setup、CLI、仓库发现、API 和工作台。规划登记仍沿集中入口直推；快照与发现缓存升版重建。个人偏好在接口边界转换名称，磁盘键、凭据和会话保持原结构。

验证：现有 Node 回归 248 项通过；分支契约与偏好专项 7 项通过，其中包含旧偏好读取、再次保存及凭据密文不变；Setup / hook 的 12 项测试通过，覆盖暂存区、部分提交、clone 和 worktree。类型检查与项目格式检查通过。

本 Change 修改自身所用的 workflow 契约。在合入前，集中入口仍运行 v2；本次状态登记暂用移交提交中的原版 CLI 和集中配置，命令结束立即恢复待交付的 v3 配置。此操作只用于当前仓库实施，不向新工具添加旧 workflow 兼容或升级流程；新契约使用 v3 fixture 验证。

## T2 · PR 交付流程

集成脚本只保留 preflight / verify / cleanup，平台合并由 Agent 的现有工具执行；两类 PR 以末尾元数据段关联。未集成归档可通过 rework 恢复活动目录及原型路径，已集成归档仍冻结。主 skill 替换原直推规则，发布内容集中到短篇 release.md，未加入 changelog、tag 或 Release 管理。

验证：20 项状态命令回归通过；修正新增 fixture 后，20 项合入、返修、标记和清理专项全部通过；类型检查与格式检查通过。模拟平台普通合并，检查预检与验证无 push、目标推进、未推送来源、重复核实、已集成冻结、Git 原型恢复和逐项清理。发布指令核对了首次整理、复用已有 PR、候选变化、仅准备 PR 与合入失败的处理，未向发布分支执行合码。

## T3 · 只读 PR 关联与交付状态

Provider 增加 PR 列表、详情和按提交回查；发布分支只定向获取 Git tip，不作为文档入口。现有快照保存交付投影，正常刷新在 Git 不变时仍更新 PR，结果相同不创建新快照。按编号刷新已有匹配，关闭后再发现新候选；PR 缺权、分页不完整和网络错误局部降级，保留旧结果并标明过期，401 仍使读取失败。发布标记和实际合并祖先关系共同决定“已合入发布分支”。

验证覆盖 PR-only 更新、关闭/重开/重建、冷缓存删源分支后回查、改标题、发布清单变化、缺权/限流/401、分页未完成、冲突与非法 M、最终权限拒绝，以及 PR 信息时间不制造快照。Provider/store/权限等首轮 37 项通过，新增权限拒绝后 delivery 专项 4 项通过。全量回归发现的 5 个旧路径断言已调整：发布 tip 纳入刷新但不读取其文档、定向读取多一个发布引用、两个 fixture 改用模拟 PR merge。

## T4 · 工作台交付入口

复用 Badge、现有范围筛选与详情区域，增加待集成/待发布入口、列表和卡片标签，以及 Change PR / 发布 PR 的链接、版本、历史和局部诊断。交付筛选覆盖归档，切换时移除开发阶段/等待条件；详情链接不嵌套在列表按钮内。

验证：受影响的 20 项 Playwright 场景中，19 项首轮通过；原“4 个范围入口”断言调整为 6 后单项复测通过。新增用例覆盖两阶段筛选、类型/紧急度组合、关闭不取消 Change、发布 PR 合入、Draft、历史、缺权和键盘；1440 / 390 / 320px 检查无横向溢出，已人工查看窄屏截图。生产构建、类型检查与格式检查通过。最终 Node 全量 257 项通过。

独立评审见 [review.md](review.md)。按实际发现分开两类 PR 的降级状态，防止无关查询失败覆盖已核实阶段；冷缓存缺权不再生成“无 PR”结论。修正后 delivery/discovery 15 项与类型检查通过，浏览器对缺权空列表增加明确断言。

当前集中入口仍为待本 Change 集成的 workflow v2；新工作台在该真实仓库的完整读取、长期服务更新与登录冒烟将在验收归档、PR 合入后执行。此次先验证隔离 fixture 的完整界面和真实 GitHub PR 读取，不改中央配置或现有运行数据来绕过交付步骤。

评审修正后的两项交付浏览器回归与生产构建再次通过，格式检查和 diff 空白检查通过。

## T5 · 真实 PR 读取复验

以本 Change 的 [Draft PR](https://github.com/iTgo-lyq/open-folio/pull/1) 进行真实 Provider 读取，发现 REST `2026-03-10` 已移除 `merge_commit_sha`，导致原 fixture 通过而真实响应校验失败。仅将 PR 列表、详情和提交回查固定到仍受支持的 `2022-11-28`；其他请求不变，依据及支持期限见 [Technical](technical.md#平台读取刷新与降级)。测试固定该请求版本并覆盖提交回查的实际合并字段。

修正后，真实列表、详情和按源提交回查均返回同一 Draft PR，目标 develop、来源 codex/pr-release-delivery 和 Change 标记一致；未合入的临时合并 SHA 不被当作合入结果。Provider/delivery 的 17 项回归、类型检查、格式检查和生产构建通过。此验证只读取现有 PR，正式发布与合并事实的完整路径仍由 Git/Provider fixture 覆盖。

## T6 · 未归档合入约束与 CI

按用户补充要求，Agent 合入规则明确未归档不得合入，预检与已接入的归档 CI 均需通过。新增只读 `check-pr.mjs` 和随 skill 分发的 GitHub workflow 模板，本仓库已接入；Setup 推荐首次配置 CI 与必需状态检查，区分平台强制与规划直推例外。

9 项专项测试覆盖未归档/返修失败、恢复归档后通过、缺验收/Specs/未完成任务、重复记录、错误标记/归属/目标/提交/仓库、额外归档、发布清单、准备分支、自定义分支、CLI 退出与只读行为。Setup 12 项、合入/返修/标记/状态命令 30 项回归通过，类型与格式检查通过。独立评审发现发布准备分支的有效 M 可位于候选第二父系；现从集成分支扫描 M，再核对候选祖先和归档子树，9 项复测及复评通过。
