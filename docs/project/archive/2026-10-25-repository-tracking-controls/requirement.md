# 仓库追踪控制

GitHub 已归档的旧仓库仍出现在目录并继续刷新，且用户无法主动停止追踪单个仓库。修复归档识别，并为现有仓库列表补充可恢复的个人追踪选择。

## 范围与方案

- 平台明确标记归档的仓库不出现在常规仓库列表，不检查其工作流或抓取新的工程快照；已有发现记录也要在元数据复验后遵守归档状态。解除平台归档后可通过重新发现恢复。
- 可阅读及需要处理的仓库提供「不再追踪」，从常规目录和自动刷新目标中移除；在「已停止追踪」入口恢复。此选择按稳定仓库身份保存到当前 Token 工作台偏好，跨设备、服务重启和重新发现保留，不修改远端仓库。
- 复用现有偏好写入及列表组件，增加可选偏好字段；不改变凭据、权限或存储版本，不删除已有快照及公开原型。已有明确阅读链接继续按权限读取，停止追踪后不采集新快照。
- 沿用现有权限有效期复验平台归档状态，不另建平台轮询。停止追踪时阻止新的刷新及在途刷新发布；恢复后使用现有发现与刷新流程。

这是一个 small Change：复用仓库元数据、工作台偏好和现有目录，只新增追踪筛选与列表操作，预计不足 300 行有效实现。方向来自用户本轮提出的归档隐藏、停止追踪需求；沿用本会话直接推进的要求。

## 验收

- 新发现的归档仓库不执行工作流或 Git 探测，不出现在目录；缓存仓库变为归档后也不会继续生成快照。
- 手动停止追踪后立即隐藏，重新发现、重新登录和服务重启保留选择，其他工作台不受影响；可恢复并重新出现在目录。
- 自动刷新、显式刷新和在途发布均遵守追踪选择；已有阅读和原型数据不删除。
- 覆盖归档识别、偏好持久化与隔离、后台刷新及列表操作，检查类型、构建和真实开发机服务。
