# 执行计划

依据 [Requirement](requirement.md) 与 [Technical](technical.md)，交付从集中规划到独立执行、再到后台定向阅读的完整路径。按用户本轮要求提前整理计划草案；有效确认与任务状态仅由 `change.json` 管理。

任务默认按编号串行。每项包含自身的规则说明、实现和必要验证；实现边界稳定后才能判断是否适合拆出并行工作，不预先为多个 Agent 创建任务分支。

## T1 — 定义集中入口与引用契约

交付含 collaborationBranch 的 WorkflowConfig 与基于现有 `change.json.branch` 的统一定位规则，不新增引用格式。默认 develop 承担讨论与预发布集成，所有 Change 默认合入这里；保护分支合入/PR 仅由用户主动要求触发。更新 SpecTrail、Setup 与状态命令说明，明确继承副本与合入后归档的读法，保留完整 ChangeState 结构；旧配置项目提示接入，不保留全量扫描。

验收：同一套 fixture 在语义命令、提交校验和后台中得到一致结论，覆盖新配置、待接入旧配置、branch 指向自身或工作分支、非法分支、目录 ID 不符、集中副本与目标状态不同、不可用目标和归档边界。核对 ID 查重、依赖和原型跨文件检查不被其他 Change 的继承副本阻塞；实际提交验证暂存区与失败传播。对应 A1、A2、A7、A9、A11。

## T2 — 实现集中规划与可恢复移交

交付集中创建与规划操作、限定路径提交规则，以及先发布目标、再推进集中入口的单个幂等 handoff 命令。两端复用同一个 branch 登记提交，不另建恢复日志、规划锁或分段命令；保留原 JSON 与正文，不为格式替换、目录清理或状态镜像制造提交。交付在独立 worktree 内同步 develop 后快进推送，主工作区干净时跟进。阶段前置与实际授权仍需满足。

验收：临时 bare remote、两个克隆和 worktree 中，验证从 develop 派生并只推进所属 Change、主工作区不换分支、集中目录不被删除或替换格式、并发修改不同/相同 Change、目标推送失败、branch 登记推送被拒和确认响应丢失。完成后默认合回 develop，保留其他活动规划；保护分支不被自动合入或创建 PR。每个故障点核对公开来源、未提交现场和重试结果。对应 A1、A2、A5、A8、A11。

## T3 — 实现工作区定位与会话续接

交付按入口定位分支/worktree 的只读命令、本地工作区准备和客户端续接规则。输出足够重建上下文的结构化结果和续接提示，复用 Git worktree 登记与宿主已有会话能力，不新建占用/会话登记库。支持已有会话复用、新会话及人工打开降级；通用 CLI 不调用客户端专有 API，也不声称能证明宿主绑定。

验收：覆盖任意 worktree 发起、新克隆、worktree 缺失/失效、detached HEAD、本地领先/落后/分叉、脏文件和重复准备。核对输出的路径、分支、提交与续接提示，并用实际宿主能力检查验证自动路径或人工打开降级；没有创建接口时明确报告人工步骤，不用模拟客户端或 shell cwd 假称已完成会话绑定。对应 A3、A4、A5。

## T4 — 实现后台定向收集与增量刷新

交付从默认配置到集中目录再到指定目标的 Git 来源收集，调整仓库接入探测、来源限制、快照清单与缓存 fingerprint。删除旧全量扫描及其兼容分支；配置未就绪给出 Setup 提示。各来源固定提交读取，普通目标持续更新不阻止其他结果发布。

验收：记录 Git 命令与访问目录，在大量无关分支 fixture 中证明新模式没有全量 heads 拉取或全分支正文扫描。验证集中分支不变而目标变化、入口集合变化、远端删除/强推、读取中途来源变化、权限/网络失败、超限与缓存语义升级。对应 A6、A7、A10。

## T5 — 统一工作台与关联材料的权威来源

交付按入口解析的 Change 索引、来源诊断和实际文档链接，贯通任务、澄清、依赖、父子关系与固定原型。沿用现有界面，在来源依据中区分集中入口和完整记录来源；项目 Specs/当前原型只读 develop 并显示预发布来源，已集成归档不因副本重复计数。

验收：集中副本停留在 requirement 而目标已执行或归档时，视图采用目标状态且不重复计数。非法目标、目标无完整记录、规划父项与执行子项、取消/返工/归档、祖先和 squash 证据、Specs/当前原型/历史固定原型分别读取正确来源。浏览器检查进行中、取消、归档、来源异常及深链接，不能以集中旧字段回填进度。对应 A2、A7、A8、A9、A10、A12。

## T6 — 交付迁移接入与本仓库试运行

交付接入预览、已知入口登记与冲突处理，完成 Setup 的 develop/保护分支配置引导和本仓库隔离试运行。来源限于基线、已知 Change、worktree 与明确提供的工作分支，不保留旧扫描引擎。报告覆盖依据，不把本次调查时没有活动 Change 当成切换时仍无活动工作。现有归档及用户运行数据保持可用。

验收：用包含活动、取消、归档、来源冲突和原型的旧仓库演练接入、重复执行和中断；缺少配置明确提示，失败不退回旧扫描。用本仓库隔离克隆验证 develop 的存在性/权限/用途检查、默认合入方向、主工作区现场及保护分支配置发布前置；验证旧分支合码的 live/archive 冲突、连续两次保护分支发布与规划目录保护，生成具体差异和恢复说明。对应 A1–A12，重点 A8、A9、A11。

本 Change 用当前可用的状态命令完成关闭，交付默认进入准备好的 develop，不自动发布到 main。真实入口配置若位于保护分支，配置与新版校验器需一起发布，同样由用户主动要求；本次实现授权不被解释为保护分支发布要求。本地 CLI 可在 develop 使用新配置；新后台部署后，默认分支尚未发布协作入口的项目明确显示待接入，不以旧扫描维持过渡。后台与主工作区切换前重新检查配置和现场。T6 演练不代表真实主工作区已切换，实际切换证据不回写只读归档。

## 整体验证与交付证据

自动验证以现有状态命令、Setup、Change 索引、增量缓存、仓库发现和原型测试为基础，增加跨分支故障 fixture；浏览器测试验证可观察的来源行为。执行相关测试与类型检查后，按服务规则停止使用 `.next` 的进程、串行构建、启动、冒烟验证；浏览器构建使用既有 `.next-e2e` 约定。

集成演示：两个 Change 在 develop 规划 → 分别移交 → 两个绑定工作区的会话推进 → 主会话按入口恢复其中一个 → 目标更新在后台可见 → 一个返工、另一个归档并默认合回 develop → 本地 worktree 清理后按记录重新定位。另验证保护分支只有用户指令才进入发布流程，候选排除尚未完成的规划材料。

实现时按 T 编号在 Execution 记录实际改动、命令、结果和限制；方案评审问题与复验记录到 Review。按用户授权，方案相互评审完成后直接实施，不逐阶段等待；iclaude 仅用于本次方案评审，不参与代码评审。同步 Prototype 子 skill 和 AGENTS 的预发布服务规则，关闭前同步 [Change 状态维护](../../specs/change-workflow/spec.md)、[项目知识工作台](../../specs/project-knowledge/spec.md)、[Change 追踪](../../specs/project-knowledge/change-tracking/spec.md)、[配置管理](../../specs/project-knowledge/configuration/spec.md)以及受影响的文档/原型来源说明。

客户端准确绑定能力是 T3 的外部集成验证项；不能自动复用已有 worktree 时，按需求交付人工打开并核验的路径，不声称全自动。协作分支默认 develop；当前活动工作、配置发布前置及服务 checkout 在演练和真实接入时分别核对。
