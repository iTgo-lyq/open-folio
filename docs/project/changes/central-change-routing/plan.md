# 执行计划

依据 [Requirement](requirement.md) 与 [Technical](technical.md)，交付从集中规划到独立执行、再到后台定向阅读的完整路径。按用户本轮要求提前整理计划草案；有效确认与任务状态仅由 `change.json` 管理。

任务默认按编号串行。每项包含自身的规则说明、实现和必要验证；实现边界稳定后才能判断是否适合拆出并行工作，不预先为多个 Agent 创建任务分支。

## T1 — 定义集中入口与引用契约

交付 v2 WorkflowConfig、独立 Change 引用格式及统一校验，明确完整记录、入口和历史归档的来源规则。更新 SpecTrail 主规则、Setup 和状态命令说明中的分支职责，保留现有阶段确认与完整 ChangeState 语义；新协议未启用时旧项目照常工作。

验收：同一套 fixture 在语义命令、提交校验和后台中得到一致结论，覆盖 v1/v2、合法引用、非法分支、未知字段、目录 ID 不符、完整记录与引用共存、不可用目标和历史归档边界。验证暂存区而非工作树的 hook 行为，实际提交同时覆盖成功与失败传播。对应 A1、A2、A7、A9。

## T2 — 实现集中规划与可恢复移交

交付集中创建和规划操作、限定范围的共享工作区发布协调，以及目标先发布、入口后发布的移交/恢复命令。只有用户已授权且阶段前置满足时才准备执行；不将创建或移交当成阶段批准。

验收：临时 bare remote、两个克隆和 worktree 中，验证主工作区不换分支、仅移交一个 Change、并发修改不同/相同 Change、目标推送失败、入口推送被拒和确认响应丢失。每个故障点都核对公开来源、未提交现场和重试结果；无法证明输入一致时拒绝自动补发。对应 A1、A2、A5、A8。

## T3 — 实现工作区定位与会话续接

交付按入口定位分支/worktree 的只读命令、本地准备和写入占用机制，以及客户端会话续接规则。输出足够重建上下文的结构化结果和续接提示，支持已有会话复用、新会话及人工打开降级。不得将客户端专有能力硬塞进零依赖的通用状态 CLI。

验收：覆盖任意 worktree 发起、新克隆、worktree 缺失/失效、detached HEAD、本地领先/落后/分叉、脏文件、活跃及陈旧占用。假客户端验证异步创建、错误 cwd 和不可用能力；真实客户端至少验证一条准确绑定并继续的路径及不能自动复用时的降级。记录该客户端的能力证据和人工步骤，不用成功创建请求代替绑定证明。对应 A3、A4、A5。

## T4 — 实现后台定向收集与增量刷新

交付从默认配置到集中目录再到指定目标的 Git 来源收集，调整仓库接入探测、来源限制、快照清单与缓存 fingerprint。新协议失败不退回全量扫描，旧模式仍可明确识别。

验收：记录 Git 命令与访问目录，在大量无关分支 fixture 中证明新模式没有全量 heads 拉取或全分支正文扫描。验证集中分支不变而目标变化、入口集合变化、远端删除/强推、读取中途来源变化、权限/网络失败、超限与缓存语义升级。对应 A6、A7、A10。

## T5 — 统一工作台与关联材料的权威来源

交付按入口解析的 Change 索引、来源诊断和实际文档链接，贯通任务、澄清、依赖、父子关系与固定原型。沿用现有界面，在来源依据中区分集中入口和完整记录来源；历史归档不因复制进 main 重复计数。

验收：同 ID 多来源、非法目标、目标无完整记录、规划父项与执行子项、取消/返工/归档、祖先和 squash 证据、Specs/当前原型/历史固定原型分别读取正确来源。浏览器检查进行中、取消、归档、来源异常及深链接，不能从引用生成伪造阶段或进度。对应 A2、A7、A8、A9、A10。

## T6 — 交付迁移接入与本仓库试运行

交付迁移预览、登记覆盖与冲突处理，完成 v2 Setup 的接入步骤和本仓库隔离试运行。对真实当前 refs 重新盘点，不把本次调查时没有活动 Change 当成切换时仍无活动工作。现有归档及用户运行数据保持可用。

验收：用包含活动、取消、归档、来源冲突和原型的旧仓库演练迁移、重复执行和切换前失败；切换后回退必须证明可恢复旧读法。再用本仓库隔离克隆验证接入条件、生成配置与入口差异，形成可复现的接入/恢复说明。对应 A1–A10，重点 A8、A9。

本 Change 自身按 v1 完成关闭和合入，避免接入依赖尚未发布的工具形成循环。后台发布时验证真实工作台的旧模式兼容；主工作区的真实 v2 切换在工具/后台发布后按实际授权执行，重新检查当时 refs 和现场。T6 演练完成不代表主工作区已经切换，实际切换证据不回写只读归档。

## 整体验证与交付证据

自动验证以现有状态命令、Setup、Change 索引、增量缓存、仓库发现和原型测试为基础，增加跨分支故障 fixture；浏览器测试验证可观察的来源行为。执行相关测试与类型检查后，按服务规则停止使用 `.next` 的进程、串行构建、启动、冒烟验证；浏览器构建使用既有 `.next-e2e` 约定。

集成演示：两个 Change 在主工作区规划 → 分别移交 → 两个绑定工作区的会话推进 → 主会话按入口恢复其中一个 → 目标更新在后台可见 → 一个返工、另一个归档 → 本地 worktree 清理后按入口重新定位。演示同时检查没有把另一个 Change 或集中分支整体带入交付。

实现时按 T 编号在 Execution 记录实际改动、命令、结果和限制；独立评审问题与复验记录到 Review。现在不创建空的 Execution/Review 文件。关闭前同步 [Change 状态维护](../../specs/change-workflow/spec.md)、[项目知识工作台](../../specs/project-knowledge/spec.md)、[Change 追踪](../../specs/project-knowledge/change-tracking/spec.md)、[配置管理](../../specs/project-knowledge/configuration/spec.md)以及受影响的文档/原型来源说明。

客户端准确绑定能力是 T3 的外部集成验证项；不能自动复用已有 worktree 时，按需求交付人工打开并核验的路径，不声称全自动。协作分支最终名称、当前活动工作和服务发布 checkout 在演练及真实接入时分别核对；本次文档整理不提前改变项目运行方式。
