## 方案自查

2026-10-18 主 Agent 对照用户追加的 develop 预发布、默认集成、保护分支显式发布和旧扫描下线要求，复核需求、技术与计划，并阅读现有 CLI、hook、GitReader、索引和原型来源。以下结论属于方案自查，不能代替实现验证或独立代码评审。

### R1：重复登记提交会增加归档合码冲突

证据：在两个临时 Git 仓库分别比较“两端各自修改 branch”与“两端复用同一登记提交”。前者在归档合回 develop 时产生 live change.json 的 modify/delete 冲突；后者成功合码并保留另一个 Change 的讨论更新，详见 [Research](research.md#方案评审中的-git-实验)。

影响：如果入口登记提交不在工作分支共同基线中，不能保证正常归档合码自动移除旧 live 入口，还会增加用户已经明确不希望出现的重复提交。

最小修正：移交准备一个只修改本 Change branch 的登记提交，先发布为工作分支，再把 develop 快进到同一提交；并发变化按实际差异恢复，不强推。归档合码仍需核对冲突与目录互斥，不能保证所有情况下自动成功。该结论需纳入 T2 的真实远端和中断恢复验证。

### R2：继承副本需要在全局检查前排除

证据：[change.mjs](../../../../.agents/skills/spec-trail/scripts/change.mjs) 当前在 show/归属判断前对本地 records 全局按 ID 查重，并从本地副本读依赖；[pre-commit.js](../../../../.agents/skills/spec-trail/setup/scripts/pre-commit.js) 原型跨文件检查遍历所有 indexed live Change。工作分支从 develop 派生后会自然包含其他 Change 的旧副本。

影响：其他 Change 已归档、迁移或原型配置变化时，本任务可能被旧副本阻塞；不能只修改后台索引而保留本地旧语义。

最小修正：先按集中入口确定记录归属，再做当前权威记录的 ID、阶段、依赖与原型关联检查。hook 保持暂存区完整结构校验，不增加远端网络操作。Technical 与 T1 已纳入这一范围，实际通过与否由实现测试证明。

### R3：无需等待所有目标分支同时静止

证据：后台已有按固定 commit 读取和原子替换快照的基础；旧草案另外要求发布前所有目标 refs 不变。

影响：多个 Change 持续推送时，普通更新会使整个快照反复重试，增加复杂度并妨碍并行场景下的刷新。

最小修正：同一来源的状态和正文固定在同一 commit，记录实际来源提交；配置和路由变更单独处理，普通目标新提交在下一次刷新读取。Technical 已收紧为此语义，T4 验证读取竞态与持续更新。

### R4：入口配置与项目配置应分开读取

外部评审指出默认分支配置会使 CLI 和 develop 上的原型策略受保护分支发布牵制；旧 main 校验器也拒绝 v2，所以不能只发布一个 JSON。对照 CLI、prototypePolicy 和共享 schema，问题成立。

处理：后台默认分支配置仅用于发现协作分支，项目配置、Specs、当前原型和原型策略均以 develop 为准。本地 CLI 读取当前工作树配置，再核对集中来源。首次后台入口配置须与兼容校验器一起发布；保护分支未获发布指令时，新后台明确显示待接入，本地开发可继续。没有擅自修改托管默认分支，也未增加默认分支阅读兜底。

### R5：默认集成与保护分支发布的历史要避免互相删除规划

外部评审建议在独立 worktree 同步 develop 后快进推送，避免在共享主工作区合码；同时指出过滤规划的 merge 提交回流会删除集中记录。前者符合 Git 的单分支 worktree 限制，后者已用 Research 中的临时实验验证。

处理：默认 Change → develop 不 squash，在工作区完成集成验证后快进推送；主工作区干净时跟进。保护分支仅在用户请求时以验证后的 develop 交付树准备单父提交/PR，过滤规划，不回流过滤提交；保护分支独立修改先核对保留。未采纳额外的持久化发布登记或按任意 Change 组合发布引擎。旧工作分支接入后的 live/archive 冲突在该次合码中按 ID 解决。

### R6：移交拓扑与本机机制可以简化

外部评审对重复 branch 修改导致归档冲突的推断与 R1 实验一致。采纳同一登记提交、先推目标后快进 develop；一个幂等 handoff 加 dry-run，删除三段命令和本机恢复日志。

采纳限定路径提交与 Git worktree 复用，删除额外规划发布锁、要求所有正文先在外部准备以及本机会话占用登记。代价已写入 A5：同一个 worktree 内手动启动多个写入会话不会被 Git 拦截，同一 Change 的写入者仍须协调。未采纳“用户曾否决所有同类防误用机制”的归因；用户此前明确否决的是多余入口文件和提交，不能扩大解释。
