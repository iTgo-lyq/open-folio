# 准备实施时创建 Draft PR

## 目标与范围

延续 [PR 集成与正式发布交付](../../archive/2026-10-22-pr-release-delivery/requirement.md)：将 Change PR 从归档推送后默认创建，提前到准备实施、移交独立工作区时创建或复用 Draft，让协作者在实施期间查看持续更新的差异，工作台也能提前展示关联链接。

用户已明确方向：前置到开始创建工作区准备实施的时候。规模为 small，仅调整 SpecTrail 流程提示与引用文档，不改变脚本接口、平台校验或前端行为。

## 方案要点

工作区移交和登记推送成功后，通过平台工具查找同仓库、登记工作分支到集成分支的匹配 PR，复用已有 PR，缺失则创建 Draft，并保留唯一的 `SpecTrail-Change` 标记。移交提交由两端共享、尚无差异时，先提交推送真实的执行状态检查点，再创建 Draft，然后开始实现，不为创建 PR 添加空提交。

后续提交继续推送同一源分支，PR diff 自动更新；归档后更新同一 PR 的最终交付说明和验证证据，通过预检后转为可审阅，CI 通过且有实际授权才合入。未归档时归档 CI 失败为预期门禁，不跳过或放宽。已有工作台在刷新后展示 Draft 链接，开发状态和交付标签按既有规则判断。

## 验收

- 主流程、工作区移交、PR 集成和常用命令示例统一指向准备实施阶段创建或复用 Draft。
- 覆盖移交后两端无差异的实际情况，不制造空提交，真实执行检查点推送后、开始实现前创建 Draft。
- 持续推送更新同一 PR，归档后更新说明并转为可审阅；未归档禁止合入及 CI 校验保持有效。
- 当前 Change 按提前创建流程建立 Draft，后续推送后核实同一 PR 的源 SHA 更新；已有 Draft 关联与归档校验回归通过。
