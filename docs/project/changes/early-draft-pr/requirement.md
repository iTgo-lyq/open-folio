# Plan 编写前移交分支，完成后创建 PR

## 目标与范围

延续 [PR 集成与正式发布交付](../../archive/2026-10-22-pr-release-delivery/requirement.md)：开始编写 Plan 前创建独立工作分支和工作区，Plan 写完并推送后创建或复用 Draft PR，让协作者提前查看计划及后续实施差异，工作台也能展示关联链接。

用户已明确上述时机，并要求 skill 措辞精炼。规模为 small，调整移交前置校验及流程说明；不改变状态结构、PR 校验或前端行为。

## 方案要点

medium / large / xlarge 在开始编写 Plan 前移交；需求及 Technical 已准备并推送，large 还需技术确认。移交不要求 Plan、任务或子 Change 已完成，也不提前检查执行依赖是否已交付；实际执行仍检查全部确认、任务与依赖。xlarge 在同一工作分支继续聚合和关闭。

Plan 写完并推送后，匹配同仓库、登记工作分支到集成分支的 PR，复用已有 PR，缺失则创建 Draft，并保留唯一的 `SpecTrail-Change` 标记，无需等待计划确认。small 没有 Plan，实施前移交，推送真实的执行状态后创建 Draft，不添加空提交。

后续推送更新同一 PR 的 diff；归档后更新最终说明，通过预检后转为可审阅，CI 通过且有实际授权才合入。未归档时归档 CI 失败为预期门禁。工作台刷新后展示 Draft 链接，交付标签按既有规则判断。主 skill 保留时机，操作细节放引用文档。

## 验收

- medium / large / xlarge 可在 Plan 尚不存在、任务未登记或子项未关闭时移交；未获需求确认或 large 技术确认时拒绝。
- Plan 在工作分支写入，推送后创建或复用 Draft，不等待计划确认；small 在实施前以真实执行检查点创建 Draft。
- 持续推送更新同一 PR，归档后更新说明并转为可审阅；未归档禁止合入及 CI 校验保持有效。
- 当前 small Change 在实现前建立 Draft，后续推送后核实同一 PR 的源 SHA 更新；移交、Draft 关联与归档校验回归通过。
