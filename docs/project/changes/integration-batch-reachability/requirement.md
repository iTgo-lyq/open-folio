# 隔离旧 PR 对批量合入记录读取的影响

工作台刷新时，平台目录可能仍包含目标分支改写前的已合并 PR。归档差异的批量读取若收到缺失的合并提交，会丢失同批其他 PR 的差异，影响已交付 Change 的合入记录。此修复延续 `release-archive-detection` 引入的合入记录批量读取。

批量读取前，按 PR 的目标分支快照校验合并提交的可达性，复用当前刷新的 Git 历史查询。已归档子项的历史目标分支缺失时，继续以项目集成历史为可用证据。保留平台 PR 记录和既有交付判断。用户已确认启动此范围的修复。

## 验收

- 冷缓存刷新同时遇到正常已合并 PR、提交缺失的旧 PR 和提交仍存在但已脱离目标分支历史的旧 PR。正常 Change 的合入记录及差异可读，尚未发布时显示「待合入」。旧 PR 保留在对应 Change 的 PR 列表，交付仍待核实。
- 子项照常使用父 Change 的目标分支，已核实的历史合入和发布归档按现有规则展示。
