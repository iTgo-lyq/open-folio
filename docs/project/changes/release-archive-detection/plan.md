# 执行计划

## T1 发布归档识别与历史 PR 溯源

实现发布快照的有效归档校验、第一父链引入提交定位、PR 精确匹配以及已归档 tab 分类。复用现有归档规则与时间线，维护缓存失效与读取边界，补充真实 Git、交付投影和目录分类回归，并完成浏览器验收与独立评审。

验收以 Requirement 为准：发布归档决定已合入，PR 可读性只影响批次与时间；无 PR 的条目全部进入已归档中的合入时间未知。测试验证完成后交用户验收，确认后同步 Specs、归档并通过 PR 合入 develop，按项目约定更新长期服务。

## T2 从发布提交识别项目版本

补充 T1 的发布批次展示：读取常见根版本文件，按发布提交缓存并复用，版本缺失不影响合入事实。验证多语言静态格式、冲突、动态版本、历史提交固定与重启缓存；保留当前 PR 标记协议，独立评审后重新提交验收。
