# 发布归档事实与 PR 溯源

发布状态直接读取固定的 releaseBranch 远端提交。定向读取已知 Change 的归档 JSON、Plan 和活动目录痕迹，复用现有候选解析、关闭语义与唯一来源校验。发布验证不重新依赖当前工作分支的关系图或作者信息；关系与交付规范继续由合入前 CI 保证，避免冻结的取消子项来源不可读撤销历史发布事实。

发布快照有有效归档时直接生成 releaseMerged，优先于当前来源异常、Change PR 与发布 PR 的读取结果。目录分类以服务端已核实的 releaseMerged 优先，使主来源异常的已发布条目仍进入已归档。历史 deliveryOverride 保留兼容，不生成时间证据。

按发布分支第一父链从早到晚检查相关归档的有效性，定位首次有效引入提交；同 ID 目录改名不会改变首次交付。历史对象不可读时保留当前有效归档结论，仅缺少时间来源。复用按目标分支批量读取的 PR 数据，用 mergeCommit 精确匹配引入提交，检查仓库身份、发布目标和 merged 状态。PR 标记作为补充展示信息，不能成为历史匹配前置；无唯一 PR 或有效 mergedAt 时不设置 releaseMergedPrNumber，沿用合入时间未知分组。

保留现有 Snapshot 交付字段，新增读取结果为内部计算数据；提升扫描指纹与 PR 标记缓存版本，防止旧过滤结果被复用。发布快照与 PR 元数据分别刷新，只有仓库授权失效、取消或整体读取限额等原有边界可阻止快照发布。

验证覆盖真实 Git 普通 merge、无标记与错误清单、PR 权限失败、无可靠时间、后续发布、目录移动、无效归档、来源异常和已有历史补记。使用仓库测试设施构造历史，独立评审全部差异；浏览器验收复用常驻 Chrome，验证两个 tab 的互斥与未知时间分组。
