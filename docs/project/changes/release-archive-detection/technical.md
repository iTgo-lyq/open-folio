# 发布归档事实与历史补齐

## 依据与删减

既有 `change-workflow/spec.md` 约束同仓库、单个登记工作分支对应一个 Change、普通 merge 保留双亲、集成后的归档只读；子项 PR 可以合入父分支，其提交不一定在项目 first-parent 链。工作台当前归档继续使用既有关闭、目录唯一性、任务安排与快照内关系校验。固定 SHA、仓库身份、访问权限和发布前权限复查继续保留。

本次明确修改 PR 正文标记协议及发布事实来源：删除三个标记的生成要求、解析、缓存字段与 CI 依赖。历史节点重验关闭状态、每个 Change 重读合并提交的全部归档树没有额外 Spec 依据，可以删除。版本、PR 和差异信息不再决定当前归档是否已发布。

## 完整读取链路

Git 获取仍只读取集成分支、登记来源与单一 releaseBranch。当前目录使用带对象大小的 ls-tree，一批读取去重后的 blob；JSON 入口和其余正文分阶段批读。路由、目录文档、活动 ID 与 Spec 路径使用 Map/Set，避免每个 Change 扫描全体文档。保留 UTF-8、文件类型、容量和当前归档语义校验。

冷重建先把当前有效发布归档投影成 releaseMerged，并写入可读快照；无历史时暂归“合入时间未知”。手动首次刷新 HTTP 返回这份列表，既有页面自动刷新等待同一个后台任务完成，再读取最终快照，不增加队列或轮询协议。后台任务继续由凭据租约持有，每次发布都检查权限和跟踪状态；后台 Token/仓库拒绝同样使缓存权限失效。中途重启留下 historyPending 的快照，下次自动刷新继续补齐。

历史只做一次 first-parent、从旧到新的新增路径遍历，按 Change ID 记录归档 change.json 首次进入发布分支的提交。当前归档已验证后不再读取历史正文；日期目录移动不改变身份。历史不可读只使时间来源缺失。发布提交与当前 ID/读取规则不变时复用已有追溯。

合并差异的元数据、双亲和新增归档路径用一次 Git 日志批量读取；普通文件模式和唯一归档路径继续检查。非标准的已有归档边界保留原定位后备；批读整体失败不触发逐 Change 重试风暴。每个实际目标 tip 只读一次完整祖先集供集成判定，不能用发布 first-parent 规则替代子项的祖先核实。

## PR 与版本

当前登记分支与实际目标关联 Change PR；发布 PR 只匹配本地找到的首次引入提交、同仓库、发布目标和 merged 状态。必须唯一且有可靠 mergedAt 才进入日期批次；未知或歧义仍已归档。旧人工补记继续兼容，但不制造 PR 或时间证据。

完整工作台同时需要 Change PR 和发布 PR。正常规模的实测选择一份按更新时间倒序的仓库 PR 目录；按已知分支和引入提交在本地筛选、复用，禁止逐 Change 网络查询。冷读完整分页；暖读首屏 ETag，304 直接复用，变化时读到旧更新时间水位以下；时间戳相等继续翻页。PR 编号是目录内稳定键，仓库/凭据身份进入缓存 key，失败的部分分页不覆盖完整缓存。正文不保存，改 target/重新打开旧 PR 仍可更新。大量无关 PR 仓库可能更适合按提交查询，本轮不加入自适应调度框架，成本证据见 Performance。

版本按引入提交读取根 package.json、Cargo.toml（含 workspace）、pyproject.toml（含 Poetry）、pom.xml 的直接 project/version、pubspec.yaml、VERSION、version.txt。只静态解析，不执行项目代码、动态表达式或依赖版本。每个发布提交一次路径树读取，跨提交去重 blob 后批读；相同发布批次的 Change 共用结果。缺失/无效/冲突/不可读结果也按提交缓存，临时失败可重试。

无文件版本时，一次远端 tag 广告读取识别 v1.2.3、1.2.3、release-1.2.3、release/v1.2.3 等精确提交标签，支持轻量和附注 peeled 提交、预发布及构建后缀，不向祖先借版本。tag 正负缓存 5 分钟，以识别后补/移动。文件不可读或版本冲突不被 tag 掩盖。Go 使用通用版本文件或 tag，不把 go.mod 工具链/依赖版本当成发布版本。

CI 以唯一集中登记分支识别 Change PR，核实自己的有效归档及所属子项。发布范围从固定源目标归档 ID 差异得到；旧归档只读，同 ID 重复归档/活动记录拒绝；新增归档仍需有效集成 M、候选祖先和已集成归档一致性。PR 正文仅供人阅读。

## 持久化与验证

继续使用现有 SnapshotStore 原子文件写入。PR 计算器接收平台读取函数并输出可序列化目录，文件加载与写入保持在明确边界；归档按 ID、版本按提交键控。保持现有 UI 快照投影，不引入 ORM、数据库占位层或双套存储模型。旧扫描指纹、集成记录版本与 PR 缓存版本失效后有界重建。

验证覆盖当前有效归档与历史首次出现的分工、日期重命名、未知 PR/时间、跨父分支集成、权限失效、两阶段 HTTP、无标记 CI、版本缓存及全链路千级冷重建。详细样本、实测值和限制记录于 Performance。
