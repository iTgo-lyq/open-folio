## T1 发布归档识别与历史 PR 溯源

发布快照单独复用 Change 候选、关闭语义、目录唯一性及快照内关系校验；不依赖外部冻结工作分支的当前状态。发布事实优先于开发来源与 PR 可读性，目录统一进入已归档。发布 PR 通过第一父链首次有效归档提交精确匹配，PR 正文标记仅补充版本和详情，无可靠 PR 时间时归入合入时间未知。

发布历史按固定提交、已知 ID 集合与扫描指纹缓存，缺失历史的结果会重试。PR 缓存保留无标记记录；PR 限流停止后续元数据查询但保留 Git 归档结论，损坏缓存冷读恢复，Token/仓库权限与发布前权限复查保持有效。OpenFolio 与 SpecTrail 同步到 0.1.32。

## T2 从发布提交识别项目版本

发布批次优先读取归档引入提交中的根目录 package.json、Cargo.toml、pyproject.toml、pom.xml、pubspec.yaml、VERSION、version.txt。新增 smol-toml 解析 TOML，JSON/YAML/XML 使用已有格式解析器；只读取静态项目版本，Cargo 支持根工作区版本，Python 兼容旧 Poetry 字段。不执行构建或猜测动态表达式。根候选版本冲突留空，超限和符号链接结果不可由 tag 或旧 PR 标记覆盖。

文件没有静态版本时，识别精确指向归档引入提交的 v1.2.3、1.2.3、release-1.2.3、release/v1.2.3 等 tag（含预发布及构建后缀），支持轻量与附注 tag。只读取远端 tag 广告和 peeled 提交，不 fetch tag 对象、不沿祖先借用版本。Go 使用项目通用版本文件或 tag，不读取 go.mod 的工具链/依赖版本。

文件结果按提交写入 Snapshot 持久缓存，确定的缺失/冲突/不可读同样缓存；临时失败重试。tag 正负结果单独缓存 5 分钟，到期后读取远端以识别后补、移动和删除。版本未知不影响归档事实和可核实的合入时间。旧 PR 版本标记仅在确定无版本文件与 tag 时兼容；本轮没有改动 skill/CI 标记协议。

验证：全量 npm test 455 项通过（约 259 秒）；其后评审边界修正及新增用例以最终 25 项版本、归档缓存和交付回归复验通过。最终代码生产构建通过，类型检查、修改文件格式检查及 git diff --check 通过。独立子 Agent 复验 25 项通过，无未解决问题，见 R4。T1 的浏览器归档分类证据仍适用，本轮未改变 UI 结构或分类逻辑。
