# 执行证据

## T1 分享详情缓存先读与后台更新

详情默认先读快照，显式 refresh=1 等待更新；缓存缺失及旧快照找不到目标时刷新。普通详情允许交付构造时的完整授权快照，资源保持固定快照与响应前权限检查。客户端初次展示后继续更新，版本竞争安排后续重读。

验证：`node --conditions=react-server --test tests/shares.test.ts` 12/12 通过；`npm run test:e2e -- tests/browser/change-sharing.spec.ts` 7/7 通过；`npm run typecheck` 通过。覆盖刷新挂起时缓存返回、共享刷新合并、新 Change、临时失败保留、失权、分支移交/归档及图片版本竞争。现有测试中需要主动触发更新的调用已改用 refresh=1。

## T2 阅读缓存复用与暂时失败保留

每个确认后的读取身份使用有界内存缓存（128 项、约 16 MiB 上限）；工作台、按 blob 版本识别的正文及原型目录复用。身份代次变化创建新缓存，明确失权清除数据，在途正文不能重新写入失效缓存。更新快照前预取当前可见正文，随后原子替换阅读版本。阅读模块使用统一活跃条件，避免模块切换重启 workbench/refresh。目录状态和列表独立加载；会话与目录暂时失败保留已显示内容并提供重试。

验证：缓存容量/淘汰/迟到响应测试 2/2；自动刷新、分享、工作台隔离浏览器回归 19/19；新增原型往返缓存、正文响应挂起时旧版本保留、目录失败保留后的自动刷新套件 6/6；类型检查通过。已有权限首次/到期复验、失权与退出规则继续沿用，不修改服务端权限缓存期限。

## T3 跨浏览器自动恢复已有 Token

新设备恢复已登录账号后，仅在未选用且恰有一个绑定时自动调用既有选用接口；沿用 Token 身份验证和浏览器修订号并发保护。失败保留账号登录、已有绑定与手动选择入口；多绑定显示当前账号并引导选择。每个设备恢复只自动尝试一次，避免网络失败循环调用。

验证：账号/个人工作台浏览器套件 17 项通过，新增失败用例首次因定位到 Next 路由公告的 alert 而失败，限定 main 后补跑通过；多绑定首页、失败手动恢复、延迟自动恢复与手动切换竞争、跨浏览器解绑补跑 4/4 通过。唯一 Token 的第二浏览器无需再次提交 Token，服务端旧修订请求返回 409，另一设备选择不变。类型检查通过。

## T4 评审边界修复与整体验证

修复 R1–R3：正文准备循环重新核对当前阅读材料；当前原型目录与快照一起准备；目录接口明确会话/绑定失效时清空同连接阅读缓存。会话网络错误提示仅在确有阅读内容时说明保留旧内容，避免失权清空后提示误导。

验证：缓存单测 3/3；相关浏览器整套 35 项中 31 项首轮通过，4 项新测试因截图状态文本变化及多个 alert 的严格定位失败，调整为稳定标题/指定错误定位后自动刷新套件 10/10 通过，原有断言保留。覆盖账号绑定10、自动刷新10、分享7、工作台隔离8。此前全量 Node 319/319 通过，T4 新增缓存竞态测试后单独 3/3 通过；最终类型检查通过，生产构建通过。独立复审确认 R1–R3 关闭，完整差异无新增需修复问题，见 review.md。
