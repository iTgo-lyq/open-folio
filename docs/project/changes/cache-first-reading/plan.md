# 交付计划

按 T1 → T2 → T3 串行交付，使用同一 Change 工作分支；每项包含针对行为的测试和验证证据。技术方案与此计划一并确认后执行。

## T1 分享详情缓存先读与后台更新

将分享详情的缓存读取与等待更新区分，保留授权与固定版本资源范围；客户端先展示缓存，再接收更新结果。处理缓存缺失、缓存中尚无新 Change、快照竞争、来源切换和更新失败。

验收：远端更新挂起时缓存详情和材料可以先展示；更新成功替换完整版本，暂时错误保留内容；无缓存或目标尚未出现时按首次采集处理；明确失权不能继续返回缓存。使用服务端分享测试及浏览器分享用例验证请求顺序、错误和版本竞争。

## T2 阅读缓存复用与暂时失败保留

加入受作用域约束的有界内存缓存，覆盖工作台、正文和原型目录；消除阅读模块切换引发的重复快照/刷新请求，同版本正文复用，更新时保持一致的阅读版本。目录状态/列表独立加载，暂时失败保留已显示内容。会话后台失败不卸载既有阅读页，真实身份与权限变化清理缓存和在途交付。

验收：同仓库模块切换不额外触发 workbench/refresh；材料 A→B→A 和仓库往返先显示已有缓存；正文未变不重读、正文变化不闪空或混用元数据；会话/目录/更新接口瞬断后保持页面并可恢复；退出、Token 切换、解绑、账号变化和晚到响应不能恢复旧内容。扩展自动刷新及工作台隔离浏览器测试，并执行相关服务端权限回归。

## T3 跨浏览器自动恢复已有 Token

在成功登录的会话恢复中自动选用唯一绑定，复用现有服务端身份验证与并发校验。区分自动恢复中、失败可重试、多个已有绑定和无绑定的首页状态，清楚显示当前账号；沿用现有组件和布局，不扩展新的设置流程。

验收：第二独立浏览器仅使用账号密码，即可自动恢复唯一 Token 和偏好；不再次提交 Token。多绑定要求选择，零绑定要求新增；自动选用失败仍显示已登录账号和已有绑定，能手动重试。恢复与手动切换、退出、解绑的竞态不能覆盖最新状态，其他设备不被改变。

## 整体验证与交付

执行相关 Node 服务端测试、Playwright 浏览器回归、类型检查和生产构建。依据基线比较请求数量与加载行为，不把本机 API 毫秒取样等同于用户公网体验。使用独立评审检查完整差异、验收覆盖和缓存/权限边界，修复问题后提交用户验收。

用户验收通过后同步相关 Specs、归档并按授权合入 develop；在主工作区停止长期服务、串行构建并启动，用 withSmokeSession 对实际缓存读取和独立浏览器恢复冒烟，复查测试会话退出。正式发布分支保持现有发布流程。
