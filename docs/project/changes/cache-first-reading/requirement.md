# 缓存优先阅读与跨浏览器 Token 恢复

用户打开页面经常等待较久，已有缓存未稳定优先展示；换浏览器登录后出现重新绑定 Token 的提示，难以判断账号与绑定是否恢复。

## 目标与范围

对私有工作台、Change 分享页和材料阅读落实缓存优先：已有可用内容先展示，更新期间保持可读，更新成功后替换；无缓存时显示真实加载状态。减少同仓库模块切换、材料往返及无内容变化更新产生的重复加载。

普通网络故障、远端暂不可用或限流不清空已显示的内容，显示更新失败及重试入口；明确退出、账号/Token 切换、绑定撤销或失权仍及时移除不可用内容。服务端每次读取检查本地会话归属，远端权限继续使用固定五分钟有效期；首次、过期、重启后的复验要求保持。

登录同一账号时，恰好有一个已保存 Token 自动恢复该工作台；有多个 Token 时明确引导选择已有绑定；没有绑定时才引导新增。页面展示当前 OpenFolio 账号，便于核对登录身份。不同浏览器的显式选择保持独立，已保存 Token、偏好与用户数据继续保留，不迁移持久化格式。

本次覆盖私有工作台快照、正文、仓库目录、原型目录和分享详情的读取体验。复用现有服务端快照、Git/blob 缓存、权限缓存及共享刷新任务，不改造仓库发现协议，不绕过权限返回过期授权内容，也不扩大公开分享范围。

## 验收

1. 有服务端快照的分享页在远端刷新挂起时仍能取得并展示原有内容；刷新成功后展示新版本，无缓存时等待首次采集。
2. 同仓库 Specs、Changes、原型之间切换不因模块切换重复读取工作台或启动刷新；同一会话内返回已读仓库、材料、原型目录时优先复用缓存。
3. 当前文档未变时快照更新不清空正文；文档发生变化时保持旧内容直到完整新版本可用，再同步切换正文及版本信息，不能混用新旧版本。删除的材料不继续作为当前材料展示。
4. 会话轮询、目录或后台更新遇到暂时网络错误时，现有页面和目录仍可见，错误可重试；恢复后更新成功。明确身份/权限变化时旧作用域缓存不可继续展示，在途旧响应不得恢复旧内容。
5. 两个独立浏览器登录同一只有一个绑定的账号，无需重填 Token 即可读取工作台；多个绑定显示选择已有 Token，零绑定显示新增入口；其他账号不继承任何绑定或内容。
6. 现有权限过期、撤销、并发更新、分享版本一致性测试继续通过；使用真实服务时按 withSmokeSession 创建并清理独立测试会话。实现验证后交付用户验收，合入后更新长期服务并冒烟。

## 确认与证据

需求 Q1：是否以 medium Change 同时优化缓存优先、减少重复加载，以及唯一 Token 自动恢复/多 Token 选择？推荐一并处理，覆盖原始用户体验。用户回答「按建议范围推进」。此前会话已明确补充分享页等待远端刷新、目录/会话瞬断清空、正文更新闪空的问题。

调查与现有行为证据见 [research.md](./research.md)。本次不认定用户登录错账号；目前仅在专用验证账号上复现登录后有绑定但未选择的状态。
