# 默认配置与可视化配置管理

## 背景与目标

独立部署后，用户无需手工准备配置文件即可打开工作台，并能在界面中登记和维护项目。用户明确要求：增加默认配置路径；默认或指定文件不存在时创建空配置；将左下角头像替换为配置入口，界面修改同步到实际配置文件。

用户已确认默认位置采用 `OPENFOLIO_DATA_DIR/config.json`、显式 `OPENFOLIO_CONFIG` 优先，以及配置面板覆盖项目和资源限制。未设置数据目录时，默认文件为 `~/.local/share/open-folio/config.json`。

## 范围与行为变化

`project-knowledge`：MODIFIED 服务始终解析一个实际配置文件路径，首次读取时自动补齐不存在的父目录和空文件。空配置为 `{"schemaVersion":1,"projects":[]}`，没有演示项目；已存在的文件继续作为唯一配置来源。

`project-knowledge/configuration`：ADDED 左下角齿轮打开配置面板；空项目引导及移动端同样可以进入。用户能添加、编辑和移除项目，维护 id、名称、HTTPS 仓库地址、可选守护分支和原型来源；能调整已有资源限制并清除覆盖值以恢复默认。点击保存才持久化，取消放弃当前编辑。

配置保存成功后，项目列表和当前项目内容使用新配置，无需重启服务。删除当前项目后选择仍存在的项目，列表为空时回到连接引导；更换仓库地址后不继续展示旧仓库快照。离开未保存表单时提供保留或放弃编辑的选择。

权限不足、文件内容损坏、字段不合法和保存冲突均显示可操作的错误，不覆盖原文件，不把失败显示为已保存。两个已打开的面板或外部文件编辑产生冲突时，旧版本保存应被拒绝，用户可以重新加载配置。

## 约束

沿用单实例、持久磁盘部署和现有 HTTPS 仓库规则。配置入口管理的是本机服务配置，源仓库的 Specs、Changes 与流程记录仍由 SpecTrail 维护。数据目录和配置文件路径由启动环境决定，页面不能改写任意服务器路径；仓库凭据仍通过服务用户的 Git credential helper 提供。

## 验收标准

- 不传配置路径，以及指定不存在的嵌套路径，两种情况均创建有效空配置；已有配置不会被初始化覆盖。
- 页面从空配置开始添加项目，保存后文件内容与界面一致，重新打开页面仍能读取；修改、移除项目及资源限制均可持久化。
- 默认限制可见，清空覆盖值恢复默认；非法字段、重复 id 和非法仓库或原型来源被拒绝。
- 损坏文件、写入失败和过期版本保存均保留原配置，并展示明确结果。
- 保存后当前项目、仓库变更和空项目状态正确；移动端、键盘打开关闭与未保存提示可用。
- 配置初始化不在生产构建时写入个人文件或访问远端；现有阅读与刷新回归通过。
