# 技术方案

## 状态和界面

复用现有 `waitingFor.kind=pause`，不增加持久化状态或迁移。用户只记录需求时保留 `active / requirement`、空任务与暂缓说明；澄清、标题及标签更新不清除 pause。恢复推进仍需明确指令，再使用 resume；暂停期间不准备执行工作区。

处理状态优先识别 confirmation 和 pause，再识别真实任务阻塞或 dependency，最后为推进中。pause 在列表和看板单列“暂缓”，详情沿用同一文案，阻塞任务及原因继续按现有材料展示。沿用现有布局、组件和样式，Astra 在现有 Changes 原型中表达列表、看板与详情状态；原型获用户确认后才实施对应 UI。

用户已验收 Astra 原型，并明确要求对齐线上阶段列。正式列表用五个阶段圆点与名称表达进度，看板沿当前处理状态/阶段分组；保留取消、来源异常和完成交付的原有说明，窄屏按原型显示。

## 归属判定

branch 保存的名字与当前可用的材料来源分别判断。保留原始 JSON 的 branch，不另建计划分支字段、移交状态文件或全量分支索引；运行时路由给出实际读取分支和证据新鲜度。

在共享的归属判断中，目标事实来自定向读取的命名分支及其所属 Change：至少核对目录 id、记录可读与分支归属；归档继续使用现有完整归档规则。不能只因同名 ref 或 Git worktree 登记存在就宣称已移交，也不能因集中记录仍为 requirement 就宣称未移交。

| 可核实的事实 | 读取与写入行为 |
| --- | --- |
| 目标没有建立，集中材料仍为有效规划记录，未发现曾有实际交付源的证据 | 从集成分支继续读取和澄清，保留预填分支名，locate 明示尚无目标 worktree |
| 目标仅含不属于该目标的继承规划材料，未形成该 Change 的实际来源 | 仍使用集中规划；显式 handoff 时检查目标可否安全复用，不覆盖无关分支或修改 |
| 本地真实分支或已发布目标含匹配的所属 Change | 按目标最新记录处理；需求阶段也在目标工作区继续，集中副本不能提交推进 |
| 已知目标曾承载所属 Change，但实时查询确认远端丢失 | 报来源缺失，不把陈旧跟踪副本当作仍在发布，也不把旧集中材料自动改成可写规划 |
| 查询失败、记录损坏、身份冲突或重复归属 | 保留诊断与现场，不当作目标不存在、不静默采用集中旧副本 |
| 完成归档或取消记录 | 沿用现有归档读取、取消冻结和父子交付规则，不按规划回退 |

集中规划候选必须是有效的 active 记录，处于 requirement 或 technical，且没有 doing/done/blocked 实现任务与关闭交付记录。该条件只限定“可以继续集中规划”的候选；目标实际存在时仍以目标证据优先，不以集中 stage 判定移交。

## 各入口复用同一规则

共享判断只处理已收集事实，不自行联网或写状态；CLI、hook 和后台各使用其已有 Git 入口提供事实，避免为每个入口另造一套移交定义。

- **后台读取**：复用当前批量精确 ref 查询和目标材料读取。明确不存在且满足集中规划条件时，将有效材料来源保留在集成分支；目标正常时读取目标。沿用现有快照/跟踪数据识别已经观察到的真实来源，不把其丢失误作从未创建。记录解析与主候选选择接受此运行时来源解释，不改写仓库 JSON；更新扫描语义版本，使旧缓存正常重算。
- **状态命令**：联网写命令核实集中入口和所需目标；show 继续标注缓存新鲜度。有效来源仍在集成分支时允许澄清、标签、暂缓和恢复等既有规划操作；execute 仍检查真实移交、有效确认与依赖，不能因允许记录就开始实施。已移交记录继续拒绝集中修改。
- **locate / prepare / handoff**：locate 只报告事实，不创建目录；仅预填目标时输出实际集中来源与尚无工作区。prepare 不替代未完成的 handoff。显式 handoff 优先沿用预填目标，保留原有前置、基线及现场检查；分支已预填时避免产生无变化的登记提交，按原有先推工作分支、再公布集中登记的顺序完成普通和子项移交。重试核对真实分支，不覆盖已有成果。
- **pre-commit**：保留实际 index 与 GIT_INDEX_FILE，以 HEAD 的集中归属为输入，定向检查本地命名分支、有效 worktree 和已有远端跟踪记录中的归属证据。只有文本而没有实际归属证据时放行；有证据时拒绝并输出分支/工作区。hook 不联网，跟踪记录仅代表本地已观察事实，不宣称实时远端状态；明确远端状态由联网入口核实。增删、重命名与部分提交仍沿前序检查，失败保留现场。

## 原型与验证

原型按用户要求由 Astra 绘制，复用已有 quiet-changes 入口和虚构材料；发布与固定引用沿项目现有 R2 流程，不改历史版本。原型验收后作为 UI 实现依据。

验证围绕行为而非内部函数形状：空任务的暂缓需求可持续澄清且不自行恢复；仅预填目标在工作台、CLI、locate 和提交入口均可记录；实际来源存在则仍保护集中工作区；无关/继承分支不能伪造移交；远端缺失、查询失败、陈旧跟踪、取消及归档分别保持明确结果。使用临时仓库验证真实提交与普通/父子 handoff、失败重试、部分提交和现场保留。

UI 核对列表、看板、详情及窄屏；复用常驻 CDP Chrome，仅关闭本任务创建的页面。真实登录统一使用 withSmokeSession 并验证清理。实现完成后运行相称的回归、类型检查与构建，medium 按规则独立评审并等待用户验收；经授权集成后从主工作区更新长期服务和冒烟，不在本阶段改生产实现或长期数据。

## 复杂度核对

保留：已有 pause、真实来源证据、暂存区语义、错误诊断和已验证的交付边界，分别解决误分类、误移交、部分提交及丢失现场的问题。

合并：三个读取/写入入口和 hook 的归属解释复用共享判断；原型与正式界面沿用现有组件及同一状态文案。

延后：不尝试识别未同步 Change 文档的实现提交，不增加写入隔离或全分支扫描。

不引入：新持久化状态、计划分支字段、迁移脚本、hook 网络请求或额外审批层。现有全部实际分支证据消失时，仅凭一个名字无法恢复完整历史；方案只对可核实事实作判断，不虚构移交事实。
