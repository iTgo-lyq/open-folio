## T1：独立澄清额度

主 skill 与命令参考改为需求、技术各自使用既有上限。问答维持连续编号，按首次提问的内容归属分类，在正文保留类别和 Q 引用；各自统计题数、每轮题数与不同 round 数量，不使用全局轮次最大值判断某类已用额度。

验证：skill-creator 的 `quick_validate.py .agents/skills/spec-trail` 返回 `Skill is valid!`；`git diff --check` 通过；主 skill 与命令参考的 40 处本地 Markdown 链接及标题锚点检查通过。Agent 对照完整差异自查以下情景，未发现规则冲突；未进行独立 Agent 行为测试。

| 情景 | 核对结果 |
| --- | --- |
| medium 需求 round 1、2 共六题均已收敛 | 技术可在 round 3 问最多两题，计技术第 1 轮，无须因需求到限追加授权。 |
| 同轮包含两道需求题、一道技术题 | 各类各计一轮，题数分别为 2、1；无共用题数上限，不重复计题。 |
| small 已用完需求一轮三题 | 技术仍可在需求阶段独立进行一轮一题，不新增 technical 阶段或审批。 |
| 撤回技术问题后换会话或返工 | 从正文类别与 Q 引用恢复实际占用，撤回保留计数，切换阶段不重置。 |
| 技术回答改变已确认需求 | 原技术问题仍只计技术额度；需求返工后新增需求问题使用原需求剩余额度，到限须明确授权扩展。 |
| 需求关键缺口尚未解决但技术额度可用 | 仅询问不依赖该缺口的技术问题，不用独立额度绕过阶段前置或技术就绪条件。 |
