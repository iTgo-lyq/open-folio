# 修复规划期父 Change 的待创建子项读取

xlarge 父 Change 在需求或技术规划阶段可以先登记 children，再创建子 Change。目前读取会将这种登记同时判为目标缺失与父子不对称，产生读取异常，干扰父项的正常规划阅读。

当父项规模为 xlarge、阶段为 requirement 或 technical，且子项尚无集中记录时，将该关系显示为“待创建”，不产生读取异常，也不作为已满足或已结束的子项。仍可正常阅读父项文档与原型。子项已存在但主来源、状态或反向 parent 声明异常时，继续显示诊断；execution、close 阶段的缺失子项继续按异常处理。其他规模、前置依赖、父项引用、自指与循环规则保持原有校验。

方案是在关系读取中识别规划期待创建子项，跳过仅适用于已创建子项的反向声明校验，并在关系行显示中性“待创建”标记。无需修改 change.json 格式或持久数据。

验收覆盖需求和技术阶段的缺失子项、已存在但异常的目标、自指，以及执行和关闭阶段的缺失子项；通过浏览器验证待创建展示、读取异常计数、子项结束数量和父项文档、原型的实际访问。
