# 账号密码登录与账号绑定 Token

## 目标

用户目前通过 Git 平台 Token 登录 OpenFolio。Token 虽已在服务端加密保存，浏览器记住的授权集合仍依赖本机 Cookie；换浏览器或清除 Cookie 后，需要再次录入各个 Token。

提供由 OpenFolio 服务统一保存的用户账号，以用户名和密码登录。用户绑定的 Token 持久归属于该账号，在另一浏览器登录同一账号后即可选择使用，无需重新录入。

本 Change 规模为 medium：登录凭据、设备会话和 Token 归属的持久化契约发生变化，需要联动调整身份存储、API、工作台界面及验证工具。与 `frontend-style-interaction-refactor` 的整体视觉重构分别推进，本次沿用现有产品组件和样式。

## 账号与登录

提供简单的自助注册和用户名、密码登录。OpenFolio 用户名用于站内账号识别，与 Git 平台用户名和 Token 显示名称分别表达。用户名不可重复；错误密码不能建立会话。

注册后的账号可以没有 Token，登录成功后引导添加第一个 Token。账号登录状态与当前使用的 Token 分开表达：没有绑定 Token 或 Token 已失效时，用户仍可管理自己的账号绑定列表。

账号和绑定关系由服务端持久保存，刷新页面、重开浏览器和服务重启不会丢失。另一浏览器登录同一账号后可以看到相同绑定列表。各浏览器可以分别选择当前使用的 Token，同一浏览器的标签页同步当前选择。

退出当前设备撤销该设备的账号登录；设备列表与撤销操作以账号为范围，退出全部设备撤销该账号所有设备会话。退出、会话过期和设备撤销不删除账号绑定的 Token，再次以账号密码登录即可使用。

## 账号绑定的 Token

已登录用户可以添加、命名、选择和解绑多个 Token。新增时验证平台身份，失败不保存无效绑定，也不影响已有选择。同一账号重复添加同一平台实例、同一 Token 不产生重复项。

所有 Token 管理和使用都以当前 OpenFolio 账号为授权依据。一个账号无法枚举、使用、复制或解绑另一个账号的 Token；两个账号即使提交同一 Token，也分别维护绑定、工作台及偏好，不共享站内账号数据。

每次仓库发现、读取和原型准备使用用户明确选择的 Token，仓库权限仍由 Git 平台决定。Token 之间继续分别保存工作台偏好与私有缓存；切换、解绑和账号退出后，在途响应不能把旧内容恢复到新上下文。解绑对账号所有浏览器生效，使用该绑定的浏览器回到选择或添加 Token 的状态。

平台 Token 失效时提示重新绑定，保留账号登录和其余绑定；网络故障或限流不删除绑定。用户可以主动复制当前绑定的 Token，普通列表和会话响应不返回明文。

密码以带盐的慢哈希保存，Token 在服务端加密保存。密码和 Token 不进入 URL、日志、浏览器持久存储或普通响应；账号 Cookie 采用 HttpOnly，同源写入和远程 HTTPS 要求继续适用。

## 历史数据处理

用户明确要求不保留历史数据，不提供兼容或迁移逻辑（需求澄清 Q1）。以全新的账号和绑定数据开始，旧浏览器 Cookie、旧 Token 登录方式和旧身份集合不再提供访问授权；不导入旧工作台、Token、偏好或会话，不维护双模型或版本转换分支。实施时一并移除因此失效的旧兼容代码、迁移工具及相关说明，数据处理限于被替换的个人身份系统。

## 验收

1. 用户能够自助注册，并使用用户名和密码登录；重复用户名与错误密码有明确反馈，失败时不签发账号会话。
2. 未绑定 Token 的账号可以登录并添加第一个有效 Token；无效 Token 不保存，已有绑定和当前选择不受影响。
3. 在浏览器 A 绑定多个 Token 后，浏览器 B 登录同一账号，可以直接选择这些 Token 读取有权限的仓库，不再提交 Token 明文；服务重启后结果相同。
4. 两个浏览器的 Token 选择互不影响，同浏览器标签页同步；切换或退出后，晚到响应不会展示旧上下文内容。
5. 退出当前设备或全部设备后，相应会话无法再管理 Token 或读取私有内容；重新登录后绑定列表仍存在。
6. 解绑后，所有设备均不能继续使用该绑定；其他绑定和其他账号不受影响。Token 失效与平台网络故障分别呈现，不导致账号退出。
7. 使用两个账号验证 Token 列表、管理接口、复制接口、仓库读取及偏好隔离，包括两个账号分别绑定相同 Token 的情况。
8. 新系统不接受旧个人 Cookie 或旧 Token 登录协议，不读取旧身份数据来恢复账号，不含历史兼容或迁移路径；密码和 Token 按上述存储与响应要求处理。
