# 托管原型自动截图

托管原型未登记截图时，总览只能显示占位。统一由 OpenFolio 为已登记的托管入口生成截图，项目提供的图片优先覆盖对应视口；覆盖本服务托管及外部 HTTP/HTTPS 托管，不要求项目增加截图步骤。

## 方案要点

- 复用现有 Chromium 沙箱、截图缓存、并发和超时限制，为托管 URL 增加联网渲染；使用独立空白上下文，不携带工作台会话或仓库凭据，不代办登录。
- 按入口声明的设备或组件视口补齐缺失截图，保留项目图片；总览、详情、固定公开原型和 Change 分享采用同一优先级。既有无图入口刷新后可生成，已有固定公开版本保持原样。
- 沿用固定公开版本的原子发布，截图失败可重试，不阻止用户直接预览原型。skill 只简述自动生成与项目覆盖，不扩充发布步骤。
- 本次不更改持久化协议或新增配置，预计不足 300 行有效实现，以 small 单任务交付。用户已授权开发、合入 develop/main 并同步下游。

## 验收

- 未提供图片、仅覆盖部分设备、全部提供图片时，分别生成全部缺失视口、只生成缺失视口、不调用自动渲染；组件使用声明尺寸。
- 浏览器验证跨域页面及其脚本、样式和图片能生成真实截图；截图任务无工作台登录态，失败与超时明确报错，后续任务可恢复。
- 当前卡片与详情、公开原型及 Change 分享显示正确截图；Git 离线截图和既有权限、来源复查继续有效，公开图片读取不再次联网渲染。
- 更新当前规范与精简 skill 表述，通过定向测试、类型检查、构建及相关浏览器验证后归档并交付。
