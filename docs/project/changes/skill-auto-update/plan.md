# SpecTrail 版本标识与更新检查执行计划

## 交付目标

依据 [Requirement](requirement.md) 与 [Technical](technical.md)，交付随发布生成的版本标识，以及 `change.mjs` 中由项目开关控制的更新检查。保持现有状态操作、JSON 结果和退出码语义，检查不承担安装更新。

按默认编号串行执行 `T1 → T2`。T1 建立发布版本契约，T2 复用它完成使用方场景；测试、接入说明和必要文档随所属任务交付，不另拆测试或文档任务。

## T1：发布可重复执行的 skill 版本

**交付**：在现有同步发布链路生成 `version.json`，首版 `0.1.0`，后续只有 skill 交付内容变化才递增补丁号。版本语法、比较与递增共用内置模块实现；版本与内容在同一分发提交交付，保留现有 LICENSE 及其他 skill。同步配套版本说明与发布测试，不回写源分支，也不增加独立工作流。

**验收**：

- 无历史版本时为导出的已提交内容建立首版；已有版本且内容变化时增加补丁号，`0.1.9 → 0.1.10` 等比较不依赖字符串大小。
- 同一内容重复发布、源仓库无关提交以及只重跑 CI 均不改版本、不产生新分发提交；生成的版本文件本身不触发循环递增。
- 未提交的源修改不进入发布，过期普通文件被删除，分发 LICENSE 和其他 skill 保持原有行为。
- 已有版本文件非法时停止发布而不重置版本；校验失败不向 remote 发布版本或内容，失败重试以最后成功推送的版本为准。
- 发布验证包含新增的 skill 自包含测试；本地分发夹具能够单独验证版本和内容对应关系。

**验证**：扩展现有本地源仓库、分发仓库和 bare remote 夹具，运行 `node --conditions=react-server --test tests/skill-sync.test.ts` 以及新增版本模块的自包含测试；运行现有 `node --test .agents/skills/spec-trail/setup/tests/setup.test.mjs` 核对分发验证入口。验证不调用真实发布 CI，不向公开分发库推送测试版本。

## T2：按项目配置检查并提醒 skill 更新

**交付**：将 `checkForUpdates` 可选布尔开关接入 skill 与 OpenFolio 的配置校验，在 `change.mjs` 成功输出层统一检查、追加 `skillUpdate`。支持当前目录、子目录和显式 --repo 的目标项目定位；本地版本从实际执行的 skill 安装读取。落实固定公开来源、3 秒请求上限、24 小时缓存和未知结果，配套关闭方式及旧安装首次手动更新说明。

**验收**：

- 省略或 true 时开启，false 时关闭；CLI 与工作台一致接受合法配置并拒绝非布尔值，旧配置无需迁移。关闭后没有更新检查请求、缓存读写或缓存提醒。
- 从子目录运行、从项目外显式指定 --repo，以及从其他安装位置调用脚本时，都读取实际目标项目的开关；不同项目配置独立，worktree 共享缓存不绕过各自开关。
- 有新版时在原 JSON 外层增加包含当前版本、最新版本和说明的字段；等于或低于本地版本时省略提示。show 和正常状态操作采用同一路径，原字段保持原值，不写入 state 或流程文件。
- 检查发生在状态操作成功且锁释放之后；help、无效参数、原操作失败和 dry-run 不触发检查，保留原输出与退出码。
- 缓存命中时不重复请求，过期时重新检查；手动更新安装版本后重新比较，而不是沿用旧提示。缓存采用 Git common-dir 内的可重建文件，不产生项目内待提交内容。
- 请求与响应体读取共同遵守超时和大小限制。超时、非 2xx、无效版本、缺少安装版本、损坏或不可写缓存均不把原操作变成失败；无法比较时如实提示 unknown，不使用过期结论冒充新版。
- 只有 change CLI 承载检查；其他命令、提交 hook 和 PR 校验不增加检查，检查不发送项目内容或凭据、不下载安装 skill。

**验证**：使用隔离项目、带版本标识的安装副本及可控 fetch/时间验证上述成功、关闭、缓存和失败路径。关闭与跳过场景检查更新请求计数为零，状态操作场景核对 JSON、真实状态文件、锁释放与退出码；联网断言仅针对新增更新请求，不把原有协作 Git 读取混入统计。运行相关 `tests/state-commands.test.ts`、`tests/routing.test.ts`、`tests/prototype-contract.test.ts`、skill setup 测试及新增更新检查自包含测试，实际命令与结果随任务记录。

## 整体验证与交付

两个任务完成后，对照 Requirement 全部验收项核对实现与证据，集中运行 `npm test`、`npm run typecheck`，并在任务工作区构建 `.next`。构建前确认没有进程使用该工作区的产物；依赖和配置按项目现有约定准备。测试通过且没有新变化时不重复扩大验证。

按 medium Change 进行独立评审与人工验收，处理发现的问题后同步当前 Specs、归档，再经已有 Draft PR 完成交付。评审覆盖版本与内容一致、单入口范围、关闭与失败语义，以及工作台配置读取的一致性；本轮计划不预填测试、评审或验收成功。

集成后从主工作区 develop 更新长期服务，按 `service:update` 的停止、构建、启动顺序操作并检查工作台配置读取；如需真实登录冒烟，使用 `withSmokeSession` 并核对退出清理结果。任务工作区的构建不覆盖主服务产物，用户数据不重置。

公开版本标识在后续正式发布到 main 时由现有同步 CI 生成；本次执行和本地验证不提前发布正式版本。验收材料明确区分本地夹具验证、开发服务更新与真实公开发布结果。
