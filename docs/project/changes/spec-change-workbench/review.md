# 独立评审与复验

评审基线为 main 到 53e6eb4 的全差异。按大型 Change 要求，由不继承实现会话的独立 subagent 阅读 Requirement、Technical、Plan、Execution、当前 skill 与源码，检查需求对应、读取安全与状态关系，并独立运行测试和浏览器操作。评审者只读访问生产 API，没有刷新或改动实际仓库。

## R1：关系异常未影响有效完成（P1）

证据：归档 completed 记录同时引用不存在的父项与前置，关系行虽有错误，仍保持 validCompleted；其下游显示流程已满足。影响是把来源异常变成下游可满足前提。

修复：关系结构诊断进入组诊断，先完成全图校验，再以只会失效的固定点传播 completed 与父子关闭有效性，最后生成流程和祖先证据。新增反向排列的父项、多级下游、缺失上游及父项集成回归，保证结论不受遍历顺序影响。

## R2：缺失 constructor 目标使全项目刷新失败（P2）

证据：合法 id constructor 命中普通对象原型属性，环检测尝试遍历函数并抛异常。影响应局部呈现的缺失依赖升级为整体采集失败。

修复：邻接表读取使用自有属性检查；单元样例与实际 Git fixture 均覆盖 constructor 缺失目标。

## R3：按任务编号筛选漏项（P2）

证据：任务粒度输入 T2，上层 Change 筛选只检索标题，实际 T2 被提前排除。

修复：上层同时检索任务编号与标题，下层保留精确任务过滤；浏览器验证 T2 可见且 T1 不混入。

## R4：搜索命中后目录仍折叠（P2）

证据：已折叠 platform 时全文搜索命中 platform/access，正文已切换，目录选中项仍不可见。

修复：定位能力时展开祖先并清除旧目录筛选，覆盖全文搜索与深链接恢复。独立复验进一步发现重复选择同一目标不会触发 id 变化，现用仅在客户端的显式浏览版本触发 reveal；新增同目标回归再次独立复验通过。

## R5：正文搜索结果未打开命中文档（P2）

证据：technical.md 正文命中同时具有 changeId、documentId，前者分支提前消费结果，仅打开 Change 概览。

修复：文档结果优先打开精确正文，保留 Change 文档页上下文。复验又发现同时挂载两个 Radix 模态层会互相隐藏可访问性树，改为父层挂载后再打开文档；回归包括精确正文、两层弹窗和 Escape 返回。

## R6：跨项目残留不可见筛选（P2）

证据：带 spec=platform 切换至无此关联能力的项目，筛选控件消失但查询条件仍生效，造成空列表。

修复：切换项目时清除能力、名称、阶段、规模、等待、任务状态和结果等项目条件；独立浏览器响应边界测试确认新项目记录可见。

## R7：未区分缺失与不要求的材料（P2）

证据：文档列表仅列现有文件，无法区分 small 正常省略和大规模执行中缺少必须材料。

修复：实际文档继续读取；未存在的标准材料只显示规模／阶段要求与缺失标签，现有不可读文件单独标识，不生成正文。用真实 symlink 文件检验不可读提示，并覆盖 large 缺失、small 不要求和规划中尚未要求的场景。
