# Spec 与 Change 只读工作台

## Review 导读

沿用用户认可的 OpenFolio 交互原型外壳，以当前 SpecTrail 为依据，交付读取中心 Git 仓库已推送记录的真实工作台。用户已明确：首版只读，工程流程继续由 skill 推进；本次不实现原型管理。

本需求细化项目与来源、Spec 阅读、Change 与任务浏览、流程解释和异常处理。界面内容按当前规则重新设计，不继承原型的演示领域、模拟状态或旧工作流语义。技术栈、部署配置和具体接口在需求确认后形成 Technical。

## 背景与目标

当前仓库已有 SpecTrail、守护分支配置和提交前状态校验，尚无产品应用。交互原型已验证能力目录、列表、看板和详情抽屉的可用性，但工程记录来自预置数据。

本次让用户可以从真实项目的已推送文档回答：项目当前有哪些能力、正在推进哪些变化、当前阶段和等待原因是什么、任务与依赖如何组织、已有确认和验证依据在哪里。工作台展示原始记录与可验证的关系，不另建工程流程状态，也不代替 skill 作确认、验收或关闭决定。

## 范围

### 包含

- 已配置中心 Git 仓库的项目切换、已推送分支读取、手动刷新与来源信息。
- `docs/project/specs/` 下的能力树、Markdown 阅读、搜索、章节导航与原文查看。
- `changes/` 和 `archive/` 中的 Change 列表、筛选、看板、详情和文档阅读。
- 当前 SpecTrail 的规模、阶段、任务、等待、确认、返工、依赖、父子关系、关闭与取消记录展示。
- Change 和任务两种查看粒度；任务依赖以 Plan 执行顺序表为依据。
- 空数据、无权限、读取失败、格式不合法、来源不一致、关系缺失等情况的可解释反馈。
- 桌面和手机阅读、键盘操作、链接定位及浏览上下文恢复。

### 不包含

- 原型管理、AI 生成、Agent 会话和运行调度；导航中不保留不可用的原型入口。
- 页面创建或编辑 Spec、Change 和任务，以及确认、取消、归档、提交、推送、合并等工程写操作。
- 本地工作区、暂存区和未推送提交的采集。
- 团队账号、协作权限平台、任意 workflow 编排器、历史格式自动迁移和公共托管服务。
- 通过自然语言推断文档是否实现、用户是否同意或某项交付是否已经验收。

首版面向个人使用，由运行环境配置可读取的仓库和认证，页面提供已配置项目的选择与刷新。项目登记的具体配置方式在 Technical 中明确。

## 行为变化

### ADDED

### `project/sources`：可追溯的中心仓库快照

- 只读取已配置中心仓库的已推送分支。展示项目、来源分支、提交标识和最近成功读取时间；读取快照与实时运行进度分开表达。
- Specs 默认展示项目默认守护分支的版本；切换到其他已推送分支时明确提示来源，不能把分支中的内容当作默认分支已具备的能力。守护分支配置异常时给出提示，不静默猜测。
- Change 按仓库内 `id` 识别，以 `change.json.branch` 指定的已推送主分支记录为准。其他分支的副本保留来源区别，不能重复计为不同 Change，也不能拼接不同来源的确认和交付。
- 主分支缺失、同一来源存在重复记录或来源冲突时，显示具体问题和可阅读的原记录，不用文件时间或提交标题选出业务真相。
- 手动刷新后展示新的已推送快照。失败时保留最近成功快照并标明错误及时间；尚无快照时展示可处理的空状态。快照不能混用同一分支不同提交的 JSON 与正文。
- 凭据由运行环境使用，不经页面录入、展示或返回。远端仓库内容不可触发脚本、命令或任意文件读取。

### `specs/reading`：按真实能力路径阅读

- 递归识别 `specs/<capability-path>/spec.md`，完整相对路径作为能力身份。父路径可以同时拥有正文和子能力；没有 `spec.md` 的中间路径作为目录。
- 按文档实际内容展示标题、正文、表格、列表、代码块和章节目录，不要求原型中的固定“条款／场景”结构。无标题时用能力路径作为可识别的名称。
- 搜索覆盖标题、路径和正文；选择结果后展开所在目录。支持章节锚点、复制链接、返回和刷新恢复。
- 可查看原文及其分支、提交、文件路径。已识别的相对文档链接在工作台内打开；缺失、越界或不支持预览的目标给出明确反馈。外部链接保持外部来源身份。
- 仅根据显式路径引用展示 Spec 与 Change 的关联，不向 `change.json` 增加未声明字段，也不依据标题相似性创造关联。

### `changes/browsing`：变化、阶段和任务分别呈现

- 默认展示 active Changes；cancelled 单独可筛选且仍属于 `changes/`，completed 从有效归档记录查看。已取消不等于已完成，也不自动属于归档。
- 支持按名称／id 搜索，按规模、阶段、结果、等待类型和来源异常筛选；提供列表和阶段看板。看板用于浏览，不通过拖动推进状态。
- 详情使用右侧抽屉，展示目标文档、规模、主分支、当前阶段、整体结果、等待原因、返工记录、确认、任务、关闭结果和来源。关闭抽屉后保留原筛选、选择、焦点与列表位置。
- 任务状态只取 JSON 中的 `todo / doing / done / blocked`，保留编号、标题、阻塞原因、验证和任务分支。任务完成数量不替代阶段通过或 Change 完成。
- `small` 任务直接来自 JSON；`medium / large` 同时提供 Plan 的交付定义和执行顺序依据；`xlarge` 主要展示子 Change，不伪造父级实现任务。
- Requirement、Technical、Plan 和其他实际存在的 Markdown 产物可以阅读。正文不必齐全，缺失、不可读和当前规模不要求的文件须区分，不生成虚构正文补空。

### `changes/workflow`：按当前 SpecTrail 解释记录

- 阶段使用 `requirement / technical / plan / execution / close`，整体结果使用 `active / completed / cancelled`。等待类型使用 `confirmation / dependency / pause`，与阶段和任务阻塞分别展示。
- 按规模解释路线：small 从需求进入执行；medium / xlarge 的技术与计划一起确认，不强制单独经过 plan；large 展示完整需求、技术、计划、执行、关闭过程。省略的阶段不显示成遗漏审批。
- 确认展示实际时间、摘要与来源；返工显示原因、处理方式及当前仍保留的有效记录。较早阶段有文档、存在历史提交或阶段编号更小，均不能自动证明已确认。
- 关闭按“整体验证 → 人工验收 → Specs 同步 → 归档”展示 JSON 记录和缺失项；支持验证失败及 `specs.result: not_needed`。只有验收、同步或部分归档记录时不标为完成。
- cancelled 展示取消时间、原因和保留的阶段、任务及文档，不要求补齐后续关闭步骤。completed 与目录、关闭记录不一致时标记异常，保留原始声明供核对。
- 状态来源唯一为 `change.json`。未知版本、非法枚举、关键字段缺失或目录与 id 不符时展示具体字段问题；原始 JSON 仍可查看，不降级成成功或空数据。

### `changes/relationships`：可核对的依赖与父子关系

- Change 前置关系取 `dependsOn`，父子关系取 `parent / children`；支持从当前 Change 跳转到对应记录，保留两类关系的区别。
- 缺失对象、重复、自指、循环及父子关系不一致须显示异常，不能当作无依赖。
- 前置 Change 只有关闭、归档并推送仍不足以证明当前分支已具备交付。工作台区分记录所证明的前提与交付可用性；Git 来源不足或无法可靠判定时显示待核实，不自行宣布可执行。
- 任务前置关系只从 Plan 的“执行顺序”表读取，不能从任务编号、正文顺序或虚构 JSON 字段推断；无法解析时保留原文入口并提示依赖不可判定。

### `workbench/navigation`：沿用认可的 UI 外壳

- 以归档原型的 C 方案为视觉基线，保留蓝紫背景、玻璃导航、深海蓝品牌、可收起侧栏、内嵌内容面板及详情抽屉。
- 主导航只包含 Specs 和 Changes，默认进入 Specs；重新安排项目与来源切换、搜索、刷新等实际功能。
- 内容呈现采用真实仓库记录，避免硬编码“拾光笔记”等演示领域。空项目可正常浏览，说明如何通过 skill 建立第一份 Change；不预造已实现 Specs。
- 手机支持目录展开、正文阅读、列表和详情返回；键盘支持导航、焦点恢复、搜索与 Escape 关闭最上层弹层。页面链接恢复项目、来源、文档／Change、视图和筛选。

### MODIFIED / REMOVED

当前仓库尚无产品行为，本次无既有实现的修改或删除。旧原型作为独立参考保留。

## 验收标准

| 场景 | 可观察结果 |
| --- | --- |
| 配置真实中心仓库并读取已推送分支 | 展示真实文档和 JSON；来源可追溯到提交；本地未提交和未推送修改不进入页面 |
| 向远端推送更新后刷新 | 展示同一提交的状态与正文；读取失败保留旧快照并明确提示 |
| 同一 Change 出现在多个分支，或主分支缺失 | 以声明主分支为准，避免重复统计或拼接；不可判断的来源显式报出 |
| 多层 Spec、父能力正文、全文检索和相对链接 | 目录和正文正确，搜索可定位，原文可读，链接／锚点刷新后可恢复 |
| 浏览各规模、阶段、等待和结果 | 路线符合 skill，取消留在 changes，关闭四步各自呈现，不虚构已确认或已完成 |
| 浏览 Change 与任务列表／看板／详情 | 搜索筛选有效，四种任务状态准确，正文和验证可追溯；关闭详情保留上下文 |
| 浏览前置依赖、父子 Change 和任务执行顺序 | 来源分别为 JSON 与 Plan，关系可跳转；缺失或循环可识别，未知条件不显示为已满足 |
| 非法 JSON、缺文档、不支持的 schema 和空项目 | 页面继续可用，错误指向具体来源或字段，保留原文；不将异常伪装为空结果 |
| 桌面和手机完成核心阅读路径 | 使用认可外壳，布局可用、无页面级横向溢出，键盘与返回恢复有效 |
| 检查工程写入和原型功能边界 | 工作台不修改工程文档和远端分支；无原型管理入口和模拟 AI 功能 |

整体验证包含受控 Git 远端中的真实推送／未推送对照、当前私有仓库读取、状态与关系测试、浏览器交互和截图；测试夹具只用于测试，产品空状态不回退到演示数据。
