# Spec 与 Change 工作台实施计划

依据 [Requirement](./requirement.md) 与 [Technical](./technical.md)，交付真实中心 Git 数据上的只读工作台。计划只拆分已确认方案，不新增产品能力或外部依赖。

## 交付目标

保留认可的 C 方案外壳，以可追溯快照支撑 Spec 阅读、Change／任务浏览及关系核对；交付可运行服务、自动验证、运行说明和人工验收入口。

## 执行顺序

共享契约、读取服务与界面顺序落地，在同一 Change 分支串行执行。

## 任务

### T1 读取中心 Git 并保存一致快照

交付服务基础、项目配置、HTTPS 采集、固定提交文档读取、快照事务与刷新恢复。应用可启动，无配置可说明原因，真实数据可从读取接口核对。

验收：未推送内容不可见，刷新展示新提交，失败保留旧数据；源文件、路径、协议、体积和并发边界受控，重启可恢复，正文绑定指定快照。

验证：真实临时远端的推送／未推送对照、失败／删分支／并发／快照过期测试，配置与 API 请求边界，类型检查与构建。

### T2 按 SpecTrail 解析 Change 与关系

交付严格 schema、主分支归属、规模路线、取消／关闭解释、父子和 Change 前置关系、Plan 任务依赖及异常原文入口。

验收：当前字段为唯一状态依据；非法主记录不被副本覆盖；关系缺失和循环可见；流程前提与 Git 可用性证据分开；任务顺序只取 Plan。

验证：与现有 hook 共有字段约束的一致性样例，多分支冲突、各规模／关闭／取消、依赖循环、squash 未知及真实 Plan AST 测试。

### T3 用认可外壳阅读真实 Specs

交付两模块外壳、项目与来源切换、Spec 目录与搜索、Markdown／原文／章节阅读、相对链接和来源信息。

验收：真实多层能力路径正确呈现；空项目不回退到演示数据；正文与目录锚点一致，链接边界安全，桌面及手机可操作。

验证：读取 API 驱动浏览器，覆盖目录展开、全文搜索、中文重复标题、深链接、刷新、图片与无效链接；桌面／手机截图。

### T4 浏览 Change、任务及依赖

交付列表／看板／依赖视图、搜索筛选、详情抽屉、任务／子项、正文和依据；来源异常单独可查。

验收：各规模阶段与 JSON 状态对应，取消与归档分离；抽屉打开／关闭和文档弹层不丢上下文；无法判定的信息不显示为满足。

验证：完整 API 数据上的 Change／任务浏览、筛选、依赖跳转、父子详情、异常候选、关闭四步、手机返回和键盘焦点。

### T5 完成真实项目接入与交付验证

交付运行配置示例、README、当前私有中心仓库的真实运行入口、必要边界修正和验收截图。

验收：生产构建运行后可读取当前远端；服务不污染来源工程、无原型模块；所有已确认验收场景有对应验证，敏感配置不进入仓库。

验证：类型检查、Node 全量测试、生产构建、浏览器完整回归、当前私有仓库手动刷新及运行截图；记录限制与命令。

### T6 完成独立评审与复验

交付与实现上下文隔离的全差异独立评审、问题修复及复验记录。

验收：需求与交付对应，重要问题均解决或回到相关阶段处理；达到可交付人工验收条件。

验证：独立 reviewer 检查整个差异及执行证据；按发现补充有针对性的检查，修复后复验。完成后进入 close，提交人工验收结果前不生成已实现 Specs 或归档。

### T7 修正待验收 Change 的阶段展示

依据用户验收反馈，将 close 的阶段名称展示为“验收”，已验证且等待人工验收的活跃 Change 显示“验收中”；统一列表、阶段看板、筛选和详情路线，四步记录标题改为“验收与归档”。

验收：当前 Change 不再呈现为已关闭；已归档或已取消记录不显示为验收中，底层阶段与关闭事实仍准确可追溯。

验证：Change 浏览器回归、类型检查与生产构建；在真实项目复核列表、看板、详情和窄屏，并独立评审此次差异。

## 整体验证

验收矩阵沿用 Technical 的验证表，Execution 按 T 编号记录实际交付与命令，Review 记录独立问题及复验。当前仓库的空 Specs 是真实状态，丰富文档测试使用隔离的 Git fixture。单用户、单进程、HTTPS 仓库配置和未知交付可用性的边界保持不变。
