# Spec 与 Change 工作台技术方案

## Review 导读

本方案落实已确认的 [Requirement](./requirement.md)：沿用 C 方案外壳，提供中心 Git 已推送记录上的只读 Specs 与 Changes。推荐采用单个自托管 Next.js 应用，服务端维护独立 bare Git 缓存和不可变文档快照，前端只消费经过校验的数据。

需要确认的关键取舍：

- 首版为单用户、单进程服务，使用持久磁盘和运行环境已有的 Git 认证；不引入数据库、团队登录或独立后台服务。
- 项目通过服务端配置登记，首版远端传输使用 HTTPS。页面不接收任意仓库 URL、认证值或本地路径。
- 分支聚合以声明主分支为准；异常记录继续可读，不能由其他分支的有效副本覆盖主分支错误。
- 依赖分别呈现流程前提与交付可用性。无法证明交付可用时明确待核实，不增加自动放行能力。

核心路径已通过独立 bare 仓库读取当前私有远端、受控远端隔离实验和 Markdown 解析实验验证，详见 [Research](./research.md)。产品 API、缓存事务和浏览器端到端行为在执行阶段实现并验证；这些实验不代表应用已完成。

## 方案

### 运行形态与技术基线

保留归档已验证的 React / Next.js / Tailwind / shadcn-Radix 组合。采用 App Router、Node.js Route Handlers 和同源客户端请求，服务器负责 Git、校验、关系解析及正文索引。服务端模块使用 server-only 边界；客户端仅接收可展示 DTO，不导入服务配置、Git 模块和凭据。

| 部分 | 基线与用途 |
| --- | --- |
| 运行时 | Node.js 24.x；当前验证环境为 24.21.0，Git 为 2.39.5 |
| 应用 | Next.js 16.3.7、React / React DOM 19.3.0、TypeScript 5.9.3 |
| 界面 | Tailwind / PostCSS 插件 4.3.3、Radix UI 1.6.7、Lucide 0.577.0，以及原型中实际需要的 shadcn 组件 |
| Markdown | react-markdown 10.1.0、remark-gfm 4.0.1、remark-parse 11.0.0、unified 11.0.5；AST 用于目录、链接与 Plan 表格，正文安全渲染 |
| 状态校验 | Zod 3.25.76 的严格对象校验；与 skill 字段契约及现有 hook 用同一组有效／无效样例做一致性检查 |
| 验证 | Node 原生测试运行器、TypeScript 检查、Next 生产构建、Playwright 1.63.0 |

以上版本已核对归档 lockfile 与实际安装包；执行时显式登记直接依赖并生成本项目 lockfile，不复制整套依赖、构建输出或私有配置。UI 源码按功能抽取适配，不移入原型模块和演示状态管理。Next.js 路由与部署约定以安装包随附文档和官方文档为准。

### 项目配置与部署

服务从 `OPENFOLIO_CONFIG` 指定的配置文件读取已登记项目，`OPENFOLIO_DATA_DIR` 指定私有持久目录；无配置时返回配置引导，构建不需要远端认证。示例配置只包含非秘密元数据：

```json
{
  "schemaVersion": 1,
  "projects": [
    {
      "id": "open-folio",
      "name": "OpenFolio",
      "repositoryUrl": "https://github.com/iTgo-lyq/open-folio.git"
    }
  ]
}
```

可选 `specBranch` 指定初始 Specs 分支，但必须属于远端默认分支那份 `workflow.json` 声明的守护分支。未指定时使用远端 HEAD 指向的默认分支，并验证其守护身份；默认分支或配置缺失时保留显式分支选择，显示配置异常，不把任意分支包装成稳定基线。正常选择其他分支仍被允许，且始终标记分支来源。

项目 id 去重并限制为 kebab-case。配置只接受无用户名、密码、query、fragment 的 HTTPS 仓库地址；首版不支持 SSH、`file:`、`ext:` 或浏览器临时添加远端。远端地址变更时隔离旧缓存，不把两个仓库当成同一来源续读。测试通过不可由生产配置启用的独立入口注入临时 file 远端。

当前交付先运行在这台开发机，以同一 OS 用户的 Git credential helper 读取私有仓库；Node 子进程非交互读取已验证。其他机器由部署者配置同等读取权限，认证失败明确提示“检查运行环境的仓库访问权限”，不向页面索要秘密值。凭据轮换由运行环境负责，下一次刷新使用更新后的认证。

默认监听 loopback，使用独立端口 10681，保留 10680 的归档预览。远程人工验收通过单独的私有转发入口；入口提供访问控制，服务配置允许的 Host / Origin。首版不作为无鉴权公网服务，也不支持 serverless、临时磁盘或多副本部署。配置和缓存不进入 Git；代码构建与真实仓库采集分离。

### 数据流与快照事务

```text
已配置的中心 Git 仓库
    ↓ 非交互 fetch，只取 refs/heads
服务私有 bare 缓存
    ↓ 固定每条分支的 commit → tree → blob
文件清单 + 正文 + 状态校验 + 关系索引
    ↓ 完整构建新快照，原子发布
同源读取 API → Specs / Changes 界面
```

bare 缓存不关联用户工作区，不 checkout、运行仓库脚本或初始化子模块。初始化与刷新使用参数数组调用 Git，不经过 shell；关闭 hooks、交互提示、自动维护、子模块递归和替换对象，只允许 HTTPS，禁用 HTTP 重定向。认证 helper 来自可信运行环境；清除会改变仓库位置或对象库的继承 Git 环境变量。

刷新步骤作为一次事务处理：

1. 通过 `ls-remote --symref origin HEAD` 获得默认分支，再 `fetch --atomic --prune --no-tags --no-recurse-submodules origin +refs/heads/*:refs/remotes/origin/*`；不采集 tag、PR 专用 ref 或本地 refs。远端读取失败不发布新快照。
2. 一次记录远端跟踪 refs 与 commit 的映射；后续所有 tree、文件和比较均使用固定对象 id，不再解析移动中的分支名。各分支提交分别可追溯，不声称远端多个分支具有跨仓库事务。
3. 用 `ls-tree -rz` 枚举 `docs/project/`，按 NUL 分割并检查对象类型、文件模式和规范路径。只读普通 blob，拒绝符号链接和子模块。按 blob id 检查大小并用 `cat-file` 读取，不把用户路径拼成 Git revision 表达式。
4. 读取 workflow、Specs、Change JSON、同目录 Markdown 及受支持的文档图片；构造完整分支清单、记录候选、搜索和关系索引。JSON／文档格式问题成为记录诊断，不阻止其他有效文档进入快照；Git 操作、整体采集或持久化失败则终止发布。
5. 将正文按 blob id 存入私有内容缓存；将快照索引写入同一文件系统的临时文件并原子 rename，最后切换 current 指针。持久化完成后才向客户端返回新 snapshot id。

同一项目的并发刷新合并为同一个 Promise，不重叠操作 bare 仓库；不同项目可独立刷新。全局服务实例避免 Next 模块重载重复初始化，并以数据目录进程锁阻止两个服务同时写缓存。崩溃后仅在确认原进程不存在时清理遗留锁。

首次进入尚无快照的项目时触发一次同源刷新并展示进展；已有快照直接读取，后续由用户手动刷新。刷新期间页面继续可读。最近一次刷新错误另存，不改变最近成功采集时间；服务重启后可从完整快照恢复，临时文件不会成为 current。

保留当前及前两份完整快照；旧页面携带 snapshot id 获取正文，避免刷新后混用新状态与旧正文。超出保留范围返回版本过期提示，用户可切换到最新版本，不能悄悄替换当前文档。Git 自动 GC 关闭；快照只依赖已缓存正文，必要时重建 bare 缓存不会损坏已发布阅读快照。

首版完整获取分支所需 Git 对象，避免 partial clone 的隐式联网读取。首次 fetch 成本随仓库历史增长；默认刷新总时限 120 秒、单个 Markdown 1 MiB、JSON 256 KiB、图片 5 MiB、256 个分支、10,000 个文档条目、64 MiB 去重正文。限制可由运行环境收紧或放宽；单文件超限显示不支持预览，整体超限保留旧快照并提示调整配置。磁盘不足同样不替换旧快照，不静默截断分支或记录。

### 内部契约与读取 API

工程记录原样保留 `schemaVersion: 1` 的 skill 字段。应用索引另用 `cacheSchemaVersion`，不向 `change.json` 添加关系、页面状态或采集字段。

| 对象 | 关键内容 |
| --- | --- |
| ProjectSummary | 稳定项目 id、显示名、默认／所选来源、当前 snapshot、最近成功时间与刷新错误；不含凭据或磁盘路径 |
| Snapshot | id、配置指纹、采集时间、分支到 commit 的映射、文档清单、记录候选、关系与诊断 |
| DocumentRef | 项目内文档 id、分支、commit、仓库相对路径、blob id、大小、类型；id 由分支与路径确定 |
| ChangeRecord | 经 schema 校验的原始状态、所在目录、来源、正文引用、解释结果与诊断；非法记录的有效 state 为空，原 JSON 单独保留 |
| Diagnostic | 稳定错误码、影响对象、来源文档／JSON pointer／行号、说明；区分源数据异常、关系不可判定和采集失败 |
| Relationship | Change 前置／父子或任务前置关系、明确的来源、目标是否存在、流程前提与可用性证据 |

全部 API 为 Node runtime，`Cache-Control: private, no-store`，不依赖 Next 的页面缓存保存工程事实。

| 接口 | 行为 |
| --- | --- |
| `GET /api/projects` | 已配置项目和快照状态；不触发任意来源登记 |
| `POST /api/projects/:id/refresh` | 校验 Host、同源 Origin 和空请求体后刷新；等待合并后的刷新结果，返回新 snapshot 或保留旧快照的错误 |
| `GET /api/projects/:id/workbench?snapshot=…&branch=…` | 返回来源目录、Spec 目录、归属已解析的 Change／任务与诊断；列表不加载全部正文 |
| `GET /api/projects/:id/documents/:documentId?snapshot=…` | 在该项目快照清单内查找并返回正文、标题目录和来源；无自由文件路径参数 |
| `GET /api/projects/:id/search?snapshot=…&branch=…&q=…&kind=…` | 查询既有标题、路径、正文及 Change／任务名称；返回摘要、来源和可定位目标 |
| `GET /api/projects/:id/assets/:documentId?snapshot=…` | 仅返回已登记且检查通过的仓库图片，固定 MIME 与 `nosniff`；不代理外部 URL |

project、branch、snapshot、document 的组合必须在服务端清单中匹配；不接受客户端提交 commit、任意 refspec 或本地文件名。错误使用稳定 code 与中文说明：参数非法 400、来源外请求 403、不存在 404、快照过期 410、没有可用快照 503；源文件非法仍可通过正文接口查看，其诊断随记录返回。客户端忽略过期请求响应，防止快速切换项目／来源时串页。

### 分支归属与目录有效性

先为每个分支记录文件候选，再按仓库内 id 解析归属。解析身份时只信任通过基本校验的 id 与 branch；其他字段非法不妨碍定位该主分支上的异常源记录。

| 情况 | 处理 |
| --- | --- |
| 存在唯一“所在分支等于声明 branch”的候选 | 选为主记录；其他副本仅作为来源，不重复计数 |
| 唯一主记录 JSON／语义非法 | 保留主记录及错误，不使用其他分支副本覆盖它 |
| 多个自称主分支的记录，或同一主分支同时有 live／archive 副本 | 显示归属冲突与候选，不任意挑选 |
| 只有副本、声明分支不存在或该分支没有对应记录 | 显示来源不可达／主记录缺失，可逐份阅读副本，归属与依赖判断保持未知 |
| 多个正常副本内容不同，但均指向同一有效主记录 | 属于不同分支快照，不把普通落后副本误报成多个 Change |
| 主分支已删除，仅守护分支保留归档副本 | 保留历史原文供查看并注明缺失主来源；不由副本自动恢复权威流程结论 |

Spec 目录按用户当前选择的分支建立；Change 主列表跨已推送分支聚合，详情显示其自己的主分支。两者在界面上分别标明来源，避免用户误以为 Spec 分支切换会改变 Change 的主记录。同一分支相同 commit 的 tree／blob 可复用，不改变来源身份。

live 路径必须为 `changes/<id>/change.json`，archive 路径必须为 `archive/YYYY-MM-DD-<id>/change.json`，日期必须有效。取消仍在 live；completed 必须同时符合 close、四步结果、归档路径和同一主分支源目录已移除等规则。目录和声明冲突时保留声明，但从有效完成统计中排除并列入来源异常；原始位置永不自动修正。

### 状态校验与流程解释

校验分为语法、schema、关系／流程三层。严格覆盖 skill 声明的对象、枚举、非空文本、带时区时间、任务编号、blocked 原因、cancelled 记录和可选字段；未知 schemaVersion 或额外字段给出 JSON pointer。工作台不修复来源，不以 Markdown 状态声明覆盖 JSON。

流程解释只产生阅读提示，不修改状态，不输出可执行授权：

- small 使用需求、执行、关闭路线；其他规模按 skill 展示需求、技术与计划、执行、关闭，large 将技术和计划分开。规模降级后仍存在的确认可以保留展示，不因 small 不要求确认就删除旧记录。
- 按当前规模与阶段检查应具备的确认。缺失时保留原始 stage 并指出缺失记录，不在界面偷偷退阶段，也不根据序号给此前阶段画“已通过”。技术与计划合并的路线仍分别显示两个确认记录。
- rework 展示时间、原因与处理方式；系统不能通过自由文本自动判断确认覆盖范围。保留的确认显示“已有记录”，明显的缺项或来源矛盾另列诊断。
- 任务状态全部从 JSON 读取，Plan 只补充任务定义与前置关系。任务分支、verification、commitTitle 保留原意；提交标题只作线索。
- close 在界面中的阶段名称为“验收”；active 且整体验证通过、尚无人工验收记录时，当前阶段显示“验收中”。已归档和已取消记录不使用进行中的文案；原始枚举仍保留 close。
- close 中依序展示 verification、acceptance、specs、archive 的 result、时间与摘要；缺项是未记录，failed 保留失败事实，not_needed 显示原因。未满足整体验证就出现验收等顺序矛盾给出提示，不消除已有记录。
- cancelled 展示 cancellation，保留已有材料，不要求补全关闭四步；xlarge 不创建实现任务，整体判断结合子项来源，不把子任务的数量当作父 Change 百分比。
- 页面分别呈现整体结果、阶段、等待／任务阻塞与来源质量，避免用一个颜色标签混合业务状态和读取错误。

### Change、父子与任务依赖

构建有向关系时，Change 的前置边来自 dependsOn，父等子完成的边来自 children，并检查反向 parent；不得用 children 的排列顺序推断串行依赖。检查目标存在性、重复、自指、成环、子依赖父、嵌套 xlarge 和父子不对称。异常边继续显示并链接原始字段，不能当作已满足。

前置关系分开给出以下证据：

1. 流程前提：目标是否为有效 completed 归档主记录，以及记录取自哪个已推送提交；目标 cancelled、缺失或异常均不满足。
2. 交付可用性：若包含目标有效归档记录的固定来源提交确实是当前主分支提交的祖先，展示该 Git 证据；祖先不存在、历史不足或 squash 情况只说明“未获得可用性证明”。不将分支最新提交冒称首次归档提交。即使是祖先，也不推断代码此后未被撤销，最终可用性按 skill 验证。

不扫描提交标题猜测 squash 对应，不把归档文件复制到当前分支当成交付已合入。此方案满足只读追踪的边界，不承担任务调度。

任务依赖解析基于 remark AST：定位标题文字为“执行顺序”的章节，在其范围内找唯一包含“任务／前置任务”两列的 GFM 表格。单元格支持正文、行内代码、强调和链接标签；前置值接受“无”或以顿号、中英文逗号、空白分隔的完整 T 编号。忽略代码块内示例；保留表格和单元格行号。

要求每个 JSON 任务恰有一行，且前置存在、无自依赖或循环。标题／表头不匹配、出现多张候选表、空单元格、重复或不完整覆盖时标记不可判定，开放 Plan 原文入口。small 无 Plan 时显示未声明依赖；medium / large 尚在规划且未形成 Plan 时显示尚无执行顺序，不伪装为 JSON 错误。xlarge 的父 Plan 用于解释子拆分，不套用实现任务表解析。

### Markdown、搜索与文档边界

Spec 能力树由完整相对路径生成，支持任意层级及父节点正文，不沿用原型中的固定目录名。标题取首个 Markdown 标题，缺失时回退为能力路径；文本索引覆盖标题、路径和正文。前端目录与渲染正文使用同一个 heading 算法，覆盖中文、重复标题和行内格式，避免定位到同名错误章节。

正文使用 react-markdown + GFM，启用 skipHtml，不执行 MDX、脚本、HTML 或嵌入 iframe；保留默认 URL 安全处理，并对本地与外部链接另做明确分类。危险协议不给可点击目标。源码视图显示原文文本，不用 HTML 注入。

相对链接以当前来源文档目录解析，只能指向同一 commit 的 `docs/project/` 清单。拒绝越界路径、反斜线、NUL 和解码异常；编码路径只按约定解码一次。Markdown 文档内部打开，JSON 显示只读原文；不支持的格式保留路径和说明。外部 http(s) 链接在新页打开，不由服务器抓取。

仓库内 PNG / JPEG / GIF / WebP / AVIF 只有在普通 blob、大小及签名检查通过后才能通过固定 MIME 的图片接口显示。SVG、HTML、外部图片和未知格式不自动嵌入，以来源链接或不支持预览提示代替；不使用任意远端图片代理。

Spec 与 Change 的关联仅来自可解析的 Markdown 文档链接或完整 Spec 文件路径引用，保留引用文档与行号。没有显式引用就不显示自动关联，不凭中文标题相似度、代码文件路径或演示字段生成关系。

### 界面组织与浏览状态

外壳沿用认可的 C 方案：蓝紫低饱和背景、玻璃胶囊、深海蓝品牌、84px 桌面侧栏、内嵌面板和右侧详情抽屉；导航缩为 Specs 与 Changes，手机端保留两个入口。保留收起侧栏能力。来源异常使用克制的提示，不把页面改成监控仪表盘。

| 位置 | 内容与行为 |
| --- | --- |
| 顶部 | 当前项目、Specs 来源／Change 聚合来源、搜索、刷新与最近读取信息 |
| Specs | 左侧真实能力树，中间连续 Markdown 正文，右侧目录与来源；原文通过弹层阅读 |
| Changes | 进行中、已取消、已归档和全部／来源异常入口；筛选和 Change／任务粒度、列表／看板／依赖视图 |
| Change 抽屉 | 目标与来源、规模路线、概览／任务或子项／文档／依据；等待和关闭记录在当前上下文展示 |
| 缺失与异常 | 来源问题、具体字段／文件和可读原文并列；已存在资料继续可读，不填演示内容 |

以 URL 保存 project、module、specBranch、能力路径、Change id、view、粒度、筛选、详情开关及文档锚点。复制页面链接默认指向该来源的最新快照；页面内的 API 请求固定当前 snapshot。过期快照需显式切换，不宣称链接永久保存了已被远端删除的历史。

localStorage 仅保存侧栏和目录展开偏好，sessionStorage 保存阅读／列表位置，不存第二份流程状态。切换项目后按项目命名空间恢复偏好；来源变化后校验选中项，目标不存在时给出返回入口。抽屉关闭恢复原触发焦点与滚动，Escape 只关闭最上层弹层；窄屏目录和详情为独立可返回的阅读区域。

## 影响与恢复

- 新增应用与本地可重建索引，不迁移或修改远端文档，不改 SpecTrail 字段与工程流程；旧原型继续独立运行。
- 应用有三类本地写入：配置由部署者维护，服务更新 bare／快照缓存，浏览器保存显示偏好；均不能成为工程状态事实来源。远端只执行读取和 fetch。
- 凭据与配置只在服务器读取，不使用 `NEXT_PUBLIC_`，日志和 API 错误不回显认证、环境变量或完整 Git stderr。项目请求使用 allowlist，跨源刷新拒绝，关闭开放 CORS；Host 校验防止通过任意域名访问 loopback 服务。
- 以构建版本及 cacheSchemaVersion 隔离索引格式。新程序不兼容旧缓存时保留旧目录并重新采集，不破坏旧程序可读快照；退回前一应用版本不涉及远端回滚。
- 更换仓库地址或配置来源时重建该来源的索引；远端权限撤销或断网时只保留已授权使用者的本地历史阅读，并明确快照时间。删除项目配置后 API 不再暴露其缓存。
- 已知成本是首次 Git 拉取、私有缓存空间和单实例约束；这些换取统一 Git 语义、离线旧快照和无需外部数据库的可交付首版。后续扩大规模再拆采集服务，不提前引入分布式同步。

## 验证

| 验收范围 | 自动与人工证据 |
| --- | --- |
| 中心已推送来源、刷新和一致性 | 临时 bare 远端、作者仓库、独立缓存的端到端测试；覆盖未提交／未推送、更新、删除／改写分支、认证或 fetch 失败、重启和刷新竞态 |
| 单一主分支及状态可信 | 多分支副本、非法主记录、两个自称主记录、主分支删除、目录冲突；断言不拼接、不回退到更漂亮的副本 |
| schema 与各规模路线 | 覆盖所有枚举、字段、时间与任务校验，和现有 hook 的共有结构约束做一致性检查；验证规模降级确认保留、medium 路线、small 直接执行、xlarge 子项、返工、取消与关闭四步 |
| 前置和父子关系 | 缺失／循环／不对称／子依赖父、已取消前置、有效归档、普通合并与 squash；记录前提和可用性证据分别断言 |
| Plan 与文档 | skill 实际表格、代码块中的伪表、强调／链接单元格、多候选表、缺行和非法编号；中文／重复标题、相对链接、超限文档、符号链接和危险协议 |
| API 与恢复 | 清单越权组合、任意路径／ref 注入、Host／Origin、快照过期、失败保留、并发刷新合并、配置移除与无配置构建 |
| UI 与认可外壳 | 浏览器覆盖真实 API 测试数据上的搜索、过滤、看板、任务／子项、原文、来源、抽屉、前进后退和刷新；桌面 1440px 与手机 390px 截图，并检查 320px 可用性 |
| 实际交付 | 当前私有仓库的默认分支空 Specs 与本 Change 分支记录正确展示；无模拟数据兜底；独立评审、截图与最终用户验收 |

类型检查、Node 测试、生产构建和浏览器测试在实际依赖安装后执行。测试用完整临时 Git 仓库驱动读取链路；仅在鉴权拒绝、磁盘错误等难以稳定制造的单元边界注入故障。当前仓库没有已实现 Specs，集成验收应展示真实空状态，丰富文档情形由明确隔离的测试远端覆盖。

方案级结论：采集与解析能力有实验支持，配置和验证环境可用，没有必须由用户额外交付秘密值或外部服务后才能决定架构的事项。上述规模、传输、单实例和未知依赖的处理是本次待确认取舍。大型 Change 在技术确认后再制定 Plan。
