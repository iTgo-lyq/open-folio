# 核查与处理

用户补充明确：只关注自建服务中的原型；没有主动设置 favicon 时使用 OpenFolio 自己的图标。若只是缓存则接受，不为此增加不必要的实现。

## 实际服务核查

- 对本机 `http://127.0.0.1:11117` 和对外服务 `https://drwulzcazu.merlin-devbox.bytedance.net` 分别请求 `/favicon.ico`、`/icon.svg`，均为 200，返回字节分别与主工作区当前资源一致。SHA-256 前 16 位为 `7c48615a5c40762a`、`b66b2b8478c3f7e3`。
- 两个资源都返回 `Cache-Control: public, max-age=0, must-revalidate`。对外服务未返回与本机不同的旧图标。
- 使用全新 Playwright Chromium 上下文打开对外服务首页及 `/?m=prototypes`，head 均声明 `/favicon.ico` 和 `/icon.svg`；逐一读取后均与当前资源字节一致。
- 根布局统一提供新版图标，公开原型页也使用该布局，没有单独覆盖旧 favicon。ICO 的可视内容同样是新版平面标志。

上述证据没有发现自建服务返回旧图标的实现问题。用户当前浏览器缓存无法直接观察，因此缓存只是推断；先前由静态原型缺少 link 声明直接推定服务遗漏，证据不足。

## 未采用的实现

七个静态入口显式图标、旧位图移除、内联图标校验支持及项目构建器自动补图标都只在本工作分支；通用初始化模板未改。原型校验与浏览器检查曾通过，但不能证明这些修改对自建服务必要，故关闭草稿 PR，不合入、不部署。

当前 prototype.json 未登记本次临时 R2 上传，历史及当前固定引用均未切换。长期服务保持原实现。
