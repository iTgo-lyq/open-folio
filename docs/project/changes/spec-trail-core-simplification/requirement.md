# 精简 SpecTrail 主 Skill 与日常 CLI

## 目标

减少 Agent 推进 Change 时需要读的规则和命令帮助，让项目接入、日常操作和仓库维护各有清晰入口。本次范围是主 Skill、接入说明和 CLI。原型模块另行整理，本次涉及原型的改动限于随主文档调整的引用。

## 已暂存草案

- 主 `SKILL.md` 按工作流重排，合并原来分散的状态、工作区、集成和分享说明。项目接入只留一处 `cli setup check` 提示，接入文档按 `workflow.json` 的 `schemaVersion: 3` 描述。
- 接入说明和模板归入 `references/setup/`，脚本和测试分别放在主 Skill 的 `scripts/` 和 `tests/`。`cli --help` 省略 `setup` 组，接入说明提供 `cli setup --help`，Git hook 和 PR CI 沿用现有调用。
- 删除 Skill 自动版本检查及其提示和缓存逻辑。CLI、hook 和工作台将 `checkForUpdates` 视为未知字段，相关说明和更新引导从现行文档及介绍站移除。

以上是待移交工作区继续讨论的本地草案，尚未作为交付验收。

## 待讨论

- 主 Skill 是否以阶段表统领日常流程，去掉重复示例，并把完整字段定义与特殊清理步骤交给按需参考。需求和技术问询可共用一处提问规则，具体额度与记录方式单独核对。
- CLI 帮助是否改为总览列组、分组列命令、命令帮助列参数和示例。只读 `show` 的 `--dry-run` 也纳入精简讨论。
- 评估 `maintenance` 中各工具的去留，以及 Skill 脚本依赖检查是否应由本仓库 CI 承担。
- 移交前核对暂存的许可删除。分发包须保留 MIT `LICENSE`，复用的审核内容须核对相应许可声明。

## 验收

- 项目接入、状态流转和交付规则各有明确入口，主 Skill 的必读内容和 CLI 总帮助均以讨论后的范围收敛。
- 接入帮助、现有 hook、PR CI 和日常状态命令通过相关回归测试。含 `checkForUpdates` 的配置在 CLI 和工作台均被拒绝。
- 现行文档和帮助与实际命令一致，分发包带齐许可，原型命令及交付行为照常可用。
