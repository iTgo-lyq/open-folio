# 前端样式与交互重构

## 目标与交付顺序

OpenFolio 的主要使用场景是找到可访问的项目，持续阅读 Specs、跟进 Changes、查看并分享原型。本次重构希望让这些操作更清楚、阅读更舒适：内容居中，导航和工具克制，减少重复信息，以排版、间距、材质和状态反馈形成安静、精致、有个人温度的工作空间。

继续使用 `frontend-style-interaction-refactor`，保留 large 规模。已有原型、代码和文档只作参考，新的需求和原型以最新已集成的真实产品能力为依据，不能从旧演示推导新功能或权限。交付分为两个阶段：

1. **需求与原型**：重新整理需求、澄清覆盖范围和设计方向；完整需求与覆盖清单获明确确认后，完成六组主体入口的交互原型，以固定版本发布，交由用户明确验收。原型验收前不修改正式产品前端代码，不编写新的 Technical 或 Plan。
2. **验收后的技术与实施**：用户明确验收固定原型版本后，再梳理前端重构的技术方案和实施计划，按 large Change 的确认流程推进。后续正式交付须覆盖已确认原型、既有能力回归及用户最终验收。

需求重写先交付本文与原型包 DESIGN 草案，通过 SpecTrail 语义命令登记返工、澄清和实际确认。需求确认后提交推送，再进行六组页面的浅深色原型设计、验证与固定发布。原型可打开、截图检查通过、Agent 自查通过，以及局部澄清答案，都不能替代完整需求确认或原型验收。

## 设计方向

### 蓝色主题与克制的 Liquid Glass

框架以冷调中性色为主，蓝色用作选中、主要操作、键盘焦点和适用的状态强调。成功、警告、错误仍保留清楚的语义区分，并配文字或图标，不用蓝色替代所有状态，不只靠颜色传递信息。

采用 Apple Liquid Glass 的功能层与内容层区分：玻璃只用于浮在内容之上的顶部工具栏、导航、切换器、菜单、弹出层和抽屉；正文、表格、长文本、表单以及抽屉内部阅读区保持清晰实底。不叠加多层玻璃，玻璃容器内的控件用普通填充和边界表达状态。透明、模糊、高光与柔和阴影服务于层级，可读性和对比度优先；不要求复刻原生折射或弹性光学效果。

这一层级原则与 Apple [Meet Liquid Glass](https://developer.apple.com/videos/play/wwdc2025/219/) 的功能层、避免玻璃叠玻璃指引一致（2026-10-20 核对）。以下 Web 降级是本项目明确要求：不支持 `backdrop-filter` 或用户开启“减少透明度”时，使用不透明表面；用户开启“减少动态效果”时关闭动画和过渡。浏览器无法识别透明度偏好时使用实底兜底，原型评审工具应可演示降级，不能把 Web 行为说成原生系统自动提供。

### Craft 视觉与交互参考原文

以下为用户提供并要求完整采纳的参考，作为设计意图完整保留；产品能力的适配见下一节，不据此扩展业务功能。

> 请参考 Craft 近期产品的视觉与交互语言，设计一个安静、精致、内容优先的应用界面。
>
> 整体气质
>
> - 轻盈、柔和、有原生应用质感，适合长时间阅读、写作与整理。
> - 内容是视觉中心，导航和工具保持克制；精致感来自排版、间距、材质和状态反馈。
>
> 布局与层级
>
> - 侧边栏自然融入窗口背景，中央内容区呈现为清晰、完整的文档表面。
> - 使用低对比背景、细微边界和充足留白区分区域，减少厚重分割线。
> - 导航、文档、工具面板形成明确层次；辅助工具根据当前操作出现。
> - 面板展开、收起时，内容区域平滑调整宽度与圆角，保持空间连续性。
>
> 色彩与材质
>
> - 应用框架以中性色为主，强调色少量用于选中、操作和状态。
> - 文档内容允许独立的背景、封面、字体与卡片样式，个性化内容与稳定的操作界面协调共存。
> - 工具栏、导航和浮层可使用局部半透明、模糊、细腻高光与柔和阴影，正文区域保持清晰稳定。
> - 深色模式重新处理表面层级与文字对比；移动端可以采用纯黑底色。
>
> 字体与组件
>
> - 功能界面使用清晰的无衬线字体，以字号、字重和间距建立层级。
> - 注重中文、中英混排、粗体和长文本的阅读质量；文档字体可以独立选择。
> - 图标简洁、笔画统一；圆角随组件尺寸递增，小控件紧凑，卡片与浮层更柔和。
> - 按钮、列表、标签、输入框与菜单有一致的视觉节奏，避免过多边框和装饰。
>
> 交互与反馈
>
> - 常用操作容易触达，低频操作收纳在上下文菜单、浮层或辅助面板。
> - 悬停、聚焦、选中、按下、禁用和完成状态清晰可辨，反馈轻微而及时。
> - 支持就地编辑、快捷键、多选与批量操作，让连续工作尽量少被打断。
> - 选中与打开保持明确区别；任务完成、日期和逾期状态同时通过文字、图标或颜色表达。
> - 动效短促、自然、有连续性，用于解释展开、切换和布局变化。
> - 空状态与错误提示简洁明确，告诉用户下一步可以做什么。
>
> 最终呈现应让人感觉：工具随时可用，内容始终清楚，整个工作空间安静而有个人温度。

## 原型验收标准

验收对象是用户可打开的固定发布版本及其六组入口，不能用静态截图替代交互验收。

1. **范围与能力**：逐项演示覆盖表中的主体内容和主要交互；当前 Token 能力、只读工程记录、授权准备原型与匿名读取的区别准确。无搜索、收藏、编辑、批量变更、全量统计等未获授权的能力；没有用假数据补出不存在的权限或完成事实。
2. **两套主题与三种尺寸**：浅色、深色均覆盖桌面 1440×900、平板 834×1194、手机 390×844，并检查 320px 窄屏。平板/手机适当收起目录和辅助面板，保留返回与当前上下文；不遮挡主要操作或底部内容。
3. **布局与阅读**：页面及浮层无横向溢出；长中文、中英混排、长链接和文件路径可读，表格适当重排，代码/diff 必要的横向滚动限制在独立阅读区域，不撑宽页面。放大文字后主体操作仍可达。正常、空态、失败及长内容下都检查边界。
4. **视觉与材质**：蓝色作为强调色，框架冷调中性；功能层局部玻璃、阅读和表单实底，无玻璃叠玻璃。深色下的长文、辅助文字、禁用项、选中项及错误状态可辨；面板伸缩保持空间连续性。
5. **降级与动效**：禁用 `backdrop-filter`、开启减少透明度或无法可靠识别该偏好时，均可展示不透明表面且内容可读；开启减少动态效果后无动画和过渡。普通动效短促，用于说明展开/切换，不以持续运动装饰页面。
6. **键盘与触摸**：主要路径仅用键盘可完成，焦点可见，顺序合理；浮层获得恰当焦点，Escape 关闭最上层，关闭后回到触发控件或合理的存续位置。只读任务不得伪装成可操作复选框。触摸无需悬停即可找到并执行动作，设备/主题切换和手机返回均可用。
7. **代表状态**：可演示首次未登录、发现/读取中、空仓库/无文档/无原型、筛选无匹配、部分发现失败、加载失败及重试、离线、无权限/会话失效。离线与明确失权分开：临时网络失败保留已显示内容并标明未更新；失权清除私有正文并引导恢复，不提供离线授权或写入。另演示身份切换失败保留原身份、复制失败手动兜底、未回答/已撤回问答、材料缺失、合入记录缺失/异常及公开版本不存在/已撤回。
8. **运行质量**：在普通浏览器及现有工作台 iframe 环境检查导航和交互，无未捕获 JavaScript 异常、无非预期资源/控制台错误。模拟错误由内存状态表达，不故意制造浏览器错误；无外部字体/CDN 请求、真实业务请求或持久状态写入。
9. **固定发布与人工验收**：沿用项目原型包和既有托管，先形成可追溯源码提交，再构建并发布新固定版本；记录入口、设备、sourceCommit、version、digest、URL 及三种设备缩略图，不覆盖旧版本字节。检查工作台中卡片图片和入口实际可用，提供两套主题的交互与截图证据。只有用户明确验收指定版本后，才开始技术方案与实施计划；后续修改影响验收时提供新的固定版本。

## 需求澄清引用

本轮均为需求类问题，记录于 `change.json.clarifications`，共第 1 轮 3 题；未提出技术问题。

- **Q1（需求：覆盖范围）**：用户选择六组主体入口全部覆盖，排除运维配置完整页面和 UI 组件库预览；已落实到覆盖清单。
- **Q2（需求：深色模式）**：用户选择浅色和深色同时覆盖；已落实到视觉规则及验收矩阵。
- **Q3（需求：身份基线）**：用户选择全部按当前 Token 登录能力设计；已落实到入口⑤及账号边界，不采用等待账号 Change 合入的建议。

三个问题均有实际回答，需求确认依据以 change.json 为准。原型发布后须由用户明确验收；验收前不编写技术方案、实施计划或修改产品代码。
