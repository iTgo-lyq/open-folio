# 前端样式与交互重构

## 实现验收补充（2026-10-22）

本轮用户验收反馈明确以下调整，作为既定范围内的返修要求：

1. Specs 和 Change 阅读的目录收起方式统一；保留窄屏目录和键盘焦点（具体形态由第 12 项更正）。
2. 核对原型抽屉，改善其材质、留白和阅读宽度；原文与文档抽屉不能套用狭窄的通用操作抽屉。
3. Changes 的分组标题比单条 Change 标题更突出；分组内外的行内容左右边距一致。
4. Changes 与原型总览的大标题保留在内容区顶部，恢复原有标题位置与间距（用户后续撤回移入顶栏的调整）。
5. 从当前原型清单及源码入口清理被新设计替代的旧设计；已归档记录和已发布固定版本保持历史可读。
6. 查明并修复本次验收地址的分享页打开失败；保留匿名接口边界。
7. 删除仅复制当前页面地址的按钮和菜单；保留生成匿名分享、固定版本链接、凭据或 Git 命令等有独立作用的复制。
8. 首次进入默认收起网站左侧导航，后续尊重用户手动选择并记住偏好。
9. 收起态 Logo 不保留文字占位，图形在窄侧栏内居中。
10. Change 材料正文上方只保留“文件路径 · 提交”单行来源，移除重复的 Change / 材料名和分支名。
11. Specs 的相关 Change 按创建时间倒序只展示最近五项，避免长列表挤占阅读区域。
12. 目录的收起按钮不放在顶栏，改到目录面板标题行右侧。收起后（窄屏始终如此）目录以顶栏左侧的“当前位置”按钮呈现，形态与仓库切换按钮一致：图标、当前 Spec 或材料名、下拉箭头，接在仓库或“Changes”返回按钮后，以“/”连成路径；点击弹出目录可直接跳转，桌面弹层内可把目录恢复为侧栏。手机顶栏优先显示当前位置，仓库只保留字标。窄屏的本页目录继续由右侧“本页目录”按钮打开。
13. 抽屉贴合窗口边缘，不与工作区之间留边距，整体为单层玻璃：不再在玻璃外框内嵌套带边界的实底卡片，透出背后被模糊的内容；遮罩同时模糊背后的页面，使其文字不可辨认。手机上抽屉为底部弹出，原文抽屉接近全高。
14. Specs 与 Change 详情的位置按钮和左侧仓库/返回按钮具有一致的高度、字号、字重与内边距；路径分隔符两侧到按钮的距离相等，窄屏仍能显示或横向截断当前标题并操作目录。文字上下完整，包含 g 等字母的下伸部分。
15. Specs 目录条目的行高、垂直留白、图文间距和选中字重与 Change 材料列表一致，保留树层级和长标题换行；目录展开/收起图标使用更细的线条。悬浮背景与选中态一样覆盖整行，包括左侧缩进及展开箭头，使用更淡的底色。
16. 收起侧栏的 Changes 图标显示当前仓库进行中的 Change 数量，与列表进行中口径一致；数量为 0 时不显示角标，超过 99 显示 99+，辅助说明保留实际数量。同一仓库切换模块时角标持续显示，仓库或凭据切换继续隔离旧数据。

## 目标与交付顺序

OpenFolio 的主要使用场景是找到可访问的项目，持续阅读 Specs、跟进 Changes、查看并分享原型。本次重构希望让这些操作更清楚、阅读更舒适：内容居中，导航和工具克制，减少重复信息，以排版、间距、材质和状态反馈形成安静、精致、有个人温度的工作空间。

继续使用 `frontend-style-interaction-refactor`，保留 large 规模。交付分为两个阶段：

1. **需求与原型**：确认本需求后，先审查现有原型与产品的易用性、冗余和样式问题，再按协作分支最新能力重做全部主体入口的交互原型，以固定版本发布，交由用户明确验收。原型验收前不修改正式产品前端代码，不编写 Technical 或 Plan。
2. **验收后的技术与实施**：用户明确验收固定原型版本后，再梳理技术方案和实施计划，按 large Change 的确认流程推进。正式交付须覆盖已确认原型、既有能力回归及用户最终验收。

原型可打开、截图检查通过、Agent 自查通过，以及局部澄清答案，都不能替代完整需求确认或原型验收。

### 第二轮返工（2026-10-22）

用户审阅上一版六组原型后提出：

- 新侧栏去掉了原有的侧边玻璃按钮，展开态因此更清晰，予以保留；但点击 Logo 收起后仍回到原先的“悬浮胶囊图标导航”模式，并重新设计其样式，旧玻璃按钮的观感不再沿用。
- 继续深入检查交互是否易用、内容展现是否合理、有无冗余、样式有无优化空间；确有改进空间时可以大胆改造，不默认后端完全不改。
- 上一版原型已落后于协作分支，需要同步新增能力；进行中的 Change 分享要连同其原型一起按新设计重做。
- 内部布局多参考 shadcnuikit，视觉风格参考 Craft（参考原文见[设计方向](#craft-视觉与交互参考原文)）。
- 以产品经理的身份、从用户角度调整设计：此前功能“无脑加列表筛选”不是真实诉求，各个控件留不留由本次自行判断；表格信息应适当外露，例如此前缺失的 Change 创建者。

因此上一版需求确认失效，回到需求阶段；上一版六组原型不再请求验收，仅作参考。

### 第三轮调整：颜色与标志（2026-10-22）

用户审阅第二轮七组原型（version `676ba2c9…`）后认为阅读体验明显改善，但蓝色主题不搭，蓝色 Logo 尤其突兀。核对发现：Logo 是带渐变与高光的浅天蓝（约 `#4090d0`–`#60a0e0`），界面强调色是更饱和的宝蓝 `#2c6ce0`，两种蓝在色相、饱和度和材质上互不呼应；蓝色同时铺在导航、胶囊、主按钮、链接、开关、目录、阶段、进度和提示条上，界面读起来是“蓝色应用”而非安静的阅读空间。

调整为墨色框架与平面单色标志（见[设计方向](#craft-风格墨色框架陶土强调与局部材质)），网站图标与应用图标一并更换（**Q7**），评审栏提供陶土与上一版蓝色作对比（**Q8**）。布局、交互与内容沿用第二轮结论，第二轮版本不再请求验收。

### 第四轮调整：陶土强调与可见材质（2026-10-22）

用户审阅第三轮版本（version `46c2404c…`）后决定：强调色用陶土（**Q8** 更正），标志保持墨色；并指出界面上几乎看不出玻璃效果。核对原因：材质只用于收起胶囊、菜单弹层、提示和手机导航，胶囊浮在纯色窗口底上、背后没有内容可模糊，弹层 72% 不透明度盖在白色页面上与实底无异；需求列出的顶部工具与抽屉外层仍是实底，正文也不会从顶栏下方经过。

因此顶栏改为正文可从下方滚过的玻璃层，加强胶囊与手机导航的高光和层次，弹层更通透，抽屉外层与标题区使用材质。用户明确默认浏览器都支持模糊效果，不需要减少透明度适配，删除透明度相关降级；减少动态效果照常遵循系统设置。第三轮版本不再请求验收。

用户已验收第四轮固定版本 `06e078ce…`（源码 `9351a48`，见 [Research](research.md#原型验收2026-10-22)），技术方案与实施以此为准。

## 体验审查与改造原则

重做原型前，逐页审查上一版原型与当前产品，按“易用性 / 内容冗余 / 样式”记录问题、证据和处理方式，写入 Research，原型据此改造。已观察到的问题示例：

- 同一信息重复出现：侧栏项目切换器、顶栏面包屑与页面大标题重复表达当前仓库和模块；身份同时出现在侧栏底部、顶栏设置图标和首页右上角。
- 装饰性文字占据首屏：页面眉标、口号式副标题和“状态来自实际记录”等说明性脚注，对完成任务没有帮助。
- 控件层级偏多：Changes 同时有范围页签、四个原生下拉、变更/任务切换和列表/看板/依赖切换，分散在三行。
- 低信息量的列：仓库列表中每行相同的阅读分支、所有行一致的箭头。
- 有价值的信息反而缺失：Change 列表看不到是谁创建的。

改造范围不限于视觉。确有明显收益时，可以调整信息架构、页面组合、交互路径和信息密度，也可以提出需要后端配合的新能力，只要满足：

- 服务于找到项目、阅读 Specs、跟进 Changes、查看与分享原型这些核心任务；
- 原型中标注“需后端配合”，并在本节列出，技术方案阶段再评估实现成本；
- 不用示例数据把不存在的事实表现为真实能力，例如全量统计、逾期、负责人或审批权限。

工程记录仍保持只读：Specs、Changes、任务和差异来自 Git，工作台不提供编辑、推进流程、批量变更或拖动改状态。营销页面、分析看板和跨仓库动态流不在本次目标内。

**控件取舍**：以产品经理身份、按真实使用频率决定每个筛选、排序、切换和按钮是否保留。既有交付中的筛选和排序（例如类型、紧急程度、规模、关联能力）不是必须保留的界面；数据不足以形成有效筛选时不展示，低频条件收进一个筛选菜单，不为每个字段平铺控件。删除或合并既有入口在审查记录中写明理由；后端读取能力可以保留不用。

**信息外露**：列表和表格优先直接展示用户判断所需的信息，减少“点开才知道”。新增展示 Change 创建者，取首次进入 Git 的提交作者，与已实现的创建时间同源；平台账号可识别时显示头像或登录名，否则显示 Git 作者名。

候选新能力（需后端配合）：

- **Change 创建者**：Git 读取层随创建时间一并返回首次提交作者。

按 **Q5**，不加入搜索或快速跳转；旧原型的搜索是冗余功能。审查中发现的其他候选会在原型设计时补入本节，并在原型验收中逐项确认。

## 主体页面与交互覆盖

入口是用户可辨认的页面/视图，不要求每个状态拆成独立 HTML。公共壳层、菜单、浮层、抽屉和反馈随所属页面一起验收。

### 公共壳层与侧栏收起

- **展开态**：沿用上一版的完整侧栏方向：融入窗口背景，包含品牌、项目切换、模块导航和账号入口；模块导航不再使用胶囊玻璃按钮。
- **收起态**：点击 Logo 收起，侧栏变为窄轨：Logo 留在顶部，我的仓库、Specs、Changes、原型四个图标组成垂直居中的悬浮胶囊，账号入口在底部；图标有名称提示，当前模块清楚可辨。再次点击 Logo 展开。胶囊重新设计，采用 Craft 式的细腻半透明、高光和柔和阴影，不沿用旧的玻璃按钮样式。
- 收起状态按现有偏好保存，刷新后恢复。展开、收起时内容区平滑调整宽度与圆角。键盘可操作 Logo 切换，焦点保持在 Logo 上。
- 平板默认使用收起态，手机使用底部导航；上述行为在三种设备上都可演示。

| ⑦ Change 分享阅读页 | 指定 Change 的全部详情：概览、任务、需求、技术方案、计划、执行与评审、澄清问答、确认与关闭依据、图片、原型、合入记录与差异 | 匿名打开，无需账号或 Token；材料目录、内联正文、章节导航、专注阅读与字号切换；范围外引用提示；目标不存在或暂不可读、同步失败（保留已显示内容并标明未同步）。不提供编辑、确认或分享管理。 |

⑦ 及 ③ 中分享入口的行为以 `change-sharing` 已确认的需求为准；本次重做视觉与交互，不改变其分享语义。

主体页面选有代表性的内容即可，不复刻每个历史 Change、每篇 Spec 或所有设置表单。Changes 的不同详情页签、只读看板/依赖、问答状态和合入异常必须有可到达的代表场景；原型分享与 Change 分享各有授权侧入口和匿名查看闭环。运维配置完整页面、管理员上传管理、UI 组件库独立预览、营销页面不在本次原型范围。既有权限边界不得被设计成普通用户的新权限。

## 设计方向

### Craft 风格、墨色框架、陶土强调与局部材质

视觉风格以 Craft 为主要参考。框架以墨色与中性灰为主，强调色为陶土（浅色约 `#a8502c`、深色约 `#e8926b`，**Q8**），少量用于主要操作、选中项图标与文字、正文链接、开关、进度、当前阶段和键盘焦点；选中底、正文和界面框架仍为中性色，不使用蓝色。彩色只表达状态：琥珀表示等待确认，红色表示受阻或失败，绿色表示已同步或已发布，推进中等常态用中性灰；状态同时配文字或图标，不只靠颜色传递信息。原型中的示例产品画面保留其自身配色。

标志保留现有造型，重绘为无渐变、无高光的平面矢量图：外框为墨色，内侧面板为同一墨色的浅色调，深色模式下反白，用于侧栏、手机顶栏、登录页及公开/分享页页头。标志不随强调色着色。网站图标与应用图标改用同一标志，置于浅色方底（**Q7**）。原型评审栏保留墨色与上一版蓝色作强调色对照（**Q8**），只用于评审，不进入产品设置。

材质分层：半透明、模糊、高光与柔和阴影只用于浮在内容之上的功能层，包括收起后的侧栏胶囊、顶部工具、切换器、菜单、弹出层、抽屉和手机导航；材质必须可感知：顶部工具栏浮在内容面上，列表、正文和目录滚动时从其下方经过并被柔和模糊；背后没有内容的胶囊以高光、明暗层次和悬浮阴影表现质感；正文、表格、长文和表单保持清晰实底；抽屉按实现验收第 13 项整体为较高不透明度的玻璃，背后由遮罩模糊。不叠加多层玻璃，材质内的控件用普通填充和边界表达状态。可读性和对比度优先，不复刻原生折射或弹性光学效果。

目标浏览器默认支持 `backdrop-filter`，不提供“减少透明度”或不支持模糊时的实底降级（用户决定：默认用户浏览器都支持，不需要减少透明度）。开启“减少动态效果”时关闭动画和过渡，原型评审工具可演示。

### Craft 视觉与交互参考原文

以下为用户提供并要求完整采纳的参考（2026-10-22 再次提供并强调），作为设计意图完整保留；产品能力的适配见下一节，不据此扩展业务功能。

> 整体气质
>
> - 轻盈、柔和、有原生应用质感，适合长时间阅读、写作与整理。
> - 内容是视觉中心，导航和工具保持克制；精致感来自排版、间距、材质和状态反馈。
>
> 布局与层级
>
> - 侧边栏自然融入窗口背景，中央内容区呈现为清晰、完整的文档表面。
> - 使用低对比背景、细微边界和充足留白区分区域，减少厚重分割线。
> - 导航、文档、工具面板形成明确层次；辅助工具根据当前操作出现。
> - 面板展开、收起时，内容区域平滑调整宽度与圆角，保持空间连续性。
>
> 色彩与材质
>
> - 应用框架以中性色为主，强调色少量用于选中、操作和状态。
> - 文档内容允许独立的背景、封面、字体与卡片样式，个性化内容与稳定的操作界面协调共存。
> - 工具栏、导航和浮层可使用局部半透明、模糊、细腻高光与柔和阴影，正文区域保持清晰稳定。
> - 深色模式重新处理表面层级与文字对比；移动端可以采用纯黑底色。
>
> 字体与组件
>
> - 功能界面使用清晰的无衬线字体，以字号、字重和间距建立层级。
> - 注重中文、中英混排、粗体和长文本的阅读质量；文档字体可以独立选择。
> - 图标简洁、笔画统一；圆角随组件尺寸递增，小控件紧凑，卡片与浮层更柔和。
> - 按钮、列表、标签、输入框与菜单有一致的视觉节奏，避免过多边框和装饰。
>
> 交互与反馈
>
> - 常用操作容易触达，低频操作收纳在上下文菜单、浮层或辅助面板。
> - 悬停、聚焦、选中、按下、禁用和完成状态清晰可辨，反馈轻微而及时。
> - 支持就地编辑、快捷键、多选与批量操作，让连续工作尽量少被打断。
> - 选中与打开保持明确区别；任务完成、日期和逾期状态同时通过文字、图标或颜色表达。
> - 动效短促、自然、有连续性，用于解释展开、切换和布局变化。
> - 空状态与错误提示简洁明确，告诉用户下一步可以做什么。
>
> 最终呈现应让人感觉：工具随时可用，内容始终清楚，整个工作空间安静而有个人温度。

## 原型验收标准

验收对象是用户可打开的固定发布版本及其全部入口，不能用静态截图替代交互验收。

1. **范围与能力**：逐项演示覆盖清单中的主体内容和主要交互，包括账号与 Token、类型标签与紧急程度、创建者、交付标签与 PR、Change 分享。只读工程记录、授权侧准备与匿名读取的区别准确；“需后端配合”的能力有标注并列入[改造原则](#体验审查与改造原则)；没有用假数据补出不存在的权限或事实。
2. **侧栏收起**：展开态无胶囊按钮；点击 Logo 收起为悬浮胶囊窄轨、再次点击展开，提示、当前项、键盘操作和平滑过渡可用；平板默认收起态、手机底部导航；胶囊样式为新设计。
3. **审查落实**：Research 中记录的每项审查问题都有对应改动或保留理由，包括每个保留、合并或删除的控件；不再出现上文列举的重复信息和装饰性文字。
4. **两套主题与三种尺寸**：浅色、深色均覆盖桌面 1440×900、平板 834×1194、手机 390×844，并检查 320px 窄屏。窄屏适当收起目录和辅助面板，保留返回与当前上下文，不遮挡主要操作或底部内容。
5. **布局与阅读**：页面及浮层无横向溢出；长中文、中英混排、长链接和文件路径可读，表格适当重排，代码/diff 横向滚动限制在独立阅读区。放大文字后主体操作仍可达。正常、空态、失败及长内容下都检查边界。
6. **视觉与材质**：符合 Craft 参考；框架为墨色与中性灰，陶土强调色少量使用，其余彩色只表达状态，标志与网站图标为平面墨色；材质仅用于功能层且可感知（顶栏下滚过的内容被模糊、胶囊有层次），阅读和表单实底，抽屉为单层玻璃且遮罩模糊背后页面，无玻璃叠玻璃。深色下的长文、辅助文字、禁用项、选中项及错误状态可辨。
7. **动效**：开启减少动态效果后无动画和过渡。普通动效短促，用于说明展开/切换。不要求透明度降级。
8. **键盘与触摸**：主要路径仅用键盘可完成，焦点可见、顺序合理；浮层获得恰当焦点，Escape 关闭最上层，关闭后回到触发控件或合理位置。只读任务不伪装成可操作复选框。触摸无需悬停即可执行动作。
9. **代表状态**：首次未登录、注册账号重复、密码错误、登录暂缓（限流）、已登录无 Token、Token 验证失败或失效、发现/读取中、空仓库/无文档/无原型、筛选无匹配、部分发现失败、加载失败及重试、离线、无权限/会话失效；切换 Token 失败保留原选择、复制失败手动兜底、未回答/已撤回问答、材料缺失、合入记录缺失/异常、公开版本不存在/已撤回、分享目标不存在或暂不可读、分享内容同步失败。临时网络失败保留已显示内容并标明未更新；明确失权清除私有正文并引导恢复。
10. **运行质量**：在普通浏览器及现有工作台 iframe 环境检查导航和交互，无未捕获异常和非预期资源/控制台错误；无外部字体/CDN 请求、真实业务请求或持久状态写入。
11. **固定发布与人工验收**：沿用项目原型包和既有托管，先形成可追溯源码提交，再构建并发布新固定版本；记录入口、设备、sourceCommit、version、digest、URL 及三种设备缩略图，不覆盖旧版本。检查工作台中卡片图片和入口实际可用，提供两套主题的交互与截图证据。只有用户明确验收指定版本后，才开始技术方案与实施计划。

## 需求澄清引用
