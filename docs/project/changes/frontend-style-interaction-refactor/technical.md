# 前端样式与交互重构：技术方案

## 实现验收修订

目录面板标题行提供收起按钮；收起或窄屏时，Reader 在顶栏左插槽渲染当前位置按钮（Popover 弹出同一目录，桌面可恢复侧栏），以路径分隔接在仓库或返回按钮后，焦点在收起按钮、位置按钮和当前目录项之间衔接；右插槽保留本页目录和阅读设置。文档/原文抽屉使用阅读专用宽度与布局，避免通用 Sheet 默认 420px 限制。Changes 与原型总览恢复内容区顶部的唯一页面标题及原有间距；原型详情关闭后的备用焦点仍指向内容区标题。侧栏缺少已存偏好时默认收起，显式展开偏好仍生效。

分组标题、单条标题和连续交付组分别表达层次；行布局共享同一左右内边距，不用嵌套 padding 改变列起点。删除当前页面地址复制入口，保留有独立目标的匿名分享与固定产物链接。旧原型仅退出当前清单与源码入口，既有归档和已发布不可变版本不变。

Specs 与 Change 顶栏的位置按钮和相邻仓库/返回按钮统一采用小号按钮规格（28px 高、13px / 500、两侧 10px 内边距）；路径分隔符两侧各 8px，不叠加顶栏原有 gap，侧栏展开且无前项时移除分隔及占位。

依据[需求](requirement.md)与用户已验收的原型 `06e078ce`（源码 `9351a48`，设计规则见[原型包 DESIGN](../../../../packages/prototype/DESIGN.md#覆盖与能力依据)，逐页取舍见 [Research](research.md)）。本次重做工作台、公开原型页和 Change 分享页的表现层，沿用现有服务端接口、会话、仓库发现、快照与原型托管；后端只新增“Change 创建者”。

## 设计系统与样式组织

### Token 与主题

`@open-folio/ui` 的 `--of-*` token 按已验收原型重定义浅色与深色两套取值：窗口底、内容面、次级面、正文三级灰、分隔线、悬停 / 选中 / 按下叠加、陶土强调色（浅 `#a8502c`、深 `#e8926b`）、状态色（绿 / 琥珀 / 红）、玻璃色与模糊、阴影和圆角阶梯。取值以原型 `style.css` 与 DESIGN 为准，组件只引用 token。

主题挂在 `<html data-theme>`：默认跟随系统 `prefers-color-scheme`，用户在账号菜单选择后保存在本机浏览器存储，公开页与分享页的切换按钮共用同一键。根布局在 `<head>` 用内联脚本于首帧前写入主题，`<html>` 加 `suppressHydrationWarning`。主题是设备偏好，不写入账号；这样匿名页面也能使用，且不改服务端偏好结构。

材质只用于浮层：顶栏、收起胶囊、手机导航、菜单与弹层、提示和抽屉使用半透明加 `backdrop-filter`，阅读区、表格、表单和确认对话框为实底。抽屉贴合窗口边缘，为单层 `--of-sheet-glass` 玻璃；遮罩以 `--of-scrim-blur` 模糊背后页面。按用户决定不提供减少透明度或不支持模糊时的降级；`prefers-reduced-motion` 关闭动画与过渡。

### 共享组件

`@open-folio/ui` 补齐页面反复使用、交互语义复杂的基础组件：菜单（单选 / 多选 / 普通项）、弹层、对话框与侧边 / 底部抽屉、提示（tooltip）、分段控件、开关、头像与字标、状态标签（扩展现有 Badge 的色调）、品牌标志。交互与可访问性由 `radix-ui` 对应原语提供（方向键、Escape、焦点回到触发控件、焦点限制），样式用 `of-ui-` 前缀的普通 CSS，供工作台与组件预览共用。新增前按包 README 先用 shadcn CLI 查看来源与差异，转换为本包 token 后再接入，并补充预览示例与 `ui:test`。

业务组合放在 `src/components`：阅读布局（材料目录 + 正文 + 本页目录）、Change 行与看板卡片、同步状态、侧栏与胶囊等。业务样式改为与组件同目录的 CSS Modules；`globals.css` 只保留 reset、基础排版、主题 token 的全局部分与正文 prose 样式。旧 `globals.css` 的其余部分和 `shared-change.css` 在对应页面替换后删除，不保留兼容类名。

### 标志与图标

标志使用原型已验收的平面墨色矢量（`packages/prototype/src/assets/openfolio-mark.svg`），作为品牌组件内联渲染，颜色跟随文字色，深色模式反白；侧栏、手机顶栏、登录页、公开页与分享页页头统一使用。应用图标改为 `app/icon.svg`（浅色方底上的墨色标志，取自 `openfolio-icon.svg`），`favicon.ico` 由同一图形重新生成并替换；不再引用 `public/brand/openfolio-mark.png`。描图来源 `openfolio-mark-deep-blue.png` 保留。

## 壳层与导航

壳层由侧栏、内容面和手机导航组成。侧栏展开态包含标志、我的仓库、仓库切换及其 Specs / Changes / 原型和底部账号按钮；点击标志或 ⌘\ / Ctrl+\ 收起为窄轨，四个模块图标组成悬浮胶囊。收起状态沿用 `railCollapsed` 偏好；平板宽度（761–1023px）始终使用收起态但不改写偏好；手机（≤760px）改为底部胶囊导航。展开与收起只切换类名并以过渡调整内容面宽度，焦点留在标志上。

顶栏浮在内容面顶部，内容从下方滚过。左侧是页面上下文（侧栏收起或手机时显示紧凑仓库切换；详情页显示返回与标题），右侧是页面操作与一个“同步状态”按钮。同步状态由现有工作区状态派生：读取中为“正在读取”；浏览器离线或请求因网络失败为“离线”；`ApiError` 中的无权限、Token 失效与其他错误分别显示；否则为“已同步”。弹层显示读取来源、集成分支、快照时间与刷新。临时失败保留已显示内容；明确失权按现有逻辑清除私有内容并引导恢复。

账号入口只保留侧栏底部的账号菜单：切换 Token（沿用现有切换接口，失败保留原选择）、账号与 Token 设置、浅色 / 深色、退出登录。原顶栏设置图标、首页身份区和凭据快捷入口删除。

## 页面实现

**我的仓库**：沿用发现、分页、重新检查与添加仓库检查。列表只显示仓库名、路径与集成分支；需要处理的仓库单独成组并附原因和操作，状态页签、阅读来源列和逐行“可阅读”删除。未登录进入登录页，已登录无 Token 时显示绑定首个 Token 的引导。

**Specs**：阅读布局为左侧能力树、正文、右侧本页目录。目录取 `DocumentRef.headings`，滚动高亮以顶栏下沿为起点，跳转后标题不被顶栏遮挡；窄屏目录和能力树收进抽屉。文末“相关 Change”由快照中 Change 的 `relatedSpecs` 反查。复制阅读链接与查看原文移到正文顶部的更多菜单。字号与专注阅读保存在本机。

**Changes 列表**：一行工具栏：范围分段（进行中 / 已完成 / 已取消）、“筛选”弹层（类型、紧急程度、创建者，选中后显示可单独清除的标签）、“显示”弹层（列表 / 看板、分组方式、排序：最新创建 / 紧急程度优先）。进行中默认按“等待确认 / 受阻 / 推进中”分组：等待确认取 `waitingFor.kind=confirmation`，受阻取有受阻任务或其他等待，其余为推进中；已完成按交付标签分组。分组、筛选与排序写成纯函数，便于单测。行内显示标题、ID、类型、紧急 / 高旗标、等待原因或受阻任务、PR 状态、阶段、任务进度、创建者与创建时间。来源异常有记录时才在列表上方提示。看板只用于进行中。删除任务粒度、全局依赖视图、规模 / 关联能力 / 阶段 / 等待 / 任务状态筛选及对应页签。

**Change 详情**：以完整阅读页取代 640px 抽屉和文档弹窗。左侧材料目录（概览、任务、需求、技术方案、计划、执行与评审记录、原型、合入变更、依据；未产生的置灰），中间内联正文，右侧本页目录。概览包含等待 / 受阻提示、进度、交付与 PR、关联（依赖、父子、延续）和澄清问答；合入变更沿用现有文件列表与 diff；原型沿用现有预览组件。顶部显示阶段流程，提供返回列表（恢复滚动与焦点）、上一项 / 下一项（按当前列表的筛选、分组和排序）与“分享”弹层（复制链接、打开分享页，沿用 `ShareManager` 与 `share-link` 的地址生成和复制兜底）。

**分享页**：与 Change 详情共用阅读布局和材料组件。数据仍由 `SharedProvider` 提供，它对工作区上下文的实现不变；本次只按新的材料参数同步其参数白名单（工作台文档用 `doc`，分享页沿用 `document`）。去掉侧栏、账号与仓库操作，页头为单行玻璃栏（仓库、只读分享标记、阅读设置、复制链接、主题）。不存在、暂不可读与同步失败状态沿用其语义。

**原型**：总览只保留“预览设备”分段，同时决定卡片缩略图的设备；卡片显示名称、说明、适配设备、关联 Change 与公开状态，组件以标签标注，缩略图沿用已发布截图与服务端渲染。详情为抽屉，预览画布沿用现有设备、方向、缩放、重载与公开链接准备逻辑，改为新的工具栏与画布样式。

**账号与 Token**：账号卡片、Token 列表（当前项标记；更多菜单中命名、复制当前 Token、解绑）、添加 Token 对话框（验证失败不保存）、登录设备（当前设备只做标记）和页面底部的退出全部设备（确认时说明 Token 会保留）。登录与注册页使用新的居中卡片，错误、限流与重名状态沿用现有接口结果。

**公开原型页**：单行玻璃页头（标志、名称、固定版本、设备工具、复制链接、主题）加满屏画布；不存在与已撤回状态沿用现有判断。

## Change 创建者

`changeCreationTimes` 扩展为同时返回首次加入 `change.json` 的提交作者：日志格式增加作者名与邮箱，与取最早时间的逻辑一并取该提交的作者。`ChangeGroup` 新增可选的 `creator: { name: string; login?: string }`：邮箱只用于识别 GitHub noreply 地址（`<id>+<login>@users.noreply.github.com` 或 `<login>@users.noreply.github.com`）以得到登录名，本身不进入快照与接口响应。界面优先显示登录名，否则显示 Git 作者名，头像为按名称取色的字标；不请求平台接口或外部头像，避免额外配额与跨域图片。历史不能确定时不显示创建者，与创建时间一致。

快照缓存版本升到 9，旧快照在下次读取时重建；账号、凭据、设备会话与公开原型不受影响。分享接口从快照中的 `ChangeGroup` 组装单个 Change，组装时一并带上创建者。

## 关键取舍

- **一次切换**：新旧视觉不并存，不设功能开关；在工作分支上按壳层、页面逐步替换，最终一次合入。中间提交保持可构建、可测试，但只在完成后更新长期服务。
- **保留数据层**：接口、Provider 与快照不重构，只做读取层的创建者扩展，降低回归面。
- **删除而非隐藏**：已在原型验收中删除的筛选、视图与页签，连同组件和测试一起删除；后端读取能力（如依赖关系计算）保留，供详情“关联”使用。
- **本机偏好**：主题、字号、专注阅读存本机；侧栏收起继续用账号偏好，保持既有跨设备行为。

## 对抗式审核

用户真正要的是：按已验收原型替换现有工作台视觉与交互，补上创建者，保持既有能力可用。最小验收是原型中的页面、状态与交互在产品中可用，旧能力不回归。

| 机制 | 结论 | 依据与替代 |
| --- | --- | --- |
| 新增 Radix 基础组件 | 保留 | 菜单、弹层、对话框的焦点与键盘行为是验收项，自写成本与风险更高；项目已依赖 `radix-ui`。 |
| CSS Modules 拆分 | 保留 | 工作台、`/share`、`/preview` 共用全局样式表，旧全局类已互相覆盖；作用域样式让删除旧样式可控。 |
| 快照缓存版本升级 | 保留 | 不升级时旧快照缺少创建者且不会刷新，属已知正确性问题。 |
| 对比度与布局矩阵检查 | 保留 | 对应验收第 4、6 条，原型已有可移植的检查方法，成本低。 |
| 旧查询参数逐项兼容 | 合并 | 只做删除与就近映射，不还原已删除视图。 |
| 主题写入账号偏好 | 删除 | 无证据需要跨设备同步，且匿名页无法使用；改为本机存储。 |
| 平台接口识别创建者头像 | 延后 | 原型以字标展示；noreply 登录名已覆盖常见情况，需要时另提。 |
| 视觉回归截图比对 | 删除 | 无基线且对样式微调过于敏感；以布局、对比度断言与人工验收替代。 |
| 新旧界面开关并存 | 删除 | 需求为整体替换，并存会让样式与测试翻倍。 |

本节未削弱任何安全或授权边界：匿名分享与公开原型的读取范围、Token 与会话处理均不变。
