# 历史原型统一使用 main 当前配置

## 背景与目标

历史原型的固定提交仍含已移除的 prototype.decision，当前读取器校验历史 workflow 导致原型无法展示。用户明确要求：历史只读取当时产物，配置统一使用 main 当前 workflow.json；按当前字段读取失败时直接显示失败。

## 范围与行为

MODIFIED `project-knowledge/prototype-preview`：Change 原型、归档原型及项目固定版本分享均使用最近一次成功刷新得到的 main 配置；固定提交只提供当时的原型记录、清单与产物。当前配置无效或停用时明确拒绝预览。

固定提交、归档标签及产物引用保持既有校验。旧引用字段、无效路径、缺失产物或按当前包路径找不到历史清单时显示失败，不读取旧配置兜底，不替换为新产物，不迁移或改写历史。

## 方案要点

集中读取指定 main 提交的原型配置，将配置来源与产物提交分离。历史 Change 沿用固定记录及 HTML，项目固定链接沿用固定清单及 HTML，均按现行字段校验。复用现有失败展示，不调整界面布局。

本次是一个读取职责内的局部修正，预计不足 300 行有效实现，按 small 推进。用户本轮“按这个方向修改吧”已明确授权方向。

## 验收标准

- 历史配置包含 decision、格式损坏或缺失，不影响有效产物按 main 当前配置预览；历史 HTML 内容保持原版本。
- Change 默认/固定链接、归档标签与冷缓存，以及项目固定分享和旧快照均使用 main 当前配置。
- main 配置停用、损坏，或当前包路径无法定位旧清单/产物时明确失败；非法旧引用仍失败，不回退历史配置或最新产物。
- 相关原型、托管和截图回归、类型检查通过，生产构建与真实归档预览验证通过。
