# 交付计划

依据 [需求](./requirement.md) 与 [技术方案](./technical.md)。交付可复用的三种发布选择、无数据库静态托管和内置上传命令；三项任务顺序执行。

## T1 保存托管选择并取消原型来源限制

交付：workflow 的服务地址和托管选择、setup 持久化与兼容、精简 skill 引导；删除设置表单及运行时的 prototypeOrigins 限制，接受 HTTP/HTTPS 与同源引用。新建原型包按托管方式提供合适输出，已有工程保留。

验收：已保存选择不重复询问或丢失，三种方式均能配置，旧 workflow/config 可读取并保存；来源输入消失，已有原型不因域名或同源策略被拒绝。

验证：共享契约、setup、配置存储测试，来源处理回归、设置表单浏览器测试、skill 结构及人工场景检查；不另画原型。

## T2 提供凭地址上传与公开读取的本地静态服务

交付：管理员取得稳定上传地址；无项目隔离的流式上传、摘要校验、原子发布；本地固定版本存储与公开 GET/HEAD、多文件资源响应及沙箱隔离。

验收：只有管理员可取得地址；正确地址无需 Cookie 即可上传，错误地址无写入；匿名读取完整版本，重启、并发、重复上传不改写历史；失败不暴露半成品。

验证：接口及存储集成测试覆盖权限、路径、大小、摘要、失败清理和稳定版本；浏览器验证模块、动态 import、样式、图片及与工作台隔离。

## T3 贯通 skill 上传和原型引用登记

交付：publish 内置上传适配器，按 workflow 选择执行；上传结果转换与校验、当前清单和 Change 固定引用登记；部署与操作说明保持简短。

验收：已构建原型可用内置命令发布至临时 OpenFolio 实例，匿名预览正常；失败保留旧引用，已上传但登记失败可恢复；custom/Git 流程不受影响。

验证：从配置选择、构建、上传、登记到浏览器读取的端到端测试，回归现有发布及归档；类型、格式、生产构建和独立评审。整体验证后向用户提供验收结果，验收后同步 Specs 并归档。
