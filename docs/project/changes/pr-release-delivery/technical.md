## 双分支配置与读取入口

`workflow.json` 升为 `schemaVersion: 3`，必填合法且不同的 `integrationBranch`、`releaseBranch`；移除 `collaborationBranch`、`protectedBranches`。保留既有 prototype、服务地址等无关配置，Change schema 仍为 1。共享校验器、Setup、CLI、Provider、仓库发现、API 和展示统一使用新角色名称，不双读旧 workflow。

本仓库目标仍为集成 `develop`、发布 `main`，实现和样例使用同一新契约；测试必须覆盖自定义名称。平台保护规则不写成发布目标列表，也不自动调整。工作分支不得使用这两个长期分支名，主工作区仍在集成分支。

工作台从选定的集成分支读取配置与集中 Change 登记，再读取登记来源；额外定向读取配置的发布分支，不枚举其他分支来发现 Change。发布分支暂不可读时，交付信息局部降级，已有集成文档仍可阅读。规划与分支登记继续直推集成分支；hook 保持本地结构校验，不联网检查 PR，也不禁止所有集成分支提交。

发现缓存和快照版本更新后按原策略重建。账号、凭据、设备会话、公开原型和用户偏好不重置；个人存储中既有偏好键在边界映射为运行时 `integrationBranch`，不因此增加旧 workflow 兼容。现有项目升级由用户处理，不编写迁移工具或升级提示词。

## Change PR 与归档返修

### 关联与合入协议

Change PR 的末尾独立段落保留唯一标记，标题可自由表达交付行为：

```text
SpecTrail-Change: pr-release-delivery
```

精确解析末尾元数据段，不从标题、代码示例或普通正文提及建立关联。核对稳定仓库身份、登记源分支、`integrationBranch` 和合法 Change id；同仓库分支是本次支持范围。可信 PR 链接与集成校验分别展示：是否完成集成仍核对平台合并提交与 Git 中的有效 M，M 异常不隐藏已匹配的 PR。未合入 PR 的 `merge_commit_sha` 不能作为合入证据。[GitHub PR 接口](https://docs.github.com/en/rest/pulls/pulls#list-pull-requests)

沿用现有 M 协议：恰有两个父提交，末尾唯一同名标记；M 位于集成分支主链，只首次引入该 Change 的有效归档，且归档子树与第二父提交一致。Agent 使用普通 merge 合并 PR，显式保留 trailer 并核对预期源 SHA；平台规则仅允许 squash/rebase 或无法保留消息时，报告受阻，不绕过规则。手动合并也须保留该协议，否则显示无效合入记录，不伪造修补历史。[GitHub 合并接口](https://docs.github.com/en/rest/pulls/pulls#merge-a-pull-request)

`integration.mjs` 收敛为 `preflight → verify → cleanup`：预检给出源提交、目标及所需消息；Agent 通过现有授权工具创建/复用 PR、补齐最终说明并按授权合并；verify 刷新远端完整集成历史，确认实际 M；项目验证后才 cleanup。删除默认直推合并实现，不在 skill 内新增平台写入 SDK。受理、排队或响应丢失都先核实平台与 Git，不能当作合入成功或直接重建 PR。[异步合并接口](https://docs.github.com/en/rest/pulls/pulls#merge-a-pull-request-asynchronously)

Draft PR 可提前建立，交付前持续更新同一 PR。合入授权沿用会话，准备 PR 不自动授予合并。源或目标推进后重新检查受影响差异与验证；不静默扩大已审阅内容。清理继续复用有效远端 M、项目验证提交、来源 tip、依赖占用和脏工作区检查。

### 归档与完成的区分

保留 `archive` 在源分支写 completed 并移动目录的行为；这只说明开发关闭材料齐备。工作台根据有效 M 判断是否完成集成，不能把源分支 completed 单独当成交付成功。依赖与父项关闭仍核对集中路由和实际交付可用性，不等待正式发布。

扩展既有 `rework`，只允许尚未集成的归档在登记工作分支恢复：刷新集中入口与完整合入索引，确认没有有效 M、中央归档或已经合入的源提交，再移回活动目录，恢复 Git 原型路径、active 与目标阶段，清除失效关闭记录及确认，保留已完成任务并追加返修任务。移动失败沿用现有回退处理，返修提交保持普通历史。

Agent 返修前核实 PR 未合入并取消已有自动合并请求，必要时恢复 Draft；本地锁不承诺阻止远端并发合并。重新交付时复验最新远端状态及源 SHA。已集成、路由冲突、疑似无标记集成或读取不完整均不自动恢复归档；已集成历史继续只读。

## 发布 PR 内容与关联

发布由用户明确触发，不为每次发版建立新的审批生命周期。Agent 按[发布整理要求](requirement.md#发布内容整理提示词)固定发布分支基线与集成候选，阅读实际 diff、Change / PR 和验证记录，在发布 PR 中集中说明版本、功能和修复、升级影响、包含的 Change / PR 及验证结果。提交标题只作线索，不能替代内容整理。

发布 PR 指向 `releaseBranch`，来源为集成分支；需要冻结审阅范围时才使用短期发布准备分支，不增加第三个必填长期角色。候选变化须更新说明和验证；新的实质修复先按 Change 集成，再更新候选。本次不强制生成版本文件变更或额外的元数据回流 PR。

发布 PR 正文末尾用一个独立段落声明版本和包含的 Change，复用 Change PR 的精确元数据解析方式：

```text
SpecTrail-Version: 1.2.0
SpecTrail-Includes: change-a
SpecTrail-Includes: change-b
```

Version 是 PR 声明的版本号，沿用项目约定，不要求对应 Git tag；Includes 是本次包含的 Change id 集合。核对同仓库、配置的发布目标、版本字段与合法 id，再与已知 Change 关联；源分支可以是集成分支或其发布准备分支。清单由 Agent 按实际差异维护，已撤回内容移出清单并在正文说明，不增加 Withdraws 协议。标记只存在于 PR，不复制进 Git 文档、Release 或 change.json。

发布 PR 尚未合入时展示其真实状态；合入后核实实际合并提交属于发布分支，再将清单内的已集成 Change 标为“已合入发布分支”。祖先关系用于核实提交来源，不能单独推断语义包含。PR 已合入但 Git 尚未核实时，保留 PR 合入事实并提示待核实。

工作台展示 PR 当前声明的版本和可核实的 PR 历史，不另建版本注册表、正文编辑历史或“首次正式发布”结论。部署单独报告，不由 PR 合入推断服务上线。

## 平台读取、刷新与降级

在现有 Provider 增加只读分页方法，覆盖 PR 列表/详情与提交关联 PR；沿用绑定的 credential lease、请求取消及限流错误，不新增独立身份或写权限。

1. 先由 Git 得到已知 Change、登记源分支和有效 M，再按 head/base/state 查询其 PR。已知 M 可以定向反查 PR，用于来源分支删除后的恢复；返回结果仍核对完整关联条件，不直接相信接口命中。[提交关联 PR](https://docs.github.com/en/rest/commits/commits#list-pull-requests-associated-with-a-commit)
2. 发布 PR 仅按配置的发布目标查询，以其正文清单关联已知 Change。GitReader 定向获取发布分支，其 tip 变化也参与刷新判断；不查询 Release 或 tag。PR 查询始终不参与发现 Change。
3. 匹配后的仓库身份和 PR 编号保存在可重建缓存，后续定向刷新；未匹配或需要发现新候选时才重新查询。关闭、重开和重建按稳定 PR 身份合并历史；多个当前候选显示冲突，不按更新时间任选。源分支删除后的冷缓存路径必须有测试，不能仅靠旧缓存保住链接。

Snapshot 增加 `deliveryByChange`，包含交付阶段、Change PR 历史与当前项、发布 PR 及局部诊断；版本为发布 PR 的属性。阶段可为 `pendingIntegration / pendingRelease / releaseMerged / unknown`，未具备交付条件时不赋交付阶段；PR 事实仍可提前显示。查询结果保存完整性与最近成功时间，未完成分页不能产生“没有 PR”或“未合入”的否定结论。

保留正常读取的刷新节流、仓库锁和请求合并。Git 未变时复用文档与 blob，继续刷新 PR 信息；只有有效内容或可见诊断变化才发布新快照，不因检查时间变化不断制造快照。扩展现有刷新检查记录，保存 PR 最近成功时间并随响应提供；时间更新不改变不可变快照，失败检查不能延长成功有效期。新的元数据快照仍执行既有发布前权限复核。

PR 的 403、404、限流和网络错误只影响对应信息；权限提示说明需要 `Pull requests: read`。401 或确证仓库内容失权仍走现有授权失效路径。局部失败保留文档、有效 M 和标明过期的最近成功结果；冷缓存没有结果时显示待核实。请求受既有总超时与有界分页控制，不引入 webhook、后台扫描或独立缓存服务。

## 工作台呈现

**Q4（技术，round 2）：用户选择复用现有界面，不单独绘制原型。** 实现复用 `@open-folio/ui` 的 Badge、现有列表、筛选与详情组件，验证桌面及窄屏。

| 展示           | 派生条件与交互                                                                                                      |
| -------------- | ------------------------------------------------------------------------------------------------------------------- |
| 待集成         | 交付归档有效且尚无有效 M；显示当前 PR 状态，没有可靠关联时给出诊断。执行中的 Draft 只显示 PR 状态，不提前赋此阶段。 |
| 待发布         | 有效 M，尚无包含它且已核实合入的发布 PR；显示正在准备的发布 PR。                                                    |
| 已合入发布分支 | 发布 PR 明确包含该 Change，且实际合并结果已核实；版本取自该 PR，不推断服务上线。                                    |
| 待核实         | 必要信息缺失、冲突或读取失败；同时保留已核实的 PR 与集成事实及最近成功时间。                                        |

在现有列表、卡片显示简短交付徽标，详情概览增加交付区，包含 Change PR、发布 PR、PR 声明的版本及可展开的历史/诊断。列表行本身是按钮，不在其中嵌套 PR 链接；链接放详情的独立交互区域，外链只使用经过 Provider 校验的 GitHub 地址。

增加“待集成”“待发布”范围入口，跨活动/已完成记录筛选，不能把归档待发布藏在完成列表里。交付筛选与开发阶段分开，切换交付范围清除不适用的阶段条件，保留类型、紧急程度等通用筛选；不增加新的开发看板列，不改写 change.json 的 status/stage。取消记录、未知状态和已合入发布分支的记录均不凭空纳入待交付计数。

## 精简取舍与验证

| 处理 | 依据、影响与最小方案                                                                                                      |
| ---- | ------------------------------------------------------------------------------------------------------------------------- |
| 保留 | M 协议、预期源 SHA、清理检查分别保护历史 diff/原型、已审阅范围和未合入工作；复用现有校验，不增加第二套交付审计。          |
| 合并 | Git 集中入口、授权、刷新锁、文档快照和 UI 均复用；版本说明及包含清单只维护在发布 PR 中。                                  |
| 延后 | 多平台写入、merge queue、自动语义回滚识别、后台同步和独立发布系统不进入本次；Agent 执行、只读平台查询和显式发布清单足够。 |
| 删除 | 默认直推 Change 合并、旧分支角色和重复提示词；移除独立 changelog、tag / Release 管理及三处清单校验，不新增历史数据库。    |

主 SKILL 仅保留分支职责、两条 PR 路径、归档冻结边界及发布触发入口；替换现有集成参考，发布整理与标记集中在一份 `references/release.md`。Setup 说明新契约及读取权限，原型和其他引用只同步必要角色用语，不复制整套发布规则。

验证使用现有 Node 测试、临时 Git fixture、Provider HTTP fixture 与 Playwright：覆盖自定义分支、规划直推、普通 PR 合入和拒绝非标准 M、归档返修闭环、删源分支冷启动、多 PR 候选、分页与缺权、Git 无变化的 PR 刷新及发布 PR 清单变更。浏览器检查待发布归档可达、实际链接、筛选组合及手机布局；保护既有登录和偏好。具体任务与验收映射见 [Plan](plan.md)。

真实 PR 写入仍按实际任务授权执行；本 Change 不为验证发布规则而擅自向发布分支合码。实施结束按项目约定评审、人工验收、集成并更新长期开发服务。
