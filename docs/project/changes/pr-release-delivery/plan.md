# PR 集成与正式发布的实施计划

按[需求](requirement.md)与[技术方案](technical.md)交付，默认 T1 → T2 → T3 → T4 串行执行；任务状态只维护在 change.json。

Technical 与 Plan 确认后，从最新集成分支移交到 `codex/pr-release-delivery` 和独立 worktree。沿用 Q4：复用现有 UI，不单独制作原型。实施前核对其他活动 Change 在共享配置、仓库读取和详情组件上的新交付，保留其有效改动；不因同文件修改虚构交付依赖。

## T1 · 统一集成与发布分支契约

交付 workflow v3、必填且不同的 integrationBranch/releaseBranch，以及 Setup、CLI、Provider、仓库发现、API 和工作台的统一角色命名。保留集中规划及登记直推，新配置贯穿本仓库与样例。可重建缓存失效重建，个人存储只做接口映射，不重置账号、凭据和偏好；不实现旧 workflow 兼容或迁移提示。

验收：默认和自定义分支名均可接入、登记及读取；非法、相同、缺失配置被拒绝，不从默认分支或平台保护推断发布目标。工作台只从集成入口发现 Change；发布信息缺失不隐藏文档。已有身份和最近仓库选择仍可使用。

验证：扩展共享 schema、workspace-routing、Provider、发现和 personal-sessions / preferences 测试；临时 Git 仓库验证实际 hook 的成功与失败传播，以及规划登记仍可直接提交。检查新旧名称只在明确保留的磁盘字段和历史文档中共存。

## T2 · 通过 PR 交付 Change 与正式版本

交付 preflight / verify / cleanup 集成命令、未集成归档 rework 和最小关联标记解析。Agent 通过已有工具创建/复用 PR、保留普通合并协议并验证远端；移除默认直推合并。精简主 Skill 与 Setup，更新集成参考，集中编写发布 PR 参考：固定比较范围，整理版本、实际变化、包含的 Change / PR 与验证依据，按授权合入并如实处理失败。

验收：已归档但未集成的同一 Change 可返修并重新交付，已集成归档不能恢复；实际 M、diff、固定原型和安全清理继续成立。Change 和发布均默认走 PR，失败不回退直推。准备 PR 与批准合入沿用真实授权；发布 PR 正文说明版本及实际包含内容，不额外维护 CHANGELOG.md、tag、GitHub Release 或清单副本。change.json 不保存 PR 动态数据。

验证：临时远端 Git fixture 模拟平台普通合并，覆盖源/目标推进、结果不确定、无标记/squash/rebase 拒绝、归档与 Git 原型返修往返、已集成冻结和清理竞态。纯解析测试覆盖两类 PR 的精确标记、重复与冲突。按真实输入演练首次发布、已有发布 PR、候选变化、仅准备 PR 及合入失败的说明，核对 skill 无旧规则或重复大段提示词；不为测试擅自向发布分支合码。

## T3 · 自动关联 PR 并派生版本交付状态

交付 Provider 的只读 PR 方法、发布分支定向读取及 Snapshot.deliveryByChange。以已知 Change、源分支和 M 查询 Change PR，以发布 PR 正文清单关联多个 Change；缓存匹配结果，交付事实不参与发现 Change。让 Git 未变化的正常刷新仍更新 PR 状态，并隔离局部缺权、分页未完和网络错误。不读取 tag、GitHub Release 或独立 changelog。

验收：改标题、关闭/重开/重建 PR 和删源分支均保留正确关联；歧义明确显示。发布 PR 的实际合入可核实，版本取自 PR；不从祖先关系单独推断本次包含，也不推断外部发布物或部署完成。PR 缺权不撤销仓库文档读取；过期结果标明时间，失败或不完整查询不生成否定事实。

验证：扩展 Provider HTTP fixture、store 和 Git 集成测试，覆盖冷缓存、定向提交回查、分页/限流/403/404/401、PR-only 更新、发布分支推进及包含清单变化。检查新快照仍执行授权复核，相同结果不因检查时间产生重复快照，可信 PR 不因 M 校验异常而隐藏，现有 diff 和原型读取保持有效。

## T4 · 在工作台呈现可追溯的交付进度

交付列表/卡片徽标、待集成/待发布范围入口、详情交付区及两类 PR 链接，复用现有 UI。待发布入口覆盖归档记录，发布 PR 合入核实后显示“已合入发布分支”；开发状态和交付状态独立，未知状态与 PR 历史可查看。

验收：用户从工作台即可找到两个待交付阶段，打开实际 PR 并查看其中声明的版本；执行中的 Draft 不被误判待集成，关闭 PR 不等于取消 Change。不增加“版本待发布”或外部 Release 状态。筛选与类型、紧急程度等组合可用；手机和桌面不溢出，键盘可达，列表按钮中无嵌套链接，已有详情页签仍可阅读。

验证：使用 Playwright fixture 覆盖准备交付→Change PR 打开/关闭/合入→待发布→发布 PR 合入及缺权/冲突显示；检查 URL 筛选恢复、归档入口、链接目标、桌面及 390/320px 窄屏。实际仓库读取冒烟复核平台事实与页面一致；真实登录遵循 withSmokeSession，失败清理必须报告。

## 整体验证与交付

验收标准 1、2 的配置与集中入口由 T1 覆盖；2、4–6、11 的流程由 T2 覆盖；3、6、8、9 的事实读取由 T3 覆盖；7 及链接呈现由 T4 覆盖；10 的范围和数据保留贯穿全部任务。

运行类型检查、受影响的单元与浏览器回归、格式检查和生产构建；复用现有测试工具，不增设常驻同步服务或固定冒烟脚本。安排与实现上下文隔离的独立评审，核对完整差异、验收映射、授权和数据边界。测试通过后提供人工验收，实际结果再记入关闭记录。

验收后同步 Change 工作流、Change 追踪和个人访问相关 Specs，归档并用本次新的 Change PR 路径合入集成分支，核实实际 M。主工作区安全快进，按项目约定执行 service:update 和针对性冒烟后再清理来源；保留持久数据、不创建例行备份或额外构建目录。此次集成交付不自动触发 main 正式发版，也不改变 skill 分发与自动升级范围。
