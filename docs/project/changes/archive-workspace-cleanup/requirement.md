# 归档后清理本地工作区

## 目标

已完成并集成到协作分支的 Change 不再默认遗留本地 worktree 和工作分支。Agent 主动推送并核实远端记录，再清理本地执行现场，使后续工作区列表只保留仍需使用的任务。

用户要求：“归档合入协作分支后，需要自己推送分支保证远端有记录，然后清理本地残留工作区。”用户同时指出现有分支未采用 `change/<id>`，本次明确 SpecTrail 命名优先于客户端通用默认前缀。

## 范围与方案

- 在 SpecTrail 主 skill 和工作区说明中统一归档后的收尾规则：推送同名工作分支、核实远端完整提交与协作分支集成、检查必要原型标签，随后默认删除本次已完成的本地 worktree 与工作分支，保留远端分支和标签。
- 清理前核对 Change 已完成，无活动或取消入口依赖，无未提交、未推送的工作及仍需使用该目录的会话或服务。保留未保存配置、用户数据和无法判定用途的忽略文件；可重建产物可随工作区删除。核验或清理失败时保留剩余现场并报告，不强制删除。
- 新 Change 默认使用 `change/<id>`，并行任务沿用 `task/<id>/T<n>`；客户端通用前缀不覆盖该约定，用户明确指定的名字优先。已有远端分支不为统一命名而改名。
- 同步当前工作流 Spec。本次只调整 Agent 指令，不增加自动删除脚本、不改变状态字段、不影响服务实现。

## 验收

1. 正常归档集成路径会主动推送并核实远端留存，然后清理本地 worktree 和分支，无须再次询问常规清理。
2. 未完成或取消的 Change、远端核实失败、未提交或未推送现场、仍在使用的目录均不会被误删；远端分支及原型保留标签保持可用。
3. 主 skill、工作区说明和当前 Spec 对清理时机与命名规则一致，链接与 skill 校验通过。
4. 本次 Change 使用 `change/archive-workspace-cleanup`，归档集成后实际核实远端并清理自身工作区；已有清理候选重新核对后按同一规则处理。
