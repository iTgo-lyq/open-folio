# 背景与目标

OpenFolio 需要在当前 Git 仓库内沉淀可复用的 UI 组件，让主应用、原型和后续维护者使用同一份组件实现。个人拥有的 Shadcn 相关素材可以用于按需接入，但其获取方式、凭据和私人供应商配置不应成为项目协作、构建或运行的前提。

项目已启用唯一原型包，支持页面与组件预览、Change 关联、固定 Git 版本和归档保留。现有原型采用静态 HTML 与共享 CSS，设计依据引用主应用，但尚未直接复用 React 组件。因此，引入组件库时需要同时打通原型消费组件的路径，避免为组件库另建展示平台、复制组件实现或维护重复的预览入口。

目标是形成“个人按需获取素材 → 适配并沉淀到项目组件库 → 主应用与原型共同使用 → 随 Git 正常维护”的完整路径。组件入库后以本地源码为准，后续维护不依赖素材提供方。

# 范围

## 项目组件库与个人资源协同

- 在当前仓库建立独立维护的组件库，纳入现有 workspace 与 Git，沉淀可复用组件、必要的主题样式、依赖声明及使用约定。包边界和导出方式在技术阶段明确，不要求发布 npm 包或建立独立远程仓库。
- 主应用与原型可以消费同一份可复用组件。业务数据获取和页面业务逻辑保留在相应消费方，演示需要的数据由原型提供 mock。
- 优先复用项目已有组件；接入新素材时按项目设计规范、组件接口与依赖约束适配，避免同时保留同职能的多套基础组件或主题定义。
- 个人获取资源所用的 skill、连接配置和凭据放在用户级环境。仓库只保存协作维护需要的通用规范、适配后的组件源码及普通项目配置，不要求协作者安装个人工具或持有资源下载凭据；协作使用仍须满足适用授权。
- 个人接入 skill 说明首次使用与后续维护方式：真正需要获取新素材时，检查个人环境，按需初始化最小临时工作区；完成适配后交付项目源码。缺少凭据时说明缺失项，不向项目写入私人配置。临时工作区不作为长期维护对象。
- 项目文档、配置、提交说明和交付产物不主动记录私人供应商名称、registry 命名空间、来源链接或账户信息；依法或依授权必须保留的声明仍须保留。不承诺组件外观或源码无法被辨认来源。
- 首批接入覆盖有代表性的实际复用场景，验证主应用与原型的共同消费；具体组件在技术阶段结合现有 UI 确定，不将全站组件化或视觉改版纳入本次范围。

## 原型消费组件与统一预览

- 继续使用项目已启用的唯一原型包，支持直接引用组件库源码及设计规范；调整开发与构建方式，使其满足现有自包含 HTML 交付要求。
- 新组件应有可观察、可操作的展示入口，优先复用已有页面或展示页。基础组件可共用展示入口，独立且复杂的可复用模块可建立组件预览，已由业务页面充分展示的组件无需再建同内容的预览。
- 演示只负责实例、状态、布局和 mock 数据，不复制组件实现。组件变更后重新构建相关演示，以验证最终静态产物；Git 中保留导出产物不视为维护第二份源码。
- 沿用 Change 的 previews 关联、原型总览、页面与组件类型、视口和版本机制。需要在工作台展示的入口通过 Change 登记，不为每个组件单独新建 Change，也不新增第二份原型清单或独立组件预览服务。
- 同一演示入口可被多个 Change 引用；已有归档预览继续绑定原提交，组件后续变更不覆盖历史展示。与本次无关的入口及关联保持有效。
- 将组件接入、使用、演示和维护约定落实到适当的项目指引及原型协作指引，明确个人工具、项目组件库、原型工程和工作台各自负责的事情。

## 不包含

- 主动检查素材更新、追踪上游版本、自动同步或覆盖已入库组件。
- 私人素材归档数据库、完整素材镜像、复杂的跨机器恢复或按项目管理的长期下载仓库。
- 另行搭建组件展示网站、模板商城、公共素材分发或在线编辑与构建服务。
- 全站视觉重做、全面替换现有组件、与首批复用场景无关的重构。

# 行为变化

- ADDED — `ui-development/component-library`：维护者可在当前仓库发现、使用和修改已沉淀组件，主应用与原型共享组件源码及适用的主题规则；普通构建和维护不依赖私人资源访问。
- ADDED — `ui-development/material-intake`：资源持有者通过个人环境按需获取素材并适配入库；首次使用只初始化获取所需的最小环境，已入库组件后续按项目代码维护。
- MODIFIED — `project-knowledge/prototype-preview`：原型从静态示例中的局部样式复用扩展为直接消费项目组件库；组件演示与页面原型共用现有导出、关联和展示机制，继续交付自包含 HTML。
- MODIFIED — `change-workflow`：组件接入与原型协作指引明确展示入口的复用规则及维护边界，沿用现有 Change、原型关联和归档流程。

# 验收标准

1. 在不提供个人密钥、不安装个人接入 skill 的干净环境中，协作者可按仓库指引安装项目依赖，构建主应用及已入库组件的原型，并修改这些组件。
2. 至少一个代表性组件由主应用和原型直接使用同一份实现；修改其共享样式或交互并重新构建后，两处均体现该变更，无需同步修改组件副本。
3. 展示一次按需素材接入流程：个人工具检查并准备必要环境，素材适配到项目组件库，项目产物不依赖私人 registry 或服务。凭据缺失时有明确反馈，且不会把凭据或私人连接配置写入项目。
4. 审阅新增的受 Git 跟踪文件、依赖与导出 HTML，确认不包含秘密值、个人工具配置或非必要的私人供应商标识；普通构建、测试和运行不发起私人资源请求。
5. 首批组件的展示能复用现有页面或组件入口；OpenFolio 通过既有 Change 关联展示它们，没有另建预览应用、重复清单或同内容的演示实现。
6. 引用组件库的原型通过现有静态校验和实际浏览器检查，在声明视口中可查看并操作关键状态，且离线运行、不依赖真实接口或持久存储。现有无关原型入口仍可用。
7. 已有固定版本和归档预览保持可访问且内容不随新组件修改而改变；新演示沿用现有 Git 产物及归档保留方式。
8. 项目与个人使用指引明确：已入库组件以项目源码为准，只有明确需要获取新素材时才使用个人工具，不主动检查上游更新；展示入口仅随相关组件或场景变更维护。

# 约束与后续设计事项

- 本次需求不预设具体私人供应商、密钥名称或素材条目。实际获取与提交素材前，应核对持有者授权是否覆盖仓库的可见性、协作方式和交付用途；不能通过省略来源标识替代授权判断。
- 真实私人资源接入验证依赖合法可用的素材授权和个人环境中的凭据。尚未核实这些条件，不视为已接通；这不影响先设计和验证项目组件库与原型复用路径。
- 技术阶段明确组件库与主应用的边界、首批复用组件、主题规则的唯一来源，以及原型引用 React 组件并导出离线 HTML 的方法。不得直接假设现有 HTML 导出器或普通前端构建产物已满足这些要求。
- 现有工作台通过 Change 关联汇总原型，不自动扫描组件目录。本次优先复用该机制，组件示例无需全部各占一个总览条目。
