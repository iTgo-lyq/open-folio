# 将 OpenFolio 原型迁移为复用业务代码的页面片段

[SpecTrail 精简 Change](../../archive/2026-11-15-spec-trail-core-simplification/requirement.md#后续) 已更新原型制作规范，并把 OpenFolio 自己的原型包迁移留给后续交付。当前七组 `quiet-*` 原型通过拼接包内 HTML、JS 和 CSS 构建，工作台界面需要在业务代码和原型包中分别维护。

## 目标与范围

- 将 `packages/prototype` 迁到 [SpecTrail 的页面片段方式](../../../../.agents/skills/spec-trail/references/prototype/prototype.md#原型包与业务代码)。原型入口直接复用业务代码，用 mock 提供示例数据和交互状态；片段的拆分、复用边界和构建方案由接手 Agent 决定。
- 覆盖当前七组原型代表的主要场景，迁移后仍可独立静态访问，并可使用既有清单和发布链路。已有 Change 的固定原型引用继续可用。
- 初定 `medium`，涉及原型入口、业务代码复用、静态构建与发布验证，接手后按实际影响复核。

## 验收

- 检查代表性片段确实复用业务组件，示例数据和交互在原型环境内运行。
- 验证原型包可构建、产物可静态访问，覆盖主要场景、交互和声明视口，并核对当前清单与发布兼容性。
- 用户委托接手 Agent 自主决定技术方案和推进步骤，完成代码后由用户验收。如果服务无法启动或运行效果暂时无法核实，先完成并提交推送代码，记录已完成的检查、未验证项及复现方式，交用户验收。
