# 单个 Change 的实时只读分享

依据[已确认需求](requirement.md)。分享链接授予读取指定 Change 的能力；内容继续来自中心 Git，并复用工作台的来源解析、缓存、文档与差异阅读。本方案尚未实施。

## 实现重点与调查依据

采用持久分享记录、账号绑定的仓库读取、单 Change 数据投影和共用详情组件。新增部分负责“谁可以通过这个链接看到什么”，既有模块继续负责 Git、Markdown、原型与 diff。

| 事实 | 已核实的代码与影响 |
| --- | --- |
| 当前设备会话与账号 Token 绑定分开保存 | `personal-sessions.ts` 的 `lease/workspaceLease` 创建时仍要求 Cookie；不能把它直接当匿名分享授权，也不能保存浏览器 Cookie。 |
| 仓库读取已有合并刷新与定期权限检查 | `repositories.ts`、`repository-permissions.ts` 按工作台及稳定仓库身份复用权限结果，固定 5 分钟有效；`store.ts` 的自动读取复用 60 秒成功检查时间。保留这些机制。 |
| 工作台快照包含整个仓库的资料 | `store.workbench()` 展开 Snapshot，包含其他 Change、Specs、路由、集成索引和可能含上传地址的原型配置。公开响应必须从白名单构造，不能先展开后仅删几个字段。 |
| 正文存储没有单 Change 授权边界 | `store.document()` 验证文档属于仓库快照；分享层必须再检查该文档属于当前分享的 Change。 |
| 文档 id 由分支与路径计算 | `git.ts` 的 id 不含 commit，普通更新稳定，但移交分支或归档路径改变后会变。持久分享深链须使用 Change 内相对路径。 |
| 合入差异已固定到该 Change 的集成提交 | `IntegrationReader` 已处理文件 id、游标、二进制及大小限制；无需新建任意 Git 比较接口。 |
| 公开原型是独立永久发布物 | `PublicPreviews.prepare` 产生的公开版本不随 Token 失效或设备退出关闭。Change 分享须使用自己的受控原型入口，不能借此生成绕开分享撤回的新公开版本。 |

技术依据以 `develop` 已集成的 `change-labels-urgency` 为基线，保留标签、紧急程度和快照 schema 7。Next.js 16.3.7 的本地 Route Handler 文档已核对：动态参数为 Promise，支持 GET/HEAD；分享 API 显式使用 `no-store`，不引入框架数据缓存。现有账号 schema 与缓存格式无需因分享而升级。

## 分享记录与管理

在现有数据目录新增 `shares/state.json`，使用独立 `schemaVersion: 1` 和记录集合，沿用单实例、进程内串行写锁、同目录临时文件原子替换、0700 目录与 0600 文件。解析严格校验；文件损坏报错，不覆盖初始化。记录数量沿用当前个人存储的 10,000 级有界集合做总量保护，不新增套餐、配额 UI 或清理调度。

每条记录只保存：

| 字段 | 含义 |
| --- | --- |
| `id` | 32 字节随机数的 base64url 编码，也是不可枚举的阅读链接标识 |
| `accountId`、`workspaceId` | 创建账号及其已有 Token 绑定；不复制 Token 密文或明文 |
| `repository` | provider、instance、稳定仓库 id 与供重解析使用的名称 |
| `collaborationBranch`、`changeId` | 已授权的固定读取范围；不接受访客覆盖 |
| `createdAt`、可选 `revokedAt` | 创建及永久撤回时间 |

同一账号、绑定、仓库、协作分支和 Change 的有效记录重复创建时复用。撤回是写入 `revokedAt`，不会被创建操作重新开启；重新分享分配新 id。更换绑定需要重新创建分享，不把旧记录悄悄迁到其他凭据。创建记录与查重在同一写锁内完成。

创建需要当前有效设备会话及选中绑定，强制复验一次仓库内容权限，并确认 Change 可解析。提交记录前后复核设备代次与绑定；若提交后发现创建请求已失权，立即撤回新记录且不返回链接。其他账号不能查询管理信息、创建为别人的记录或撤回；撤回只检查有效账号和记录归属，不要求 Token 仍可用，避免失权后反而无法关闭分享。

## 独立于设备的读取授权

把设备 lease 中“账号绑定、凭据上下文、有效性复核和释放”的公共部分提为内部 `WorkspaceLease`；设备 lease 继续增加设备标识与选择代次。分享入口先从服务端读取有效分享记录，再按其账号与绑定申请专用 lease，检查账号存在、归属一致、绑定未移除并解密原有凭据。调用者不能通过 HTTP 直接传账号或绑定取得此 lease。

`Repositories` 内部共用上下文构建、Git transport、缓存位置、稳定仓库身份校验与刷新合并。私有入口仍要求设备会话；分享入口从已验证记录取范围。权限检查通过内部 lease/factory 工作，不用空 Cookie 或假设备字段伪装私有请求，也不回退其他 Token 或管理员权限。

分享状态每个请求都检查；响应交付前再次检查未撤回、绑定仍有效、权限未被其他请求明确拒绝。子资源及 HEAD 同样执行。撤回 A 阻止 A 的在途交付，但不取消正在供私有页面或分享 B 使用的仓库刷新；解绑取消整个绑定的工作。设备退出不撤回分享；退出全部设备可能中断当次共享任务，但绑定仍在时下次分享读取可恢复。

仓库权限继续采用现有固定 5 分钟复验：明确拒绝立即失效，远端静默撤权最迟在下次周期复验识别。临时网络或限流不延长权限有效期。Token 解绑不能通过旧缓存继续交付，重新绑定会产生新工作台，不恢复旧分享。

## 实时更新与内容范围

接收者打开、手动刷新及可见页面每分钟检查均执行既有 `refresh(automatic: true)`，多个访问者复用同工作台成功检查时间和在途任务，避免公开链接每次访问都强制远端 fetch。没有活跃请求时不新增后台轮询。已登录 Agent 在推送后可以执行现有显式刷新。

详情响应采用独立 `SharedChange` DTO，只包含快照 id、读取时间、项目展示名、当前 ChangeGroup 的允许字段及文档引用。后端白名单投影保留该 Change 的标题、类型、紧急程度、阶段、任务、问答、确认、关闭、来源与已有诊断；不输出账号、绑定、会话、仓库克隆地址、上传地址、全仓库诊断、其他 Change、Specs 或当前原型总清单。前端若需满足现有阅读类型，由适配器填空集合，不从服务端拿完整 Workbench。

文档白名单来自该 Change 合法候选的 `documentIds`，逐项核对分支、提交和目录边界，并纳入其集中入口 `change.json` 以保留“依据”阅读。JSON 正文只交付该 Change 自身文件。目录内图片与图表同样按白名单读取，不递归跟随链接扩张范围。关联 Change、父子项和 Specs 仅保留本记录已声明的引用及现有状态说明；范围外目标明确标注“未分享”，不能因未携带其他记录而产生“前序不存在”的假诊断。

详情给出当前 `snapshotId`，所有子资源绑定这一快照。服务端只接受当前读取快照中的目标资源；其他或已被刷新替换的 snapshot 返回 `409 SHARE_VERSION_CHANGED`，客户端合并触发一次重读并重新定位当前文档。不能借任意历史 snapshot、Change、branch、revision、base/head 或路径访问别的内容。刷新切换后取消旧请求，晚到响应不得恢复旧正文。

临时同步失败时可保留浏览器已经显示的内容并标明未更新，服务器不把读取失败冒充最新；已撤回、绑定消失或明确失权则清空页面内容并展示不可读状态。找不到权威来源时显示不可用，不选择其他同名仓库或不明确的候选作为兜底。

## API 与页面契约

下列名称为拟实现契约，当前服务尚未提供：

| 入口 | 访问与结果 |
| --- | --- |
| `GET/POST /api/repositories/[key]/changes/[changeId]/share` | 登录用户查询本人当前绑定的分享，或创建/复用分享；输入沿用仓库 selector、实际协作分支和 connectionId，写入检查同源及会话版本。返回状态与相对 `/share/<id>` 路径。 |
| `DELETE /api/shares/[id]` | 登录拥有者停止分享；重复停止返回已停止，其他账号不泄露记录存在性。 |
| `GET/HEAD /api/shares/[id]/change` | 无需账号的受分享授权读取；自动刷新后返回裁剪后的当前详情。 |
| `GET/HEAD /api/shares/[id]/documents/[docId]`、`assets/[docId]` | 校验 snapshot 和文档成员身份后读取正文或图片。 |
| `GET/HEAD /api/shares/[id]/integration`、`integration/files`、`integration/files/[fileId]` | 仅用该 Change 固定集成记录读取摘要、分页文件与差异，沿用当前限制。 |
| `GET/HEAD /api/shares/[id]/previews`、`previews/[entryId]/[asset]` | 返回该 Change 的原型描述，以及受分享授权约束的 Git HTML/截图。 |
| `/share/[id]` | 独立阅读页面，支持页签、文档路径及原型 entry 深链。 |

未知或非法 id 返回通用 404；已撤回返回 410；来源或授权不可用返回不含内部凭据/账号信息的错误；临时失败保留可重试语义。所有分享数据响应包括图片、HTML 与错误均 `Cache-Control: no-store`，使用 `nosniff`、`Referrer-Policy: no-referrer`；页面 metadata 禁止索引，页面壳不嵌入可被框架静态缓存的工程内容。公共读取只允许 GET/HEAD，不开放泛化代理、写入或远端 URL 参数。

## 原型与代码差异

代码 diff 复用 `IntegrationReader` 的当前固定记录、文件 id 和游标，不接受访客提供提交或仓库路径。保持已有二进制、LFS、符号链接、文件及总大小限制，读取失败与没有合入记录分开呈现。

分享模式用专门的原型源适配器，复用 `store.preview`、自包含 HTML 校验、`ThumbnailCache` 与当前画布。Git 原型的 HTML 和截图经 share-scoped 路由交付，即使缓存命中也先检查分享状态；不调用永久公开发布的 `PublicPreviews.prepare`。iframe 保持 `sandbox="allow-scripts"`、无凭据及 `no-referrer`。

外部 hosted 原型继续使用已登记的固定 URL 和缩略图，不代理外部登录或下载；停止分享会关闭分享入口及受控资源，不能收回此前独立公开的 `/preview` 版本、外部公开 URL 或已下载字节。这是既有原型保留语义，不新增跨托管撤回机制；管理界面在涉及此类原型时简短说明。

## 页面复用与原型

从 `ChangeDrawer` 提取共用详情内容，私有工作台保留 Dialog 外壳，分享页使用以文档阅读为主的独立页面容器。默认进入指定材料，未指定时优先技术方案，其次需求及其他已有材料；没有文档时进入概览。共用摘要、标签、任务、问答、文档、依据、原型画布和合入差异；页面不挂载个人账号或完整工作台 Provider。

按用户对首版原型的反馈，Change 摘要放入左侧材料导航，整体布局铺满窗口，正文占满导航之间的剩余空间，仅保留阅读边距，并提高字号与对比度，桌面右侧提供本页章节导航；手机使用文档和章节目录弹层。保留全部六类内容入口，文档直接内联阅读，减少反复打开弹层。页面和正文不设最大宽度；专注模式收起辅助栏后也使用全宽，字号仅在当前阅读会话切换，支持章节定位、当前章节/阅读进度与上一篇/下一篇，不新增账号偏好持久化。章节锚点复用现有 Markdown 标题生成，调整布局或内容版本时重新计算，目录关闭和选中后恢复正确焦点。

提供精简的分享阅读上下文，实现 `nav/readUrl/openDocument/refresh/notice`。把 `useSavedScroll` 对个人身份的隐式依赖改为上下文阅读 scope；原型读取从 `usePublication` 的账号发布逻辑中分开。修正 DocumentModal 等待 `.change-drawer` 的条件，使独立页深链可以打开，保留键盘导航和焦点恢复。

公开深链采用 `?ct=documents&document=technical.md&anchor=...`，原型采用 `?ct=previews&preview=<entryId>`。文档路径相对当前 primary candidate 的 Change 目录解析；移交或归档后重新映射到当前文档 id，不把文档 id、snapshot 或提交固定在链接里。集中入口等来源材料通过明确的来源角色定位，不允许任意仓库路径。

**Q3（技术：原型）**用户选择先制作分享模式原型，随后要求更适合文档阅读。原型 `change-sharing` 沿用正式产品的浅蓝白色基线，以材料、正文、章节导航组织阅读，覆盖创建/复制/停止/重新分享、全部详情、同步更新与失败、链接失效和来源不可用，支持桌面、平板及手机。发布证据见 [Research](research.md)；对应产品实现须在用户验收原型后开始。

## Agent 获取链接与精简 Skill

复用现有 `workflow.openfolioUrl`；地址可用原型设置命令的 `--configure --openfolio-url` 配置并保留原托管方式，不另建服务地址字段。浏览器创建链接用当前可信 origin；CLI 用项目配置的对外地址，不使用 loopback 冒烟地址或上传地址。

新增可分发的零第三方依赖 `scripts/share.mjs`，仅负责获取链接，参数为 `--repo`、`--change` 和可选 `--document`/`--preview`。服务地址来自 workflow，秘密由执行环境注入；拟采用 `OPENFOLIO_SHARE_USERNAME`、`OPENFOLIO_SHARE_PASSWORD`、`OPENFOLIO_SHARE_CONNECTION_ID`，可由 Node 的 env-file 参数加载 Git 忽略的本地文件。UUID 绑定显式指定，避免在多个 Token 中猜测；不自动注册账号、绑定新 Token 或使用管理员密码。

调用顺序：

1. 核对项目地址与明确配置的账号，读取当前仓库 origin 并正规化为 GitHub HTTPS 仓库地址；只支持现有 GitHub.com provider，不接受任意 API 主机。远程服务必须 HTTPS，带凭据、query/hash 的基址拒绝；不跨 origin 跟随重定向发送秘密。
2. 用独立临时 Cookie jar 登录，写请求携带配置地址的 `Origin` 和当前 `X-OpenFolio-Revision`；先捕获响应 Cookie 再解析正文，确保登录正文异常仍可清理。按最新 revision 选用指定的既有绑定，调用已有仓库地址检查定位稳定身份与协作分支，再显式刷新。
3. 读取当前 Change 确认存在及目标材料可读，调用幂等创建/复用接口；使用返回的相对路径构造深链。对相对路径、id 与 origin 做结构校验，不接受服务返回的任意跳转地址。
4. 在不带 Cookie 的独立请求中验证分享详情及目标文档/原型可用，保留链接与读取来源。Agent 先提交推送，再调用；以返回的来源分支/提交或原型固定引用核对本次交付，不能仅凭同名材料存在声称已提供最新内容。
5. `finally` 获取最新会话版本，退出本次设备并复查匿名状态；清理成功后才输出链接与来源。清理失败报告错误，不打印成功结果、密码、Cookie 或原始请求。账号绑定与已创建分享保留，不退出其他设备。

工具正常获取链接不是冒烟测试，不借用专用冒烟账号配置，也不引入新的服务端机器密钥或 OAuth 流程。测试真实服务时仍必须使用项目 `withSmokeSession`。

主 `SKILL.md` 只增加一段：技术文档推送或原型引用登记后，按项目配置和已有分享授权获取/复用链接并主动提供；失败如实说明。配置、命令及失败处理集中在一份 `references/sharing.md`，原型子 skill 只链接到它，不重复整套规则。不给每个阶段增加新的确认，不修改原有状态命令、确认字段或 `change.json` schema，不将分享 URL 复制进每个 Change。

## 取舍与规模复核

| 处理 | 内容、依据与最小方案 |
| --- | --- |
| 保留 | 随机链接、持久撤回、服务端白名单、绑定与交付前复核；分别防止枚举、旧链接恢复、跨 Change 泄漏和撤回后在途交付。 |
| 合并 | 远端权限复验、Git 缓存、刷新去重、Markdown、原型画布、diff 和账号登录继续复用既有实现；只增加分享授权与读取适配。 |
| 延后 | 密码、收件人、统计、到期、通知、后台任务和新的机器凭据系统；已确认需求不需要这些机制。 |
| 不采用 | 复制 Token、保存 Cookie、为每次变化生成公开快照、任意历史读取、自动永久发布原型、第二套全仓库 DTO 或详情 UI。分别会增加敏感数据、设备耦合、撤回漏洞或重复实现。 |

授权范围明确扩展为持有链接者可读取该 Change 的全部已确认内容；其他私有 API 和独立公开原型语义保持。三项交付预计约 700–950 行新增或实质改写产品逻辑，复用组件的提取搬移及本轮原型不计入产品重写规模，维持 medium；若实际边界迫使大范围重写，再按事实复核。

## 验证、部署与可用性

单元/接口测试覆盖重启持久化、幂等创建、所有者管理、撤回/解绑/失权竞态、分享间隔离、GET/HEAD、越界文档与提交、版本变化、刷新与权限检查合并。浏览器使用独立匿名上下文覆盖六页签、原型沙箱、相对路径深链跨移交/归档、窄屏、键盘与复制兜底；确认没有个人 session/connections 或私有 repositories 请求。

CLI 使用本地 HTTP fixture 验证登录、指定绑定、刷新、复用、匿名校验与退出失败，不靠字符串匹配 Skill 文案证明行为。保留已有分享链接、公开原型、账号设备及权限测试回归。真实登录冒烟每个浏览器独立使用 `withSmokeSession`，清理失败不能标记通过。
