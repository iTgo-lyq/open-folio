# Change 协作者识别与展示

## 数据来源

沿用创建者的 Git 历史来源。创建者仍由 `change.json` 首次加入 Git 的提交识别；协作者取当前可读协作来源及所属工作分支历史中，曾修改该 Change 目录内材料的普通提交作者，包括需求、方案、计划、状态及附件。活动目录与归档目录按稳定 Change id 合并，避免归档后丢失成员。仓库其他文件的作者、PR 评论者及仅合并分支的操作者不因此计入协作者；合并提交首次创建记录时，已有创建者规则仍适用。

复用现有批量 Git 历史读取模式，一次批量收集全部 Change 的参与作者，不逐 Change 发起远端请求，也不读取未路由分支。创建者保持第一，其余按首次参与的提交时间排序，同时间采用稳定身份排序。身份优先采用 GitHub noreply 数字 id，其次可识别的登录名；普通 Git 作者在服务端以规范化邮箱作为去重依据，未提供邮箱时使用作者名。邮箱只用于内存识别，不进入工作台、分享响应、截图或日志；不同身份的同名作者不强行合并。

工作台 `ChangeGroup` 增加协作者集合，成员沿用已有创建者公开身份形状（名称、可选登录名与平台数字 id）。找不到参与历史时仍可展示已知创建者，身份完全未知时显示“—”。分享阅读仅投影当前 Change 自身成员，避免引入其他 Change 的信息。更新扫描指纹，确保未变化仓库的旧快照也能重新索引新字段；原始工程 `change.json` 与 SpecTrail 技能格式不变。

## 视图配置与界面

在现有个人视图查询中增加默认 false 的创建者列开关，URL 读取、切 tab、管理编辑、另存和显式保存保持一致。旧账号与旧视图缺少开关时归一为 false，保留筛选、名称、顺序等设置，继续复用账号存储的权限和版本冲突保护。

业务层复用 `@open-folio/ui` 现有 Avatar、Popover、菜单及焦点管理能力。列表、看板和已归档时间线共用协作者展示：最多三个字标加 `+N`，点击整组打开有界高度的完整名单。创建者第一且标注身份，其余标注参与推进；显示可用姓名和用户名，不拼接未经识别的平台头像 URL。独立创建者列默认隐藏，通过显示菜单恢复；手机布局与原型一致。保留整行进入详情的可点击范围，协作者按钮不会同时触发导航。

“我的”、本人识别、固定创建者筛选以及 Change 默认排序均保持现状；详情中的创建来源说明继续准确表达创建事实。本次只实现协作者展示及必要联动，不把整页原型作为整体改版要求。

## 验证

使用真实临时 Git 仓库验证创建者与推进者不同、多人去重、无关代码修改排除、纯合并操作者排除、工作分支与归档历史、热刷新及邮箱不外泄。验证旧视图读取、列开关 URL 与保存恢复、列表/看板/时间线展示一致。类型检查、相应单元测试及生产构建后，复用常驻 Chrome 检查键盘、焦点、浅深主题和 1440/834/390/320px，并按已确认原型核对还原。
