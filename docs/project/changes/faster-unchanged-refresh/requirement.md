# 缩短无变化刷新等待

## 背景与目标

分支增量缓存已跳过重复文档扫描，但相同工作台无变化的手动刷新仍约 4 秒。用户要求确认剩余耗时并继续优化。依赖已归档并合入 main 的 incremental-workspace-refresh，沿用分支缓存、保护主分支 Specs/原型与自动刷新。

## 范围与行为

MODIFIED：手动刷新及到期的自动检查仍实时查询远端，但远端分支及归档标签对象与本地 Git 一致时不再执行 fetch；默认分支变化仍生效。无变化复用已授权快照时不重复执行发布新快照所需的末尾远端鉴权。

保留请求入口的仓库身份和内容权限检查、共享任务所属凭据与本地会话撤销检查。发生变化需要采集及发布新快照时仍做末尾远端复验；读取失败不返回刷新成功，不更新成功检查时间。

## 方案要点

一次 ls-remote 同时读取 HEAD、全部分支和归档保留标签，对比本地原始引用对象（包括附注标签对象），有差异才 fetch/prune。复用既有快照时只检查任务取消及本地凭据有效性；新快照沿用发布前远端检查。

本次为 small：约数十行有效实现，涉及 Git 采集与刷新授权编排两个职责，不更改 API 或持久化格式。采用用户本轮明确的继续优化授权。

## 验收标准

- 用真实凭据与同一工作台缓存测出刷新总耗时和远端往返占比；部署后相同场景对比。
- 无变化只进行一次远端 Git 引用查询，无 fetch、文档扫描或末尾重复平台请求；快照 ID 与采集时间不变。
- 分支增删、强推、默认分支切换、轻量及附注归档标签变化仍正确；有变化时仍采集并复验。
- Git/权限失败与本地设备撤销不会返回刷新成功，旧快照保留；自动刷新与 Specs/原型主分支范围不变。
