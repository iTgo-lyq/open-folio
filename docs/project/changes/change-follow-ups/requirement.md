# 连续交付通过延续关系折叠展示

## 目标与范围

用户围绕同一交付结果连续补充时，已经归档的 Change 保留独立交付事实，后续 Change 声明延续关系，工作台以折叠组呈现，减少平铺记录造成的碎片感。用户已确认采用“延续关系 + 工作台折叠展示”，并明确要求关联 technical-clarification 与 independent-clarification-budgets 两个已归档 Change。

- 一个后继通过可选 followUpOf 指向同仓库已有效归档的直接前序；正文说明补充或修正的具体决定。关系与规模、执行依赖、父子拆分独立，不引入新的话题生命周期。
- Change 列表按延续链折叠，根目标为分组标题，提供成员数、进行中数量和展开入口；展开保留每次交付的原入口与状态。默认进行中突出符合筛选的活跃后继；已归档分组提示同组存在进行中调整，不把原始完成等同于整个目标永久完成。
- 规模、阶段、等待和能力筛选继续按各 Change 生效；详情深链接、任务与依赖视图保持可用。详情可查看直接前序及本组交付。
- 缺失、自指、成环或不可判定的延续关系显示明确提示，相关记录仍可独立查看；这些阅读关联不影响已有执行依赖或验收事实。
- 对用户指定的两个历史记录执行一次性关联迁移：只在 independent-clarification-budgets 的 JSON 增加 followUpOf，保留全部正文、任务、关闭记录和时间；迁移用普通提交记录，不新增通用归档编辑入口。

## 验收

1. 新建或修改 active Change 可用语义命令登记合法前序，非法目标、未归档目标、自指和循环拒绝且不写状态；旧记录缺失字段仍兼容。
2. 两个已归档 Change 在列表折叠为一个入口，可展开分别打开，直接深链接仍定位原记录。
3. 归档根存在进行中后继时，进行中可见后继，归档入口明确提示仍有调整；筛选不隐藏匹配后继或错误展示所有成员都匹配。
4. 同一前序的多个后继及多跳链可聚合；非法关系安全降级，取消成员保留真实状态，不合并任务进度或阶段。
5. 键盘可展开/收起并打开成员，窄屏无横向溢出；单独 Change 沿用现有布局。
6. 更新 SpecTrail 指引和当前 Specs，完成单元、命令、浏览器、类型与生产构建验证，独立评审通过后提供可验收交付。
