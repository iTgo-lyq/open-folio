# 延续关系与分组展示

基于 [需求](./requirement.md)，为 ChangeState 增加可选 followUpOf 字段，值为直接前序 id。沿用现有 JSON 版本，旧记录省略时行为不变；共享校验、工作台 schema 与类型同时接受字段，写入结构层拒绝非法 id，语义命令拒绝自指。读取时隔离格式错误的可选关联字段，保留独立关联提示；自指、缺失和循环同样作为关联提示，不抹除已完成的交付事实或使原执行依赖失效。

## 写入与历史迁移

create 支持 --follow-up-of；active Change 通过 follow-up 命令设置或移除关系。命令从协作入口定向读取已推送的前序，要求有效 completed 归档；沿前序关系检查缺失、无效与循环，写入走现有锁、原文核对和原子保存。followUpOf 不进入 dependsOn 或父子前置检查，不改变任务冻结、审批和归档规则。

历史迁移由本 Change 的明确授权覆盖，仅补 independent-clarification-budgets.followUpOf = technical-clarification。迁移前后对比除该字段外的数据、相关正文与前序记录完全一致，采用单独普通提交；不改变归档时间，不更新原验收结论，也不提供可任意改历史的命令。

## 阅读与分组

在工作台已有权威 Change 记录上解析延续图，与执行依赖图分开。可解析的前序边形成以根 Change 为入口的组，允许多个后继；对无法解析、未有效归档、自指或成环的边给出独立关联提示并停止该边分组，保留记录可见性。展示错误不改变交付的有效完成状态。

列表先按原范围与筛选选出匹配成员，再按完整图聚合这些成员。组头只保留独立分组标题，组内始终显示当前筛选匹配的原记录，详情可追溯其他成员；无展开状态、统计说明、当前记录说明和组级按钮。单成员无关联时保留原行。不合并阶段、任务、验收，不为分组增加流程状态。任务看板和依赖图仍按独立 Change 工作。

分组使用带标题的 section 和现有列表行，沿用 UI token 与列表样式。标题以背景遮罩嵌在外框上沿，增强字重与字号，长标题仍参与正常文档流；行分割线缩进，末行不画分割线，外框上下留白。窄屏保留内边距与自动换行。原 Change 详情深链接保持不变，在概览显示延续上下文。

## 独立分组标题

ChangeState 增加可选 followUpTitle，用于后继声明整个延续组的共同目标；不替换 Change.title，不要求改写归档前序。首次关联通过 create / follow-up 的 --group-title 写入，后续通常省略并从完整关系组继承，解除或更换关联时清除旧声明。命令拒绝无关联的标题和与前序已有声明冲突的标题；规则要求先读取组名，分叉也沿用已有名称。

阅读时在完整关系组中选取最靠近根的有效标题声明，同层按 id 稳定排序；筛选、成员状态和列表排序不改变组名。无声明的旧记录暂用根标题；格式错误的标题只产生独立提示，不破坏延续关系或交付完成事实。多个声明冲突时保留稳定标题并提示核对，不把显示冲突变成执行依赖。

本次按用户明确命名，只给 independent-clarification-budgets 追加 followUpTitle = 完善技术方案问询机制，以独立提交保留迁移证据；原字段、正文、时间均不变。

## 验证

命令测试覆盖已推送归档目标、active 写入和移除、拒绝非法关系不改文件。图与筛选测试覆盖多跳、分叉、缺失、循环、状态混合及范围筛选。浏览器验证分组记录直接可见、与普通记录的间距、活跃后继、规模筛选、深链接、键盘和 320px。完整类型检查、测试、生产构建与独立评审核对依赖隔离和历史迁移。
