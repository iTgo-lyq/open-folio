# 独立评审

评审使用独立 subagent，仅提供需求、技术方案、计划、差异基线和验证证据，未共享实现推理。基线为 `672e9f71932bfd7b743e8305f2dcc8ca19b5da13`。

## R1：前序有效性校验不一致

初次评审用临时 Git 远端复现：缺阶段确认、Plan 引用不存在任务、依赖不存在目标的归档均能登记为前序，但工作台不认为它们有效完成，导致关联登记后无法折叠。

命令复用关闭四步与任务顺序的公共判定，补齐阶段确认、规模形状、遗留活动目录、历史依赖、父子反向声明和循环检查；缓存定向读取结果。它只核实前序已有交付，不把前序加入当前 Change 的执行依赖，也不要求代码祖先关系。回归包含非法登记不改源文件、合法 medium 及含取消子项的已关闭父 Change。

复审补查出 cancelled 子项的错误关闭阶段也会影响父项完成状态。已将关闭阶段、步骤及时间顺序校验应用到所有历史状态，并增加取消子项含矛盾关闭记录的失败回归；定向关联测试 4/4 通过。

## R2：错误关联污染原交付事实

初次评审用真实 SnapshotStore 复现：有效归档增加非法 id 格式的 followUpOf 后，整个状态解析失败，依赖它的另一归档也失去有效完成状态。

读取端隔离错误的可选关联字段并保留 warning，正文及 JSON 原文不改写；分组层独立显示关联问题。回归覆盖字符串路径、数字、null 和同时损坏的原型关联，核对原记录与消费者仍有效完成、执行依赖仍满足。写入校验继续拒绝这些非法字段。
