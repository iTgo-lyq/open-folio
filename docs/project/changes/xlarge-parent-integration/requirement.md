# 让子 Change 先集成到 xlarge 父分支

## 目标与现状

用户预期 xlarge 的子 Change 优先合入父 Change 对应分支，父项完成整体集成后再交付到项目集成分支。当前 SpecTrail 虽要求父项有独立工作分支，却要求所有子项直接合入 `workflow.integrationBranch`，父项最后核对项目集成分支上的交付。父分支因此没有承载整体代码集成。

现有移交、PR 目标、合入核实、归档校验和来源读取均围绕单一项目集成分支实现，单独修改 skill 文字会使流程与工具不一致。本次按 medium 推进：改变父子 Change 共用的分支与交付契约，需要命令、CI 及读取端联动；围绕一个完整的父子集成流程交付。

## 目标行为

### 分支与规划

- xlarge 父项必须在编写 Plan 前拥有登记的独立工作分支；该分支同时承载整体规划、子项交付集成和父项关闭。
- 子项各自使用独立工作分支与 worktree。建立子项工作分支时以父分支的最新已推送版本作为代码基线，纳入该子项已确认的规划记录；交付 PR 的目标为父分支。
- 项目集成分支继续提供 Change 集中发现入口。登记子项时不得把父分支尚未整体交付的实现带入项目集成分支。
- 普通独立 Change 和 xlarge 父项的最终 PR 仍以项目配置的集成分支为目标，适用于自定义分支名。父子关系仍由 `parent / children` 表达，子项规模为 small、medium 或 large。

### 子项交付与依赖

- 子项独立完成验证、验收、Specs 同步和归档，再通过 PR 普通 merge 合入父分支；保留各子项自己的 PR 与合并提交。
- 同一父项内的后续子项，可以在所依赖子项已关闭并合入父分支、且交付已同步到自身工作分支后开始执行，无需等待父项进入项目集成分支。
- 子项合入父分支后，状态与材料仍可通过集中入口可靠定位；核实交付并满足安全清理条件后可清理子项分支和 worktree，不依赖永远保留子项分支。
- 子项已合入父分支即视为完成该子项的交付，之后的修正走后继 Change；未合入的归档仍可按原流程返修。取消项继续保留记录与冻结分支。

### 父项关闭与整体交付

- 父项关闭要求全部子项已完成或取消；已完成子项必须有合入父分支的可核实证据，相关交付在父分支可用。父项在该分支完成跨子项整体验证、验收、Specs 核对和归档。
- 父项 PR 向项目集成分支交付父项及其所属子项的归档与实现。校验允许这一完整交付集合，同时拒绝夹带无关新归档、关系不一致、未完成子项或目标错误的交付。
- 父项合入后，父子材料均从有效的集中归档读取。子项保留自己的合并边界；父项的合并边界用于整体交付，不覆盖子项证据。
- 来源清理按实际合入目标及所需记录的可读性判断；仍被活动或取消记录引用、尚有未合入成果或存在未保存现场的来源继续保留。

### 命令、校验与 OpenFolio 一致性

- skill、工作区命令、状态命令、合入与清理命令及 Setup 提供的 PR 校验使用一致的父子交付规则；CI 能覆盖以父分支为目标的子项 PR。
- OpenFolio 的来源读取、PR 关联、差异和交付判断适配这一流程。子项仅合入父分支时，不得显示为已进入项目集成分支或已发布；父项整体合入后能识别子项随之进入项目集成历史。
- 发布核实能够沿父子交付历史识别已整体集成的子项，保留发布分支仅由用户主动要求触发的规则。
- 已按旧规则直接合入项目集成分支的历史子项，继续按真实 PR 与 Git 证据读取，不改写历史归档或重新制造合入记录。已有活动子项如需改目标，先核对其实际合入事实和父分支；本次不批量操作其他 Change 的分支或 PR。

## 验收

1. 在配置自定义项目集成分支的隔离仓库中，建立一个 xlarge 父项及两个有依赖关系的子项；子项移交继承父分支的已推送交付，集中登记不会泄漏父项实现。
2. 第一子项归档后能通过 PR 校验并合入父分支；其 PR 错指项目集成分支或其他父分支时被拒绝。父项缺失、未移交、已取消或父子关系不一致时给出明确诊断。
3. 第二子项在同步第一子项交付后可执行；第一子项未关闭或交付未纳入当前分支时拒绝执行。该过程不要求父项先进入项目集成分支。
4. 子项合入父分支并安全清理其来源后，CLI 与工作台仍可读取子项归档及 PR 证据；工作台不提前将其计为已进入项目集成分支。
5. 父项有未结束或未合入的子项时不能完成整体交付；全部满足后，父项 PR 可携带父子归档一次合入项目集成分支，无关新归档仍被拒绝。
6. 父项合入后，CLI、工作台与发布核实能识别父子交付；父子各自 diff 仍对应各自合并提交，删除来源分支不丢失材料或证据。
7. 普通 Change、取消、未集成归档返修，以及旧规则下已交付的历史子项通过回归验证；技能校验通过，发布时同步递增技能补丁版本。
