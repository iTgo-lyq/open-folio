# 修复原型截图登记并补齐卡片验收

「Change 澄清问答」原型已在 2026-10-15 生成并上传三种设备截图，但当前总览显示「尚未提供截图」。原发布请求以页面目录为产物根目录，截图与 index.html 同级；R2 适配器按入口 id 拼接子目录，漏掉了 thumbnails 引用。现有截图已确认可公开读取。

用户明确要求补齐该原型截图引用、修正发布脚本路径判断，并将发布后的卡片截图展示纳入验收。本次为 small：仅修复现有发布适配器、当前清单及验证约定，不改变协议或产品界面。

## 行为与方案

- R2 发布按 entryPath 所在目录识别标准设备截图，支持以单页面目录发布、普通多页面目录，以及目录名称与入口 id 不同的情况；仅登记实际包含在已校验产物中的图片。
- 复用已发布固定版本的截图，补齐 clarification-detail 当前清单的桌面、平板、手机引用；记录本次修复的固定预览，不改写原 Change 归档或覆盖远端产物。
- 项目原型发布约定要求发布前生成声明设备截图，登记后核对引用，并在刷新后的工作台总览逐设备确认图片加载成功。页面可打开、原型交互通过或上传成功不能替代卡片截图验收。

## 验收

- 发布回归测试覆盖单页面根目录、目录与 id 不同、多入口隔离及原有目录布局；未提供截图时不误登记其他入口图片，已有不可变发布校验继续通过。
- 当前 clarification-detail 三种设备引用均指向原固定版本可读取的 PNG，版本、源码提交、摘要保持不变。
- 浏览器验证卡片图片实际加载完成（naturalWidth > 0），桌面、平板、手机切换均无「尚未提供截图」或「截图暂不可用」占位，并可进入原型页面。
- 在 develop 集成后完成真实工作台刷新与卡片冒烟，测试登录结束后撤销本次会话并核验结果。
