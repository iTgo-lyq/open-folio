# 技术方案

按 [需求](requirement.md) 将协作分支作为接入输入，而非从另一个分支发现。保留每个凭据工作台的仓库发现记录，增加明确的协作分支选择；自动发现初次建议 develop，手动仓库检查允许覆盖。重新发现沿用已保存选择，阅读位置及偏好携带选择，后台逐次授权仍按稳定仓库身份和当前凭据检查。

GitHub 适配器在明确分支引用上读取 workflow，不借托管默认分支检查内容权限。GitReader 只精确查询协作分支、集中登记的工作分支和必要归档标签，发布快照前复核协作配置和路由。保护分支名只作发布策略元数据，不影响读取路由。协作分支选择进入缓存身份/有效性判定，防止切换来源后交付旧快照；不清理用户凭据和偏好。

共享 workflow 校验只接受版本 2 和合法 collaborationBranch，删除 CLI 的 legacy 分支及旧版迁移执行入口；保留当前 Change schema 及归档只读规则。手工接入旧仓库须先配置当前协议，再运行检查，不自动推导或扫描旧工作。保护分支的发布限制保留在写入与合码规则。

测试覆盖任意协作分支、无默认入口、无保护引用、错误/旧版配置、来源切换与并发、权限拒绝及集中目标读取。更新共享脚本的现有测试与 hook 集成验证，进行类型检查、浏览器交互和生产构建；独立 Codex 评审后归档集成，更新主工作区长期服务并做真实认证冒烟。不调用 iclaude。
