# 执行证据

## T1 接入与读取直接使用指定协作分支

接入表单允许指定协作分支，推荐初值为 develop；按凭据工作台和稳定仓库身份保存选择，重新发现、分享链接、最近仓库偏好和原型准备请求均保留来源。GitHub 内容权限使用选定分支的匹配引用接口并严格匹配完整 ref：缺失分支不冒充失权，前缀相近分支不被误选。接口语义依据 [GitHub Git references 文档](https://docs.github.com/en/rest/git/refs#list-matching-references)，另有 mock 与真实服务冒烟验证路径。

采集只读取所选协作分支、登记目标和精确归档标签。默认分支配置、HEAD 指向与保护引用存在性不参与来源判定；保护分支只保存策略元数据。不同协作分支的 Git 缓存、快照和共享刷新任务按摘要隔离；切换来源取消旧前端代次，旧响应不能恢复旧正文。旧快照与发现结果重新建立，不迁移旧通配 fetch 配置。

验证：`npm test` 206/206；应用与 UI `npm run typecheck` 通过；`npm run build` 通过；Prettier 全范围和 `git diff --check` 通过。浏览器覆盖 16 个不同用例：自动刷新、集中入口、分享、凭据工作台和两项自定义来源用例。首轮 15 项通过；一项新增测试错误地期待恢复具体 Spec，而现有约定只恢复仓库与模块，修正断言后两项自定义来源测试 2/2 通过，产品代码未因此改变。自定义来源覆盖接入、重新发现、跨 token 分享、同 token 新设备恢复、原型准备和晚到旧响应。

## T2 移除旧版工作流兼容并统一 Skill 规则

共享校验、状态命令、Hook 与 Setup 只接受 workflow v2；删除现代/旧版分流和默认保护基线推导。Change 与原型清单本身的 schemaVersion 1 保留，登录数据格式不属于本次删除范围。已配置项目的只读入口检查仍可用于核对已知工作；旧配置须先补齐当前协议。保护分支的写入与主动发布约束保留。

测试夹具改用当前配置、真实协作入口和 workspace handoff，保留状态、时间、任务顺序、依赖、原型发布及归档覆盖；另验证自定义协作名和旧配置拒绝。独立验证：状态/路由 27/27，最终自定义分支与版本拒绝定向 5/5，原型契约与工具 12/12，原型发布 7/7。Setup/hook 集成 12/12；主 Skill、Setup、Prototype 三项 quick_validate 通过。

通用 Skill 使用项目实际配置的协作分支，develop 为推荐名称；本项目 AGENTS 中固定 develop 与主工作区 .next 的部署约定继续适用。同步主 Skill、Setup、工作区说明、原型 Skill、README 和相关 Specs。独立评审结论见 [Review](review.md)。

主工作区长期服务按用户授权在归档合入 develop 后更新，实际运行提交与部署结果以服务 runtime-version 和本次会话最终报告为准。
