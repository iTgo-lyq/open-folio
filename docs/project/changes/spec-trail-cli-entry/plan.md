# SpecTrail CLI 实施计划

依据 [需求](requirement.md) 和 [技术方案](technical.md)，交付统一的项目内入口及全部当前调用方。

## T1 统一入口和 Change 工作流

通过 `cli.mjs` 提供总帮助、分组帮助和命令帮助，接通 Change、工作区、集成及分享命令。复用现有结构化结果和状态检查逻辑。同步相关参考文档与测试中的实际命令调用。

验收覆盖无项目目录查看帮助、未知命令和参数、缺少必填参数、分享链接、工作区定位、Change 只读与实际写入，以及 dry-run 的无写入行为。运行现有状态、路由、集成与分享回归测试。

## T2 原型和维护命令输出 JSON

接通原型配置、发布与校验及版本和归档标签维护命令。统一操作结果，处理原型脚手架的子进程输出，更新原型使用示例。

在临时仓库执行原型配置或初始化、静态校验和发布请求准备，直接解析各自的 `stdout`。运行已有原型发布、子模块、版本和标签维护测试。标签操作使用测试仓库及本地远端。

## T3 通过统一入口接入项目校验

接通项目准备检查、路由预览、提交钩子和 PR 归档检查。切换 OpenFolio hook、归档 workflow、接入模板及相关文档。检查文档、示例和自动化中的当前调用。

用临时 Git 仓库实际触发 hook，覆盖成功、拒绝和部分提交。用 PR 事件夹具通过 CLI 验证拒绝未归档 Change、接受有效归档。检验接入检查的只读行为、建议命令和返回码。

## 整体验证

- 按仓库约定在修改 skill 的提交中同步 SpecTrail 与 OpenFolio 版本。
- 在 Node.js 20 和 24 验证帮助及非原型基础命令，在 Node.js 24 验证原型命令。
- 运行 skill 内的 setup、更新、版本测试及项目测试，使用现有测试覆盖流程行为，补足统一入口特有的参数、退出码、帮助和 stdout JSON 回归。
- 核对主 skill、子 skill、参考文档、项目示例、Git hook 和 PR CI 均已改用统一入口。归档后检查同一 PR 的 `SpecTrail archive` 状态。
