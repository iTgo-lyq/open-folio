# SpecTrail CLI 实施计划

依据 [需求](requirement.md) 和 [技术方案](technical.md)，交付统一的项目内入口及全部当前调用方。

## T1 统一入口和 Change 工作流

通过 `cli.mjs` 提供总帮助、分组帮助和命令帮助，接通 Change、工作区、集成及分享命令。复用现有结构化结果和状态检查逻辑。同步相关参考文档与测试中的实际命令调用。

验收覆盖无项目目录查看帮助、未知命令和参数、缺少必填参数、分享链接、工作区定位、Change 只读与实际写入，以及 dry-run 的无写入行为。运行现有状态、路由、集成与分享回归测试。

## T2 原型和维护命令输出 JSON

接通原型配置、发布与校验及版本和归档标签维护命令。统一操作结果，处理原型脚手架的子进程输出，更新原型使用示例。

在临时仓库执行原型配置或初始化、静态校验和发布请求准备，直接解析各自的 `stdout`。运行已有原型发布、子模块、版本和标签维护测试。标签操作使用测试仓库及本地远端。

## T3 通过统一入口接入项目校验

接通项目准备检查、路由预览、提交钩子和 PR 归档检查。切换 OpenFolio hook、归档 workflow、接入模板及相关文档。检查文档、示例和自动化中的当前调用。

用临时 Git 仓库实际触发 hook，覆盖成功、拒绝和部分提交。用 PR 事件夹具通过 CLI 验证拒绝未归档 Change、接受有效归档。检验接入检查的只读行为、建议命令和返回码。

## T4 帮助一次给全并精简提交钩子输出

验收返修，关联 T1 的帮助和 T3 的提交钩子。在命令定义中补充每个命令的用途、参数取值与说明、约束及示例，生成三级帮助，并由入口校验固定取值。OpenFolio hook、Setup 示例和检查器建议命令丢弃成功 JSON。同步主 skill 与 Setup 文档。

在 Node.js 20 和 24 上，于无仓库目录检查三级帮助的内容和退出码；测试覆盖每个参数都有说明、固定取值报错列出可选值。用临时仓库通过实际 hook 提交，确认成功时无 `stdout`、拒绝时有 `stderr` 诊断。运行 CLI 与 Setup 回归。

## T5 隔离服务管理测试的 tmux 环境

用户在验收时追加的修复。服务管理测试改用独立 tmux server，并在结束时关闭它，`scripts/service.mjs` 不变。

在本机沙箱、且存在外部 tmux server 的条件下运行该测试并通过；运行后确认默认 tmux server 上没有遗留的测试会话。

## T6 修正独立评审发现的帮助与测试隔离问题

评审返修，关联 T4 与 T5。帮助文案改为与实际行为一致：`prototype recover` 是回滚中断的登记；`integration cleanup` 需要完整提交号；浏览器校验在默认视口逐个加载入口；change 分组除 `change.json` 外还会移动目录或更新暂存区；依赖约束由 `execute` 检查；各原型接入参数分别适用于哪些命令；small 只记录 merge 确认。接入检查器同时核对 `groups` 导出。测试新增一项：按定义解析每个命令的示例，确认示例可直接运行。服务测试的私有 tmux server 改用短路径、不加载用户配置，并在启动前注册清理。

运行 CLI 与 Setup 回归，在 Node.js 20 与 24 下检查帮助。服务测试在沙箱内、`TMPDIR` 较长时、宿主环境各运行一次，并确认默认 tmux server 上没有遗留。

## 整体验证

- 按仓库约定在修改 skill 的提交中同步 SpecTrail 与 OpenFolio 版本。
- 在 Node.js 20 和 24 验证帮助及非原型基础命令，在 Node.js 24 验证原型命令。
- 运行 skill 内的 setup、更新、版本测试及项目测试，使用现有测试覆盖流程行为，补足统一入口特有的参数、退出码、帮助和 stdout JSON 回归。
- 核对主 skill、子 skill、参考文档、项目示例、Git hook 和 PR CI 均已改用统一入口。归档后检查同一 PR 的 `SpecTrail archive` 状态。
