# Change 合入历史执行计划

按 [Requirement](requirement.md) 与 [Technical](technical.md)，交付“归档后一次合入，删除来源后仍可回看整体 diff 与原型”的完整路径。沿用 T1 → T5 串行推进；每项包含实现、对应验证及必要文档，验证后提交推送。

## 实施准备

计划与“合入变更”交互原型确认后，从最新 develop 建立本 Change 的独立工作分支、worktree，并登记来源。原型使用现有包和 custom 托管，覆盖桌面、iPad、手机及 320px 窄屏；其示例数据不接入真实仓库。

[打开交互原型](https://pub-cc623a99ce8e4606a3491cc2d4b4436c.r2.dev/open-folio/f31e062b0c4c6eb4283be8829854e2a2c56655dd396401e7d2cb260cf441b10f/index.html)。顶部场景选择仅用于审阅；可检查文件切换、归档移动、展示限制和读取异常。

复用当前 GitReader、授权入口、快照和测试设施。T1–T4 在任务工作区验证，不提前启用新归档规则或清理真实来源；新旧读取方式的正式切换集中在最终交付。

## T1 · 识别并校验唯一的 Change 合入记录

**交付**：CLI 与服务端共用合入协议识别；固定协作 tip，建立 first-parent 索引，返回 found / missing / invalid / unavailable。将索引纳入同边界快照及一致性判断，不写回 Change。

**验收**：唯一、合法的双亲 M 关联正确；重复标记、归档子树不一致、多 Change 混入及不可读历史分别报告。删除源分支后仍可识别，其他正常 Change 可继续阅读。对应 A1、A2、A7、A8。

**验证**：复用临时 Git 仓库与 bare 远端，构造可快进和分叉提交图；从只拉协作分支的新缓存复查身份与状态，验证快照刷新和历史不完整场景。

## T2 · 生成正式合入并安全清理交付来源

**交付**：集成入口提供预检、推送源交付、生成并推送 M、远端核实及继续清理；逐对象输出结果。清理依据有效 M 和来源实际状态，支持执行到一半后恢复。

**验收**：可快进仍生成 M；并发推进时重建未发布候选，响应未知先查询远端。新增源提交、脏文件、未知忽略文件、有效依赖或占用阻止相应删除；保护主工作区、协作/保护分支和持久数据。清理失败不重复集成。对应 A1、A5、A6、A8、A10。

**验证**：在临时远端和多 worktree 中完成真实推送与删除，注入推送拒绝、响应丢失、tip 变化及部分失败。核对最终提交图、保留内容和逐对象结果；真实项目仅做只读预检。

## T3 · 在工作台阅读 Change 整体合入差异

**交付**：授权后的合入摘要、分页文件清单和单文件 diff；详情新增“合入变更”页签，按已验收原型实现文件选择、固定提交展示、窄屏阅读和反馈。

**验收**：内容等于 `git diff M^1 M`，包含归档移动和全部目录；特殊文件、不可展示和超限明确标识，统计不冒充完整。正常空态、无效记录与读取失败有区别，切换 Change/快照不串用旧响应。对应 A2、A3、A7、A10。

**验证**：Git fixture 对照文件集合与文本；沿用授权测试检查失权、伪造 fileId/cursor 和跨仓库读取。浏览器覆盖选文件、重试、键盘、直接链接、前进后退及声明视口。

## T4 · 以合并提交定位历史原型

**交付**：集中归档从 M 读取 previews，Git HTML 固定至 M；hosted 保留原版本、地址、摘要、截图和源码提交。活动及未合入来源继续使用已推送的固定 SHA，项目总览与公开发布沿用现有入口。

**验收**：删除来源与标签后，新 Git/hosted 交付仍可准备及分享；无有效关联的旧归档留空，不通过显式 revision 绕回旧逻辑。原有公开版本、当前总览和活动预览可读。对应 A4、A7、A8、A10。

**验证**：覆盖两种产物、固定版本请求、sourceCommit 保真及来源切换；用新的协作分支缓存验证独立于源分支和标签，检查已有公开内容的读取。

## T5 · 完成标签退出与完整交付演练

**交付**：统一更新主/原型 skill、命令提示和发布说明，停止创建保留标签；提供精确标签及旧缓存引用的清理能力。用临时仓库串起归档、合入、删除来源、重建缓存、阅读 diff 和原型的完整演练。

**验收**：完整链路满足 A1–A10；旧关联无兼容回填，旧正文正常，清理仅针对目标命名空间和可重建缓存。演练说明真实切换顺序及遗留处理，实际标签删除在新服务生效后执行。

**验证**：检查旧标签生成/读取路径退出，运行相关回归、类型检查与构建；对临时仓库重复清理和重新读取，核对保护对象及公开发布不受影响。

## 整体验证与交付

完成独立评审并修复实质问题后，提供完整演练证据和工作台效果供用户验收。各模块已通过的检查不无故重复；新增修改按影响补测。执行证据按任务写入 execution.md，评审问题及复验写入 review.md。

验收后同步 workflow、Change tracking 与 prototype preview Specs，提交归档并推送源分支。以新协议生成本 Change 的 M，推送并核实远端，再安全快进主工作区、更新长期服务，完成独立登录冒烟与会话退出复查。

新服务验证成功后，重新核对并清理精确旧标签、旧缓存引用及本 Change 的可清理来源；保留受占用或含未保存资料的工作区并报告原因。真实切换结果写交付报告，不回填已归档文档。保护分支发布不包含在本计划中。
