# 执行记录

## T1 · 识别并校验唯一的 Change 合入记录

新增 CLI 与服务端共用的零依赖合入识别模块：固定协作 tip，分批扫描 first-parent 历史，仅识别末尾精确 trailer；校验唯一标记、双亲关系、单一新增归档和源/合并归档子树一致。删除源分支不影响读取，部分对象读取失败与正常缺失分别返回。

快照升级至 schema 6，纳入合入索引及一致性判断；相同 tip 的有效索引可复用，暂不可读的候选会重试。旧标签字段暂供现有原型读取使用，在 T4/T5 统一退出，不形成最终双读兼容。

验证：合入记录、增量缓存、集中路由及 Store 共 22 个用例通过；补充同 tip 下临时失败恢复后，合入记录专项 6 个用例通过。用例使用临时 bare 远端、真实合并及来源删除，覆盖重新建立协作分支缓存、重复标记、错误父提交、归档改动、多 Change 混入与历史读取失败。类型检查通过。

## T2 · 生成正式合入并安全清理交付来源

新增集成命令的 preflight、merge、cleanup 入口。以共享仓库锁串行操作，先推送固定归档来源，再从远端最新协作提交生成并校验双亲合并；推送后重新查询主链。并发拒绝从新的第一父提交重建候选；响应丢失查询已有结果，冲突或核实失败保留候选现场。

清理从远端有效 M 读取历史归属，独立报告远端分支、worktree、本地分支的结果。校验保护分支、主工作区、集中路由依赖、祖先关系、占用声明、Git 操作及全部未保存/忽略文件；未知忽略文件由 Agent 区分资料与可重建产物后再试。远端采用预期 tip 条件删除，worktree 和本地分支使用非强制删除；部分失败重试不重复合入。

验证：6 个真实临时仓库用例通过，覆盖可快进合并、并发重建、推送响应丢失、私有忽略文件/脏文件/占用/共享入口保护、新提交与远端删除竞争、部分清理后的恢复。类型检查通过。真实仓库仅执行 preflight，当前 Change 尚未归档，正确拒绝集成；未推送合并、未删除任何真实来源。

## T3 · 在工作台阅读 Change 整体合入差异

新增授权后的摘要、分页清单和单文件差异接口，固定快照派生 M/B；fileId 回查提交对，cursor 绑定快照与提交对。清单和统计用 NUL 分隔，保留原始文件名字节用于关联，界面转义不可见字符；通过固定 blob 读取正文，不将任意路径或 base/head 交给 Git。二进制、非 UTF-8、LFS、子模块、符号链接、mode-only 和大小/行数限制分别说明，不跟随外部内容。

“合入变更”页签按已确认原型接入，包含固定 SHA/命令复制（含手动兜底）、文件选择、分页、统一差异及行号。详情宽度随页签调整，窄屏在列表/正文间切换；URL 保存文件选择与视图，支持前进后退和页签键盘导航。请求按仓库/Change/快照隔离，旧响应不跨记录呈现。

验证：3 个服务端真实 Git/API 用例通过，覆盖所有目录、归档重命名、特殊及非 UTF-8 文件名、展示限制、分页、伪造参数、跨连接快照及失权后的 GET/HEAD 拒绝。2 个浏览器场景通过，覆盖删除来源后读取、直接链接、前进后退、复制失败兜底、读取重试、过期响应，以及桌面/iPad/390px/320px。检查桌面与 320px 截图，布局与原型一致；截图保存在本 worktree artifacts/integration-*.png。类型检查通过。

## T4 · 以合并提交定位历史原型

集中归档的原型从唯一有效 M 读取，显式 revision 也必须等于 M；缺失关联显示正常空态，异常记录保留诊断。活动或仅在登记来源归档的 Change 沿已推送来源读取固定 SHA。Git 原型从 M 的归档快照读取；hosted 的 version、url、digest、thumbnails 和 sourceCommit 原样保留。原有公开版本继续由持久发布记录服务。

移除快照中的 archiveRefs/archivePins 和旧标签查询/拉取逻辑，更新扫描 fingerprint。单个合入标记异常不再误使整个项目的原型策略失效。集成清理校验复用原型入口契约，验证目录内的 index.html，而不是将入口目录当成文件。

验证：原型及新合入发布专项 12 个用例通过，覆盖 Git/hosted、删除来源及标签后冷缓存读取、sourceCommit 保真、旧公开版本继续访问、合入后拒绝旧源 revision、重复记录诊断、旧标签/显式 revision 均不能恢复旧关联；集中路由、增量缓存和集成清理相关回归此前 16 个用例通过。类型检查通过。真实服务和标签尚未切换。

## T5 · 完成标签退出与完整交付演练

主 skill、原型 skill、命令参考和 README 统一到单次合并提交交付；删除旧保留标签生成脚本。归档命令将 Git HTML 固定到本 Change 的快照目录，保持 sourceCommit；xlarge 父项先从协作分支移交独立关闭分支，再生成自己的 M，其 diff 不重复已交付子项。

新增精确旧标签清单及条件删除命令，核对仓库身份、命名空间与预期对象，逐项报告并发变化或失败；缓存刷新在写锁内删除旧专用引用，新快照发布成功后淘汰旧标签快照。公开原型、当前清单和用户持久数据不参与清理。

临时仓库完整演练已覆盖语义归档 → 推送来源 → 单次合并 → 核实并清理远端/工作区/本地分支 → 冷缓存重建 → 阅读整体 diff 与原型 → 退出旧标签及旧缓存；重复执行可恢复，非目标标签与引用保留。独立评审发现的共享 HTML 固定、索引隐藏修改及部分复制回滚问题均已修复，见 [Review](review.md)。

验证：最终 `npm test` **246/246 通过**；`npm run typecheck`、`npm run format:check`、`npm run build` 及两个 skill 的 quick_validate 检查通过。相关五组浏览器测试共 **26 个通过**：首次 24 个通过，另两个因新增归档 fixture 数量及预览错误文案变化而调整断言，定向重跑 2/2 通过。最终协议/清理修正另经完整 Node 回归及独立复验，不重复无关浏览器测试。

生产构建位于任务 worktree 的 `.next`；主工作区与长期服务未切换。真实旧标签、原始分支和本地工作区均未清理。本次切换的剩余动作按 Plan 在人工验收后执行：同步 Specs、归档推送、生成 M、安全快进主工作区、更新服务及独立登录冒烟，最后清理精确旧标签和安全可删来源。
