# Change 合入记录、整体 diff 与来源清理

## 技术目标与现有接点

以远端协作分支的 Git 历史作为交付事实来源。SpecTrail 负责生成和验证合并提交，OpenFolio 使用同一识别规则派生合入记录，diff 与历史原型均固定到该记录。分支和标签不承担归档索引职责。

复用现有集中 Change 路由、共享状态校验、GitReader、仓库权限入口和 Store 快照；增加合入协议校验及 diff 读取能力。共享规则放入 SpecTrail 自带的零依赖模块，由命令行和服务端调用，避免两端对“有效合入”的理解不同。仓库现状和 iclaude 讨论结论见 [Research](research.md)。

不修改 `change.json`、workflow 或原型 artifact 的持久化契约。OpenFolio 的可重建快照允许升级并重建，不增加旧标签兼容层。

## 1. 合入提交协议

### 提交形态

固定三个提交：`B` 为本轮合入前远端协作分支提交，`S` 为已归档并推送的源提交，`M` 为合并结果。

```text
M 的第一父提交 = B（协作分支合入前）
M 的第二父提交 = S（已归档的 Change 交付）
整体 diff     = git diff M^1 M
历史原型      = M 中的归档记录及产物
```

从 `B` 创建候选，用 `--no-ff` 形成恰有两个父提交的普通 merge。提交信息格式为：

```text
Merge Change <id> into <collaboration-branch>

SpecTrail-Change: <id>
```

标题供人阅读；只解析提交信息末尾 trailer 区域中精确的 `SpecTrail-Change` 键，值必须是合法 Change id。一个提交只允许一个该键，不能用标题包含、分支命名或正文提及匹配。同步协作分支、内部任务合并和普通文档检查点不写此标记。

### 有效性条件

以已拉取并核实的远端协作分支 tip 为边界，只沿其 first-parent 链查找。对相同 id 收集所有标记，重复时诊断，不取最新一个掩盖异常。候选必须满足：

1. 恰有两个父提交，且 Change 标记唯一、合法。
2. `M` 内有且仅有该 id 的有效 completed 归档，关闭各步、归档目录和 `closure.archive.path` 一致；该 id 不同时残留于 changes。
3. `M^1` 尚无该 id 的归档；相对 `M^1`，`M` 新引入的归档 id 集合恰为此 id，拒绝一次携入多个交付。
4. `M^2` 内具有同一有效归档，整个归档子树的 tree identity 与 `M` 一致，包括正文、状态、证据和 Git 原型快照。不可在合入时修订归档。
5. 两个父提交及校验所需对象均可读取。对象缺失或 Git 失败属于读取错误，不转换成“暂无合入记录”。

上述验证只依赖 `M`、`M^1`、`M^2`，不依赖 `change.json.branch` 当前是否存在或是否仍指向原提交。原型 sourceCommit 另按既有产物规则校验，不参与猜测合入记录。

合并记录描述历史事实。之后的回滚或替代交付不会让该记录自动消失，也不根据提交标题推断“已撤销”状态。配置的协作分支历史是索引边界，本次不提供跨协作分支自动迁移映射。

## 2. 识别与派生缓存

刷新时先固定协作 tip，拉取其完整可达历史，按 first-parent 分批读取提交元信息；只对带标记候选读取归档树并校验。默认不扫描所有远端分支或所有标签。已有 active Change 的定向分支读取保留。

初次建立索引完成后，可在新 tip 的 first-parent 链包含旧 tip 时只追加区间；否则重建。历史缓存以仓库身份、协作分支、tip 和协议版本为键，可丢弃重建。历史不完整时继续获取必需对象；达到现有读取时限或资源限制后返回未完成诊断，不能因扫描截断断言记录不存在。

派生结果为 `found / missing / invalid / unavailable`：

| 结果 | 含义 | 工作台处理 |
| --- | --- | --- |
| found | 唯一且通过校验的记录 | 返回 M、两个父提交、归档路径、标题、提交时间 |
| missing | 对固定 tip 完成扫描，未找到对应标记 | 显示“暂无合入记录” |
| invalid | 有重复标记或不满足协议的候选 | 显示具体诊断和可识别的候选提交 |
| unavailable | 历史或校验对象暂不可读取 | 显示读取失败及重试入口 |

将结果挂到快照派生数据中，不写回仓库文档。升级快照 schema 与扫描 fingerprint，替换当前 `archiveRefs`、`archivePins`；老快照失效后重新读取，失效链接提示刷新。新的合入结果即使工程文档树没有变化，也必须进入快照一致性判断。

快照的协作 tip、文档和合入索引采用同一边界；远端并发推进时固定当前完整快照，或重新拉取后整体重建，不拼接两个 tip 的结果。重复标记等异常局限于受影响 id，其他 Change 文档继续可读。索引整体不可用时各 id 不冒充 missing。

## 3. 整体 diff 的读取与呈现

### 接口与权限

沿用仓库只读 API 的会话、connectionId、仓库身份、协作分支和权限复验。新增以下相对接口：

| 读取入口 | 内容 |
| --- | --- |
| `changes/<id>/integration?snapshot=<snapshot>` | 关联状态、固定合并提交、时间、差异统计与文件总数 |
| `changes/<id>/integration/files?snapshot=<snapshot>&cursor=<cursor>` | 分页文件清单，含稳定 fileId、旧/新路径、变更类型、增删行和可展示性 |
| `changes/<id>/integration/files/<fileId>?snapshot=<snapshot>` | 单文件 diff、行号及展示限制 |

客户端不传任意 base/head 或任意路径，服务端从该快照的有效合入记录派生固定提交对，fileId 从提交对和原始路径生成并回查清单。页码游标绑定快照与提交对，过期或串用时明确要求刷新。

不经 GitHub PR API，也不把私有 diff 发往匿名原型接口。每次读取沿用现有仓库授权，不因 SHA 已缓存绕过权限检查。

### Git 差异与限制

采用两端 tree diff：`M^1` 到 `M`。禁用 external diff 与 textconv，不运行仓库配置中的外部工具，路径采用参数数组和字面 pathspec。文件清单与统计使用 NUL 分隔结果，保留含空格、制表符、换行及 Unicode 的真实文件名；显示时转义控制字符。

固定 Git 重命名识别策略，清单、统计和单文件 diff 使用一致选项。归档目录移动按真实差异呈现，可识别的移动不重复展示为整文件删除再新增。增删数对二进制、子模块和不可统计项为不可用，不伪填零。

列表分页，正文按选中文件加载，默认统一 diff、三行上下文，保留新旧行号。文本只作为文本渲染。二进制、非 UTF-8、LFS 指针、子模块、符号链接及 mode-only 变化分别标识；不展开指针背后的外部资源，不跟随符号链接。

单文件展示初始上限为 1 MiB diff 文本或 10000 行；超过任一上限显示“内容过大，未完整展示”，保留文件名、类型和可获得统计，并给出复制固定 Git 比较命令的入口。分页清单须能遍历全部文件；若 Git 读取触发整体资源限制，显示错误或不完整状态，不伪造完整统计。限制属于服务端参数，后续可按验证结果等价调整。

### 详情交互

在 Change 详情增加 `ct=integration` 的“合入变更”页签，保持现有概览、任务、文档、原型、依据入口。顶部显示时间、短 SHA 和汇总；文件列表支持选择，正文显示当前文件差异；窄屏可切换列表与正文。复制 SHA 时使用完整值。

正常空态、读取失败和非法记录分别呈现。切换 Change、快照或仓库时清空旧的请求结果，避免显示另一任务的 diff。直接链接、刷新、浏览器前进后退和键盘操作沿用现有详情交互。

该页签包含新的列表与差异阅读区域；进入对应产品实现前，使用项目已有原型包准备可审阅原型并验收。本轮仅描述布局、状态和交互，不制作或发布原型。

## 4. 历史原型切换

| 来源场景 | 定位规则 |
| --- | --- |
| 已合入且 found | 固定 revision=M，从 M 的归档读取 previews；Git HTML 也从 M 读取 |
| 集中归档但 missing | 无法定位的旧交付显示空态，不使用标签、当前 tip 或 sourceCommit 替代 |
| 合入记录 invalid/unavailable | 展示诊断，不回退至工作分支 |
| 进行中或仅在所属工作分支归档 | 从已核实的登记分支固定 SHA 读取，并维持现有来源与产物校验 |
| 项目当前原型总览 | 从当前协作清单读取，沿用现有规则 |

已合入 Change 的新准备请求始终以 M 为交付 revision。旧请求不能仅凭某个任意祖先 SHA 可达就绕过交付定位；无有效 M 的集中旧归档不因显式传 revision 恢复旧标签逻辑。

hosted 的 version、url、digest、thumbnails 和 sourceCommit 原样读取。Git HTML 使用 M 中归档路径对应的字节；archive 子树一致校验证明其未在合入时改变。已准备公开版本仍由现有持久发布记录服务，不重新依赖 Git，也不为此次切换删除已有发布。

清理前验证引用结构、Git 文件及源码对象可读；外部托管仍由宿主承担版本留存。OpenFolio 不新增服务器代理抓取第三方资源的行为，浏览器预览与发布适配器承担既有的实际可用性验证。

## 5. 交付命令与自动清理

### 形成并推送 M

增加 SpecTrail 的集成入口，接受 Change id、只读预检和继续清理操作。它复用仓库配置、精确远端查询与仓库锁，输出结构化的合入、远端核实和清理结果；不使用任意 JSON patch，也不新增流程事实文件。

1. 在归档前同步最新协作分支，解决需修改交付的冲突并验证。归档提交后不再修改归档。
2. 核实 source 中已关闭的唯一目标、实际交付范围和工作区状态；推送工作分支，查询远端确认固定 S。
3. 获取最新远端 B；在隔离候选中从 B 合并 S，生成双亲 M。工作区无关改动不能被纳入。只有目标 Change 的新归档随本次进入协作历史。
4. 验证协议、合入结果及相关测试。存在需要改变已归档交付的实质冲突时，停止受影响集成，按新 Change 处理；不恢复旧归档为 active。
5. 普通推送 M 到协作分支，查询远端并核对 M 位于其 first-parent 链。远端可能已继续前进，无须要求 tip 恰好等于 M。
6. 完成主工作区的安全快进和项目要求的服务更新，再从主工作区或其他明确不待删的位置协调清理。

若 B 在推送期间被并发推进且推送被拒绝，重新读取远端：已存在同 id 的有效 M 时复用；否则从新的 B 重新生成尚未发布的候选并复验。不能在旧候选上追加“合并远端协作分支”，否则会让其他交付落在 second-parent 历史中。协作分支不 force push。

网络错误导致推送结果未知时，先查远端，不立即重建或删除。源提交已通过非标准路径提前合入而没有合法记录时报告不支持的状态，不伪造补合并。

普通 Change 使用自己的交付分支。仅承担规划的 xlarge 父项也须在最终归档前转入独立关闭分支形成 S；父项 M 只表示父项自身的交付，不聚合子 Change diff。各子 Change 分别保留自己的合入记录。

### 清理条件与顺序

仅在远端已验证的 M 存在、交付与原型读取前提成立后进入清理。再次读取源分支 tip，要求本地及远端待删提交均已包含于 M，不能仅因 id 归档就删除后来追加的工作。

沿用集中路由核对其他 active/cancelled Change 的有效来源；继承的旧规划副本不算新增依赖。保护主工作区、协作分支、保护分支及用户持久数据。worktree 必须与仓库、登记分支和路径匹配，不能按目录名称猜测。

执行位置先移出待删 worktree。Agent 通过实际客户端和服务状态确认没有继续写入的会话或服务；脚本检查 Git 操作锁、worktree 登记和文件状态。无法确认占用时保留本地现场，不能假设普通文件系统检查能证明所有会话空闲。

未提交、未跟踪和未知忽略文件阻止删除。已知可重建依赖与构建产物按项目约定处理；包含独有环境配置或资料的 worktree 保留，不能把所有 ignored 内容当作缓存。正常 Git 删除不使用强制 worktree 移除或无条件强删分支。

完成预检后，按“远端源分支 → 本地 worktree → 本地源分支”清理，每步执行前复验。远端删除使用预期 tip 条件进行原子比较删除；tip 改变即拒绝，禁止覆盖新提交。本地分支由非待删 worktree 以已合并条件删除，已不存在的目标视作该步完成。远端权限不足时保留本地来源并报告。

结果分别列出 merged/remoteVerified 和各对象 cleaned/retained/failed 及原因。继续清理从远端 M 重新证明事实，允许源分支或 worktree 已部分不存在；不要求原始分支存在才能定位历史。清理证据由命令输出、Git 和交付记录保存，不回填已归档 Change。

## 6. 旧标签与缓存切换

采用一次性切换，不保留双读、旧标签兜底或历史映射。实施顺序为：

1. 在同一交付中更新主 skill、原型子 skill、归档命令提示和相关发布说明，停止创建保留标签；读取端和测试完成新协议支持。
2. 新实现验收并归档后，以新协议合入本 Change，核实远端 M；更新开发机长期服务并验证新读取方式。
3. 对协作分支建立全新缓存，验证新增合入记录、旧记录空态、原型总览与公开版本；随后重新列出目标命名空间的本地和远端标签。
4. 核对没有仍使用旧归档脚本的执行会话；对精确清单中的远端标签按预期对象删除，再删除对应本地标签。出现新标签或标签值变化时先确认来源，刷新清单，不覆盖并发操作。
5. 在缓存写锁下删除 `refs/openfolio/archive-v2/*` 旧引用和不再使用的 archivePins 快照数据，重建受影响仓库缓存。仅处理可重建部分，不重置登录、凭据、偏好或 public-previews。

新服务不依赖标签，故标签删除失败只记为清理遗留，不回滚读取协议。无需立即执行 Git GC，不能用清理整个持久目录替代精确操作。

上述实际切换发生在交付集成与服务更新阶段；实现任务交付的是命令、校验和演练证据。切换后不为了补记执行结果修改已归档文档。

## 7. 验证路径

遵循 SpecTrail testing-strategy，复用现有 Node 测试、Git fixture 和 Playwright，不引入新的测试框架，不在多层重复同一断言。以下场景对应交付可追溯性、删除数据和权限的实际风险；优先扩展现有用例，只补实质缺口。本文档整理仅进行状态、链接与内容一致性检查，不运行产品构建或新增自动化测试。

使用临时 bare 远端和多工作区 fixture 验证真实提交图：可快进/分叉合入、并发协作推进、结果未知重试、重复标记、错误父提交、归档不一致和多 Change 混入。删除 source ref 和 worktree 后，从仅取协作分支的新仓库重新识别并读取，证明没有隐式依赖本地残留对象或标签。

diff 验证新增、删除、重命名、归档移动、模式变化、特殊文件名、二进制及超限；用实际 `git diff M^1 M` 对照文件集合与文本。权限测试覆盖未授权、撤权、伪造 fileId/cursor、任意 SHA/路径与跨仓库读取。

原型测试覆盖 Git 与 hosted、sourceCommit 保真、活动及未合入固定版本、旧归档空态、已发布公开内容继续读取。清理测试在临时仓库覆盖推送失败、tip 竞态、活动依赖、脏文件、忽略文件和部分失败恢复，不以真实用户工作区做破坏性测试。

前端验证页签、选文件、加载/错误/空态、窄屏和键盘交互；运行与改动相关的现有测试、类型检查和生产构建。整体验证须有独立评审，验收后同步 workflow、Change tracking 和 prototype preview Specs，再按本仓库 AGENTS 更新长期服务并完成登录冒烟。
