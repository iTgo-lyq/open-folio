# 独立评审记录

由与实现上下文隔离的评审 Agent 只读检查整个 Change（包含未提交 T3），覆盖需求、方案、全部差异、子权限/缓存、固定版本、发布恢复和普通目录兼容。以下问题均以临时真实父子仓库复现，修复后由评审方聚焦复验。

| 编号 | 问题与影响 | 修复及证据 |
| --- | --- | --- |
| R1（P2） | Git register 只按 id 验证基线入口，清单未提交的 sourcePath 改写可能使产物追溯到另一份旧源码 | Git 模式与 hosted 一样比较 sourcePath 与固定基线；新增 sourcePath 指向另一已提交文件时拒绝登记的回归 |
| R2（P2） | 生成文件豁免覆盖整个 preview，可能忽略其中声明源码或依赖的未提交变化 | 收窄到声明入口的生成 index.html，并对全部声明源码额外检查工作区和基线差异；新增 preview/source.tsx、preview/dependency.js 脏内容回归 |
| R3（P2） | 任意 .gitmodules 变化都会要求初始化原型子模块，阻止无关 backend 变更提交 | 只比较配置路径经过的 gitlink 和其 path/url 映射；新增 frontend 未初始化时 backend 变更允许、frontend 地址变更拒绝的回归 |

评审方复验三个针对性回归和 diff 检查均通过，未发现其他确定性可操作问题。真实 GitHub 私有子仓库授权与远端旧对象保留未实测；实际版本无法获取时走明确错误提示，不计为已验证的远端能力。

## T4：前端先发布、主仓库单次关联

独立评审 Agent 只读检查本次返修的全部差异、需求/方案和验证证据，并以真实父子仓库独立复现、复验。以下均已修复，无未解决阻断：

| 编号 | 问题与影响 | 修复及证据 |
| --- | --- | --- |
| R4（P2） | 新来源只存源码 A 和挂载路径，活动 Change 迁移路径后无法追溯 | 主关联补 Q/B 固定绑定；远端先按 Q 授权仓库后读取 B/A。本地优先按 Q 的子模块 section 对象库定位，路径迁移及旧路径被另一真实子模块复用的独立复验通过 |
| R5（P2） | 源码未变时，忘记暂存新清单 B 也可能通过 hook | 新/修改引用要求 index 最终 gitlink 等于 catalogCommit；新增源码不变、只暂存 Change 时拒绝的回归 |
| R6（P2） | 单库事务日志缺 HEAD，提交清单后 recover 可能写回旧文件 | 每个新事务记录所属仓库 HEAD；真实 SIGKILL 中断后提交清单，恢复拒绝且保留字节 |
| R7（P2） | 前端清单已删除旧引用时，新关联漏查主仓库历史固定 URL 冲突 | associate 校验父当前清单和活动/归档 Change 的已知 URL；不同 digest/version 的同 URL 拒绝写入 |
| R8（P2） | preflight 从主工作区执行时错误地按当前 HEAD 检查 Q | 使用实际待交付 commit 作为父历史基线；Q 仅在 Change 分支、从 develop 执行归档预检的回归通过 |

评审方确认四种发布组合、嵌套、Q/B 绑定、迁移、SIGKILL 恢复、URL 冲突与从 develop 预检均通过；旧请求 ID 保持，来源凭据仍受固定父映射约束。未重复完整套件，完整结果另见 Execution。真实 GitHub 私有子库授权、远端对象保留与真实托管上传仍未实测。
