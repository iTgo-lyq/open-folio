# 子模块原型的读取、发布与固定追溯

## 方案概要

主仓库继续作为项目、配置和 Change 的唯一入口。增加一个按 Git 对象解析原型包的来源解析器：先固定主仓库提交，再沿 packagePath 中实际存在的 gitlink 找到原型包所在仓库与提交。OpenFolio、发布工具和校验共用解析规则，分别提供远端只读和本地对象读取能力。

保留现有 `artifact.sourceCommit` 的语义：它是**主仓库的构建来源提交**，代表包括 gitlink 在内的完整源码基线，不改成子仓库 SHA。子仓库身份及 commit 从这个父提交的配置和 Git 树推导，避免重复存储一份可能与 gitlink 冲突的版本字段。hosted 请求、结果、requestId、artifact 及 Change previews 的持久化格式均保持现有版本。

例如主仓库 P 记录 `frontend → A`，从该基线构建发布后，artifact 仍记录 `sourceCommit: P`；原型清单登记产生子仓库新提交 A1，主仓库后续提交 D 记录 `frontend → A1` 和 Change 引用。当前清单来自 D/A1，构建源码来自 P/A，二者不会混淆，也没有“子仓库提交必须先引用自己所在的父提交”的循环。

## 仓库、路径与版本规则

| 信息 | 归属与规则 |
| --- | --- |
| `workflow.json`、Change、归档、归档合并提交 M | 主仓库，沿用现有来源路由与交付规则 |
| `prototype.packagePath` | 相对主仓库根目录；可为 `frontend` 或 `frontend/packages/prototype` |
| 包内 `prototype.json` 的 `sourcePath` | 相对**实际存放清单的仓库根目录**；普通目录继续使用现有主仓库路径，子模块示例为 `packages/prototype/src/orders.tsx` |
| 包内 Git artifact 的 `path` | 相对清单所属仓库根目录；子模块示例为 `packages/prototype/preview/orders` |
| 包恰在子模块根目录 | 源码可以是 `src/orders.tsx`，Git 产物为 `preview/orders`；内部包路径用空前缀表示，不把 `.` 写入配置或清单 |
| Change 中 Git artifact 的 `path` | 主仓库内 `docs/project/changes/<id>/previews/<id>`，归档时随 Change 移动 |
| `artifact.sourceCommit` 与发布请求 `sourceCommit` | 主仓库的构建来源提交 P；发布请求 `repository` 仍为主仓库地址 |
| 子仓库源码 commit | 从 P 的 workflow、同版本 `.gitmodules` 和 gitlink 推导，不使用子仓库 HEAD 或默认分支 |
| 当前清单 commit | 主仓库浏览版本 D 及沿其 gitlink 解析出的实际清单仓库 commit；可与构建源码基线 P/A 不同 |

解析器返回主仓库提交、每层子模块的挂载路径/规范仓库地址/固定 commit、最终包内路径及所属 reader。逐段检查 Git tree 的 mode：普通 tree 继续，`160000 commit` 才进入子模块，符号链接和非目录直接报错。若路径经过嵌套 gitlink，对该层仓库的固定提交重复相同规则；只沿配置路径解析，不遍历或更新无关子模块。剩余路径每次缩短，避免无限递归。

子模块配置只读取该层固定提交中的常规 `.gitmodules` blob，通过关闭 include 的 Git config 解析读取 path/url；缺失、重复或冲突映射均报配置错误。忽略 `branch`、`update` 等不参与固定读取的设置，不执行自定义更新命令，不读取工作目录或本地 Git 配置覆盖历史地址。

清单和源码先在所属仓库中验证；只有源码位于实际原型包内、且对应对象为常规文件时才通过。对子模块源码缺失的单项保留错误，其他合法入口仍展示。OpenFolio 返回工作台数据时将子模块清单中的源码路径和当前 Git 产物路径映射为主项目挂载路径；归档快照路径保持主仓库路径。映射是读取适配，不回写子仓库清单。

## OpenFolio 读取与权限

### 获取固定对象

复用 GitReader 的命令隔离、认证和禁重定向规则；由仓库访问层向来源解析器注入子仓库 reader 工厂，不在 GitReader 内隐式复制父仓库 token。

1. 根据固定 `.gitmodules` 中的地址解析目标。相对地址按 Git 的仓库目录规则解析；当前 GitHub 连接支持的 HTTPS、SSH/SCP 写法规范化为平台返回的 HTTPS cloneUrl。拒绝带凭据、query、hash、控制字符或不受当前 provider/instance 支持的地址。远端模式不接受本地路径、file、自定义 helper 或 shell 协议。
2. 通过当前 provider 解析子仓库身份并校验当前凭据的可读权限，再为该仓库单独生成 GitTransport。子仓库不需要 SpecTrail、develop 或其他指定集成分支；不能用 workflow 探测判断它是否可读。
3. 在当前凭据工作台的独立子仓库缓存中获取**指定 SHA**，校验对象类型为 commit，再读取该提交的树和 blob。不执行 `submodule update`，不 checkout，不读取最新分支来替代失败的 SHA。远端拒绝获取指定对象时明确报告版本不可用。
4. 子仓库缓存按工作台和平台稳定仓库身份隔离；写入复用现有缓存锁模式，网络与对象读取受本次取消信号、超时和大小限制。主仓库清单提交未变时复用已解析内容，不因子仓库分支推进重新换版本。

### 缓存与权限边界

现有 RepositoryPermissions 用于主项目；子仓库复用其凭据租约、5 分钟复验和拒绝失效机制，但检查不要求某条集成分支存在。子仓库 identity 解析、权限判断与传输都使用同一连接，不能仅持有父仓库权限就读子仓库。

快照和 catalog 当前直接交付已缓存清单，需要同时适配响应组装：交付从子仓库派生的目录、详情或 Git 内容前复核对应子仓库权限，包括主仓库 tip 未变化、读取旧 snapshot 和命中对象缓存的路径。已知拒绝立即生效，未知撤权在现有复验窗口内发现；新公开版本发布前对实际依赖的子仓库强制即时复验，复用已发布版本沿用现有规则。

权限失败只遮蔽受影响的子仓库派生内容并展示错误，不将子仓库 READ_DENIED 记录成主仓库 READ_DENIED，不阻止主仓库文档阅读。凭据整体失效仍沿用现有全工作台失效规则。主仓库 Change 自身保存的 hosted 引用和 Git 快照属于主仓库内容，可在源码无法读取时继续提供固定产物，但追溯结果必须标记不可用；不得用缓存中的子仓库源码填补拒绝。

### 当前与历史预览

- 当前总览从集成分支提交 D 解析包、清单和适用的 Git HTML。固定当前预览使用请求的主仓库历史提交 D，以及 D 的子模块配置和 gitlink；当前启用策略及允许历史范围仍按最新主项目校验。
- 子模块包迁移后，旧子模块原型仍按其固定 D 的历史路径读取；普通目录原型沿用既有最新配置范围校验，不顺带放宽原有历史路径权限。
- Change 的入口集合与展示信息只来自该 Change 固定版本中的 previews。已集成归档继续从唯一有效 M 读取；不从 artifact.sourceCommit 推测或替代 M。
- Git Change 快照直接在主仓库 Change/归档树读取，不为读取 HTML 再遍历当前子模块。hosted 使用原固定 URL。源码追溯另外从 P 解析来源：验证父提交与交付历史关系、gitlink、子仓库对象及源码文件，避免只检查 P 存在就宣称源码可用。
- 追溯时可按入口 id 读取 P 中清单的 sourcePath；P 是登记前源码基线，因此不要求 P 的清单已经包含本次 artifact。包路径取 P 的 workflow，不能拿当前 packagePath 去解释旧发布。

运行时描述增加可选来源信息与错误信息，用于区分主仓库构建基线、子仓库源码提交和当前清单提交；来源信息由解析器产生，不作为第二套持久化权威。详情沿用现有来源区域显示这些值，现有 `sourceAvailable` 同时要求正确子仓库对象可读。扫描指纹随读取语义升级，让可重建快照重新采集；已公开产物和业务数据无需迁移。

## SpecTrail 接入、发布与恢复

### 接入及构建前提

setup 在主仓库保存配置，在原型所属仓库核对已有 package.json、清单和源码；采用前端已有工程，不向主仓库添加指向子模块的 workspace，不安装框架或改写子仓库脚本。未初始化子模块时提示先按主仓库记录初始化；工具不自行 checkout、拉取最新分支或覆盖已有工程。普通目录 scaffold 保持现有行为。

所有发布命令仍从主仓库或显式 `--repo <主仓库>` 进入。prepare 固定父提交 P，并逐层检查实际子模块 HEAD 与 P 的 gitlink 相符、所有源码和依赖干净、manifest 与声明源码已提交。hosted 构建产物可以是忽略的 dist；Git 兜底允许既有规则中的待登记 HTML 和清单更新，不把这些生成文件当成源码可随意修改的豁免。Git 路径分别基于子仓库包上下文与主仓库 Change 上下文校验。

先提交子仓库源码 A，再把 gitlink A 提交到主仓库 P，随后构建并准备发布。request/result 和 requestId 继续使用主仓库 repository/P 及现有摘要与入口算法，内置托管、custom 适配器与已发布请求无需新增协议字段。upload 的重新 prepare 校验必须使用同一套来源解析，防止准备与上传之间源码漂移。

### 登记及提交顺序

register 校验 request/result、产物摘要与固定源码后，更新子仓库当前清单，并按需更新主仓库 Change；Git 模式同时复制自包含 HTML 到主仓库 Change 快照。普通目录仍走现有单仓库路径。子模块模式在已有本地事务机制上扩展仓库参与方，不增加跨仓库 Git 自动提交。

完整顺序如下：

1. 子仓库源码 A 和父仓库 gitlink 基线 P 已提交；prepare 固定 P，构建、上传并保存 request/result。
2. register 在本地登记当前清单、Change 引用和适用的快照；此时两个仓库均可能有未提交变更，不能宣称已经远端发布引用。
3. 用户或执行 Agent 在已授权的子仓库工作分支提交并推送清单及适用的 Git HTML，得到 A1；工具只提示，不自动切换或提交子仓库。嵌套子模块从最内层向外提交、更新 gitlink。
4. 主仓库暂存 gitlink A1、Change 及快照，完成校验后提交并推送 D。OpenFolio 读 D/A1 的当前清单，构建追溯仍使用 P/A。

本地登记继续使用共享锁、写前日志、原文比对及失败恢复：主仓库与实际写入清单的仓库按固定顺序取得状态锁，事务写入前先验证全部目标；日志保存在主仓库 Git common-dir，记录相对文件路径、原/目标字节及参与仓库的预期 HEAD。recover 在持锁下先检查所有文件和仓库版本，再恢复；任一文件被新编辑、提交边界已变化、子模块未初始化或更换检出版本时停止并保留日志，不覆盖它们。该事务只保护本机文件登记，不承诺两个 Git 仓库的提交或推送原子性。

上传成功但登记失败时保留 request/result，可修复原工作区后重试 register；本地登记中断使用 recover。子仓库清单已提交而父仓库推送尚未完成时继续完成父仓库 gitlink/Change 提交，不回滚已推送子仓库历史，也不重新上传覆盖旧产物。重试须核对固定源码基线；仅有清单/生成产物登记变化可接受，源码或依赖变化应重新构建发布。

### 暂存、归档与合入检查

pre-commit 不访问网络。主仓库暂存校验读取**index 中**的 workflow、`.gitmodules` 和 gitlink，而不是子模块工作目录 HEAD；从已初始化子模块的本地对象库读取该 gitlink 的清单/源码/产物，校验对应来源。暂存 gitlink 与当前检出版本不同也必须校验暂存版本。所需对象缺失时提示初始化或获取确切版本后重试，不取最新版本兜底。与原型接入或引用无关的提交不额外要求初始化所有子模块。

登记与 previews-set 使用同一来源校验；归档保留 Git 快照在主仓库，更新路径不改 sourceCommit。integration preflight 校验 P 的父仓库对象与子模块真实源码对象，缺对象给出获取提示；不自动获取未经审核的 `.gitmodules` 地址。

现有 PR archive CI 不 checkout 子模块，也没有私有子仓库凭据。保持其职责为父仓库固定对象、完成归档和 Git 快照结构校验，不向 PR 注入额外跨仓库 token、不联网绕过检查；报告区分“归档校验通过”和“子仓库源码校验未执行”。子仓库完整对象校验由有权限的本地发布/preflight 与 OpenFolio 读取执行，证据写入任务验证，不把 CI 绿色当作私有源码可读的证明。

## 失败与兼容

| 条件 | 行为与提示 |
| --- | --- |
| URL 不受当前连接支持、非法路径或 `.gitmodules` 映射冲突 | 显示子模块路径及配置原因；获取前拒绝，凭据不发送到目标 |
| 子仓库不存在或当前凭据无权访问 | 使用平台允许的合并提示，遮蔽对应私有派生内容；主仓库可读内容保持可读 |
| 指定 SHA 获取失败、非 commit 或读取中断 | 明确列出子模块路径、目标版本及重试/补齐历史提示；不读分支头 |
| 清单、源码或 Git HTML 缺失/非法/超限 | 清单错误显示当前来源失败；单项错误保留不可用原因；沿用已有内容限制 |
| hosted 或主仓库 Git 快照存在，子源码不可读 | 固定产物仍可用，源码状态为不可追溯并显示原因 |
| 本地检出/暂存/构建来源不一致 | 在相应准备或校验环节拒绝，指明应修复的版本，不修改 checkout |
| 登记恢复遇到用户后续改动 | 停止恢复，保留日志与原发布结果，要求核对差异后重试 |

普通目录发布和历史 artifact 保持原有格式与语义，不批量改写归档、不引入双版本发布协议。缓存只作可重建迁移。技能交付时将根 package.json、package-lock.json 和 skill version.json 同步到相同的下一个补丁版本，以实施时最新基线为准；本次整理文档不提前升级发行版本。

## 依据、验证与部署

已从现有实现核实：GitReader 不递归获取子模块；原型清单及预览只用父 reader；hosted 源码可用性只检查父对象；prepare/register、hook 和 integration preflight 均假定单仓库；SnapshotStore 在 tip 不变时可直接复用当前清单；RepositoryPermissions 有凭据工作台隔离与 5 分钟复验；公开准备有发布前即时复验。实施应扩展这些入口，避免新建平行扫描与权限系统。

已用隔离临时父子 Git 仓库在本机 Git 2.39.5 验证：子仓库 HEAD 与父 index 推进到 B 后，旧父提交的 gitlink 仍为 A；index gitlink 可独立读取；独立 bare cache 可按 SHA 获取并读取 A；`git config --blob --no-includes` 可解析历史 `.gitmodules`。实验未修改项目文件，临时仓库已清理。这证明本地对象解析路径可行，尚不证明 GitHub 私有仓库授权或远端保留策略已验证；执行时用 provider 测试和可用真实权限场景补证，远端无法提供旧对象则走版本不可用提示。

验证覆盖父子仓库版本矩阵、嵌套路径、根目录包、URL 规范化与拒绝、index/HEAD 差异、权限复验及缓存拒绝、历史迁移、hosted/Git 完整发布归档和中断恢复。普通目录现有测试作为回归。服务交付按项目约定构建、浏览器验收与真实登录清理执行；数据格式兼容，无主动清理持久数据。

本次整理只交付方案和计划，不实现代码或更新长期服务。实施经确认、整体验证和用户验收后按已有 PR 普通合入 develop，再从主工作区停止长期服务、构建 `.next`、更新并冒烟；不触发正式发布分支 PR。浏览器复用共享 Chrome CDP，每次只关闭本任务页面；真实登录使用 withSmokeSession，清理失败须报告。

## 复杂度取舍

| 决定 | 依据、影响与最小方案 |
| --- | --- |
| 保留 | 固定父提交、gitlink、独立子权限与现有内容摘要分别保护版本不漂移、权限不越界和产物不被覆盖，均有本次明确需求 |
| 合并 | 读取、发布、hook、preflight 共享来源/路径规则，分别提供异步远端与同步本地对象能力；不复制四套解析逻辑 |
| 合并 | 两库本地登记复用现有锁和恢复日志，不另建发布数据库或跨仓库协调服务 |
| 建议删除（不采用） | 额外持久化 childCommit/repository 与新版 artifact 协议；父提交已完整保存相同信息，直接推导即可，不改变已确认范围或削弱校验 |
| 延后 | 自动提交/推送子仓库、自动追最新分支、跨平台新增凭据及 CI 私有子仓库授权；本次用明确步骤与错误提示完成已有范围，不扩大外部写入和授权边界 |
