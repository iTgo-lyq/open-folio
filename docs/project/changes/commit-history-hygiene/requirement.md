# 归档前提交整理与平台 squash 防护

归档交付前检查短期功能分支中的提交质量，合理压缩本 Change 内反复试错、修格式和修测试的噪声提交；首次接入和代操作 PR/MR 时明确防止平台自动 squash，保留现有普通 merge 交付协议。

## 范围与方案

- 在主 skill 增加简短的归档前提交整理规范。整理仅限尚未归档、未合入的本 Change 短期工作，不改写共享分支、交付边界或固定原型来源。已推送来源的整理须保护协作更新并使用固定预期 SHA 的 lease。
- 压缩后核对 Change 正文、状态、任务和提交定位线索；追踪信息缺失时依据原始证据及时补齐，保留真实确认、验收与验证事实，再继续归档。
- Setup 明确提醒用户不要开启自动或强制 squash。用户委托创建、更新、合并 PR/MR 或设置自动合并时，检查平台规则和本次请求的实际合并方式；显式使用普通 merge，无法关闭 squash 或无法核实时报告受阻。
- 同步冲突的既有规则与稳定 Specs，按仓库约定统一递增应用和 skill 补丁版本。不新增 squash 交付兼容、不新增脚本或状态字段，不修改平台全局配置。

## 验收

1. 归档前存在明确检查点，只压缩无独立交付价值的噪声，不因追求单提交丢失有效边界或追踪事实。
2. 压缩造成的追踪缺失必须依据真实证据修复；已推送历史整理与现有提交规则无矛盾。
3. 首次接入明确提醒禁止自动 squash；PR/MR 操作检查覆盖 Change 和正式发布，区分自动合并与 squash，不把平台允许 squash 等同于本次使用 squash。
4. skill 元数据与引用有效，应用、锁文件和 skill 版本一致，差异检查通过。
