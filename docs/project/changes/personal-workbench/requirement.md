# 个人工作台与 SpecTrail 仓库自动发现

## 背景与目标

OpenFolio 当前由部署者登记项目，服务进程使用本机 Git 凭据读取仓库，访客通过项目邀请码查看内容，管理员可以查看所有项目。新增项目只校验配置字段；仓库是否可读、是否有有效的 SpecTrail 配置，要到采集时才知道。

用户要求将产品改为个人工作台：首次连接自己的代码托管账号并登记 token，自动发现自己参与且已接入 SpecTrail 的仓库；协作者分别使用自己的凭据访问同一仓库的已推送记录。仓库平台决定访问权限，OpenFolio 不再维护空间、成员名单、角色或邀请码。用户明确要求后续所有远端仓库操作都使用当前用户提供的 token，不能借用服务机器或其他用户的凭据。

本 Change 覆盖这条完整使用路径，以及权限、导航和旧配置的联动变化。按 `large` 估算：凭据连接与会话、平台仓库发现、仓库读取与缓存授权、工作台交互、旧配置迁移均需要实质改造，预计超过 1000 行有效实现代码。它们共同交付个人工作台，可在同一个 Change 中分阶段集成；本次不拆成独立产品功能。

## 范围与行为变化

### ADDED：连接自己的代码托管账号

首次打开进入「连接 GitHub」，输入个人 token；Git 用户名从经平台验证的账号身份取得。页面提供对应平台的令牌生成入口和最小权限说明，验证成功后展示平台返回的账号身份与连接状态，随即发现仓库。

公开版本首批仅支持 GitHub.com。一个个人工作台可连接多个 GitHub 账号；界面清楚标识连接归属。平台接口需可扩展，其他平台由用户维护的内部版本接入，本仓库不增加对应实现、配置或占位入口。这里的“注册”指连接托管账号，不增加 OpenFolio 用户名、密码或邮箱注册流程。

连接验证区分身份识别、仓库发现和 Git 读取能力；能执行 Git 拉取不等于可以列出用户仓库。发现所需权限不足、组织授权未完成、token 失效或网络不可达时，给出对应的恢复入口，不把失败显示为连接成功或空仓库列表。不能证明个人账号身份的凭据不冒充个人连接。

有效会话内刷新或重新打开浏览器可以恢复已连接状态。用户可替换 token、移除单个连接或退出当前工作台；移除和退出撤销对应会话的服务端访问能力。更换设备或清除会话后重新连接，本期不增加独立账号恢复或跨设备偏好同步。

token 只用于所属连接，不出现在 URL、分享链接、日志、错误详情、仓库配置或可读回的接口响应中；不以明文持久化，也不放入浏览器 localStorage。页面仅展示脱敏状态，替换时重新输入。会话隔离、持久化与失效机制在技术阶段确定。

### ADDED：自动发现并识别 SpecTrail 仓库

连接成功后，通过平台提供的个人仓库列表能力，发现当前账号拥有、参与或经组织／组继承访问的候选仓库；候选范围还受 token 所选仓库、scope 和平台策略限制。默认不遍历整个平台的公开仓库，也不要求仓库写权限或管理员身份。

对候选仓库检查其远端默认分支中已推送的 `docs/project/workflow.json`，依据受支持的 SpecTrail 契约判断是否接入。有效的工作流配置是识别依据；仅有同名目录、README 描述、仓库名称或尚未推送的本地文件不算接入。刚完成接入但没有 Specs、Change 或原型内容的仓库也可进入工作台，并展示真实空状态。

缺失配置记为未接入；内容损坏、契约不支持、声明的守护分支不可用或默认阅读来源无法确定，展示相应诊断。有效配置但阅读来源异常的仓库可以标为需要处理，不能显示为健康可读。读取被拒绝、网络异常和接口限流属于未能完成检查，不据此判断未接入。识别远端配置不宣称已验证每位协作者的本地 hook 执行情况。

发现过程展示进度、已发现结果及可恢复的失败，逐步呈现可以进入的仓库；支持重新发现。处理平台分页和限流，不把第一页或部分成功结果宣称为完整列表。发现和采集应避免启动时全量拉取所有候选仓库历史；具体读取策略在技术阶段验证。

提供按仓库名称或路径查找，以及输入仓库 HTTPS 地址重新检查的补充入口。该入口仍使用用户选择的个人连接并执行同样的权限、地址和接入校验，不建立全局项目登记，也不能越过 token 范围。它不能替代本 Change 所要求的平台自动发现能力。

仓库身份区分平台实例与平台内仓库；同名仓库不会混淆，同一仓库由不同协作者发现时指向相同的协作内容。仓库转移、改名或失去访问权限的处理在技术方案中明确。

### MODIFIED：每次读取都以当前用户的仓库权限为准

所有访问远端的 Git 操作（包括 `ls-remote`、`fetch` 及后续扩展）与平台 API 请求，都明确使用当前用户所选连接的 token。禁止回退到 credential helper、`.netrc`、SSH agent、宿主登录态、共享服务账号或其他用户 token。本期使用 HTTPS token；不引入 SSH 私钥上传。

工作台内的个人项目列表、工程记录搜索、Specs、Changes 正文、文档、文档附件和对应历史快照均受同一权限边界约束。新请求返回受保护内容前，必须基于当前连接向平台确认所需权限；没有 token、会话失效或权限无法确认时不返回缓存内容。公开仓库也不能通过匿名成功掩盖失效 token。原型展示产物及截图采用下文明确的公开读取规则。

共享 Git 对象或文档缓存可以减少重复读取，但“缓存已存在”“其他用户刚读取成功”和“以前发现过仓库”均不能作为当前用户的授权依据。并发采集不能串用凭据；更换或移除连接后，进行中的请求不能发布到错误的个人上下文。权限撤销后新请求被拒绝，页面清理失效连接对应的内容并引导恢复；已交付浏览器的字节无法远程收回。

刷新失败时，只有重新确认当前用户仍有仓库权限，才可以显示先前成功快照及失败提示；平台不可达、无法确认权限时不降级开放旧数据。其他正常连接和仓库仍可使用。

Git 平台只负责确定用户能否读取仓库。OpenFolio 仍负责会话、秘密保管、连接与缓存隔离、请求校验和清晰的错误恢复；本次不另建仓库成员授权系统。

### MODIFIED：个人工作台的完整交互

主流程为「连接服务 → 自动发现 → 选择仓库 → 阅读与协同」。首页展示当前个人连接可用的 SpecTrail 仓库及发现状态，支持搜索、切换和重新发现。仓库详情继续提供 Specs、Changes、原型和来源信息；仓库是协作上下文，不创建空间或工作台成员列表。

重做首次进入、连接管理、仓库首页与切换、导航、阅读容器和设置入口。视觉延续既有窄侧轨、侧边玻璃胶囊按钮与圆角白色工作面；个人工作台新流程融入原有框架。个人设置集中管理连接与展示偏好，页面不再要求填写全局项目 id、项目邀请码或服务管理密码。覆盖未连接、发现中、没有接入仓库、部分发现失败、token 过期、无仓库权限、仓库缺少工作流、内容加载与刷新失败等真实状态。

工程记录分享链接表达仓库和阅读位置，可保留分支、文档或 Change 等上下文，不携带 token、邀请码或任何可转让的仓库访问能力。接收者使用自己的连接完成验证，成功后返回原目标；不同用户的连接 id 或本地项目排序不影响链接解析。无权读取时提供连接／更换账号的路径，不泄露受保护内容。原型有独立的公开预览链接，接收者无需先连接账号。

同一仓库的协作者从相同已推送提交读取一致的流程事实；本地草稿不成为协作内容。OpenFolio 保持只读，流程修改继续通过 SpecTrail 和 Git 提交完成，不增加聊天、评论、在线编辑、Git 写入或成员管理。

桌面、平板和手机均覆盖完整路径，键盘操作、焦点恢复、深链接和浏览器前进后退可用。本仓库已启用原型协作；本次属于大范围 UI 变化，技术阶段先在既有原型包中呈现主流程与关键异常状态并提供可交互预览，再进入正式产品实现。

### MODIFIED：所有原型公开预览

用户明确选择“原型全部可以公开访问，不需要做另外权限校验”。OpenFolio 内置托管、外部托管和 Git 来源的原型展示产物、必要静态资源及截图均提供公开访问；打开固定版本的原型预览链接不要求 token、邀请码或仓库成员身份。公开预览不因发布者或访问者 token 过期而失效。

Git 来源仍通过某次有权限用户的连接取得仓库内容，再提供可公开读取的原型产物。匿名预览只读取已准备好的公开版本，不能借用其他人的 token 触发仓库拉取；尚未取得的版本明确显示未就绪或不可用。原型公开不扩大为公开读取任意 Git 文件、完整 Change 正文、个人仓库列表或秘密配置。

公开预览页面仅取得展示原型所必需的信息，不能借公开页面返回受保护的工程文档。产品清楚表达原型公开范围；上传／发布、服务配置及密钥获取继续使用其受控入口，公开读取不授予这些写入或管理能力。保持原型固定版本、产物完整性与沙箱隔离，停用、撤回和历史保留的兼容方式在技术方案中说明。

### REMOVED：全局项目与邀请码驱动的访问流程

移除工作台中的空间／邀请／成员角色概念，以及现有项目邀请码输入、生成、复制和自动兑换流程；现有实现没有独立空间模块，无需为删除概念新增对应实体。

移除部署者维护全局项目列表才能使用产品的前置条件。旧 `projects`、`inviteCode` 和管理登录态不自动转化为任何个人的仓库授权；旧用户需要连接自己的托管账号。旧链接有足够仓库定位信息时可在完成本人鉴权后恢复目标，无法确定时明确提示重新选择，不沿用邀请码授权。

迁移保留现有工程记录和可复用的本地内容缓存，旧缓存只能在新授权边界后读取。旧服务配置保留可恢复副本，必要资源限制和部署参数继续由部署端管理；这些运维设置不向普通仓库读者开放，也不能赋予部署管理员仓库阅读权限。

## 范围边界与约束

- 本仓库仅交付 GitHub 适配器，GitHub Enterprise、GitLab 和 Codebase 不在首版范围。平台身份、仓库发现、内容探测及凭据注入有明确扩展契约，公共 Git 读取能力复用；扩展平台不需要重写会话、索引或工作台。
- 自动发现只覆盖 token 可见范围；用户拥有某仓库权限但未把它授权给 token 时，工作台不能越权发现或读取。
- 本期不做 OAuth 应用注册、组织 SSO 产品、Webhooks 驱动实时同步、独立 OpenFolio 账号或空间体系。允许后续增加连接方式而不改变仓库作为权限来源的原则。
- 继续使用仓库内既有 SpecTrail 契约，不为 OpenFolio 发现新增项目管理员登记步骤。默认分支不硬编码为 `main`；原型的现有来源约定若需要调整，在技术阶段说明兼容影响。
- 部署保持当前单实例与持久磁盘前提。首版连接仅允许 GitHub.com 及其明确的数据 API 主机；扩展适配器必须声明受信的目标和凭据发送规则，不允许浏览器提交任意主机来接收 token。
- 原型统一公开读取，包括 Git 来源。既有内置上传地址的获取属于部署运维能力，不能因删除工作台管理入口而变为所有用户可取得，也不能使既有上传流程无提示中断。外部静态服务仍需配置为可公开访问，OpenFolio 不代持或转发第三方登录凭据。

## 验收标准

1. 全新访问无需空间、邀请码或管理密码；从连接 token 开始，能发现并进入已接入的仓库。有效会话恢复连接；替换、移除和退出均产生可观察且正确的失效效果。
2. GitHub 完成个人身份、候选仓库分页发现、SpecTrail 识别和实际 Git 内容读取的端到端验证；单纯 mock 或 `ls-remote` 成功不能代替集成验收。连接页准确列明所需权限和未满足项；通过无真实平台信息的测试适配器证明扩展不依赖 GitHub 特有字段。
3. 已接入且有内容、已接入但无内容、未接入、配置损坏、声明来源异常、检查失败六类样本能够区分。未接入仓库不作为正常 SpecTrail 项目加入；分页和部分失败不被误报为完整空结果。
4. 两个隔离用户分别能发现各自授权范围；共同协作的仓库能指向同一提交的内容，只有其中一人有权的仓库工程记录不能被另一人通过列表、深链接、搜索或缓存读到。仓库身份含适配器与实例边界；同名仓库正确区分。
5. 在服务机器配置有效的本地 Git 凭据、另一个用户已留下缓存的条件下，当前用户缺少、错误或无权的 token 仍然被拒绝；有效 token 能完成 `ls-remote`、`fetch` 和内容读取，所有远端请求可证明来自该连接。
6. token 过期、被撤销、token 仓库范围缩小、用户仓库权限被移除、主动移除连接，以及平台无法确认权限时，后续受保护请求不能继续返回旧内容。覆盖 GET、HEAD、工程记录历史快照、文档附件缓存和进行中请求。
7. 连接错误或发现失败有明确恢复入口；一个连接失败不妨碍其他有效连接。令牌不能从响应、分享链接、浏览器持久化、日志、仓库或错误输出中读回。
8. 工程记录分享链接由有权限的第二位协作者使用自己的 token 打开并恢复原位置；无权限账号不能读取，链接不携带仓库访问能力。原型链接在未登录的浏览器中直接打开。
9. 桌面、平板与手机的首次连接、发现、切换、阅读、分享和连接失效流程可演示；原型先于正式 UI 实现完成。原有分支／提交来源、Change 聚合、固定原型引用与阅读能力通过回归验证。
10. 带旧项目、邀请码、管理 Cookie 和缓存的部署可以升级；旧权限不绕过新校验，用户有可理解的重新连接路径，部署资源限制和既有托管能力有明确去向，配置可恢复。
11. 内置托管、外部托管及 Git 来源的原型和截图均可匿名读取，GET／HEAD 不检查仓库成员身份；已准备好的固定版本在用户 token 失效后仍可预览。未准备的 Git 版本不会触发无用户授权的拉取，公开接口也不能读取 Specs、Change 正文、任意仓库文件或上传密钥。

## 可行性与待明确边界

已有 token 实验确认 GitHub 私有仓库可以使用用户提供的 token 执行隔离凭据的 `ls-remote`；本轮仓库列表与工作流文件探测已验证。完整采集与撤权场景在实施阶段验证。详见 [调查依据](./research.md)。

公开仓库仅实现 GitHub，其他平台由内部版本维护；本次明确设计可扩展接口，不把尚未实现的平台描述为已接入。原型统一公开读取沿用用户明确选择。

凭据存储、账号／会话标识、平台接口、撤权校验、缓存组织、原型公开交付和迁移契约由 Technical 定义；本文件不表示已批准技术方案或执行计划。
