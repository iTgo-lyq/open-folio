# Token 工作台与多设备登录

## 背景与目标

现有连接归属于浏览器会话：会话到期或退出会删除连接，同一 token 在另一设备登录会建立新连接和缓存。用户希望减少重复登录，让多个设备恢复同一份工作台，同时避免独立账号体系和 GitHub OAuth 登录依赖。

用户选择以 token 区分工作台；登录后提供复制原始 token 的入口。不同 token 即使属于同一托管账号，也不复用仓库缓存。用户在完整行为说明后回复“没什么问题”，并进一步明确用户名可选，默认使用 Git 账号名填充。

## 范围与行为变化

### ADDED：以凭据恢复工作台

平台、实例与完全一致的 token 对应一个工作台。首次登录验证凭据后创建，再次登录验证后恢复。用户名是可选显示名称，省略、空字符串或仅空白时首次登录默认使用 token 对应的 Git 账号名；恢复时保留已有名称。自行填写不要求与 Git 账号一致，不影响身份、权限或缓存归属。Git 传输用户名由适配器从已验证身份取得。通用工作台模型不依赖 GitHub 用户 ID、OAuth 应用或组织安装。

工作台保存当前凭据、连接摘要、仓库发现状态、私有缓存及必要偏好。一个工作台只包含该 token 的资源，不能通过当前 token 找回其他 token 的连接。首版继续只交付 GitHub.com 适配器，保留其他平台的接口扩展性。

### MODIFIED：设备会话与凭据分离

每个浏览器建立独立会话，并使用随机 HttpOnly Cookie。相同 token 可同时在多台设备登录；新增设备不会轮换其他设备的 Cookie。活动期间续期，刷新页面与服务重启恢复当前登录。

退出默认只撤销当前设备会话，保留工作台与其他设备会话；提供退出全部设备的操作。设备会话到期不删除工作台凭据与缓存，再次提供有效的相同 token 后可恢复。

### MODIFIED：凭据隔离的发现与读取

相同平台、实例和 token 的设备共用工作台的发现状态与缓存；不同 token 的工作台分别发现、采集和保存私有数据。同一托管账号名或同一仓库提交不能成为跨 token 复用缓存的依据。

查找到缓存不等于获得读取权限。沿用工程请求对当前 token 的身份、仓库 API 与 Git 读取校验，以及长操作交付前复验。撤权或无法验证权限时不返回旧正文。

### MODIFIED：登录与切换凭据

登录界面使用“用户名（可选）”与 token，说明留空时自动使用 Git 账号名，不重复展示工作台名称字段。平台实例来自受信适配器配置，不接受任意鉴权主机。当前仅有一个适配器时不展示尚未支持的平台选项。

“替换 token”改为“切换凭据”：先验证新输入，成功后切换当前设备所属工作台；失败保留原工作台。相同 token 恢复原工作台，不同 token 新建或恢复另一个工作台，不把旧仓库、快照或阅读偏好迁入新 token。

账号详情提供当前凭据及设备会话操作。切换不让当前设备继续访问旧工作台，不退出其他设备正在使用的旧工作台。

### ADDED：主动复制当前 token

登录用户在当前凭据详情点击“复制 token”时，可以取得服务端保管的原始 token 并写入剪贴板。只允许复制当前设备已登录工作台的凭据。

普通会话、连接与仓库响应继续不返回 token；复制通过独立接口处理，响应禁止缓存。token 不进入 URL、日志、Git 配置、localStorage 或 sessionStorage；复制失败提供可重试反馈。

本项明确调整现有“原始 token 永不读回”的契约，授权仅覆盖用户主动复制当前已登录凭据，不扩大为枚举其他 token 或批量导出。

### MODIFIED：旧数据兼容

已有浏览器会话及其连接可以升级为凭据工作台。旧会话中的不同 token 分别归属不同工作台；只有平台、实例和完整 token 一致的连接才能合并。迁移不按平台账号名、subjectId 或仓库名称合并。

可证明来源一致的旧发现与缓存可在同 token 下恢复，不把不同 token 的私有缓存互相复制。迁移保留受控备份；密钥丢失、解密失败或迁移不完整时停止恢复并保留现场。

## 约束与依赖

- 依赖 `personal-workbench` 的加密凭据、平台适配、Git 隔离、授权读取与公开原型能力。当前在该 Change 分支规划，正式实施前按 SpecTrail 完成前置交付的关闭与归档。
- 保持单 Node 实例、持久磁盘、现有数据目录与受信反向代理前提；不引入 OAuth、邮箱密码注册、组织／空间体系或新的托管平台实现。
- 公开原型仍按原有公开发布契约读取，私有凭据缓存隔离不改变已发布原型的公共资源。
- 丢失或更换 token 按另一个工作台处理，不新增跨 token 找回、账号合并或自动更新凭据的能力。

## 验收标准

1. 两个隔离浏览器使用同一平台、实例、用户名与 token 登录，恢复同一工作台、发现结果及已采集快照；每个浏览器具有独立会话，登录第二台不使第一台退出。
2. 同一平台账号的两个不同 token 登录后工作台、发现任务、Git 目录、快照和错误状态均隔离；即使目标仓库和提交一致，第二个 token 首次读取也不借用第一个 token 的私有缓存。
3. 服务重启、页面刷新和有效会话续期不要求重新输入 token；当前设备退出／到期后重新登录相同有效 token，仍能恢复原工作台。
4. 退出当前设备只撤销该设备；退出全部设备撤销该工作台全部会话。被撤销设备在途读取不能继续交付，凭据及缓存仍可通过新的有效登录恢复。
5. 切换不同 token 进入对应独立工作台，旧设备的其他会话不受影响；无效凭据切换失败时原工作台仍可用。任何 token 都不能枚举或复制另一个工作台的凭据。
6. 点击复制能取得完全一致的原始 token；未登录、跨工作台、跨站及会话已撤销的复制请求被拒绝。普通响应及持久浏览器存储不包含原始 token，复制响应不缓存。
7. token 撤销、过期、权限缩小及平台校验失败时，已有缓存不能绕过授权；覆盖普通读取、HEAD、历史快照、文档图片和长操作交付。
8. 含多个连接及重复 token 的旧部署可幂等升级；相同 token 合并而不同 token 隔离，旧 Cookie 能恢复自己的已授权凭据集合。缺失密钥与中断场景保留原始备份，不生成新密钥覆盖。
9. 桌面、平板、手机及 320px 窄屏可完成首次登录、同 token 恢复、切换凭据、复制和退出；用无真实凭据的交互原型先演示主要路径。
10. 非 GitHub 测试适配器可走通登录、凭据恢复和缓存隔离，证明通用身份模型不依赖 GitHub；原有仓库分享、原型发布及独立管理权限通过回归验证。

- [GitLab：Personal access tokens](https://docs.gitlab.com/user/profile/personal_access_tokens/)，2026-10-12 读取。文档确认 Git HTTPS PAT 用户名可为任意非空值；仅用于检验适配器边界，不表示本仓库已支持 GitLab。
