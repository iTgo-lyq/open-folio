# Token 工作台独立评审

评审方式：不继承实现会话的独立 Agent，覆盖自 `18e9e307` 前置归档后的完整差异及 T5 工作区，核对 Requirement、Technical、Plan、Execution。只读检查与受控 Chromium 复现，不修改实现或共享夹具。修复后由同一独立评审者再次复验。

## R1 / P2：晚到 GET 覆盖已切换 Cookie

每日续期或失效清理的 GET 响应可晚于成功登录响应到达，重写旧 Cookie 或清掉新 Cookie，导致当前设备误退出。独立评审以受控时钟和阻塞 `store.get` 复现。

已修复：首次签发 Cookie 覆盖 90 天绝对期限，30 天闲置续期由服务端每天至多更新一次。普通 GET 与授权读取均不写／清 Cookie，登录、恢复和退出才变更 Cookie。旧单连接摘要由前端自动 POST 兑换，多连接仍需一次性选择；包括首页和当前凭据书签。Technical 与 README 已同步传输细节，身份隔离和有效期边界不变。

复验：新增每日续期、晚到旧 GET 和失效旧 GET 的竞争测试；定向会话／复制／迁移／偏好／轮换共 24 项通过。独立 Chromium 确认首页与当前凭据入口均自动 POST 恢复。R1 关闭。

## R2 / P2：晚到偏好响应复活旧账号

显式会话恢复清空页面状态却保留内部旧快照；旧偏好 PATCH 若在切换成功且新 GET 未返回时到达，可以把旧账号摘要重新写入页面。独立 Chromium 延迟响应后复现旧账号卡片重新出现。

已修复：显式恢复先使内部快照失效，偏好请求记录会话请求序号，响应只在序号和工作台均一致时合并；设备摘要与页面归属同时包含设备 id。旧正文与目录按工作台、设备和页面 epoch 丢弃，凭据组件卸载时清除临时 token 文本。

复验：真实服务浏览器的延迟偏好＋切换、延迟偏好＋退出均通过；独立评审者另用全 mock API 的隔离 Chromium 重现原时序，旧卡片保持 0，新 GET 放行后分别显示新账号与未登录。R2 关闭。

## R3 / P3：异步手动复制关闭后焦点丢失

整合浏览器检查发现，复制按钮在请求时禁用会先丢失焦点，手动复制弹层因此无法通过默认 activeElement 找回触发按钮。

已修复：点击时保存确切触发元素，弹层关闭后显式恢复。390 与 320px 复验通过；1440 与 834px 纳入最终完整浏览器回归。

## 结论

独立复验未发现新增待修问题，也未发现可复现的跨 token 授权绕过、普通摘要秘密泄漏、共享任务借用其他凭据或迁移错误归并。评审者独立运行 24 项定向测试及 diff 空白检查通过。完整浏览器、构建和验收对应证据由 Execution 汇总。
