# 实施证据

## T1 多设备恢复同一凭据工作台

新增 personal-v2 原子状态、私有 HMAC 索引、随机工作台 UUID、绑定工作台的 AES-GCM 密文和独立设备 Cookie。相同 token 并发收敛，不同 token／实例隔离；退出与过期保留工作台，切换成功仅撤销当前设备。落实每日活动续期、30 天闲置／90 天绝对期限、32 设备上限、密钥缺失拒绝恢复。Provider 接口接受可选用户名并返回 Git 传输名；GitHub 核对已验证 login。登录改用 POST /api/session，旧连接写接口返回 410；表单加入用户名以保持新入口可用，完整凭据页面随 T4／T5 完成。

验证：会话与 Provider 的 20 项测试通过，覆盖并发、新实例、同账号不同 token、改名、重启、失败切换、退出全部设备、续期上限、密钥缺失、AAD 绑定、文件权限、数量上限、同源与反向代理。类型检查通过。当前发现／缓存路径仍使用设备范围，共享任务与缓存归属在 T2 集成；旧数据迁移在 T3 交付，运行实例未更新。

## T2 工作台缓存与逐设备交付

发现状态改存 discovery-v2/<workspaceId>/state.json，仓库 Git／快照改存 repositories-v2/<workspaceId>/<repositoryKey>。稳定仓库身份绑定快照，不用设备 id 或可变仓库路径区分同一工作台。新增工作台任务 lease，单设备退出取消该设备请求而共享发现／刷新继续，退出全部设备取消工作台任务；每个设备响应仍单独复验身份、仓库 API、Git refs 与会话。登录恢复已有发现记录不重新清空，活动成功请求按日续期 Cookie。公开原型目录及匿名读取不变。

验证：发现、仓库、公开原型、快照和会话 36 项定向测试及类型检查通过。真实 HTTPS Git 读取、缓存失权、HEAD／图片／历史快照及交付前撤权覆盖保留；新增同 token 两设备共享快照／目录、不同 token 同账号隔离、并发刷新单次 collect、单设备退出不影响另一设备、退出全部后发现中断恢复用例通过。旧全局链接恢复和公开产物准备沿用逐设备授权，运行实例未更新。
