# 实施计划

依据 [需求](requirement.md) 与 [技术方案](technical.md)，交付可按真实合入日期和 PR 批次浏览的归档列表，并统一 Change 交付文案。

## T1 支持按真实合入批次浏览归档 Change

补齐 GitHub 合并时间的 provider 映射和 PR 页面缓存，复用交付核实输出有效批次引用；在现有目录筛选之后呈现日期与 PR 批次时间线、3 条预览和展开收起，处理无可靠时间、详情往返和手机布局。统一列表、详情及分享页的“待集成 / 待合入 / 已合入”文案，并同步当前 Specs。

验收以需求中的六类数据场景为依据：同日多批次、跨天跨年、多 PR 包含同一 Change、时间未知、筛选结果变化、非归档视图回归。使用真实的合入证据选择算法，不从 PR 更新时间或归档目录推测时间。

验证：定向运行 provider、PR 缓存、交付与目录的单元测试；用浏览器验证筛选、展开收起、详情返回和混合视图，检查 1440/390/320 宽度、明暗主题、键盘与无横向溢出；运行类型检查及受影响构建。每项结果记录真实命令、范围与限制，失败修复后复验。

## 整体验证与交付

任务开始前同步最新 develop，核对 xlarge-parent-integration 是否已集成到交付模块，按其已落地规则适配；该 Change 未交付不是本任务的功能依赖，不修改其工作分支。

按用户选择不新增独立原型。开发完成后提供实际界面证据与验收结果，再按 SpecTrail 关闭及 PR 流程交付。归档前同步并验证，准备可审阅 PR；合并按会话授权执行，不能将创建 PR 视作合并授权。

交付到 develop 后，在主工作区按服务约定串行停止、构建、启动长期服务；使用 withSmokeSession 完成真实登录冒烟并核实清理。任务 worktree 的构建只用于本任务验证，不覆盖运行中的主工作区 .next。实现前技术方案与本计划须完成共同确认。
