# 浏览器多身份技术方案

落实[已确认需求](./requirement.md)。保留 token 工作台，在其上增加浏览器身份集合：浏览器持有一枚随机 HttpOnly Cookie，集合记录已登录身份和当前选择。切换修改服务端当前选择，不更换 Cookie；用户无需把 token 留在浏览器。

## 依据与就绪性

2026-10-14 已核对当前实现：凭据匹配与加密、原子私有状态写入、单进程串行锁、设备／工作台操作中止、仓库缓存隔离和测试 Provider 均可复用。Next.js 16.3.7 本机 Route Handlers 指南确认继续使用 Request／Response 和独立 API 路由；基础组件沿用 `@open-folio/ui` 包入口，不新增公共组件。

浏览器原型只验证交互和布局，不证明真实鉴权已实现。正式实现的期限、并发及撤销由隔离的会话／API 测试和浏览器回归覆盖。当前无待接入的新平台、依赖包或外部服务；开发机运行配置与原型 R2 发布配置沿用已有环境。

## 浏览器集合与身份授权

仍在 `personal-v2/state.json` 原子保存完整状态，外层 schemaVersion 升为 3，不改工作台 UUID、凭据匹配索引或缓存目录。数据关系如下：

| 实体 | 主要字段与职责 |
| --- | --- |
| Workspace | 沿用 token 对应的身份、显示名称、加密凭据和偏好；不因切换或移除删除 |
| BrowserSession | 随机 id、Cookie 摘要、当前授权 id 或 null、递增 revision 与 selectionRevision、创建时间；仅浏览器 Cookie 能取得所属集合 |
| DeviceSession | 随机 id、browserId、workspaceId、创建／最近使用／闲置到期／绝对到期时间、设备标签；同时作为该浏览器记住此身份的授权 |

DeviceSession 不再持有独立 Cookie 摘要。一个浏览器与一个工作台最多一条有效授权，不同 token 仍分别指向不同工作台；切换时授权 id 保持稳定，便于其他设备撤销。BrowserSession 的当前指针只允许指向所属的有效授权。

保留全局最多 10,000 个工作台、10,000 条身份授权与同工作台最多 32 个设备的限制；浏览器集合最多 10,000 条，单浏览器最多记住 32 个身份。达到上限拒绝新增，保留既有授权和当前身份。

每条授权独立沿用 30 天闲置、90 天绝对期限。普通活动只触达当前身份，按已有每天一次的方式更新闲置期限；查看列表不会延长非当前身份。点选切换可更新目标最近使用时间，但不重置绝对期限；显式重新输入有效 token 才重新签发该身份授权。过期授权清理后，当前指针置空、revision 递增，并中止对应读取；无剩余授权的集合可清理。

Cookie 仍名为 `openfolio-session`，随机值只在新集合建立时产生，服务端只存摘要。Cookie 的保留期覆盖集合内授权的最晚绝对期限，新增／重新登录时可用同一个值更新保留期；各身份期限始终单独检查。GET、点选切换、移除和退出不改 Cookie，避免延迟响应覆盖较新的登录状态。Cookie 丢失后只能凭 token 重新添加，不按用户名找回集合。

## 添加与切换的状态提交

添加沿用 `POST /api/session`：先规范化输入并调用适配器验证，再进入状态锁。按原 HMAC 匹配工作台；新工作台加密保存 token，原工作台保留 UUID、缓存和偏好。浏览器已有该身份时替换该授权，不重复添加；其他身份授权保留。最后在一次提交中更新授权、当前指针和 revision，提交成功后中止原当前身份的设备读取。平台验证、限额或持久化失败均不能提交新选择。

点选使用 `POST /api/session/switch`，请求只含所属身份授权 id。先在锁内确认目标属于当前浏览器、未过期，并捕获集合 revision、授权 id 和工作台凭据标识；离开锁后解密目标凭据并验证平台身份。验证成功再次进入锁，复核集合 revision、目标授权和期限仍一致，再原子切换。平台账号 subjectId、providerId 和 instanceId 必须与工作台一致，可变 login 与适配器返回的 Git 用户名按验证结果更新。

切换期间若另一标签页已经切换、退出、移除或撤销目标，复核失败返回 `SESSION_CHANGED`，不自动覆盖新状态。目标 token 无效或身份变化返回重新登录提示；网络与限流保留目标授权和原当前身份。用户可输入新 token 重新添加；不同 token 建立独立工作台，不把旧工作台换成新凭据。

## API 摘要与并发边界

`GET /api/session` 保留当前工作台摘要和只含当前连接的 `connections` 字段，新增 `identities`、`browserRevision` 和 `selectionRevision`。每个列表项仅含授权 id、工作台安全摘要、是否当前和授权期限，不含 token、Cookie 摘要或匹配索引。当前指针为空时 `connected: false`，仍可返回该浏览器其他有效身份；无有效集合则返回空列表。

`DELETE /api/session/identities/[id]` 单独移除所属身份。既有 `DELETE /api/session`、`POST /api/session/logout-all`、设备列出与撤销、偏好写入和复制 token 继续按当前身份工作。设备 API 的 id 即身份授权 id，当前凭据的设备列表包含其他浏览器记住但暂未选中的授权。

浏览器身份动作及依赖隐式当前身份的操作携带 `X-OpenFolio-Revision`。对有效集合，服务端要求与当前 revision 一致；缺失、不合法或不一致则拒绝执行，客户端重新读取会话。首次无有效集合的 token 登录不要求此字段。该字段只防止旧请求修改新上下文，不提供授权；Cookie 和所属关系仍必须验证。切换的两次复核和移除／退出的状态提交都检查此条件，偏好写入保留现有工作台校验。

仓库读取沿用显式 connectionId 和现有 lease。lease 捕获 browserId、selectionRevision、当前授权 id 和工作台凭据标识；`assertCurrent` 同时核对集合当前选择、selectionRevision、授权有效性和凭据。因此即使 A → B → A，第一次 A 的读取也不能交付。成功切换后调用原设备操作中止机制，不删除原授权。

工作台共享发现与刷新任务仍按 workspaceId 归属，切换或单设备退出只撤销设备交付；已运行的共享任务继续使用原工作台 token。全设备退出仍中止该工作台共享任务。共享任务不能因当前浏览器切换而借用其他工作台凭据。

复制接口不接受目标身份，始终取得当前 lease；响应前复核当前授权和 selectionRevision，配合 private、no-store、同源、HTTPS 和 nosniff。其他秘密处理规则沿用现有实现。

## 移除与设备撤销

移除非当前身份仅删除对应授权；集合 revision 递增以使并发身份操作重新核对，当前选择不变，不主动中止当前读取。移除当前身份／退出当前设备同时清空当前指针并中止该授权读取，其他身份继续保留，无自动切换。

撤销单设备按当前工作台查找授权，再在同一次原子提交中删除它、清理所属集合指针并增加 revision。全设备退出删除该工作台所有授权，并逐一更新受影响的浏览器集合；其他工作台授权不变。这样即使被撤销身份暂非目标浏览器当前身份，也不能再从列表切入。工作台加密凭据、偏好和已提交缓存均保留。

为避免只移除非当前身份时干扰当前读取，读取 lease 捕获的是独立的当前选择 revision，列表变更另以集合 revision 防止身份动作竞态。BrowserSession 保存 `revision` 与 `selectionRevision`：添加／切换／当前指针清理增加二者；非当前授权增删只增加 revision。读取检查 selectionRevision，隐式当前操作检查 revision。

## 界面与标签页同步

复用“当前凭据”入口和现有卡片：在当前摘要上方增加“此浏览器的身份”列表，标识显示名称、平台账号和当前身份，提供切换与移除。页头“添加身份”复用 token 表单；重复 token 不生成重复项。没有当前身份但有有效集合时，首页及凭据页可选择其余身份；无身份时显示登录表单。移除确认说明只影响此浏览器，其他设备和工作台保留。

每次身份动作成功后，先增加客户端请求代次、清空旧正文／列表／错误／临时凭据并中止旧请求，再读取新会话。列表移除非当前身份仅更新集合，不清空阅读。读取到相同工作台但不同 selectionRevision 也要更新代次，覆盖 A → B → A。会话 GET 和偏好请求均保留序列检查，较早响应不能恢复旧状态。

使用同源 BroadcastChannel 通知其他标签页“会话已改变”，通知不包含 token、Cookie 或身份摘要。接收后先失效本地请求代次，再读取服务端会话；非当前列表变更只触发列表更新。保留已有 focus、visibilitychange 和定时会话检查作为恢复路径。后台标签页再次可见时先恢复会话再读取正文。

桌面身份行横向排列，窄屏将操作移至下一行；沿用项目字阶、颜色、按钮、弹层焦点和 Escape 约定。实际键盘与 1440、834、390、320px 交互验证覆盖添加、切换、移除、复制和错误状态。原型使用 demo／demo-other，只在内存运行，固定版本随 Change 登记。

## 现有数据与开发机更新

按用户确认，不延续旧 Cookie 或设备会话。读取原 schemaVersion 2 时，严格验证既有工作台及配套密钥，仅保留工作台，构造空的新浏览器集合与授权；首次成功写入原子保存为版本 3。此过程只为保留凭据与工作台数据，不恢复旧登录。不存在状态时直接使用空版本 3；损坏状态或密钥缺失仍拒绝恢复，不覆盖原数据。

工作台的 AES-GCM AAD 保持现有凭据格式 `[2, workspaceId, providerId, instanceId]`，其版本与外层会话 schema 分开，不为新增浏览器关系重加密 token。离线密钥轮换读取并保留新集合、授权和缓存归属；轮换与本次上线无关，不在更新时执行。

生产与验证构建仍使用 `.next`，浏览器 fixture 使用 `.next-e2e`。更新按 service:stop → build → service:start → service:status 执行，然后用隔离浏览器和本机真实服务冒烟验证。旧会话统一需重新登录；不删除数据目录，不做例行备份。构建失败不启动未验证产物；修复后重新构建启动。新状态若确需退回旧服务，必须停机将工作台数据转换为旧外层格式并清空会话，重新验证再启动；不通过恢复旧 Cookie 回退。
