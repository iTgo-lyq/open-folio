# SpecTrail 状态命令与提交校验技术方案

范围与验收见 [Requirement](./requirement.md)。五个命令接入现有 `change` 分组，复用参数定义生成帮助和示例，沿用 active 状态、所属分支、仓库锁、共享校验、原子写入及 `--dry-run`。JSON 沿用 schemaVersion 1，无新增持久化字段。命令或提交校验失败时返回诊断，由调用方修正后重试。

## 任务维护与编号

`task-update --task Tn` 至少传入 `--title` 或 `--branch`，`--branch none` 清除任务分支；`task-remove --task Tn` 删除任务。两者沿用 `task-add` 的可编辑阶段，复用 `task-retry` 对已提交完成记录的检查，允许纠正尚未提交的 `done`。任务标题、分支和删除只影响所选任务，Plan 的对应任务和执行顺序由调用方同步，现有执行前检查仍会核对 Plan。

`task-add` 从当前任务和 `HEAD` 可达历史中同一 Change 的已提交任务取最大编号。Git 查询限定该 Change 的活动及归档记录路径，覆盖归档后返工、合并带入任务，以及删除编号已经提交的情况。读取去重后的状态对象，从 `tasks` 的键计算上限；自动分配取上限加一，显式编号必须高于上限。只存在于未提交修改中的编号在删除后可重新分配。历史读取失败或浅克隆无法确定该 Change 的历史时给出诊断，不用当前最大值猜测。编号检查只在新增任务时运行，提交 hook 无需扫描历史。

## 规模、依赖与子项

- `resize --size small|medium|large` 调整规模。升级时按新规模把最早缺失确认映射到可补录它的阶段，medium 的技术和计划确认都在 `technical`，large 的计划确认在 `plan`。已有确认继续有效，已全部确认且已在执行或关闭阶段时保留该阶段。large 的 `plan` 降为 medium 回到 `technical`；降为 small 时，`technical`、`plan` 对齐到 `requirement`，`execution`、`close` 可保留。规模变化保留已完成任务；若从关闭退回规划，清除原关闭结果及合码确认。用户暂缓继续有效。
- `depends --depends-on <id,id|none>` 替换依赖，`none` 清除。声明时从集中入口核对引用已经推送；进入执行时继续使用现有依赖交付检查。执行中增加或替换前置项时复用同一交付检查，防止未就绪的依赖进入已执行状态。`children --children <id,id>` 替换 xlarge 的非空子项列表，沿用 `create --children` 对列表的规则，支持父项先登记计划中的子项。该命令只改父记录，子项归属和交付沿用现有工作区、关闭与 PR 检查。涉及实质需求或方案调整时先用既有返工流程。
- 子项直接依赖父项和协作者显示名含邮箱都由共享状态校验报错。前者报在 `/dependsOn`，后者报在对应的 `/collaborators/<序号>/name`，只对形如 `name@example.org` 的地址片段报错，保留普通含 `@` 的显示名。CLI、暂存校验、PR 归档校验继续消费同一规则。工作台已有 `collaboratorsSchema` 接入 `validateCollaborators`，对无效补充名单沿用现有诊断并保留 Git 识别的成员。

## Skill 脚本的提交检查

在 `setup pre-commit` 中对本次提交新增、修改或移入 `.agents/skills/spec-trail/` 的 JavaScript 脚本检查模块引用，读取 Git index 中的内容。检查静态 `import`、`export … from`、副作用导入和字面量 `import()` / `require()`，接受相对路径和有效的 `node:` 内置模块，报错包含脚本路径及模块名。用本地、零依赖的轻量扫描识别模块语句，跳过注释、普通文本和本地同名函数调用。原型浏览器验证按需从业务项目解析 Playwright 的既有入口继续可用。此检查聚焦直接声明的依赖，覆盖常规提交与部分提交，保持 Node.js 20+ 的 hook 支持。

## 取舍与验证

- **保留**已有状态写入流程与暂存区校验。锁和原子写入保护现有 worktree 并发与失败重试语义，索引读取保证检查的内容就是本次提交的内容。
- **合并**可共用的状态规则。父子依赖和协作者规则放在共享校验，工作台、命令和 hook 无需各维护一份。已提交任务保护沿用 Git 事实。
- **省去**编号计数器和历史缓存。按单个 Change 路径读取 Git 历史即可恢复编号上限，旧数据无需迁移。提交前模块检查局限在变更脚本，继续使用已接入的 hook。
- **延后**完整 JavaScript 依赖分析和全仓依赖图审计。它们需要更重的语法或跨分支处理，现有直接引用检查与工作流前置校验覆盖本次验收。
