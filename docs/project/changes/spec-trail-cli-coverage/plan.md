# SpecTrail 状态命令与提交校验执行计划

依据 [Requirement](./requirement.md) 和 [Technical](./technical.md)，补齐现有 CLI 的状态维护入口，在命令或提交环节拦截约定的无效操作。

## T1 通过 CLI 编辑任务并保留已提交编号

交付 `task-update`、`task-remove` 与 `task-add` 的历史编号校验，更新命令帮助及用法。使用隔离 Git 仓库验证更新标题、设置和清除分支、删除任务及 dry-run，覆盖当前已完成但未提交与 HEAD 已提交完成两种状态。提交 T1–T3 后删除并提交 T3，自动分配 T4，显式 T3 被拒绝。新建后在提交前删除最高编号时可再次分配该编号；归档返工后保留已提交的编号上限。

## T2 通过 CLI 调整 Change 规模和确认阶段

交付 `resize` 及帮助，复用现有确认和执行入口。用命令串联验证 small 执行中升 medium 后重新确认并进入执行、large 计划中降 medium 后保留确认、降为 small 的阶段对齐以及 xlarge 互转拒绝。复验已完成任务、有效确认、暂缓状态和 dry-run。

## T3 通过 CLI 更新 Change 关系并拒绝无效状态

交付 `depends`、`children` 及帮助，加入共享状态校验。验证替换和清空依赖、替换 xlarge 子项、错误规模拒绝，以及 CLI、pre-commit 和 PR 归档检查对新增无效状态的处理。使用工作台读取测试验证含邮箱的补充协作者触发诊断、原有 Git 成员仍可读，复验仓库现有 Change 记录。

## T4 提交时拦截 Skill 脚本的第三方引用

交付暂存脚本依赖检查。通过实际 Git 提交覆盖第三方模块拒绝、相对路径和 `node:` 放行、注释及普通字符串无误报、部分暂存以索引为准、只改其他路径时跳过检查，并验证原型浏览器验证仍可使用项目提供的 Playwright。

## T5 修复独立评审发现的脚本扫描与流程边界

复验 T1–T4 已承诺的行为，补齐独立评审发现的边界。以实际提交覆盖 Unicode 导入绑定、模板插值中的直接导入、正则字面量和局部同名函数。验证归档恢复尚未提交时，已完成任务仍受保护。验证 small 已有验收记录时，升为 medium 后按新规模重新验收。

## 整体验证

运行 SpecTrail CLI 和 setup 测试、`npm test` 与 `npm run typecheck`，对照需求逐项复核五个命令的总帮助、分命令帮助、示例及 dry-run。整体验证包含独立评审和人工验收。合入后从主工作区执行 `service:update`，检查运行提交及服务冒烟结果。
