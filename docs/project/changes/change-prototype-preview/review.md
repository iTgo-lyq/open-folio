## R1：无原型旧归档错误要求保留标签

证据：生产构建调用 `spec-change-workbench` 的预览描述接口，未关联原型却返回缺少 `spec-trail/archive/spec-change-workbench`。服务在读取是否存在关联前，对所有归档要求标签，影响旧 Change 的空态解释。

修正 T3 的归档入口判定：无关联或空数组保持正常空态；指定历史提交同样不要求多余标签。新增临时中心仓库回归，覆盖字段缺失、空数组及固定版本读取。`tests/previews.test.ts` 5 项通过，同时补充两个 Change 复用一个入口的验收验证。

## R2：annotated tag 发布后的核实误报失败

证据：归档工具能解析已有 annotated tag 的目标，但发布后仅比较 tag object id 与 commit id，实际分支/标签已推送仍报未完成。临时远端回归在修正前复现 `Remote branch/tag verification failed`。

修正 T2 的远端核实：读取 peeled commit 并比较最终目标，保持同提交重试与异提交拒绝的规则，不覆盖已有标签。`tests/prototype-tools.test.ts` 5 项通过，包含新 annotated tag 和重试场景。

## R3：停用后不能只移除部分旧关联

证据：原 Change 有两个 previews，项目 disabled 后仅删除其中一个，hook 仍以整数组不同拒绝提交，与允许删除旧关联的契约冲突。

修正 T1：未启用时逐项深比较，所有保留项必须属于原有集合，新增或改写仍拒绝。暂存回归覆盖停用后普通流程编辑、删除部分、删除全部和改写拒绝；hook 五项既有回归同时通过。

## R4：pnpm 无关的排除规则阻塞接入

证据：`packages/*` 已包含原型包，`!**/test/**` 不匹配原型目录，接入仍失败，反复 `--enable` 都留在 pending。

修正 T2：仅读取顶层 packages 分行列表，使用 Node 内置 glob 匹配分别核对包含与排除项，保留整个 YAML；明确脚本使用 Node.js 24 或更新版本。回归覆盖无关排除正常启用、真正匹配排除保持 pending、修复后重试成功。

## R5：内联源码中的替换字符串被改写

证据：共享脚本 `'abc'.replace(/b/g, '[$&]')` 被导出器自身的字符串 replace 当作替换表达式，生成错误字面量，而非预期的 `a[b]c`。

修正 T2 的基础包和 T5 的项目包导出器：使用替换函数返回原始内容。回归实际执行导出后的脚本，结果为 `a[b]c`；本项目三个产物重新构建后未发生无关内容变化，并通过 Chromium 离线检查。

## R6：累计归档标签数误用单提交入口限额

证据：两个归档标签、每个只有一个入口，服务配置 `previewEntries: 1`，文档 refresh 却整体抛 SOURCE_LIMIT，混淆了累计历史与每个提交的资源限制。

修正 T3：移除归档标签总数与 previewEntries 的耦合，保留既有 Git 超时、输出/文档容量边界与每提交原型限额。回归验证两个标签下的文档刷新及两个历史预览均正常。

## R7：合法 id constructor 无法固定归档

证据：普通对象上的继承属性使 `archivePins[id] ??=` 对 `constructor` 不赋值，快照序列化后没有此 pin，首次读取就被误判标签改写。

修正 T3：用 own-property 判定记录 pin。回归覆盖 `constructor` 归档首次刷新、快照持久化及重启再读取，均恢复正确提交。
