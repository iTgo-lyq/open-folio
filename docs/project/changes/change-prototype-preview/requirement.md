# Change 关联项目原型包与静态预览

## 背景与目标

OpenFolio 已能读取中心 Git 仓库已推送的 Spec 与 Change。技术方案讨论还需要查看页面或局部组件的交互效果，以及不同容器尺寸下的布局。原型应与对应 Change 一起追踪，同时允许用户使用自己的 Agent、设计规范、组件库和开发工具。

一个项目维护一个原型包，作为 monorepo 中的普通包参与 Git 管理。Change 关联包内的静态预览入口，OpenFolio 提供只读浏览。用户可以继续编辑共享源码，回看旧 Change 时仍能看到对应版本。

本 Change 实现这一完整能力，交付范围与验证证据见技术方案、计划和执行记录。

## 范围

包含项目接入选择、SpecTrail 原型子 skill、基础工程约定、Change 关联契约、Git 静态资源读取、项目原型总览、Change 详情预览及历史版本追溯。延续当前单用户私有部署和持久磁盘缓存，不引入数据库。

不包含独立的原型数据或开发平台、模板市场或模板服务、在线编辑器、Agent 调度、云端构建、上传下载原型工程服务、独立制品存储服务、截图生成或截图验收要求。Impeccable 和其他工具均为用户可选工具，不成为运行依赖。现有原型工程也不因为接入而被强制替换框架。

## 行为变化

### ADDED：按项目选择是否接入原型追踪

在技术方案阶段，主 SpecTrail skill 可提出使用原型辅助设计。项目尚未选择时，说明用途并征求用户同意；只有同意后才加载原型子 skill，完成所需接入与初始化。已有明确同意可以复用，无需重复确认。

用户拒绝时，将决定写入项目 Git 配置，阻止原型追踪启用；后续 Change 不再自动反复提议。用户明确改变决定后才重新接入。用户同意但初始化失败时保留未就绪状态，不能显示为已启用。

原型能力放在 SpecTrail 内，组织方式与现有 setup 子 skill 一致。主 skill 只保留入口、选择规则与交接信息，详细操作和基础材料由子 skill 维护。是否使用原型不改变普通需求、技术方案、执行与验收的流程。

### ADDED：一个原型包承载多页面与组件

默认目录为 `packages/prototype/`，已有 monorepo 可以采用自身包布局；项目配置只登记一个包位置。包内共用依赖、设计规范、组件、样式、素材和构建入口，不按 Change 或页面复制工程。

子 skill 提供最低限度的工程结构、`AGENTS.md`、`DESIGN.md` 及静态输出约定。项目已有规范或组件库时优先引用和复用；原型专用差异明确写为补充，避免再维护一套互相冲突的设计标准。没有现成包时才使用基础脚手架初始化，已有兼容包直接接入。运行时没有“模板”实体，也不记录模板选择。

源码和静态产物随项目提交。用户的 Agent 负责开发、验证、构建和推送；OpenFolio 只读取已推送产物。局部原型修改不要求生产应用依赖或打包原型包。

### ADDED：在 Change 内关联预览入口

直接在 `change.json` 增加可选 `previews`，不新增原型清单文件。一个 Change 可关联多个页面或组件，同一包内入口也可被不同 Change 引用。

每项记录稳定 id、标题、仓库相对的 preview 文件夹路径、页面或组件类型，以及适配声明。每个入口目录包含自包含的 `index.html`，脚本、样式、素材和 mock 数据在导出时内联；共享源码和素材继续在同一个包内复用。

页面声明支持的 PC Web、iPad、移动设备；组件可以声明这些设备，也可以声明自定义宽高。适配声明决定可选预览尺寸，不等价于自动验证通过。无原型关联的旧 Change 继续正常读取；禁用、字段错误或产物缺失时给出可理解的原因。

### ADDED：在 Change 详情查看静态效果

沿用现有工作台 UI，在 Change 详情增加“原型”入口。用户选择页面或组件，再切换其已声明的设备尺寸；局部组件按声明宽高展示。画布适应容器的缩放和原型实际布局尺寸分开表达，不能通过缩小浏览器窗口伪装完成了响应式适配。

预览支持随产物携带的本地交互、样式、图片、字体和 mock 数据，不调用真实业务接口。展示关联入口和 Git 来源，支持回到确定版本的链接。页面仍为只读，不从工作台修改源码、流程状态或关联信息。

### ADDED：项目级原型总览

工作台提供与 Specs、Changes 并列的「原型」页面，汇总当前项目已关联的原型，帮助用户了解项目已有多少页面、组件及关联 Change。相同入口路径和类型的关联合并展示，保留各 Change 的来源与版本选择；同一个共享入口不会因为多个 Change 引用而重复累计。

总览支持按名称、入口路径或 Change 搜索，以及页面/组件、设备适配筛选；展示关联的 Change 和状态。用户可直接打开预览，或进入关联 Change 查看设计背景。总览与已有 Change 内预览共用固定版本读取与沙箱，原型关联仍以 change.json 为唯一来源。未关联源码不纳入已关联原型数量，不新增独立原型清单。

未启用、空项目、无匹配项与关联异常分别说明；关联元数据不等于产物已验证可用，点击后仍执行既有资源检查。项目切换与浏览器前进/后退不能串用另一个项目的筛选、原型或版本。

### ADDED：一致读取与历史回看

活动 Change 的每次预览使用其选定 Git 提交中的关联元数据、包配置与完整静态资源，避免刷新到一半混用两个版本。本地未提交、未推送代码不进入预览。

归档 Change 的原型固定到归档交付版本。后续共享组件改版、分支继续推进或正常删除已合并分支，不应改变其历史效果；入口目录不需要搬进 Change 文档目录。若历史引用或产物被仓库管理员删除，应明确提示不可用，不能静默回退到最新版。

原型 HTML/JavaScript 与工作台权限和页面环境隔离；私有项目的预览继承私有访问边界。OpenFolio 内建资源读取与响应能力，复用工作台的同一域名、端口和私有认证；通过不授予同源权限的浏览器沙箱隔离运行，无需额外域名或原型服务。

## 验收标准

| 编号 | 可观察结果                                                                                                                                                                         |
| ---- | ---------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| A1   | 新项目同意接入后完成子 skill 初始化；拒绝后决定可从 Git 读取，后续技术阶段不反复提议，手写 `previews` 也不能绕过禁用状态；显式重新同意可恢复接入。                                 |
| A2   | 重复初始化保留既有文件；初始化失败不启用追踪。已有设计规范和组件库的项目复用原规范，项目内只有一个被登记的原型包。                                                                 |
| A3   | 同一包交付两个页面和一个组件，源码共用组件与依赖；一个 Change 可关联三者，另一 Change 可复用其中一个入口，无需清单文件或截图。                                                     |
| A4   | 页面仅出现其声明的设备选项；自定义组件按宽高渲染；画布缩放不改变 iframe 的 CSS 布局尺寸。入口、设备和固定版本链接可恢复查看上下文。                                                |
| A5   | 多个入口从共享源码导出为自包含 HTML；交互、内联模块、样式、图片、字体和 mock 数据在不请求额外资源时正常运行。同域私有认证仍有效，未推送改动不影响服务中的预览。                    |
| A6   | 同一次预览全部文件来自同一提交。归档后更新共用组件、删除 Change 开发分支、重启或清理派生缓存，仍可通过保留的归档 Git 引用回看原效果。                                              |
| A7   | 禁用、缺少入口、非法适配配置、Git 引用丢失、导出物依赖外部资源和资源超限均给出针对性说明；不影响已有 Spec 与 Change 文档阅读，不把旧缓存当作更新成功。                             |
| A8   | 原型不能读取工作台 DOM、存储或 API 返回的私有内容，不能触发工作台刷新；匿名访问私有预览、路径越界、符号链接、源码读取及不匹配的跨项目版本/入口组合均被拒绝；服务端不运行仓库脚本。 |
| A9   | 既有无 `previews` 的 Change、未接入原型的项目和现有归档语义保持兼容。主 skill、子 skill、hook 与工作台对扩展字段的解释一致。                                                       |

| A10 | 模块导航可直接进入项目原型页；可查看去重后的数量、页面/组件、适配设备与关联 Change，搜索筛选、直接预览、跳转来源、链接恢复及移动端可用；旧 Change 内预览保持可用，异常与停用不会误报为空项目。 |

## 约束与依赖

依赖已归档的 [`spec-change-workbench`](../../archive/2026-10-02-spec-change-workbench/requirement.md)，复用其 Git 采集、只读工作台和 Change 来源解释。其交付已包含在当前分支基线 `446c198` 中。本 Change 为 large，涉及跨 skill、配置、校验、Git 数据与浏览器隔离的共享契约。

静态预览用于设计沟通，不承诺真实设备、浏览器引擎或业务后端的兼容性验证。Git 长期保留产物会增加仓库体积；包约定排除依赖、开发缓存和非交付文件，后续若出现大规模制品管理需求另行设计。
