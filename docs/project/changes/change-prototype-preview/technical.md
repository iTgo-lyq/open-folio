# Change 原型关联与预览技术方案

## 方案

### 总体路径

依据 [Requirement](./requirement.md)，原型是项目内一个 Git 跟踪的 monorepo 包。用户 Agent 在其中开发并生成静态产物，`change.json.previews` 引用输出目录；OpenFolio 从已推送提交读取并通过同一域名下的沙箱 iframe 展示。

```text
技术方案讨论 → 读取项目选择 → SpecTrail prototype 子 skill
                                  ↓ 用户同意后接入
单一 prototype 包：共享源码 → 本地构建 → preview/ → Git 提交并推送
                                                     ↓
Change 主来源提交 → 关联与包配置校验 → Git blob 静态读取
                                                     ↓
工作台 Change 详情 ← 版本与入口元数据     同域沙箱 iframe
```

服务端不 checkout 运行用户工程，不执行安装、构建、Git hooks 或 submodule 初始化。Git 是持久来源，磁盘缓存是可重建派生数据，不引入数据库。以下 JSON 定义项目接入与 Change 关联契约。

### 总览截图与缓存

原型清单仍只汇总元数据。可见卡片按需请求同域 `GET /api/projects/:project/thumbnails/:change/:entry?snapshot=<id>&device=<declared-device>`；服务复用固定提交的预览解析，仅读取当前截图入口的 HTML，其他入口保留树元数据与整体限额检查；生成后的复查也只读取选中入口。当前开关、关联、包路径、历史标签、资源限额均在缓存读取前核实，不接受任意 URL 或 HTML。来源与快照确定被截图的版本，设备必须已声明；无设备参数时页面选首个设备、组件用固定尺寸。

Playwright Chromium 作为显式生产依赖，部署时安装匹配浏览器。每次生成使用带 OS 沙箱的独立浏览器和空白上下文，丢弃宿主凭据环境，不注入 cookies/storage/工作台登录态；通过路由拦截仅返回内存中的已校验 HTML，所有其他请求、WebSocket 和导航被阻断，叠加已有 CSP 沙箱。浏览器沙箱不可用时失败关闭，不降级到 no-sandbox。页面仅离线执行自包含脚本；等待字体、图片和短暂稳定期后，捕获声明 CSS 视口的 JPEG 首屏，禁用动画、不截整页。单次生成含启动和页面运行有总时限，并结束该浏览器，避免脚本卡死占用工作台。

缓存键包含项目/仓库身份、HTML 内容摘要、视口与渲染器版本，因此无关文档提交不重复截图，HTML/适配变化必然更新；来源权限独立于缓存键，每次读取均重新校验。同键并发共享生成，单进程最多 2 个浏览器、24 个排队任务；失败短暂退避，用户可重试。图片写入数据目录内专用私有缓存，原子写入、重启复用；总量上限 100 MiB，闲置 7 天可回收，按最近使用清理。单图片上限 4 MiB。缓存可删除重建，错误不影响 Git 快照和原型预览。

图片响应采用私有缓存并强制重新验证，ETag 对应内容与视口；304 也须先通过当前权限、开关及来源检查，不开放公开静态目录。卡片按进入可视区域加载，等待显示占位、失败提供重试和原有预览入口；版本切换即时重置图片状态。保持卡片截图原始比例，声明尺寸及首屏说明放入按需信息面板，复用现有雾蓝布局。

验证 A11：真实浏览器确认 JS/图片/字体渲染、各设备尺寸及网络/存储隔离，真实 Git 验证来源/历史/当前开关；缓存验证并发去重、重启复用、内容/尺寸隔离、淘汰、失败恢复与超时；UI 验证可见加载、切换来源/适配、错误/重试和手机布局。生产构建使用外部 Playwright 包，保留浏览器依赖安装与沙箱要求说明。

### 项目接入配置与子 skill

扩展已有 `docs/project/workflow.json`，保持 `schemaVersion: 1`，增加可选 `prototype`。缺失代表未选择；已有文件的守护分支字段与含义不变。

```ts
type PrototypeConfig =
  | { status: "disabled"; decision: Decision }
  | { status: "pending"; packagePath: string; decision: Decision }
  | { status: "enabled"; packagePath: string; decision: Decision };
type Decision = { at: string; summary: string; source?: string };
// at 使用带时区的 ISO 8601；summary 记录真实用户选择，不推断同意。
```

默认 `packagePath` 为 `packages/prototype`，可采用项目既有 workspace 布局。必须是仓库内规范相对目录，不可为仓库根、文档目录、依赖目录或符号链接；配置不支持多个包或模板 id。静态根固定为 `<packagePath>/preview`，避免维护两个可漂移的根目录。

本地 Agent 先读当前分支配置并与配置基线核对；如果已有拒绝决定，不得因为切换到旧分支而自动重新提议。项目配置基线使用服务端项目已有 `specBranch`，未指定时使用远端默认分支，来源须明确显示。OpenFolio 以最近成功采集的该基线决定是否开放追踪；基线缺失或非法时关闭预览并诊断，不能取任意分支的 enabled 兜底。新接入决定尚未推送到配置基线时，提示需要发布配置；实现验证可显式配置验证分支。

预览的包路径和契约仍从原型固定提交中的配置读取。当前基线的禁用决定是额外的访问开关，对历史版本同样生效，不篡改历史配置；重新启用后可读取旧提交中当时有效的包路径。这区分“当时的产物结构”和“当前是否启用追踪”，也避免旧链接绕过拒绝决定。配置仅为功能开关，私有权限仍由部署认证边界保证。

原型子 skill 位于 `.agents/skills/spec-trail/prototype/SKILL.md`，与 `setup/` 平级；配套基础材料与初始化/校验脚本放在子目录内。主 skill 增加技术阶段入口和共享类型摘要，通过相对路径加载完整规则；分发 SpecTrail 时连同子目录交付，不安装新的顶层 skill。

接入按如下状态转换进行：

| 当前配置        | 用户或操作                                 | 结果                                                                |
| --------------- | ------------------------------------------ | ------------------------------------------------------------------- |
| 缺失            | 明确拒绝                                   | 写 disabled 与选择依据；停止接入及重复提议。                        |
| 缺失或 disabled | 明确同意或要求重新启用                     | 写 pending，确定唯一包位置，复用或初始化工程。                      |
| pending         | 包结构、设计规范引用和基础静态构建检查通过 | 写 enabled；与相关文件一起提交并推送。                              |
| pending         | 初始化或验证失败                           | 保留 pending 和现场，向用户说明失败；不写 enabled、不覆盖已有工程。 |
| enabled         | 后续技术方案需原型                         | 直接使用原包，不重复安装或创建第二套标准。                          |
| enabled         | 用户明确停用                               | 写 disabled；保留历史源码、关联和产物。                             |

初始化幂等：先检查目录、workspace、包名和已有规范，已有兼容工程只补充缺失约定；内容冲突先报告具体差异，不重写用户文件。共享设计规范作为 `DESIGN.md` 引用的权威来源，包内只补充原型约束。源码优先 workspace 依赖现有组件库；需要后端或运行时耦合的组件使用轻量适配/mock，且注明差异，不伪称原组件已验证。

### 原型包与静态产物

```text
packages/prototype/
  package.json                 # 独立 workspace 包；不成为生产应用运行依赖
  AGENTS.md                    # 开发、构建、关联及交付规则
  DESIGN.md                    # 引用项目规范，补充原型特有约束
  src/                         # 用户自行组织；页面、组件、主题可复用
  preview/
    order-list/index.html
    order-detail/index.html
    price-card/index.html
```

源码目录和构建工具不属于运行时协议。基础示例直接生成自包含 HTML；使用 Vite 或其他构建器的工程在用户侧完成离线导出，按入口将脚本、样式与素材内联。普通 HTML 也有效，不强制 React、组件库或 Impeccable。共享源码和依赖仍在一个包内管理，导出多个 HTML 不等于复制多个原型工程。

每个关联目录的 `index.html` 是自包含交付物：JavaScript 与 CSS 内联，图片与字体使用 data URL，mock 数据内联。源码可以正常引用共享资源、组件、ES modules 和 JSON；导出时合入 HTML，不能遗留外部 import、动态 chunk、fetch/XHR、相对资源请求或 CSS @import。无外部导入的内联 module 脚本可运行，构建产物不需要改成特定框架。

入口内使用 hash/memory 路由或本地状态切换；多个独立 HTML 由工作台入口选择器切换，不能依赖沙箱内部导航到另一个受认证页面。服务不实现任意路径回退，不负责打包或改写用户脚本。子 skill 的本地交付检查应验证在阻断子资源网络请求时仍能工作，指出不兼容的导出依赖；不能仅删除引用以使检查通过。禁止依赖开发服务器、真实业务接口、外部 CDN、密钥和环境变量注入。

Git 跟踪源码、锁文件、必要设计文档和 preview 输出；不跟踪 node_modules、工具缓存、开发日志和 sourcemap。构建后由 Agent 检查关联目录、资源与已声明视口，并提交源码和产物。未改动的输出可以沿用；服务不能仅根据提交时间判断构建过期，也不声称证明了源码与产物一致。整包构建时保留仍被其他活动 Change 引用的入口；删除入口前检查引用，历史版本由归档提交保留。

### Change 关联契约

```json
{
  "previews": [
    {
      "id": "order-list",
      "title": "订单列表",
      "path": "packages/prototype/preview/order-list",
      "kind": "page",
      "devices": ["pc-web", "ipad", "mobile"]
    },
    {
      "id": "price-card",
      "title": "价格卡片",
      "path": "packages/prototype/preview/price-card",
      "kind": "component",
      "viewport": { "width": 640, "height": 320 }
    }
  ]
}
```

`previews` 可省略或为空；非空数组保留展示顺序。id 为 Change 内唯一 kebab-case，标题非空，path 为仓库相对目录且必须在已配置 preview 根下，目录中必须有常规 blob `index.html`。拒绝绝对路径、URL、查询串、fragment、反斜杠、控制字符、空段、`.`、`..` 和目录外引用。不提供自定义远程预览 URL。

`kind` 仅为 page/component。page 必须有非空且去重的 devices；component 在 devices 与 viewport 中二选一。viewport 的 width/height 是 1–4096 的整数 CSS 像素，禁止同时声明两种显示模式。设备枚举仅支持 pc-web、ipad、mobile，显示名为 PC Web、iPad、移动设备。默认画布分别为 1440×900、834×1194、390×844 CSS px，设备内可切换横竖方向；这些是预览预设，不能宣称模拟了真实硬件、触控或浏览器。

关联字段、已发布的 skill 类型、hook 校验和服务 schema 同步扩展。hook 校验暂存版本的字段、配置和入口存在性，不读取未暂存工作区来证明可交付；资源超限等服务部署约束由服务明确诊断。禁用或 pending 时拒绝新增或改写非空关联，允许删除旧关联及编辑普通流程字段，不因停用就锁死后续 Change 推进。历史关联仍可被读取为元数据，不能触发实际预览。

已知扩展字段单独解析：原型字段非法时保留 Change 核心流程、文档和原始数据入口，报告具体关联错误并禁用该入口，不让整个 Change 从工作台消失；原有未知核心字段仍严格校验。不以 Markdown 修复或覆盖 JSON 关联。

### Git 版本固定与归档

活动预览在服务采集时先选定 Change 主来源分支及完整 commit id，再从同一提交读取 Change、workflow 和 preview 树。包内所有资源固定到这个提交；UI 刷新后只通过新的入口描述整体切换，不在文件请求时重新解析分支 HEAD。

固定链接表达 project、Change id、完整 revision、preview id 以及设备/视口选项，不接受任意仓库 URL。历史 revision 必须可从该项目当前已拉取的允许分支或专用归档引用到达，并在该提交中找到匹配的合法 Change；只知道 SHA 不是读取权限。超出允许来源或丢失的版本明确不可用。

对携带非空关联的 Change，归档子流程创建保留引用 `refs/tags/spec-trail/archive/<change-id>`，指向同时包含归档 JSON、配置及静态产物的归档提交。标签不是另一份原型元数据，所有原型详情仍在该提交的 Change 中。无关联的旧 Change 不要求补标签。

标签首次创建后禁止自动覆盖；同名且同提交可幂等重试，同名异提交报告冲突。分支与标签优先原子推送；远端不支持时按分支、标签顺序推送并验证，任一步失败不得报告完成归档交付，也不伪造远端状态。OpenFolio 对非空关联的归档记录只有在标签目标包含一致的 id、归档路径及 completed 记录时才接受其预览版本。标签缺失时普通归档文档仍可读，但预览显示缺少固定引用。

扩展现有 fetch：分支保持原策略，显式只拉取 `refs/tags/spec-trail/archive/*` 到服务专用远端命名空间，不自动拉取全部标签。每次成功刷新核对远端引用清单，已删除引用不因本地残留或缓存而继续被接受。服务不向用户仓库写标签；创建和推送属于 Agent 的归档流程。共享源码继续演进不改变标签目标，归档目录只读。人工强删或改写远端引用无法保证永久回看，应诊断而非回退最新版。

### Git 资源采集与缓存

采用两阶段读取：先沿用文档快照确定配置和 Change 关联，再按有效关联读取同一提交中的各个 `<path>/index.html`。读取 preview 树的文件元数据进行容量检查，仅读取被关联的 HTML 正文，不暴露通用目录浏览或资源代理，也不为了预览抓取源码、依赖或整个仓库文件系统。共享源码及素材已在用户侧导出时内联。

仅读取常规 Git HTML blob，拒绝 symlink、gitlink 和 Git LFS 指针代替实际内容。关联外的 CSS、JS、JSON、图片、源码及其他路径不能通过预览路由读取。内联图像作为 HTML 中的数据资源呈现，不提供 SVG 等独立可执行文档入口。HTML MIME 与 nosniff 一起明确执行格式。

增加可配置的资源限额，初始默认单 HTML blob 10 MiB、单项目单提交 preview 根内 HTML 合计 100 MiB、2000 个入口；重复引用同一 blob 不重复计费。超限只使对应原型不可用，不拖垮全部文档刷新。读取受现有 Git 超时、并发与错误脱敏约束。入口缺失、LFS 指针、非法资源和超限均给出项目/入口级诊断。

缓存键包含仓库指纹、完整提交、包根、blob id 和缓存格式版本，文件权限沿用私有缓存。新旧快照原子切换。历史预览缓存可按容量回收，需要时从仍可达的 Git 引用重建，不依赖当前仅保留三个文档快照的策略。每次响应先核对项目仍配置、原型功能仍允许、提交仍属于合法来源；撤销配置、仓库替换和最新成功刷新确认的引用删除优先于缓存命中。刷新失败可保留先前成功快照并标记时间，不宣称获得最新撤销信息。

### 内建静态服务与浏览器隔离

工作台与预览复用同一个域名、端口、OpenFolio 进程和私有访问网关。取消 `preview.origin`、双 Host 分流、额外域名/端口及第二套登录配置。部署认证继续覆盖所有预览请求；不提供绕过网关认证的资源通道。本地无认证模式继续只绑定 loopback。

iframe 通过同站页面导航加载 `/preview/<project>/<revision>/<change>/<preview-id>/index.html`。路由只接受 GET/HEAD，按关联 id 在固定提交解析真实路径，浏览器不能传任意文件路径或仓库 URL。沿用 Host 白名单及同站请求校验，保留项目配置、功能开关、提交可达性和关联存在性检查。非法参数、编码越界和不匹配的跨项目版本/入口均拒绝，不进行跨边界重定向。

iframe 使用 `sandbox="allow-scripts"`，绝不加入 allow-same-origin。虽然请求 URL 与工作台同域，浏览器将沙箱文档视为 opaque origin，无法访问工作台 DOM、Cookie、localStorage 等。HTML 响应同时设置 CSP sandbox，让直接打开原型 URL 也保留这一限制。CSP 基线为：

```text
sandbox allow-scripts;
default-src 'none'; script-src 'unsafe-inline'; style-src 'unsafe-inline';
img-src data:; font-src data:; connect-src 'none';
object-src 'none'; frame-src 'none'; worker-src 'none';
base-uri 'none'; form-action 'none'; frame-ancestors 'self';
```

这一选择要求自包含 HTML。实际浏览器探针表明，去掉 allow-same-origin 后子资源请求的 Origin 为 null，SameSite=Lax 登录 Cookie 不随模块、字体和 fetch 子请求发送，即使请求声明 credentials: include。只给资源增加 CORS 不能解决私有网关认证问题。将运行资源内联后，只有 iframe 文档导航请求需要认证，不再依赖匿名资源路由、短期访问令牌或跨 origin CORS。来源与实验边界见 [Research](./research.md)。

不启用 unsafe-eval、弹窗、下载、表单提交、顶层导航、网络访问或 Service Worker。Permissions-Policy 禁用相机、麦克风、定位等设备能力。响应使用 `text/html; charset=utf-8`、`X-Content-Type-Options: nosniff`、`Referrer-Policy: no-referrer` 和 `Cache-Control: private, no-store`，不放入 Next public 目录或公共 CDN。工作台 API 仍拒绝 Origin:null，不给沙箱开放 CORS，不接受原型消息来执行导航、读写文件或调用父页面 API。

该模式只授予内联脚本完成局部交互的能力，不给原型持久存储和后端访问能力。运行中 mock 状态保存在页面内存，重载后重置。沙箱内自身导航可能发生，不能以 CSP 宣称完全杜绝出站导航；原型产物不得包含秘密。不承诺防御浏览器漏洞，但原型不能借当前应用同域的 URL 获得工作台 origin 的权限。原型 HTML 包含的内容对有项目访问权限的用户可见，属于预期交付。

### 项目原型总览

工作台增加 `m=prototypes`，与 Specs、Changes 并列。受保护的 `GET /api/projects/:id/prototypes?snapshot=` 从指定文档快照中的 Change 主记录汇总关联元数据；使用当前成功快照的 prototype 开关，停用时仍可解释已关联内容，但不加载 HTML。仅读取已采集的 JSON，不为总览枚举工作区、运行构建或提前执行所有原型。

按「入口 path + kind」分组，合并同一入口被多个 Change 引用的情形。每条关联保留 Change id、标题、状态、入口 id、适配声明和记录 commit；默认优先活动 Change，其次归档、取消，并按 id 保持稳定顺序，不把不同分支排序解释为时间上的最新版。归档真正可预览的 revision 仍由既有保留标签解析。

总览统计已关联入口、页面、组件及关联 Change 数；支持 `pq` 搜索名称/路径/关联 Change、`pkind` 类型、`pdevice` 适配筛选。异常单项不计入有效入口，其他合法项继续展示，提供对应 Change 的可读诊断。无法确定主来源时不猜测版本，不用重复的分支副本增加计数。

界面延续工作台雾蓝底、深蓝操作色、现有字体与细边框。页面头部说明项目总量，卡片以截图为主体，底部仅保留可点击名称、轻量类型标记与更多信息按钮。更多按钮通过已有 Radix Popover 在独立浮层展示路径、声明适配、截图尺寸和关联版本，提供查看 Change 操作；浮层支持 Escape、关闭后焦点归还、窄屏边界及触屏，不依赖悬停。点击图片或名称打开既有 Change 原型抽屉，保留总览筛选与返回路径。复制固定版本链接在原型模块打开时保留该模块；主导航/项目切换清理旧预览和版本参数。手机上卡片单列，工具栏换行，保留键盘操作。

### 工作台入口与可读错误

在 Change 详情现有标签中增加“原型”，入口列表取关联数组顺序，首次选第一项，后续从 URL 恢复。URL 增加 preview/device/orientation/revision 查询参数；失效的选择回到第一个有效项并说明，不错误套用其他 Change 的入口。无关联时显示空态；项目拒绝或待初始化时说明原因，不提供可绕过选择的启用按钮。

页面固定 iframe 的 CSS 宽高，再通过外层缩放适应画布。工具栏同时显示设备/自定义尺寸和缩放比例，提供适应画布与 100% 查看；组件居中，超过容器可滚动。使用可访问的 iframe title 和键盘控件，保留原抽屉的返回与焦点行为。

入口描述由受保护的主 API 返回：包含提交、关联、视口和经过校验的预览 URL/不可用原因。先完成元数据和资源存在性检查，再创建 iframe。iframe load 不作为构建成功或运行验证的证据；运行错误由浏览器验证与原型包交付检查发现。入口加载、认证失败、配置缺失、产物不可用分别展示，不自动构建或改写 Change。导出校验检查静态外链并在浏览器中捕获网络请求/CSP 违规，不能只靠正则断言动态脚本没有网络依赖。正式预览可由服务在 HTML 起始处加入固定的 CSP 诊断引导，向父页面发送受限错误码；父页面仅在消息来自当前 iframe 且与当前加载实例匹配时显示转义后的提示，不执行消息指定的动作。不把诊断消息或 iframe load 当作验收证明。

## 影响与取舍

原有 `schemaVersion: 1` 增加可选字段，新客户端读取旧数据；旧版本严格 schema 不兼容新增字段，发布需先升级主 skill、hook 和服务，再启用配置并写入关联。回退旧应用前移除或恢复旧契约提交，不能声称任意降级兼容。缓存格式升级可丢弃旧派生缓存重建，归档 Git 引用保留。

项目级启用基线与 Change 来源分支分开，避免一个旧分支重启被拒绝的功能；代价是首次接入需把配置发布到服务认定的基线。同域沙箱避免新增部署配置；代价是导出物必须自包含，不能直接预览仍依赖外部文件的普通构建目录。用户继续自由组织源码和复用组件，离线导出责任在用户侧 Agent。多个入口可能重复内联共用代码和字体，需要遵守 HTML 大小限制；首版不通过放开沙箱权限来换取外部资源兼容。

归档标签保留一次交付的所有静态资源，也保留整包当时的源码；代价是 Git 历史持续占用空间。首版不引入制品清理、存储去重产品、构建证明清单或原型版本数据库。服务可做 blob 缓存去重，不改变仓库协议。

停用原型功能时只关闭入口和资源响应，保留现有文档读取；源码、产物和关联不自动删除。正式实现经用户验收后再同步 Specs。
