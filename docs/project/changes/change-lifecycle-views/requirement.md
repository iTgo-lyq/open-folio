# 按 Change 状态简化浏览视图

## 背景与目标

用户确认只有进行中的 Change 需要突出阶段，要求取消“全部”视图并开始优化。归档、取消和来源异常的浏览重点分别是完成结果、取消依据与数据问题。沿用已认可工作台样式和已合入 main 的原型/Change 能力。

本轮为 small：单一展示调整，不改变状态契约、流程判定、历史记录、读取权限或部署架构。复用已明确方向及持续推进授权，不另行确认 Plan。

## 范围与行为

- REMOVED：Changes 的“全部”标签及清除筛选跳到全部的行为；旧 scope=all/非法范围链接兼容为进行中，保留具体 Change 深链接。
- MODIFIED：仅进行中提供 Change 阶段筛选、等待/阻塞筛选和阶段看板。切换范围清理不再适用的参数；非进行中旧看板链接回到列表。任务粒度的状态看板和关系追溯保留，它们不表示 Change 阶段。
- MODIFIED：进行中列表保留当前阶段与进展；已归档列表显示归档时间和完成结果；已取消显示取消时间/原因；来源异常显示主来源与实际问题。保持共同搜索、规模、关联能力筛选，清除筛选留在当前范围。
- MODIFIED：仅可信的 active 记录在详情头部显示阶段徽标和流程进度。其他记录显示结果/来源提示；归档概览突出结果与归档时间，取消概览突出原因与时间。历史阶段、关闭步骤、任务和确认仍保存在依据/任务页签与原始记录中。
- MODIFIED：无此类记录与筛选无匹配有不同空态，不通过已移除的全部范围恢复。

## 方案要点

仅调整现有客户端 Changes 组件与相关样式、URL 展示规范；数据模型和 API 不变。范围参数统一解释，禁止隐藏筛选继续影响结果；详情按实际记录判断，不因来自原型页、搜索或其他范围的深链接误判生命周期。来源错误不展示当前阶段；任务依赖等警告仍单独提示，不抹除合法 active 状态的阶段。沿用雾蓝配色、列表行与抽屉，手机布局和键盘返回保持可用。

## 验收

A1：仅四个状态标签，旧 all 链接落到进行中，直达归档/取消详情仍正确；没有入口或清除操作重新写出 all。
A2：进行中阶段筛选/看板仍正常；切到其他范围时隐藏对应控件和阶段列，旧阶段/等待参数不筛空结果，任务状态看板保留。
A3：归档/取消列表和详情不出现当前阶段/流程进度，来源异常展示具体问题；时间与说明取实际记录，历史阶段与关闭证据仍可查看。
A4：清除筛选留在当前范围；空态、浏览器历史/深链接、搜索/原型打开详情与320px布局可用；已有Change/原型浏览回归通过。
