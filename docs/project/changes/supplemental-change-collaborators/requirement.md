# 补充 Change 协作者配置

Git 材料提交作者不能覆盖所有实际参与者。延续 `change-collaborators`，允许为 Change 显式补充协作者，供现有列表、看板、归档及分享阅读展示。

用户明确要求：“这个协作者只做补充，不是覆盖”。配置名单与 Git 历史识别的创建者和参与者合并，不能覆盖、隐藏或删除历史成员，也不改变创建者及其排序。

## 行为与验收

- `change.json` 可选 `collaborators` 数组，每项包含必填显示名 `name`，可附 GitHub 登录名 `login`、数字身份 `subjectId`；不保存邮箱。省略或空数组沿用 Git 识别结果。
- CLI 支持在创建时传入名单，以及单独设置、更新或清空活动 Change 的补充名单；清空仅移除配置补充的成员，保留 Git 识别的协作者及其他流程记录。
- 成员按既有 GitHub 数字身份、登录名规则与自动名单去重；身份相同时保留历史成员的显示信息。仅同名但身份不同的成员不强行合并。
- 创建者仍固定第一，其他 Git 参与者保持既有顺序，新增补充成员按配置顺序追加；不存在 Git 记录时仍可展示配置成员，但不冒充创建者。
- 非法名单由状态命令及提交校验拒绝；工作台对非法可选配置提示诊断并保留 Git 识别与原有流程事实。分享投影展示合并结果且不增加邮箱泄漏。

## 方案要点

规模为 small：这是既有协作者能力的可选配置扩展，复用状态校验、CLI 和协作者索引，不改变页面交互或持久数据迁移；预计不足 300 行有效实现代码。

共享校验统一定义成员形状，读取器复用该校验并将配置成员合入现有身份去重流程。配置只取 Change 的正式材料来源，不采用过期集中副本。通过定向测试验证状态读写、身份合并、非法配置与分享投影，再做类型检查、构建和必要冒烟。
