# 数据模型不兼容升级的方案取舍

## 目标与范围

用户要求补充技术方案设计规则：「涉及数据模型升级无法兼容的时候，都要询问用户方案，你不要擅自制定过分防御性兼容的方案。很多时候其实不兼容也就不兼容了。」

在 SpecTrail 技术问询中明确：数据模型升级不兼容时，Agent 先查明影响，再由用户决定是否接受不兼容及旧数据如何处理；已有明确决定直接沿用。不能把保留兼容当作默认目标，也不能未经确认自行放弃或清理旧数据。

本次为 small：仅补充 skill 的方案决策规则和对应 Spec，不修改产品实现、状态契约或实际数据；用户本轮已明确要求补充，沿该方向直接完成。

## 方案要点

在技术问询规则中说明影响、可行选项和复杂度代价，允许直接接受不兼容；只按实际需要讨论迁移或兼容，不预设兼容层、双版本读写或自动迁移。技术就绪条件要求相应取舍已有用户决定，未明确时不推进受影响实施；沿用现有问询额度和确认机制。

## 验收

- 数据模型不兼容升级明确属于必须由用户取舍的问题，且要求先查明影响。
- 接受不兼容是有效方案；兼容或迁移须有已确认需要，不自动增加防御性机制。
- 已明确的决定不重复问询，未明确时不擅自实施；small 同样适用。
- skill 校验与差异检查通过，长期 Spec 与最终规则一致。
