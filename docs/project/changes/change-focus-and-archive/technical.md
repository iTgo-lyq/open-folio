# Changes 动态视图与已发布归档：技术方案

个人视图保存一组查询条件与显示选项，结果随仓库数据和当前 GitHub 身份变化。复用已有工作台快照、账号文件存储和目录过滤，只新增账号级视图配置与编辑草稿；不为每个视图重新请求仓库、拉取 Git 或维护一份 Change 名单。

## 现状与调整依据

| 现状 | 本次调整 |
| --- | --- |
| `personal-sessions.ts` 的 `Workspace.preferences` 属于 Token 工作台，仅含仓库、模块和侧栏偏好 | 个人视图按账号与稳定仓库键保存，切 Token 后仍可使用；原工作台偏好保留 |
| `change-directory.ts` 使用单个 scope，已完成包括已发布 | 共享查询支持四类状态多选，交付已发布单独归档；列表、计数、相邻详情使用同一分类 |
| `changes.tsx` 会清除非进行中的 `view=board` | 保留保存的显示偏好，只计算当前可用的展示方式 |
| 首次提交作者只解析出 name/login；当前连接已有 GitHub subjectId/login | 保留可识别的 GitHub 数字 ID，“本人”动态匹配当前连接身份 |
| 页面已有会话内阅读缓存、后台刷新、身份切换隔离 | 原样复用；视图切换只过滤已加载数据，视图配置单独读取和缓存 |

代码依据：`src/server/personal-sessions.ts`、`src/server/providers/types.ts`、`src/server/changes.ts`、`src/lib/change-directory.ts`、`src/components/context.tsx`、`src/components/changes.tsx`。独立只读调查核对了上述边界；本轮不修改这些正式实现。

## 账号存储与契约

在已有账号记录增加可选 `changeViewsByRepository`。外层键复用 `repositoryKey(providerId, instanceId, repositoryId)`，由服务端核对当前连接可读仓库后确定；仓库显示名、集成分支和 Token ID 不进入此键。不同账号拥有独立记录，视图中的本人条件跟随当前 Token 身份。

```ts
type ChangeDirectoryState = "active" | "completed" | "archived" | "cancelled";
type SavedChangeQuery = {
  states: ChangeDirectoryState[]; // [] 表示不限制，包含四类正常记录
  creators: { self: boolean; values: string[] }; // 本人或固定作者，组内并集
  types: string[];
  noTypes: boolean;
  urgencies: ("urgent" | "high" | "normal" | "low")[];
  display: "list" | "board";
  group: "status" | "stage" | "none";
  sort: "created" | "urgency";
};
type SavedChangeView = {
  id: string; // 默认我的为保留值 mine，其余为 UUID；改名不变
  name: string;
  hidden: boolean;
  query: SavedChangeQuery;
};
type SelectedView =
  | { kind: "personal"; id: string }
  | { kind: "system"; id: ChangeDirectoryState };
type RepositoryViews = {
  revision: number;
  views: SavedChangeView[]; // 数组顺序即个人 tab 顺序
  selected: SelectedView;
};
```

仓库记录不存在才初始化默认“我的”：`active + self`，列表、按处理状态分组、最新创建；记录存在但数组为空表示用户已删除所有个人视图，不再次初始化。默认“我的”以保留 ID `mine` 识别，回退时不依赖用户可修改的名称；其他个人视图生成 UUID，服务端拒绝重复 ID。系统快捷 tab 保持固定，个人 tab 在前按保存顺序排列；“我的”可编辑、隐藏、删除。

新增可选字段允许新版本直接读取旧账号数据，无需清空数据、重建账号或重绑 Token。继续由 `PersonalSessions` 的进程内锁、单实例文件锁和原子文件写入保证持久化。新字段写入后旧二进制的严格 schema 未必能读取，不提供降级运行承诺；正常发布使用完整新版本。不新增数据库、独立同步服务或迁移任务。

约束：每账号每仓库至多 30 个视图；名称 trim 后 1–40 个 Unicode 字符，同仓库个人视图名称不重复；固定作者及类型各最多 50 项、单项最多 128 字符，数组去重，状态和显示选项严格枚举。按整个仓库视图配置限制 UTF-8 JSON 不超过 64 KiB；请求体带 revision 的上限设为 72 KiB，仅此路由使用该上限，其他个人 API 保持现有 16 KiB。UI 与服务端给出同一可操作的超限错误。

### 接口与并发

新增 `/api/repositories/:key/change-views` 路由，沿用当前 connectionId、仓库选择上下文与 lease 验证；账户 ID 取 HttpOnly 会话，不能从请求体指定。复用已有仓库权限校验，不为读取视图配置触发 workbench refresh 或 Git 同步。未知、失权或已切换连接返回现有权限/身份错误，不将账号视图写入另一个仓库。

| 请求 | 内容与结果 |
| --- | --- |
| GET | 返回当前仓库记录或 `null`；只读，不触发首次写入 |
| POST | 首次进入时 ensure 默认记录；锁内“存在则返回，不存在才创建”，两个浏览器同时进入只生成一份“我的” |
| PUT | `{ expectedRevision, views, selectAfterSave? }`；一次确认整体提交管理草稿。`selectAfterSave` 仅用于选择本次新增且可见的视图。成功返回完整记录及新 revision |
| PATCH | `{ selected }`；记录最近选择，独立于定义 revision；不让普通 tab 切换制造管理冲突 |

PUT 在锁内比较仓库配置 revision（账号会话 browserRevision 仍独立验证）。两个浏览器编辑同一仓库时，后提交旧 revision 的请求返回 `409 VIEW_CONFLICT`，不覆盖已保存数据；客户端保留草稿，提供重新加载管理列表或复制本地配置的可见途径，避免静默丢失。此版本不做自动三方合并。保存当前视图也通过同一 PUT、同一 revision，不能只在客户端用旧列表覆盖服务端。

PATCH 只处理最近选择，目标已被隐藏或删除时回到可见的“我的”，否则进行中。PUT 不携带打开面板时的旧 selected；除明确新增后的选择外，保留服务端最新选择，并在同一事务中处理隐藏/删除当前项的回退。同一页面 PATCH 排队合并为最新目标，响应不反向跳转当前页面；其他设备的最近选择只影响下一次无显式查询进入，不抢占正在阅读的页面。

写请求复用 `requirePersonalOrigin`、`requestRevision`、身份 lease 与 `renewPersonalResponse`，响应使用 private/no-store。保存成功必须以成功响应为依据；不能沿用 `updatePreferences` 在 SESSION_CHANGED 恢复后直接返回的成功语义。身份过期、换账号或失权时终止保存并清除相应私有 UI；普通网络失败保留草稿与已显示数据，提示重试。

## 查询、缓存与恢复

客户端区分三个对象：服务端已保存定义、当前 URL 查询、管理面板草稿。主列表临时调整只修改 URL 和当前结果，定义不变；规范化后比较完整查询决定“未保存修改”，支持恢复、保存到当前视图和另存。个人视图 ID 用于本账号选中提示，不能替代可独立复现的查询。

| 入口 | 查询来源与优先级 |
| --- | --- |
| 包含筛选/显示参数、scope、states 或指定 Change 的链接；刷新、历史前进后退 | URL 优先，异步视图响应不得覆盖；详情目标始终可打开 |
| 无显式目录查询的新入口 | 同账号同仓库最近选中的已保存定义；第一次为“我的” |
| 点击个人 tab | 原子写入该视图完整查询及 `changeView=<personal-id>`，排队保存最近选择 |
| 点击系统 tab | 对应单状态和默认其他条件，写入 `changeView=system:<state>`；随后可临时调整或另存 |
| 隐藏/删除当前个人视图 | 切到可见“我的”，否则进行中；不删除 Change；仅修改其他视图时不重置当前临时查询 |
| 详情返回 | 仅清除详情参数，保留原视图及临时查询 |

新增 `states` 参数用 JSON 数组编码（含显式 `[]`），优先于旧 scope；新生成的链接始终显式包含 states。旧 `scope=active/completed/cancelled` 仍正常解析，并支持 archived；旧 issues、pendingIntegration、pendingRelease 的映射沿用原逻辑。`creatorSelf=1` 表达当前阅读者的本人条件，固定作者继续使用现有 creator 数组；其他筛选/显示沿用现有参数。系统与个人 ID 分命名空间。未知、已删或其他账号的个人 ID 不加载他人的定义，按 URL 条件显示临时查询，允许另存自己的视图。

分享当前目录条件时省去个人 view ID，保留独立查询；本人条件在接收者账号下重新计算，不表示发送者。现有 Change 公开分享仍只定位 Change，不暴露私人视图名称或定义。没有显式目录查询但带 `c` 的历史详情链接直接阅读，列表上下文采用确定的默认进行中，不等待个人偏好来打开详情。

复用现有 workbench ReadingCache：切视图、排序和筛选不发仓库刷新请求、不清空列表；正文和原型缓存不受影响。视图定义使用会话内按 `accountId + repositoryKey` 的缓存，已有缓存立即展示、后台核对；新会话的视图读取和工作台读取并行。无配置缓存且无显式查询时，在 tab/列表区域展示短暂加载态，避免先显示全部再突然变成我的；工作台数据与指定详情不等待该请求。

后台返回定义只更新缓存，不覆盖用户已经调整的当前 URL 或打开的草稿。另一设备更新定义时仅提示“视图已更新”，由用户重新点击该 tab 或恢复视图后采用新定义；即使当前未标脏，也不覆盖从显式 URL、刷新或历史恢复的条件。当前会话已选中的视图被隐藏/删除后按既定回退；首次解析已经失效的个人 ID 则按 URL 临时查询显示。写操作返回后以当前请求 generation、账号、连接和仓库身份复核再应用，晚到响应不跨账号或仓库污染。缓存于退出清理；不在 localStorage 另存一套视图，不新增轮询或 BroadcastChannel，重新进入/打开管理面板/窗口重新聚焦时按需核对即可。

## 状态分类与“本人”

### 状态分类

单一 `classifyDirectoryState(change, delivery)` 服务于过滤、tab 计数、分组、详情相邻项及延续组：

| 条件 | 分类 |
| --- | --- |
| 当前有效流程状态 active | 进行中 |
| 当前有效流程状态 cancelled | 已取消 |
| 有效 completed 且既有交付证据为 releaseMerged | 已归档 |
| 有效 completed，交付为 pendingIntegration / pendingRelease / unknown | 已完成 |
| 无法形成有效流程记录 | 既有来源异常入口，不归入普通状态集合 |

不将工程文档归档、合入 develop 或待发布当成已发布。继续使用 `delivery.ts` 的 PR/祖先关系核实和有效历史发布补记，不新增归档按钮、流程状态或删除操作。临时更新失败保留既有成功快照及其分类；收到没有发布依据的新结果时仅使用其可确认状态，不凭前端记忆新增已发布事实。

状态组内 OR，与类型、创建者、紧急程度组间 AND；创建者的 self 与固定值也是 OR。只在一次过滤后计算延续组，关联成员不绕过过滤。系统 tab 数量按整个可读仓库数据统计；个人 tab 数量按保存定义统计，当前临时过滤的实际数量体现于列表分组。取消总数为 0 时只隐藏系统取消 tab，自定义取消视图和编辑器选项保留。当前页面接收仓库更新，取消总数从非零变为零且正在系统取消 tab 时，切回进行中并保留显式详情参数 c；首次打开数量已经为零的历史取消链接仍显示空结果或指定详情，不强制改写 URL。

多状态列表先按进行中、已完成、已归档、已取消分组；进行中内部沿用按处理状态/阶段，已完成内部按待集成/待发布/待核实，已归档与已取消不套用处理状态。`group=none` 始终平铺。各组内部沿用创建时间/紧急程度排序，详情相邻项按实际列表顺序展开。看板的 effectiveDisplay 仅在“只选进行中、非来源异常、桌面”时为 board，其余为 list，原始偏好不被写回覆盖。

### 本人身份

在现有首次 Git 提交作者解析中，保留 GitHub noreply 邮箱携带的数字 subjectId 和已识别 login；不向前端发送邮箱。数字 ID 存在时优先与当前 Token 的 GitHub subjectId 精确比对；ID 不同则不能因 login 或姓名相同而匹配。旧式 `<login>@users.noreply.github.com` 只有 login 时不能自动确认本人，仍允许固定创建者筛选；普通 Git 姓名/邮箱不猜测归属。本期“本人”只自动匹配可解析的 GitHub 数字 subjectId，login 仅供展示与固定筛选。该匹配反映 Git 提交作者资料，不是提交签名认证。

历史 login 改名或重新分配的归属无法由旧邮箱可靠追溯；界面说明仅可识别的平台作者可自动归入“我的”，其余可通过固定创建者筛选阅读。已有快照中的 creator 作为可读旧数据保留，缺少增强标记时不把任意 name 或不明来源 login 当本人；下一次正常刷新由 Git 资料重建，无需逐 Change 请求 GitHub、全量删缓存或阻塞首次阅读。

## 交互方案与原型

原型复用 `quiet-changes`，保持七组现行入口，不创建第二套工作台。用户截图仅用于视图切换、末尾齿轮和列表式管理弹层的交互参考。页签复用 OpenFolio 现有紧凑圆角分段样式，筛选和显示保留在同一工具栏右侧，额外条件标签在下方；系统状态入口的对应状态，以及初始“我的”的进行中/本人条件不重复展示、不计入筛选角标，无额外条件时省略标签行。该省略只影响展示，筛选面板、编辑表单与查询保留完整条件；自定义视图仍展示其条件。颜色、字号、间距、侧栏、表格与控件沿用现有陶土/中性主题，支持深色；窄屏页签横向滚动，右侧操作使用现有图标按钮，齿轮保持可达。

| 操作 | 原型中的反馈 |
| --- | --- |
| 打开齿轮 | 复制已保存定义为草稿，行内含排序柄、显隐、编辑、删除；底部添加及取消/确认 |
| 新建 | 带入当前状态、作者、类型、紧急程度、显示、分组和排序，输入名称；状态始终暴露四项，多选 |
| 编辑 | 从所选视图的已保存定义载入，主页面临时筛选不影响编辑初值 |
| 完成编辑 | 返回管理列表，仅更新草稿；管理底部确认才持久化，成功后选中新建视图 |
| 取消/关闭/Escape | 丢弃本次管理草稿；编辑表单内取消只丢弃该次表单修改，返回已有管理草稿 |
| 排序 | 拖拽；另有上下移按钮及 Alt+方向键，支持触屏/键盘；确认前不改 tab |
| 保存失败 | 草稿保留，明确错误和重试；不显示成功、不关闭面板 |
| 空态 | 本人无记录说明原因，并提供进行中入口；取消 0 不造成页面级空白 |

新增视图最多 30 条、名称长度和同名校验会在正式实现与服务端一致约束。原型展示关键交互与名称校验，其余容量边界由实现测试覆盖。管理弹层内滚动，底部按钮保持可见；图标有名称，焦点可回到齿轮，系统 tabs 支持方向键，窄屏列表降级不会改掉看板选择。

原型为虚构 Atlas 仓库与人员、内存状态：可以切 tab、筛选、显示、增删改、显隐排序与模拟失败；关闭页面会重置。它不连接真实账号或实现跨浏览器同步，URL 恢复与多浏览器并发以本方案和后续实现验收为准。评审栏提供“已有个人视图”“取消数量为 0”“视图保存失败（可重试）”，不进入正式产品。

## 范围与复杂度核对

| 决策 | 结论与原因 |
| --- | --- |
| 账号级仓库视图、服务端保存 | 保留：用户要求重新进入及换浏览器可恢复；仅浏览器本地保存不能满足 |
| 管理草稿与一个配置 revision | 保留：取消/确认需要暂存；两个浏览器整批保存确会互相覆盖，简单 CAS 足够 |
| 查询、分类、计数与详情顺序 | 合并为共享投影，避免各页面独立判断产生不一致 |
| 初始化标志、顺序字段、多份查询快照 | 删除冗余：记录存在性代表已初始化，数组代表顺序，URL 代表当前查询 |
| 专用数据库、自动三方合并、实时协作、每视图数据缓存、逐作者 API 查询 | 延后：当前需求没有这些成本的必要性，复用账号文件与仓库快照 |
| 截图缓存、收藏/共享视图、搜索、流程状态变更、手动归档 | 不属于本次范围 |

本次兼容读取已有数据，不清空用户目录、不触碰 Token 密文和密码配置。没有额外审批层。中等规模暂不改变；若正式实现揭示明显超过预估的职责或有效代码规模，按实际证据复核，不为了拆步骤而扩张。

## 验证与后续实施边界

- 存储/API：旧账号可读；不同账号、仓库隔离；同账号不同 Token/浏览器共享定义；并发首次初始化只一次；删除我的后不重建；管理 CAS 冲突、与最近选择并发、保存失败及身份切换不误报成功。
- 查询：四类状态并集、其他条件交集、空 states 全部；有效发布补记与临时失败；数字身份冲突、仅 login 的历史作者与普通同名作者；计数、延续组和相邻详情一致。
- 导航/缓存：旧链接、新链接、显式空状态、他人 view ID、无查询恢复、刷新/历史/详情返回；缓存优先、切换视图无额外 Git 刷新、后台更新和晚响应不覆盖当前操作；取消数量更新归零与首次打开历史零结果链接区别处理。
