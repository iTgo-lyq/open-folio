# 独立评审

由隔离上下文的 `views_final_review` 子 Agent 读取完整需求、方案、计划及本 Change 全部实现差异进行只读评审，排除同期 GitHub 请求优化的远端差异。未发现账号/仓库隔离、lease/CSRF/CAS 或范围外整体重设计问题。

## R1：迟到响应回退定义版本（P2）

证据：读取与保存共用 apply，但未拒绝较小 revision；A 保存 revision 2 的响应迟到，期间读取另一浏览器保存的 revision 3，仍可能被覆盖回 2。修复：apply 单调接受定义 revision，旧读取与保存不得导航或覆盖缓存；读取期间发生本地最近选择写入时保留其选择。浏览器控制 PUT 响应延迟、插入第二次写入与 focus 读取，复验最终 tab 仍为最新名称。

## R2：纯详情链接返回时丢失列表范围（P2）

证据：只有 c 的旧详情链接返回时清除 c，触发无查询默认恢复，跳回我的。修复：返回前检测是否原本没有目录条件，显式保留默认进行中上下文。浏览器验证旧详情打开后返回仍为进行中且不带本人筛选。

## 补充验证

7 项视图及 4 项竞态浏览器场景通过，包含桌面拖动、Alt+方向键排序、真实 Chromium 触摸事件、深色窄屏、四种宽度、草稿取消、保存失败/冲突、跨浏览器恢复及 R1–R3。最终目录、交付、延续组、账号与阅读交互 16 项定向回归通过；完整结果与基线限制见 execution.md。

## R3：同版本迟到保存覆盖最近选择（P2）

独立复验进一步指出：主列表保存响应迟到，而后续 tab PATCH 已完成时，两者定义 revision 相同，仍可能覆盖 selected。修复：保存捕获独立 selectionVersion，期间选择变化则保留最新选择；PATCH 仅接受当前选择序号的响应，管理保存先等待已有选择队列结束。新增延迟保存与无查询再次进入的浏览器用例复验。

## R4：清除最后一个显式条件触发默认恢复

全量回归发现：旧链接只有类型筛选，取消最后一个条件后 URL 变空，触发恢复我的。修复：首次规范化显式目录查询时保留 states；空条件仍明确表示当前列表范围。另将增多后的筛选菜单设为限高滚动，禁止条目 flex 收缩，防止长标签内容覆盖相邻命中区域。

## R5：发布补记必须经过服务端证据校验

最终核对发现分类器直接读取原始 deliveryOverride，可能将尚未集成、补记无效的记录误归档。修复：前端统一使用经过服务端校验的 delivery.stage；有效补记仍由既有交付流程转换为 releaseMerged。新增用例验证原始补记不构成发布事实，目录和交付相关 18 项单元测试通过，独立复验认可。

在未包含本 Change 的独立 `origin/develop`（`ede1398`）工作区安装锁定依赖并运行三项原始用例，三项均以相同断言失败，确认属于既有基线。随后只更新本分支 Token 用例的两处状态文案匹配，使其继续验证错误分类与重新绑定；不修改 Token 产品逻辑。两个既有窄屏布局问题保留为明确限制，测试未跳过。
