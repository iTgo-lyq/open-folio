# Change 状态维护

SpecTrail 通过仓库内的语义 JavaScript 命令维护 docs/project 下的 Change 状态。change.json 是流程事实来源，Markdown 保存需求、方案和证据，Git 保存版本与已推送记录；OpenFolio 工作台继续只读展示。

## 命令与责任

主 skill 自带 scripts/change.mjs，使用 Node.js 内置模块，无第三方依赖。命令覆盖创建、阶段确认、任务登记/执行/阻塞/完成、等待与恢复、返工、关闭四步、取消及原型关联。具体调用参见仓库 [.agents 状态命令说明](../../../../.agents/skills/spec-trail/references/state-commands.md)。

Agent 根据实际用户授权、验证与评审结果传入摘要和来源，脚本负责既有 JSON 契约、阶段前置、时间、失效字段清理与本地写入。脚本不判断正文质量、不替用户确认、不运行测试，不自动提交/推送或合入分支。命令成功不等于中心仓库状态已持久化。

创建与修改在 Change 声明的主分支进行，守护分支不直接写状态。同一分支只有一个执行/关闭中的 Change；取消冻结相关分支，归档默认只读。用户明确要求历史勘误时在所属分支最小修正并保留普通 Git 提交，不改写已推送历史。

## 状态与证据边界

完成任务的定义与记录保留，返工追加任务并清除失效的关闭步骤及阶段确认。small 可按真实证据自验收；其他规模使用用户验收或明确交付/合入授权，不能把测试通过或预先笼统指令替代实际授权。等待解除与确认记录分别维护。

前置 Change 必须有一致的已推送关闭记录且所需交付在当前分支可用。祖先关系是集成证据之一；squash 后不能推定缺少交付，也不能自动推定已集成。Agent 核对具体交付并记录依据后，可传 availability-note；命令输出源/目标提交与说明，保留证据类型区别。

新记录时间统一为 UTC 三位毫秒 ISO 字符串。关闭步骤按整体验证、验收、Specs、归档严格非递减；时钟早于前一步时拒绝写入，不加读取容差，不伪造未来时间。读取兼容既有合法带时区格式。

## 写入与失败恢复

字段校验由主 skill 的 state-schema.mjs 共享给命令与提交 hook，hook 继续只验证实际 index，支持部分提交及 GIT_INDEX_FILE。原型关联与当前项目开关、入口路径和暂存产物保持既有契约。

命令使用仓库级锁、原文复查和同目录临时文件 rename；错误参数、错分支、符号链接、越级关闭、重复覆盖与归档目标冲突均拒绝。提交失败的 task-retry 仅恢复 HEAD 尚未完成的任务；同时修正该任务已暂存的 done，保留其余部分暂存差异。已提交完成任务不回退；推送失败保留提交并重试推送。

archive 移动完整文档目录并标记 completed，不重建或复制原型工程。带原型的归档须再发布保留标签。目录移动与状态/index 更新不提供跨文件断电事务保证，异常终止后根据 Git diff 与实际文件恢复；普通写入失败尽量回退并报告。
