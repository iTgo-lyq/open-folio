# 原型浏览与预览

OpenFolio 在[项目知识工作台](../spec.md)提供独立「原型」模块，以及 [Change 详情](../change-tracking/spec.md)内的原型标签。总览展示仓库集成分支（名称可自定义，推荐 develop）当前登记的预发布页面，Change 保存当时的固定交付。项目维护源码和构建，产物选择 OpenFolio 内置托管、自建静态托管或 Git 单 HTML 兜底；OpenFolio 不编译项目源码或运行上传内容中的服务端代码。三类来源都可由已授权用户准备固定公开版本，匿名访问只读取已发布产物。

## 可选协作与当前清单

每项目维护一个原型包，默认 packages/prototype，复用项目设计规范与组件库。源码可使用 HTML、React 或其他宿主工具，演示使用局部状态与 mock，不依赖真实业务后端。UI 组件库的独立预览不自动进入项目原型清单。

docs/project/workflow.json 的 prototype 记录选择：缺失为未选择，disabled 为拒绝接入，pending 为接入未完成，enabled 为可用。拒绝接入后不重复提议或新增关联；已有明确同意直接沿用，初始化失败保留现场。已启用时按 UI 影响范围判断：小型变化先询问是否绘制，较长时间未回复可说明后跳过；大范围变化必须在实现前绘制或更新原型并提供预览。

workflow 的可选 openfolioUrl 保存 OpenFolio 服务 HTTP/HTTPS 地址，null 表示无自建实例，缺失表示未记录。prototype 除 status 和适用的 packagePath 外，可保存 hosting.provider（openfolio/custom/git）及适用的 uploadUrl。OpenFolio 方式要求服务地址和专用上传地址，custom 可保存项目适配器使用的上传地址，git 不需要上传地址。

托管方式尚未选择时，skill 先询问自建 OpenFolio 实例，再询问三种方式并保存选择；已有会话或配置选择直接复用，仅补该方式必需信息。setup 原子保存配置，保留不相关字段及启停前后的托管选择；接入决定的历史由 Git 保存。

原型包 DESIGN.md 记录项目设计依据、视觉方向、色彩角色与数值、字阶、布局断点、组件及交互约定。初始化可引用已有权威规范，没有时提供中立模板和简短编写指南，绘制前依据现有产品补全；不覆盖用户已有文件，不把新设计提案描述为现有事实。

工作台目录与公开版本准备从已推送集成分支的最新成功快照读取 workflow.json 的开关与包配置。固定提交提供原型记录、清单和产物，按当前配置校验与读取；当前配置无效、停用或无法读取时明确失败。已准备的公开版本独立于此开关继续可读。

包内 prototype.json 是当前总览唯一清单，只读取 workflow.json 指定的集成分支，其他分支不扫描当前清单。清单保存在持久快照中；集成分支提交及读取规则未变化时复用有效清单，页面后台发现新快照后自动更新总览。schemaVersion 为 1，entries 按稳定 id 声明 title、可选 description、sourcePath、kind、适配和可选 artifact。源码路径位于原型包内，id 在项目内唯一。页面声明 pc-web/ipad/mobile 中非空、去重的设备集合；组件在设备集合和 1–4096 CSS px 的整数 viewport 中二选一。无 artifact 表示尚未交付，不从 Change 历史推算当前版本。

Git 保存源码和描述，普通 dist 默认忽略。删除集成分支清单项即从总览移除，不删除历史交付和已公开版本；其他工作分支或仅上传未登记的产物不改变总览。源码、主题变化不强制重发参考原型。

## 固定产物与宿主发布

artifact 区分两种交付：

- hosted：记录固定 version、HTTP/HTTPS url、sourceCommit、digest，以及可选设备截图引用。项目自行构建并上传到 OpenFolio 或自建静态托管，支持 React 等多文件产物。
- git：记录 path 与 sourceCommit。显式选择兜底时，当前单 HTML 留在包内 preview/id，Change 另保存 previews/id/index.html；归档移动快照并更新路径；仍引用共享目录的入口先复制到本 Change 的 previews/<id>，目标不同则停止。sourceCommit 保持构建来源，不替换为合并提交；后续当前产物更新不覆盖旧 Change。

Change 的 previews 保留自己的入口标题、类型、适配及固定 artifact；项目当前清单与 Change 可引用同一次发布。当前清单后续更新不改变 Change 的固定交付，已归档记录只读。源码提交可用于追溯构建来源。

发布工具 prepare 生成包含仓库、源码提交、目录、内容摘要、入口及 requestId 的请求。宿主负责构建、上传和结果，成功结果回传对应 requestId/sourceCommit/digest、固定版本及各入口 URL；失败结果包含 code、message 和 retryable。宿主完整上传后原子发布，重复请求返回同版本，旧版本内容不可覆盖，历史引用版本由宿主负责保留。

OpenFolio 方式由内置 upload 命令读取 workflow 地址，上传产物、校验并保存结果，再登记引用；上传成功但本地登记失败可使用保存的 request/result 重试 register。自建托管继续由项目适配器完成上传。新建 hosted 包默认输出 dist，可指定其他产物目录；已有包保留原构建命令。

register 校验成功结果后更新当前清单及可选 Change 引用；发布失败保留旧引用，不自动转为 Git 兜底。共享仓库锁、事务日志和原文比对保护多文件登记，recover 遇到后续用户编辑会停止；异常退出遗留锁须核实持有进程已结束后处理。协议、调用和恢复细节见[原型协作 skill](../../../../../.agents/skills/spec-trail/prototype/SKILL.md)。

预览引用使用无凭据、无 query 的 HTTP/HTTPS，可包含 hash 路由；不包含临时签名 URL、上传密钥或令牌。专用上传地址作为上传凭据保存在 workflow，可提交供仓库成员使用，不复制到 artifact、截图地址或成功日志。staged hook 校验暂存配置、引用及 Git 产物；静态校验不能代替浏览器交互验证。

## OpenFolio 内置静态托管

管理员通过 GET /api/prototype-hosting 获取稳定的专用上传地址；也可在本地设置管理密码环境变量，通过 setup 自动获取并保存。上传密钥私有保存在数据目录的 prototype-upload-key。持有该地址即可上传，不要求管理 Cookie，也不能凭此地址访问管理接口。轮换上传密钥撤销旧上传地址，不影响已发布静态链接。

服务接收有明确边界的文件流，不解压压缩包、不执行构建。每次上传最多 2000 文件和 100 MiB，请求元数据最多 1 MiB，同时最多两次上传，120 秒超时。文件路径、类型、长度、摘要和入口完整性均校验；错误地址、非法或半截内容不发布可访问版本。

产物与发布元数据存放在数据目录的 prototype-artifacts 下，无数据库。版本使用绑定仓库、源码提交、摘要及入口的 requestId；先写私有临时目录，再原子发布。相同请求重试返回相同版本，并核对既有文件，不覆盖历史内容。服务重启保留版本，历史文件不自动回收，部署者持久化并备份数据目录。

GET/HEAD /prototype-assets/version/path 公开读取已发布文件，不校验项目权限；支持 HTML、JS、CSS、图片、字体等静态资源、CORS 和固定版本缓存。存储元数据和半成品不暴露。可执行文档受响应 CSP sandbox 约束，直接打开也不能访问工作台 DOM 或凭据；服务只提供静态字节。

## 本仓库的 R2 发布

本仓库的原型包通过 custom 适配器发布至 Cloudflare R2。源码保存在 Git，dist 与桶级 S3 凭据不提交；凭据由发布机器环境提供。适配器以 requestId 固定对象路径，使用条件创建并核对重复请求的既有字节，拒绝覆盖不同内容；全部文件公开 GET 的内容和类型验证通过后，才输出可登记的成功结果。

原型 HTML 与 PC Web、iPad、Mobile 截图一起发布，当前清单与 Change 记录固定 hosted 地址、源码提交和摘要。失败不替换引用。R2 已引用版本长期保留，发布与配置说明见[原型包 README](../../../../../packages/prototype/README.md)。

## 总览、详情与二级预览

总览只显示集成分支当前清单，提供类型与适配筛选和分页；没有多分支来源选择、历史版本列表或迭代时间线。目录及 Change 原型记录属于授权工程信息，读取使用当前个人连接。非法单项给出诊断而不遮蔽其他有效入口；停用、未接入、未发布、无匹配和读取失败分别提示。

卡片以截图为主。点击截图进入工作台二级预览，自动收起全局侧栏和页头来源入口，仅保留顶部路由跳转；主区左侧是完整原型目录，右侧是画布，窄屏可收起目录。预览不显示 commit 等来源信息。

点击截图以外的卡片区域打开详情抽屉，展示说明、适配、源码路径与提交、集成分支清单提交、产物位置、托管版本，以及保持原始比例的更大截图；可从详情进入预览。两个操作独立支持键盘，关闭或返回恢复焦点。

设备、方向、适应/100% 缩放及重载集中在画布内。PC Web 为 1440×900、iPad 为 834×1194、移动设备为 390×844 CSS px；组件也可使用声明的固定尺寸。缩放不改变 iframe 布局宽高，设备选项不模拟硬件。

返回总览保留筛选、展开分页、滚动和卡片焦点。预览和详情支持直接链接、刷新及浏览器前进后退；模块或项目切换清理对应上下文。

## 固定链接与归档保留

当前原型准备固定到集成分支清单提交，要求该提交属于已推送集成分支的历史；总览仍读取最新清单，不提供历史浏览入口。活动及已归档但尚未合入的 Change 通过自身登记分支中已推送的固定提交准备原型，无需先合入集成分支。

准备时固定完整 revision；Git 按该提交读取，hosted 使用记录中的固定地址。当前开关、来源可达性和入口范围每次检查，本人仓库权限沿用[个人访问](../access/spec.md)的周期复验；新增公开版本在发布前即时检查，复用已发布版本不重复远端鉴权。已合入 Change 从[合入变更](../change-tracking/spec.md#合入变更)的唯一有效 M 读取归档 previews，显式 revision 也必须等于 M。Git HTML 位于 M 的归档快照内；hosted 的 version、url、digest、thumbnails 与 sourceCommit 保持原值。来源分支及标签删除后仍可准备和分享，外部产物仍由宿主保留。

不创建或读取原型保留标签。无可识别 M 的旧关联显示“未记录可定位的交付版本”，重复或非法记录与历史不可读分别诊断，不通过显式 revision、当前分支或 sourceCommit 恢复旧关联。旧归档正文继续可读，未关联原型仍显示原有空态。已有公开版本独立保留，不因标签退出而回收。

准备成功后分享 `/preview/<publicationId>`。版本标识绑定稳定仓库身份、入口、固定提交与最终产物摘要；重复准备复用相同版本。公开页面仅返回必要的展示信息、产物和截图，不包含工程正文、连接身份、token 或上传秘密。匿名 GET/HEAD 不调用平台 API、Git 或私有授权缓存；退出、撤权和停用后续准备不删除既有公开版本。未知或未准备版本返回 404，管理员主动撤回后返回 410。

读取失败显示失败标题及具体原因，与尚未关联原型的正常空态区分；单个入口的无效引用、路径或产物保留不可用状态与原因。

## 托管预览与隔离

页面及截图使用任意 HTTP/HTTPS 来源，可与工作台同源，不需要配置来源白名单。服务端不请求远端地址、不代理登录、下载或转发凭据；外部宿主负责资源策略、版本保留和允许嵌入。

iframe 只授予 allow-scripts，不授予 allow-same-origin，保持 opaque origin。宿主 ESM、动态模块和字体等静态资源须支持无 Cookie 的 CORS，路由使用 hash/memory；不兼容的登录流由用户独立打开宿主页面。宿主响应 CSP 约束其资源和连接，工作台不为兼容而放宽沙箱。

宿主可接入 ready/error 桥接握手，页面加载完成与应用就绪独立判断。缺少可选桥接回报不产生持续警告；聚焦预览加载完成后收起正常状态，Change 原型标签可显示“页面已加载”，收到 ready 后显示“页面已就绪”。加载未完成时提供等待或加载较慢提示，明确 error 回报仍显示失败告警，不被页面加载事件隐藏。切换入口或重新加载不沿用旧页面状态。缺失引用、资源或嵌入异常保留明确提示及适用的独立打开入口。

## Git 兜底与离线截图

Git 兜底入口是 UTF-8 自包含 index.html，脚本、样式及 mock 内联，图片/字体用 data URL。不依赖外部 import、动态 chunk、网络、真实后端、持久存储、Worker 或 eval；普通 Vite dist 不等于单文件兜底，宿主负责必要的内联构建。

Git 公开版本准备只读取已登记入口和固定提交，拒绝任意文件路径、符号链接、LFS、超限或非法产物；最终 HTML 包含固定的就绪、脚本错误与 CSP 诊断桥，摘要覆盖最终字节。无 previews 的 Change 正常显示尚未关联。同域 HTML 同时受 iframe 沙箱和响应头 CSP sandbox 限制，直接导航仍受限；CSP 禁止网络连接、外部资源、嵌套 iframe、表单、对象及 worker。公开响应使用 `public, no-cache, must-revalidate`，并校验文件摘要与撤回标记；已发布字节保持不变，不因渲染器更新而覆盖。

可见卡片按需加载截图，默认采用第一个声明设备；设备筛选后截图与交互预览尺寸一致。截图保持比例，加载、失败、重试和预览入口独立。托管截图由宿主提供固定 PNG/WebP 地址，通过 no-referrer 加载；缺失时使用占位，OpenFolio 不联网为托管地址截图。

Git 截图在准备公开版本时，用启用 OS 沙箱的独立 Chromium 空白上下文离线生成，不携带登录态或宿主凭据，拦截网络/WebSocket。准备检查当前 token、开关、关联及历史引用，生成结束与发布前再次检查撤销；准备失败不发布部分快照。缓存键包含仓库、HTML 摘要、视口及渲染器版本。

临时截图在私有目录原子写入，可删除重建；默认总量 100 MiB、闲置 7 天回收、单图 4 MiB，失败短暂退避，相同任务合并。进程最多两个浏览器并行、24 个排队任务，排队与渲染有时限。准备完成的 HTML、截图及最小元数据存入独立 `public-previews` 版本目录，原子发布后供匿名 GET/HEAD 读取并长期保留，不按临时缓存清理。公开读取只核对清单、摘要及撤回标记，不使用发布者凭据，也不重新截图或采集。
