# Spec 阅读

Spec 阅读在[项目知识工作台](../spec.md)中只呈现默认保护分支的已实现能力，保留文档结构与 Git 来源；正文与目录复用持久快照，开发分支的 Specs 不参与采集和切换。

## 能力目录与定位

- 递归识别 `docs/project/specs/<capability-path>/spec.md`，完整能力路径是身份，支持任意层级。
- 有 `spec.md` 的父路径同时拥有正文和子能力；没有正文的中间路径作为目录，不产生占位能力。
- 标题来自 Markdown 首个标题，无标题时使用能力路径。正文呈现实际标题、表格、列表和代码块，不要求固定条款结构。
- 支持能力目录、章节导航和深链接定位。定位目标时展开祖先目录，重复定位同一目标同样有效。
- 章节锚点支持中文及重复标题；目录与正文使用相同的标题身份。复制链接、刷新、前进和返回可恢复阅读目标。
- 可查看文档原文及分支、提交、路径；无 Specs 或来源已删除时展示真实状态及返回入口。

## 文档与链接边界

Markdown 使用 GFM 渲染，不执行 HTML、脚本、MDX 或 iframe。原文以文本显示。文档目录和内部链接依赖 Markdown AST，正文与原文均来自当前指定快照。

相对链接只能解析到当前快照的 `docs/project/` 文档清单。指向 Specs 的链接使用默认保护分支能力，并展示其实际提交；其他工程文档保持来源分支的同一提交。Markdown 在工作台内打开，JSON 提供只读原文；缺失、越界、危险协议或不支持预览的目标给出反馈。外部 HTTP(S) 链接在新页打开，服务不抓取外部链接内容。

仓库中的 PNG、JPEG、GIF、WebP 和 AVIF 图片只有通过普通 blob、大小和文件签名检查后才能显示，并使用固定 MIME。图片及 HEAD 与正文使用同一当前连接授权链路，缓存和历史快照不绕过远端权限；外部图片、SVG、HTML 和未知格式不自动嵌入。

Spec 与 Change 的关联仅来自可解析文档链接或完整 Spec 路径引用，保留引用文档与行号。不从相似标题或源码路径推断关联，也不扩展 `change.json` 的字段契约。

## 阅读上下文

文档弹层保留所属 Change 或 Spec 的浏览上下文。关闭最上层弹层恢复焦点和原阅读位置；手机支持目录展开、正文阅读及返回。切换仓库或 token 工作台清除上一上下文的筛选条件；失权、退出或会话到期时清理正文并引导恢复，晚到响应不能恢复旧内容。分享只保留稳定仓库身份和阅读位置，接收者用当前 token 验证后恢复目标。

工作台在服务端保存最近成功读取的仓库、Specs／Changes／原型模块和侧栏折叠状态。更新只原子合并本次修改字段，切换后旧请求不能写入另一个工作台。同 token 新设备从空入口恢复这些偏好，明确阅读链接优先；恢复最近仓库仍需重新验证权限，偏好不授予访问资格。树状态与页面滚动按工作台隔离保存在浏览器，不跨设备同步。
