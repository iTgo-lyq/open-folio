# Spec 阅读

Spec 阅读在[项目知识工作台](../spec.md)中呈现当前来源分支的已实现能力，保留文档结构与 Git 来源。

## 能力目录与定位

- 递归识别 `docs/project/specs/<capability-path>/spec.md`，完整能力路径是身份，支持任意层级。
- 有 `spec.md` 的父路径同时拥有正文和子能力；没有正文的中间路径作为目录，不产生占位能力。
- 标题来自 Markdown 首个标题，无标题时使用能力路径。正文呈现实际标题、表格、列表和代码块，不要求固定条款结构。
- 支持目录筛选、标题／路径／正文搜索和章节导航。定位搜索结果时展开祖先目录并清除阻碍定位的目录筛选，重复定位同一目标同样有效。
- 章节锚点支持中文及重复标题；目录与正文使用相同的标题身份。复制链接、刷新、前进和返回可恢复阅读目标。
- 可查看文档原文及分支、提交、路径；无 Specs 或来源已删除时展示真实状态及返回入口。

## 文档与链接边界

Markdown 使用 GFM 渲染，不执行 HTML、脚本、MDX 或 iframe。原文以文本显示。文档目录和内部链接依赖 Markdown AST，正文与原文均来自当前指定快照。

相对链接只能解析到同一提交的 `docs/project/` 文档清单。Markdown 在工作台内打开，JSON 提供只读原文；缺失、越界、危险协议或不支持预览的目标给出反馈。外部 HTTP(S) 链接在新页打开，服务不抓取外部链接内容。

仓库中的 PNG、JPEG、GIF、WebP 和 AVIF 图片只有通过普通 blob、大小和文件签名检查后才能显示，并使用固定 MIME。外部图片、SVG、HTML 和未知格式不自动嵌入。

Spec 与 Change 的关联仅来自可解析文档链接或完整 Spec 路径引用，保留引用文档与行号。不从相似标题或源码路径推断关联，也不扩展 `change.json` 的字段契约。

## 阅读上下文

文档弹层保留所属 Change 或 Spec 的浏览上下文。关闭最上层弹层恢复焦点和原阅读位置；手机支持目录展开、正文阅读及返回。切换项目清除上一项目的筛选条件，避免不可见条件隐藏新项目内容。
