# Change 追踪

Change 追踪在[项目知识工作台](../spec.md)中展示变化目标、实际流程记录、任务和依赖。工作台提供阅读依据，流程推进由 SpecTrail 执行。

## 状态与主来源

流程状态唯一取自 `docs/project/changes/<id>/change.json` 或 `docs/project/archive/YYYY-MM-DD-<id>/change.json`，按 SpecTrail `schemaVersion: 1` 严格校验。Markdown 保存正文和证据，Git 保存来源；二者都不替代 JSON 状态。

同一仓库的 Change 按协作分支集中入口的 id 建立。规划入口 branch 指向协作分支时读取本地集中记录；指向工作分支时，只读取目标固定提交中唯一且 id/branch 一致的完整记录。协作旧副本仅提供入口，不用于拼接或回填进度。已集成的有效 completed 归档直接采用集中历史，branch 保留原归属，不依赖工作分支永久存在。

入口重复或非法、目标缺失、目标身份不符及 live/archive 重复均显示来源异常，不从其他分支或孤立保留标签寻找替代状态。详情区分集中入口分支/路径/提交和完整记录来源，可打开入口 JSON；关系、任务、问答和正文均采用所选权威记录。

整体结果 `active / completed / cancelled`、阶段、等待事项、任务阻塞和来源质量分别展示。默认展示进行中 Change，另有已取消、已归档、来源异常入口；不提供全部范围。非法范围链接回到进行中，保留具体 Change 深链接。取消保留原阶段、材料和取消原因；有效完成要求关闭四步、归档目录、任务／Plan 和关系满足规则，且原 live 目录已移除。异常完成声明不计为有效完成。

## 浏览、任务与材料

- Change 默认按首次进入 Git 的提交者时间从新到旧排序；同时间按 ID 排序，历史无法确定时间的置后。后续编辑与归档不重置创建时间，可切换紧急程度优先。延续组按首个匹配成员出现的位置排列，组内匹配成员沿用所选排序。
- Change 提供列表和依赖视图，共同支持类型、紧急程度、规模和关联能力筛选。仅进行中提供阶段、等待／阻塞筛选与阶段看板；其他范围的旧阶段／等待条件自动清理，旧阶段看板链接回到列表。看板只用于浏览。
- 进行中列表突出当前阶段与进展，已归档展示归档时间和完成结果，已取消展示取消时间与原因，来源异常展示主来源和具体问题。清除筛选留在当前范围；无此类记录与筛选无匹配分别提示。
- 任务粒度提供列表和四种状态的看板，按任务状态筛选。任务状态取 JSON 的 `todo / doing / done / blocked`，保留验证、阻塞原因和任务分支；提交标题只作查找线索。
- 详情包含概览、任务或子项、文档、原型、合入变更、依据，以及主分支来源、确认、返工和验收记录。关闭详情保留列表筛选、位置和焦点。
- 概览按 Q 编号数值顺序展示主来源的澄清问题与用户最终回答。未答显示“未回答”，撤回保留问答并标记“已撤回”，无记录隐藏；活动与归档均适用。内容以纯文本展示并保留换行，不展示回答历史、轮次、推荐或来源。
- small 任务直接读取 JSON；medium／large 结合 Plan 的交付定义和执行顺序；xlarge 展示子 Change 和子项结束数量，不创建父级实现任务或把子任务数量作为父项进度。
- 实际存在的 Markdown 材料可以阅读；缺失、不可读、当前规模不要求和尚未进入要求阶段的材料分别提示，不生成正文补空。从详情或深链接打开具体材料时保留所属 Change 上下文。

## 标签筛选与紧急排序

类型与紧急程度读取权威记录中的可选 `types` 和 `urgency`，契约与命令见 [Change 状态维护](../../change-workflow/spec.md#类型与紧急程度)。历史缺失字段正常读取，不补写源文件。非法字段从解析副本中单独隔离并显示 warning，合法的另一字段和核心流程事实保留，不撤销有效完成及依赖满足；隔离后的字段按缺失处理。

列表、阶段看板和详情以纯文本展示类型标签，支持多标签及长名称换行。列表和卡片仅为非普通紧急程度显示徽标，省略与显式普通均不额外标注；详情显示有效等级，无类型时显示“无类型标签”。紧急程度没有独立的未设置状态。

类型候选来自项目实际标签，合并链接中已选但暂无匹配的合法名称；推荐词不混入筛选项。类型可多选，命中任一项即匹配，“无类型标签”与已选类型同样按 OR 匹配；紧急程度及其他筛选取交集，普通同时匹配缺失与显式普通。列表、看板、任务和依赖视图共享 Change 筛选，任务不拥有独立标签。

筛选与排序保存于 URL：`types` 使用 JSON 数组，`noTypes=1` 表示无类型，`urgency` 使用四档值，`sort=urgency` 表示紧急优先；逗号、引号和 `none` 都是普通标签文字。非法新参数通过 replace 清理且保留具体 Change 深链接。清除筛选保留排序和当前范围，切换范围保留标签条件，切仓库清理条件；刷新、历史导航、详情返回及焦点沿用现有导航约定。多选浮层支持键盘操作和窄屏，触发器向读屏提供选中数量。

紧急优先依次排列紧急、高、普通、低，缺失与显式普通同级，同级稳定保留默认创建顺序，核心来源不可读的记录置后。先筛选和排序成员再聚合延续组，关系及组名仍取完整快照，成员不继承其他成员的标签。看板只改变栏内顺序，任务按所属 Change 排列且保留内部任务顺序，依赖关系不变。

## 合入变更

详情以只读页签展示一次归档正式合入的时间、协作分支、固定合并提交及第一父提交、完整文件清单、增删统计与逐文件统一 diff。比较范围为 `git diff M^1 M`，包含代码、工程文档、归档移动及 Git 原型快照等全部目录；不推断这些代码当前是否仍生效，不依赖 PR 或源分支持续存在。

CLI 与服务端共用[合入协议](../../change-workflow/spec.md#归档后的去向)，从固定的已推送协作 tip 扫描 first-parent 主链。唯一合法记录为 found，无记录为 missing，重复标记或协议不符为 invalid，所需历史/对象不可读为 unavailable。缺失显示“暂无合入记录”，不宣称从未合入；异常明确诊断，不按标题、分支名、旧标签或 sourceCommit 猜测。单个记录异常不遮蔽其他正常 Change。

合入索引绑定文档快照及协作 tip；同 tip 的有效索引可复用，临时不可读记录会重试。摘要、每页 100 项的文件清单和单文件 API 沿用仓库授权，要求明确 snapshot；服务端从索引派生提交对，fileId 回查固定清单、cursor 绑定快照与提交对，不接受任意 base/head/path/revision。

清单按 NUL 分隔解析，保留原始路径字节与重命名关系，展示时转义不可见字符。统计完整读取或明确失败，不把部分清单冒充完整；二进制无文本增删统计。单文件按已验证 blob 读取，二进制、非 UTF-8、LFS、子模块、符号链接、仅模式变化与空内容分别提示，不下载外部对象或跟随链接。源文件或差异超过 1 MiB、差异超过 10000 行时说明限制，提供 Git 比较命令。

宽屏并排展示文件与正文，窄屏在文件列表和差异间切换。文件选择与视图保存于 URL，支持直接链接、刷新和前进后退；页签键盘导航及复制失败的手动兜底可用。切换仓库、Change 或快照后旧响应不跨记录呈现，读取失败可重试。

## 延续交付分组

可选 `followUpOf` 表示同仓库已归档直接前序的延续交付，与 `dependsOn` 和父子拆分分开解析，不引入独立话题生命周期。工作台按权威记录中的完整延续关系聚合多跳与分叉；各成员的标题、状态、任务、验收及归档记录仍独立。

Change 列表先按当前范围和筛选匹配成员，再用完整关系组聚合，已归档根不会隐藏进行中的后继。分组以独立标题和外框呈现，匹配记录始终展开，保留各自详情入口与原 id 深链接；组外上下留白、组内分隔线两侧缩进。无关联的单条记录沿用普通行，任务、看板与执行依赖继续按独立 Change 展示。详情可追溯直接前序和同组交付。

组名取完整组中的有效 `followUpTitle` 声明，最靠近根的声明优先，同层按 id 稳定排序；筛选、列表顺序和成员状态不改变组名。旧组无声明时使用根标题。多个声明不一致时保留稳定名称并提示核对；命名与写入约定见 [Change 状态维护](../../change-workflow/spec.md#延续交付与分组命名)。

非法格式、缺失、无效前序、自指或循环只影响延续关联的阅读与分组，相关记录仍可单独打开。格式错误的可选 `followUpOf` 与 `followUpTitle` 分别隔离并提示，错误组名不解除合法关系；这些显示问题不抹除原交付的有效完成事实，也不使消费者原有的执行依赖失效。

## 阶段与完成标记

原始阶段为 `requirement / technical / plan / execution / close`。当前阶段徽标和流程进度只用于 active 且无来源错误的记录；任务依赖等警告单独提示，不抹除合法的阶段。small 使用需求、执行、验收路线；medium／xlarge 将技术与计划合并展示；large 分别展示技术与计划。省略的阶段不显示为遗漏审批。

已归档、已取消详情突出结果、时间或原因，不显示当前阶段和流程进度。历史阶段、关闭步骤与确认保留在依据页签，任务记录保留在任务页签；任务粒度的状态看板与依赖追溯仍可使用。详情根据实际记录判断，来自原型或跨范围深链接时保持一致。

需求、技术和计划的勾选依据实际确认记录，合并阶段仍要求对应的两个确认。阶段位置、已有文档或历史提交不自动证明确认发生。确认的时间、摘要和来源、返工的原因和处理方式均可查阅。

当前处于 execution／close 时，普通 Change 的非空任务集合全部为 done 才显示执行完成勾选；xlarge 的非空子项集合对应流程关系全部满足时显示执行完成。空集合、未完成任务、未知子项或退回规划不自动打勾。执行完成不代替验收或整个 Change 完成。

close 的通用名称为“验收”；active 且整体验证通过、没有验收记录时显示“验收中”。“验收与归档”按整体验证、验收、Specs 同步、归档提交展示各步真实结果、时间与摘要。缺项显示未记录，验证失败保留失败事实，Specs 无需变更显示原因；部分记录不等于完成。

SpecTrail 中 small 默认自验收后同步 Specs 并归档；用户要求人工验收或人工验收提出问题后，该 Change 后续须用户确认，其余规模人工验收。两种方式均记录 `acceptance.result: accepted`，摘要和来源说明实际验收方式与依据。工作台读取这些记录，不凭 small 规模或测试通过补出验收结果。状态操作与时间由 [Change 状态维护](../../change-workflow/spec.md)中的本地语义命令完成。

## 关系与依赖证据

Change 前置关系取 `dependsOn`，父子关系取 `parent / children`。缺失、重复、自指、循环、父子不对称、嵌套父项或子依赖父均有诊断；children 顺序不代表串行依赖。关系异常影响有效完成判断，并沿依赖传播，不能成为下游已满足的前提。

流程前提与交付可用性分开显示。有效归档的前置 Change 满足流程前提；已取消前置不满足。父项的子 Change 可由有效完成或有效取消记录满足结束条件。来源异常或目标缺失保持不可判定。

Git 祖先关系仅证明含有归档记录的固定来源提交在当前分支历史中；无法证明、历史不足或 squash 情况显示可用性待核实。不根据提交标题猜测对应关系，不把祖先存在当作代码未被撤销的证明。

普通 Change 的任务前置默认按编号数值递增形成串行链，例如 T1、T2、T10，与 JSON 属性顺序和正文排列无关。small 无需 Plan，medium／large 仍需可读取的 Plan 正文；缺少可选的执行顺序表不产生来源提示，仅有顺序标题或文字说明仍使用默认。xlarge 按子 Change 组织。

显式任务前置来自 Plan 中唯一“执行顺序”章节下含“任务／前置任务”两列的表格，可覆盖默认安排。每个 JSON 任务需要唯一一行，前置为“无”或合法任务编号，不能重复、自依赖或成环；代码、引用、列表和 HTML 块中的示例不作为声明。表格存在但歧义、覆盖不全或无效时保留原文和位置依据并提示不可判定，不退回默认；medium／large 缺少可读取 Plan 时提示材料缺失。任务页展示默认或显式来源，顺序规则与流程命令一致；普通 Change 的无效显式安排也影响有效完成判断。

## 原型关联

Change 可关联项目单一原型包的多个页面或组件，保留当时的显示信息、源码提交及 hosted/git 固定产物引用；详情原型标签支持入口、设备/自定义尺寸、方向、缩放和固定版本链接。工程记录及关联目录使用当前连接的仓库权限；进行中的 Change 无需合入协作分支即可由有权限用户准备公开原型，分享独立的固定版本入口。后续项目当前引用更新不覆盖历史交付。已合入归档的固定原型从同一有效 M 读取，Git 使用归档快照，托管引用保持不变；无有效历史关联的旧记录留空，异常记录显示诊断，不使用保留标签回退。当前停用拒绝新的准备，不影响已公开版本与其他文档阅读；外部产物由宿主保留。完整关联、隔离与缓存约定见 [原型浏览与预览](../prototype-preview/spec.md)。
