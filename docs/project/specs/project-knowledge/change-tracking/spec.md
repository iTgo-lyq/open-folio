# Change 追踪

Change 追踪在[项目知识工作台](../spec.md)中展示变化目标、实际流程记录、任务和依赖。工作台提供阅读依据，流程推进由 SpecTrail 执行。

## 状态与主来源

流程状态唯一取自 `docs/project/changes/<id>/change.json` 或 `docs/project/archive/YYYY-MM-DD-<id>/change.json`，按 SpecTrail `schemaVersion: 1` 严格校验。Markdown 保存正文和证据，Git 保存来源；二者都不替代 JSON 状态。

同一仓库的 Change 按集成分支集中入口的 id 建立。规划入口 branch 指向集成分支时读取集中记录；预填工作分支尚无所属 Change 来源、集中记录仍为有效 active 规划时，也从集成分支读取，保留原始 branch 名。有效规划限于 requirement/technical、任务全部未开始且没有关闭记录；无关分支或继承副本不构成移交。实际目标存在且归属匹配时，读取其固定提交中唯一且 id/branch 一致的完整记录，不按集中阶段判断移交。子项已合入父分支时优先读取父分支中的有效归档，保留子项原 branch；父项整体集成后读取集中归档。协作旧副本仅提供入口，不用于拼接或回填进度。已集成的有效 completed 归档直接采用集中历史，branch 保留原归属，不依赖工作分支永久存在。

入口重复或非法、已知实际目标丢失、目标身份不符及 live/archive 重复均显示来源异常，不从其他分支或孤立保留标签寻找替代状态。详情区分集中入口分支/路径/提交和完整记录来源，可打开入口 JSON；关系、任务、问答和正文均采用所选权威记录。已有 Git 跟踪元数据只作为历史归属证据；远端删除后连续刷新或重建读取器仍保留缺失诊断，不把缓存旧材料作为当前来源。读取、认证或网络失败不当作目标尚未创建。

整体结果 `active / completed / cancelled`、阶段、等待事项、任务阻塞和来源质量分别展示。系统 tab 按进行中、已完成、已归档、已取消固定在前，个人视图位于右侧；首次默认选中“我的”。已完成与已归档互斥，只有经过服务端交付证据校验的 releaseMerged（含有效历史补记）进入已归档，待集成、待合入和待核实保留在已完成。工程文档归档本身不等于代码已合入发布分支，也不改写流程状态或删除记录。来源异常保留独立入口。非法范围链接回到进行中，保留具体 Change 深链接。取消保留原阶段、材料和取消原因；有效完成要求关闭四步、归档目录、任务／Plan 和关系满足规则，且原 live 目录已移除。异常完成声明不计为有效完成。

已取消入口按仓库可读记录总数决定显隐，不因临时筛选无匹配而隐藏；总数更新为零且正选中该系统 tab 时回到进行中并保留打开的详情。历史取消链接仍可解析，状态筛选中的取消选项和自定义取消视图始终可用。计数、目录、延续组及详情相邻顺序共用状态与筛选规则。

## 浏览、任务与材料

- 普通 Change 列表默认按首次进入 Git 的提交者时间从新到旧排序；同时间按 ID 排序，历史无法确定时间的置后。后续编辑与归档不重置创建时间，可切换紧急程度优先。延续组按首个匹配成员出现的位置排列，组内匹配成员沿用所选排序。
- Change 提供列表与只读看板，看板仅用于只选进行中的桌面视图，按当前处理状态、阶段或不分组展示；处理状态保留四列，阶段保留五列及空列，不分组为一列。混合状态或窄屏降级为列表但保留看板偏好。筛选菜单提供四类状态、本人、固定创建者、类型和紧急程度；显示菜单提供排序和按处理状态、阶段或不分组。不提供任务粒度、依赖视图、规模、关联能力及阶段／等待筛选；旧链接移除已删除条件并保留具体 Change 深链接，非法视图回到列表。
- 进行中列表突出当前阶段与进展，单一已归档状态使用合入时间线，已取消展示取消时间与原因，来源异常展示主来源和具体问题。清除筛选留在当前范围；无此类记录与筛选无匹配分别提示。
- 列表通过独立规模列展示 S/M/L/XL，阶段看板卡片在标签区展示相同标记，悬停及可访问名称提供完整规模；规模来自主记录，无法读取状态时显示“—”。窄屏保留紧凑规模与任务进度，不增加规模筛选或看板阶段列。
- 列表、看板和归档时间线展示协作者字标组：最多三个字标，其余用 `+N` 收拢，点击查看完整可滚动名单、姓名、可识别的平台用户名和创建者/参与推进身份；键盘可打开，关闭后焦点返回触发控件，点击成员组不进入 Change 详情。单人同时显示名称，长名称横向省略且保留完整字形；手机在行底部展示协作者。
- 创建者取 Change 首次加入 Git 的提交作者，与创建时间同源；协作者取集成来源及该 Change 正式材料来源历史中修改过其材料目录的普通提交作者，活动与归档目录按稳定 id 归并。无关工作分支未合入的修改及仅执行分支合并的操作者不计入；创建者固定第一，其余按首次参与时间与稳定身份排序。身份优先以可识别的 GitHub 数字 id、登录名及服务端规范化邮箱去重，不强行合并不同身份的同名作者。邮箱仅用于服务端识别，不进入工作台或分享投影；不虚构平台身份或头像，无已知成员时显示“—”。
- Change 正式材料来源可通过可选 `collaborators` 数组补充未直接提交材料的参与者，每项必填显示名 `name`，可附 GitHub 登录名 `login` 和正整数字符串身份 `subjectId`，不接受邮箱字段。配置成员按输入顺序去重追加到 Git 自动名单，保留创建者及所有历史成员的显示信息和排序，配置别名不能折叠已有历史成员。省略或清空配置只保留 Git 识别名单；无 Git 成员时仍可展示配置成员，但不将其标为创建者。CLI 创建时支持 `--collaborators`，活动记录可用 `collaborators --members` 更新补充名单，不改写其他流程状态；归档和取消记录仍只读。非法配置作为诊断提示并忽略，不撤销原流程完成或依赖事实；工作台与分享投影使用相同合并结果。
- 独立创建者列默认隐藏，可在显示菜单恢复；“我的”与创建者筛选继续采用创建者语义。详情保留创建者及创建时间的来源说明。
- 任务材料按 JSON 展示 `todo / doing / done / blocked`、验证、阻塞原因、任务分支和执行前置依据，不提供独立任务看板或状态筛选；提交标题只作查找线索。
- 详情以材料阅读页包含概览、任务或子项、文档、原型、合入变更、依据，以及主来源、确认、返工和验收记录。材料目录、正文与本页目录共用阅读布局，收起或窄屏时通过顶栏当前位置按钮切换材料；长标题横向省略，正文上方只保留单行文件路径与提交，不重复展示任务名、分支和标题。关闭详情保留列表筛选、位置和焦点，可切换上一个或下一个 Change。
- 概览按 Q 编号数值顺序展示主来源的澄清问题与用户最终回答，并展示轮次、推荐方案及撤回原因。未答显示“未回答”，撤回保留问答并标记“已撤回”，无记录隐藏；活动与归档均适用。内容以纯文本展示并保留换行，不展示回答历史或来源。
- small 任务直接读取 JSON；medium／large 结合 Plan 的交付定义和执行顺序；xlarge 展示子 Change 和子项结束数量，不创建父级实现任务或把子任务数量作为父项进度。
- 实际存在的 Markdown 材料可以阅读；缺失、不可读、当前规模不要求和尚未进入要求阶段的材料分别提示，不生成正文补空。从详情或深链接打开具体材料时保留所属 Change 上下文。

按处理状态分组时，确认等待显示“等待确认”，pause 单独显示“暂缓”，真实任务阻塞或依赖等待显示“受阻”，其余显示“推进中”。暂缓列表、看板和详情使用中性暂停提示并展示原因；暂停与阻塞任务并存时仍保留任务原因。空任务不显示 0/0 进度，详情说明尚未安排任务；恢复后按实际等待和任务状态重新分类。

## 分享阅读

详情的分享入口提供「网页链接」及「Agent 文本链接」两组复制入口，分别说明浏览器阅读和 Agent 直接读取 Markdown 的用途；两组范围和来源规则相同，复制成功各自反馈，剪贴板不可用时聚焦并选中对应链接以便手动复制。入口沿用主题和键盘交互，窄屏下按钮换行。访问规则见[公开只读分享](../access/spec.md#单个-change-的公开只读分享)与[Agent 文本分享](../access/spec.md#agent-文本分享)。独立网页阅读页展示概览、任务、文档、原型、合入变更和依据，含澄清问答及目标 Change 的 PR 交付信息；不加载个人工作台或要求接收者登录。分享范围外的关联目标保留说明，不展开其他 Change 的内容。

页面以文档阅读为主，默认进入可用材料。桌面充分使用窗口宽度，提供材料导航、正文与章节目录，支持专注阅读和字号切换；手机通过目录入口切换材料与章节，无全页横向溢出。分享范围固定于当前 Change，不提供其他 Change 的前后导航。

链接保留材料、文档相对路径、章节、原型或合入文件位置；保留匿名分享和固定原型链接，不提供仅复制当前浏览器地址的按钮。Change 移交工作分支或归档后，按当前权威来源解析相同材料，不能把旧绝对路径当成当前内容。切换目标、来源或快照后取消旧请求并忽略晚到响应；正文、图片及原型的错误都在当前阅读范围内处理，快照变化重新读取，目标不存在、来源不可用和读取失败分别说明。

分享中的合入变更沿用同一固定合入索引、文件清单与差异读取约束；PR 查询失败保留目标最近成功信息并标明待更新，没有成功时间时不补造历史结论。

## 标签筛选与紧急排序

类型与紧急程度读取权威记录中的可选 `types` 和 `urgency`，契约与命令见 [Change 状态维护](../../change-workflow/spec.md#类型与紧急程度)。历史缺失字段正常读取，不补写源文件。非法字段从解析副本中单独隔离并显示 warning，合法的另一字段和核心流程事实保留，不撤销有效完成及依赖满足；隔离后的字段按缺失处理。

列表、阶段看板和详情以纯文本展示类型标签，支持多标签及长名称换行。列表和卡片仅为非普通紧急程度显示徽标，省略与显式普通均不额外标注；详情展示显式紧急、高、低，省略或显式普通均不展示紧急程度，无类型时显示“无类型标签”。紧急程度没有独立的未设置状态。

类型候选来自项目实际标签，合并链接中已选但暂无匹配的合法名称；推荐词不混入筛选项。类型可多选，命中任一项即匹配，“无类型标签”与已选类型同样按 OR 匹配；紧急程度及创建者筛选取交集，普通同时匹配缺失与显式普通。列表与看板共享 Change 筛选，任务不拥有独立标签。

筛选与排序保存于 URL：`types` 和 `creator` 使用 JSON 数组，`noTypes=1` 表示无类型，`urgency` 使用四档值或多选 JSON 数组，`sort=urgency` 表示紧急优先；逗号、引号和 `none` 都是普通标签文字。`states` 保存多选状态，空数组表示全部四类，兼容旧 scope；`creatorSelf=1` 表示动态本人。状态组内取并集，本人与固定创建者取并集，不同筛选组间取交集。非法参数通过 replace 清理且保留具体 Change 深链接。清除筛选保留排序和当前范围；切 tab 应用该视图完整配置，切仓库清理临时条件并恢复该仓库视图。刷新、历史导航、详情返回及焦点沿用现有导航约定。多选浮层支持键盘操作和窄屏，触发器向读屏提供额外筛选数量。

紧急优先依次排列紧急、高、普通、低，缺失与显式普通同级，同级稳定保留默认创建顺序，核心来源不可读的记录置后。先筛选和排序成员再聚合延续组，关系及组名仍取完整快照，成员不继承其他成员的标签。看板只改变栏内顺序，执行前置不受排序影响。

## 个人动态视图

个人视图按 OpenFolio 账号和稳定仓库身份保存定义、显隐、顺序与最近选择，同账号跨浏览器及 Token 可恢复，不同账号与仓库隔离。首次初始化添加可编辑的“我的”：进行中、创建者本人、列表、按处理状态分组、最新创建。用户隐藏或删除后不自动重建。本人依据当前 Token 的 GitHub 数字身份匹配首次 Git 提交作者的可识别 noreply 数字身份，不按 OpenFolio 账号名、普通姓名或仅登录名猜测；无法识别时说明边界，无匹配提供查看进行中的入口。

tab 右侧齿轮打开管理弹层。新增继承当前完整筛选与显示，编辑载入已保存定义；四类状态可多选。支持编辑、显隐、删除和桌面/触屏拖拽，键盘可排序，不展示上下按钮。排序只作用于右侧个人视图，系统 tab 不参与管理。取消或关闭丢弃管理草稿，确认整批保存，失败及冲突保留草稿并提供重新加载或复制配置。隐藏/删除当前视图时回到可见“我的”，否则进行中。每仓库最多 30 个个人视图，名称为 1–40 个字符且不重复。

固定系统 tab 与初始“我的”的自带状态/本人条件不重复展示为标签或计入筛选角标，其他条件仍可见、可移除；自定义视图展示完整条件。主列表临时调整立即生效，显式保存到当前视图或另存后才修改定义；切换不自动覆盖原配置。切 tab 仅过滤已加载数据，不触发 Git 刷新。

创建者列开关属于完整视图配置，支持显示菜单、管理编辑、URL 的 `showCreator=1`、显式保存及重新打开恢复；既有视图缺少该字段时默认隐藏，保留其余条件与设置。

无显式目录查询的新入口恢复最近选择的已保存配置；显式 URL、刷新、历史导航与详情深链接优先，详情返回保持原查询。缓存立即展示，后台定义变化提示重新选择以应用，不覆盖临时条件或已打开草稿。响应按定义 revision 和本地选择代次核对，迟到保存/读取不回退定义、抢占导航或跨账号恢复内容；退出、连接或仓库变化隔离在途请求。

视图配置复用账号私有存储和仓库授权 lease；GET 读取、POST 仅首次初始化、PUT 以 expectedRevision 整批比较并保存、PATCH 独立更新最近选择。选择写入不制造定义冲突，整批保存保留服务端最新选择并处理不可见项回退。写入检查同源、会话版本和当前仓库权限；配置不扩大读取权限，不进入共享阅读投影，也不随 Token 工作台复制。

## 合入变更

详情以只读页签展示一次归档正式合入的时间、实际目标分支、固定合并提交及第一父提交、完整文件清单、增删统计与逐文件统一 diff。比较范围为 `git diff M^1 M`，包含代码、工程文档、归档移动及 Git 原型快照等全部目录；不推断这些代码当前是否仍生效，来源分支删除后仍通过历史 PR 记录定位。

差异索引按[合入协议](../../change-workflow/spec.md#归档后的去向)，与交付状态使用同一批完整 PR 记录，精确关联唯一已合并 PR 并核实其 M 属于固定的已推送交付目标历史，再检查双亲结构与归档目录。唯一可定位记录为 found，无已合并 PR 为 missing，多个候选或差异边界无法定位为 invalid，平台读取未完成或所需历史/对象不可读为 unavailable。缺失显示“暂无合入记录”，不宣称从未合入；异常明确诊断，不从提交消息、分支名、旧标签或 sourceCommit 猜测。单个记录异常不遮蔽其他正常 Change。差异不可用不撤销已核实的 PR 合入，差异索引不作为来源清理门禁。

父子分别使用自己的 M；子项 diff 为自身交付，父项 diff 为整体交付，父子来源分支删除后仍可读取。合入索引绑定文档快照及集成 tip；每次实际刷新重新核实 PR 关联，即使 Git tip 相同也反映 PR 状态或正文变化。旧版本索引在自动刷新时重算，只有版本和 M 均一致的已找到差异可复用，临时不可读记录会重试。摘要、每页 100 项的文件清单和单文件 API 沿用仓库授权，要求明确 snapshot；服务端从索引派生提交对，fileId 回查固定清单、cursor 绑定快照与提交对，不接受任意 base/head/path/revision。

清单按 NUL 分隔解析，保留原始路径字节与重命名关系，展示时转义不可见字符。统计完整读取或明确失败，不把部分清单冒充完整；二进制无文本增删统计。单文件按已验证 blob 读取，二进制、非 UTF-8、LFS、子模块、符号链接、仅模式变化与空内容分别提示，不下载外部对象或跟随链接。源文件或差异超过 1 MiB、差异超过 10000 行时说明限制，提供 Git 比较命令。

宽屏并排展示文件与正文，窄屏在文件列表和差异间切换。文件选择与视图保存于 URL，支持直接链接、刷新和前进后退；页签键盘导航及复制失败的手动兜底可用。切换仓库、Change 或快照后旧响应不跨记录呈现，读取失败可重试。

## 归档合入时间线

单独浏览已归档状态时，目录按浏览器本地日期倒序、同日按真实合入 PR 批次倒序展示。日期显示当前筛选结果总数；同日多批次时各批次显示数量，只有一个批次时省略重复数量。批次显示存在的版本、实际目标分支、PR 链接和合入时间，不硬编码 main/master。每批先显示 3 个 Change，可展开全部和收起，保留类型、规模与详情入口。

时间线继续应用类型、紧急程度、创建者等筛选，固定按合入时间排列；显示菜单仅提供适用的列开关，不展示排序、分组及列表/看板切换。创建时间排序、紧急程度优先和阶段分组不改变时间线顺序。混合状态的个人视图沿用普通列表。详情相邻导航采用筛选后完整时间线顺序；返回保留批次展开状态，并展开、定位和聚焦原 Change。

日期只采用经 PR/Git 交付核实的发布分支 PR 的真实 `mergedAt`；一个 Change 对应多个有效 PR 时选最早有可靠时间的一次，并通过 `releaseMergedPrNumber` 引用该批次，不重复展示。PR 更新时间、Change 创建时间与文档归档时间均不能替代合入时间。历史补记及缺少可靠时间的记录置于末尾“合入时间未知”，保持可读且不补造历史。

平台 PR 和页面缓存保留可选合并时间；旧记录缺字段仍可读取，映射缓存身份更新后重新采集以补齐真实时间。合入批次引用只用于展示，不改变归档资格、历史补记或既有交付核实规则。

## PR 与交付进度

交付进度独立于开发状态，自动判定结果不写入 change.json。列表、卡片、详情及分享页统一显示待集成、待合入、已合入或交付待核实；已完成按待集成、待合入、待核实分组，已合入单独进入已归档，不提供独立待集成/待合入筛选入口。详情展示 Change PR、发布 PR、PR 声明的版本、真实状态、历史和诊断。链接来自经仓库身份校验的平台响应，位于详情独立区域。

子项仅合入父分支时仍为待集成，并展示已合入父分支、等待父项整体集成的说明；其 M 进入项目集成历史后才进入待合入判定。发布父项不自动声明包含子项，子项须明确列入发布清单。有效归档且完整查询未找到已合并 PR 时为待集成；唯一关联 PR 已合并且其合并提交属于集成历史时，确认已集成。差异索引不可用时，仍保留经 PR 与 Git 证明的合入事实，并单独提示差异不可用；多个已合并 PR 属于正式交付歧义，显示待核实。发布 PR 明确包含该 Change，实际合并提交属于发布分支且包含对应集成提交，才显示已合入；已集成且尚未合入发布分支时为待合入。阶段只依赖所需事实，必要信息缺失、冲突或查询失败显示待核实。执行中的 Draft 不提前进入待集成，关闭未合入的 PR 不取消 Change，已合入不表示部署完成。

历史补记可用 `deliveryOverride: "releaseMerged"` 优先覆盖上述自动判定，仅集成分支上的有效完成归档生效；归档内 branch 保留历史归属，工作分支和发布分支副本不参与覆盖。缺少或异常的 M、PR 查询失败及关联歧义不影响补记标签，仍保留可读 PR 与诊断，不绕过仓库读取权限或 CI。缺省或删除字段恢复自动判定；非法值读取时隔离并提示，写入时拒绝。补记不生成 Git/PR 证据。

平台读取仅补充已知 Change，不参与发现。Change PR 以同仓库身份、登记源分支、实际交付目标（子项父分支，其余集成分支）及正文末尾唯一 SpecTrail-Change 标记精确匹配；发布 PR 以同仓库、发布目标、SpecTrail-Version 和 SpecTrail-Includes 清单关联。标记不从标题、代码示例或正文提及推断。平台编号及结果保存在可重建快照，change.json 不保存 PR URL、编号或状态；多个当前候选明确提示，不任取最新项。

PR 按配置的集成、发布目标和已知父分支批量读取全部状态，以创建时间降序分页，结果供全部 Change 在本地匹配；相同查询在一轮刷新内合并。关闭、重开、重建、合并及关联标记修改在成功刷新后反映，来源分支删除后的冷缓存仍可读取历史 PR。平台数据不逐 Change 查询详情或按提交补查，增加稳定历史 Change 不逐条增加远端请求。

同来源目录保存完整 PR 页面、ETag、原始条目数量与标记摘要，不保存 PR 正文；跨账号或 Token 不共享内容。每轮按页条件读取，304 仅复用对应页面，仍检查后续页；满页继续检查尾页，不以有效标记数量决定分页结束。只在某目标分支全部页面完成后替换其集合，失败不把部分结果或空结果当作成功；缓存损坏、查询未完成或超出资源上限明确报错。

两类 PR 的普通局部失败分别保留最近成功的 PR 展示和过期诊断；Change PR 读取失败时正式合入转为待核实，不把旧结果当作本次成功证据，也不推进成功时间。单个父分支查询失败仅影响相关子项，无关查询失败不覆盖已核实阶段，非法 M 不隐藏可信 PR 链接。限流立即终止本轮刷新，保留原快照与成功时间并报告等待信息，后续入口遵循[共享冷却](../access/spec.md#github-请求冷却)。版本说明及本次包含清单取发布 PR，不另建版本注册表或推断首次发布；旧历史没有可靠依据时不补造关联。

## 延续交付分组

可选 `followUpOf` 表示同仓库已归档直接前序的延续交付，与 `dependsOn` 和父子拆分分开解析，不引入独立话题生命周期。工作台按权威记录中的完整延续关系聚合多跳与分叉；各成员的标题、状态、任务、验收及归档记录仍独立。

普通 Change 列表先按当前范围和筛选匹配成员，再用完整关系组聚合；单一已归档状态按合入日期与 PR 批次组织，已归档根不会隐藏进行中的后继。分组以独立标题和外框呈现，匹配记录始终展开，保留各自详情入口与原 id 深链接；分组主标题强于单条 Change 标题，组内外各列使用一致的左右间距。无关联的单条记录沿用普通行，看板与执行依赖继续按独立 Change 展示。详情可追溯直接前序和同组交付。

组名取完整组中的有效 `followUpTitle` 声明，最靠近根的声明优先，同层按 id 稳定排序；筛选、列表顺序和成员状态不改变组名。旧组无声明时使用根标题。多个声明不一致时保留稳定名称并提示核对；命名与写入约定见 [Change 状态维护](../../change-workflow/spec.md#延续交付与分组命名)。

非法格式、缺失、无效前序、自指或循环只影响延续关联的阅读与分组，相关记录仍可单独打开。格式错误的可选 `followUpOf` 与 `followUpTitle` 分别隔离并提示，错误组名不解除合法关系；这些显示问题不抹除原交付的有效完成事实，也不使消费者原有的执行依赖失效。

## 阶段与完成标记

原始阶段为 `requirement / technical / plan / execution / close`。目录列表用统一的五个阶段圆点及当前名称表达进度，窄屏按布局隐藏阶段列并保留主要内容；详情中的流程路线继续按规模展示。当前阶段徽标和流程进度只用于 active 且无来源错误的记录；任务依赖等警告单独提示，不抹除合法的阶段。small 使用需求、执行、验收路线；medium／xlarge 将技术与计划合并展示；large 分别展示技术与计划。省略的阶段不显示为遗漏审批。

已归档、已取消详情突出结果、时间或原因，不显示当前阶段和流程进度。历史阶段、关闭步骤与确认保留在依据材料，任务记录及前置追溯保留在任务材料。详情根据实际记录判断，来自原型或跨范围深链接时保持一致。

需求、技术和计划的勾选依据实际确认记录，合并阶段仍要求对应的两个确认。阶段位置、已有文档或历史提交不自动证明确认发生。确认的时间、摘要和来源、返工的原因和处理方式均可查阅。

当前处于 execution／close 时，普通 Change 的非空任务集合全部为 done 才显示执行完成勾选；xlarge 的非空子项集合对应流程关系全部满足时显示执行完成。空集合、未完成任务、未知子项或退回规划不自动打勾。执行完成不代替验收或整个 Change 完成。

close 的通用名称为“验收”；active 且整体验证通过、没有验收记录时显示“验收中”。“验收与归档”按整体验证、验收、Specs 同步、归档提交展示各步真实结果、时间与摘要。缺项显示未记录，验证失败保留失败事实，Specs 无需变更显示原因；部分记录不等于完成。

SpecTrail 中 small 默认自验收后同步 Specs 并归档；用户要求人工验收或人工验收提出问题后，该 Change 后续须用户确认，其余规模人工验收。两种方式均记录 `acceptance.result: accepted`，摘要和来源说明实际验收方式与依据。工作台读取这些记录，不凭 small 规模或测试通过补出验收结果。状态操作与时间由 [Change 状态维护](../../change-workflow/spec.md)中的本地语义命令完成。

## 关系与依赖证据

Change 前置关系取 `dependsOn`，父子关系取 `parent / children`。xlarge 父项在需求或技术阶段可先声明尚未创建的 children；这些子项显示“待创建”，不计入读取异常或已结束数量，不影响父项文档与原型阅读。子项已有集中记录但来源、状态或反向 parent 声明异常时仍有诊断；执行、关闭阶段的缺失子项也仍有诊断。其他关系的缺失、重复、自指、循环、父子不对称、嵌套父项或子依赖父均有诊断；children 顺序不代表串行依赖。关系异常影响有效完成判断，并沿依赖传播，不能成为下游已满足的前提。

流程前提与交付可用性分开显示。有效归档的前置 Change 满足流程前提；已取消前置不满足。父项的子 Change 可由有效完成或有效取消记录满足结束条件。来源异常或目标缺失保持不可判定。

Git 祖先关系仅证明含有归档记录的固定来源提交在当前分支历史中；无法证明、历史不足或 squash 情况显示可用性待核实。不根据提交标题猜测对应关系，不把祖先存在当作代码未被撤销的证明。

普通 Change 的任务前置默认按编号数值递增形成串行链，例如 T1、T2、T10，与 JSON 属性顺序和正文排列无关。small 无需 Plan，medium／large 仍需可读取的 Plan 正文；缺少可选的执行顺序表不产生来源提示，仅有顺序标题或文字说明仍使用默认。xlarge 按子 Change 组织。

显式任务前置来自 Plan 中唯一“执行顺序”章节下含“任务／前置任务”两列的表格，可覆盖默认安排。每个 JSON 任务需要唯一一行，前置为“无”或合法任务编号，不能重复、自依赖或成环；代码、引用、列表和 HTML 块中的示例不作为声明。表格存在但歧义、覆盖不全或无效时保留原文和位置依据并提示不可判定，不退回默认；medium／large 缺少可读取 Plan 时提示材料缺失。任务页展示默认或显式来源，顺序规则与流程命令一致；普通 Change 的无效显式安排也影响有效完成判断。

## 原型关联

Change 可关联项目单一原型包的多个页面或组件，保留当时的显示信息、源码提交及 hosted/git 固定产物引用；详情原型标签支持入口、设备/自定义尺寸、方向、缩放和固定版本链接。工程记录及关联目录使用当前连接的仓库权限；进行中的 Change 无需合入集成分支即可由有权限用户准备公开原型，分享独立的固定版本入口。后续项目当前引用更新不覆盖历史交付。已合入归档的固定原型从同一有效 M 读取，Git 使用归档快照，托管引用保持不变；无有效历史关联的旧记录留空，异常记录显示诊断，不使用保留标签回退。当前停用拒绝新的准备，不影响已公开版本与其他文档阅读；外部产物由宿主保留。完整关联、隔离与缓存约定见 [原型浏览与预览](../prototype-preview/spec.md)。
