# 服务配置

数据目录由 `OPENFOLIO_DATA_DIR` 指定，默认 `~/.local/share/open-folio`。配置优先使用 `OPENFOLIO_CONFIG` 路径，否则使用数据目录下的 `config.json`；不接受内联 JSON。不存在的父目录与文件自动创建，初始配置为 `schemaVersion: 2` 和空资源限制，已有文件不会被初始化覆盖。

配置只保存读取资源限制，不登记全局仓库、Specs 来源分支或邀请码。仓库通过个人 token 自动发现，默认阅读来源来自远端默认分支。个人 UI 不提供服务配置或管理密码表单；管理员通过独立管理 API 读取与保存限制、获取上传地址和撤回公开版本，管理权限不授予工程读取权限。

资源限制可清除覆盖值以恢复默认，合法保存立即生效，无需重启。配置使用原文摘要进行版本比较，在同目录写入临时文件再原子替换；过期版本或外部编辑导致冲突时返回 409，重新读取后才可保存。损坏 JSON、字段不合法和读写失败保留原配置并显示明确错误。数据目录按 0700、敏感文件按 0600 初始化，单进程锁防止重复写入。

首次读取 schemaVersion 1 时，先在私有 `legacy-v1` 保存原始配置字节，再生成不含邀请码的旧项目定位映射，最后原子替换为只保留限制的新版配置。失败保留原文件，重复升级不覆盖备份。旧项目、邀请码、管理员 Cookie 与旧缓存不转换成个人授权；旧链接只有在用户连接并验证仓库权限后才可恢复。旧 `prototypeOrigins` 不作为来源白名单，新配置不保留该字段。

升级、回退、密钥轮换和数据清理须停止当前服务并备份完整数据、外置配置与密钥；不允许两个版本同时写同一目录。回退恢复配套旧配置及二进制，新版独立数据与公开原型目录继续保留。持久目录、资源默认值、备份和清理步骤见仓库 README。
