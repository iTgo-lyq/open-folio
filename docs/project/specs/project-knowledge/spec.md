# 项目知识工作台

OpenFolio 使用当前凭据工作台的 token 发现可访问的 SpecTrail 仓库，从中心 Git 的已推送记录提供 [Spec 阅读](./spec-reading/spec.md)、[Change 追踪](./change-tracking/spec.md)与[原型浏览](./prototype-preview/spec.md)。工程文档和流程继续由 SpecTrail 维护，工作台只读展示，不创建或修改工程记录。

## 能力边界

- 首次进入使用自己的 token 登录，用户名可选，成功后自动发现仓库；相同平台实例与 token 在多设备恢复同一工作台。首页提供状态筛选、分页、重新发现及 HTTPS 地址检查。仓库内主导航包含 Specs、Changes 与原型，默认进入 Specs；没有在线编辑、Agent 调度或工作台流程写入。
- 用户在当前 token 工作台选择仓库，阅读默认保护分支的 Specs 和当前原型、查看 Change 材料和刷新远端记录；需要其他 token 时切换凭据。未登录、发现中、空仓库、部分失败和失权分别展示真实状态，不填充演示数据。
- 文档及详情展示来源分支、提交、文件路径和快照读取时间；原型二级预览聚焦目录与画布，来源信息在详情中查看。本地工作区、暂存区及未推送提交不属于采集来源。
- 蓝紫背景、窄侧轨、玻璃胶囊导航和圆角阅读区组成统一外壳。框架仅保留一行页头，读取来源、时间、分享与刷新集中在右上角；窄屏通过图标入口展开完整来源状态。导航提示及全局通知显示在内容区域和原型卡片之上。侧栏可收起，桌面提供详情抽屉，手机提供底部胶囊与可返回的阅读区域；键盘与 Escape 支持导航、关闭最上层弹层和恢复焦点。
- 浏览链接保存稳定仓库身份、来源、文档或 Change、视图、筛选和锚点，不携带访问凭据。重新打开链接读取该来源的最新缓存；一次阅读中的正文绑定明确的快照。同 token 设备共享服务端保存的最近仓库、阅读模块及侧栏偏好，明确链接优先；页面阅读位置保留在按工作台隔离的浏览器状态中。随机 HttpOnly Cookie 恢复独立设备会话，token 在服务端加密保存，只有用户主动复制当前凭据时读回明文。

## 仓库发现与来源选择

公开版本只支持 GitHub.com；平台身份、个人仓库枚举、内容探测与 Git 凭据注入通过适配器隔离，内部可扩展其他平台。稳定仓库身份包含平台、实例及平台仓库 id，改名或转移后按此身份重新解析路径。同一账号的不同 token 对应不同工作台，身份匹配不依赖 GitHub 登录系统或可变用户名。

候选仓库来自当前 token 可见的个人仓库列表，处理分页、限流和中断续传；不遍历平台全部公开仓库。识别依据是默认分支中的普通文件 `docs/project/workflow.json`、完整受支持契约和声明的守护分支。有效、需要处理、未接入及检查失败分别呈现；部分扫描不冒充完整空结果。发现只读取必要元数据、配置与 refs，进入仓库后才 fetch 工程记录。HTTPS 地址补充检查使用同一适配器与当前 token，不建立全局项目登记。

所有平台 API、`ls-remote` 和 `fetch` 只使用当前连接的 token，不读取宿主 Git helper、netrc、SSH agent 或继承鉴权头，也不回退其他连接。仓库地址不含凭据、查询参数或片段，只允许受信平台解析的 HTTPS 目标。

Specs 只使用远端 HEAD 指向且在 `docs/project/workflow.json` 中登记的默认守护分支。缺失或异常的默认来源给出提示，不切换到开发分支。页面展示实际保护分支身份；旧链接的分支参数不改变该来源。

Change 列表跨已推送分支聚合，主来源按 Change 自身的 `branch` 确定，与 Specs 的保护分支来源独立。主来源判定和冲突处理见 [Change 追踪](./change-tracking/spec.md#状态与主来源)。

原型总览只读取仓库默认保护分支的当前清单与开关，不从开发分支或历史 Change 聚合当前版本。未合入的原型通过 Change 页面查看和分享；已准备版本使用独立公开入口。

## 快照与恢复

服务在私有持久目录维护 bare Git 缓存、按 blob 保存的正文和不可变快照，不使用数据库。发现位于 `discovery-v2/<workspaceId>`，仓库位于 `repositories-v2/<workspaceId>/<repositoryKey>`，不包含设备会话 ID；同 token 的设备共享发现与完整快照，不同 token 不共享私有数据、锁或异步任务。采集 fetch 已推送分支及原型归档保留标签，不 checkout 来源工作区、运行仓库脚本或初始化子模块；普通文件以固定 commit、tree 和 blob 读取，符号链接和子模块不作为正文。

完整采集后原子发布快照，每份快照固定各分支的提交及对应文档、Change 和关系索引。同一分支的 JSON 与正文不能混用不同提交；不假设多分支具有同时提交的事务语义。

Specs 正文、目录和原型清单均从快照读取。默认分支采集工程文档，其他分支仅采集 Change 和归档目录；按来源、提交及扫描规则复用未变化来源的文档和 blob，默认保护分支未变化时复用有效原型清单。全部来源未变化时保留原快照和采集时间，最近成功检查时间另行持久化。旧缓存或扫描限额变化重新采集；分支删除、强推和默认来源切换在下一次成功刷新反映。

- 首次进入尚无快照的仓库时自动采集；已有快照先呈现内容，同时后台检查。可见页面在每轮结束一分钟后、重新打开仓库或回到前台时检查，隐藏页面暂停，页面关闭后不常驻扫描。发现新快照后自动更新 Specs、Change 正文及原型总览。手动刷新可立即检查。
- 同工作台同仓库的并发刷新合并，一分钟内成功检查可复用；每个设备请求仍单独检查本地会话与归属。共享任务归属于工作台，只使用其 token，不借用其他凭据。
- 刷新失败保留最近成功快照、成功时间及错误提示；后台网络、限流或采集临时失败保留已显示内容并提示更新失败，后续检查重试。明确失权清除正文，普通新读取仍需当前 token 授权；没有可用快照时说明读取失败。
- 服务重启恢复已成功保存的快照。保留当前及前两份完整快照；访问已清理版本时明确提示过期，不静默换成新正文。
- 单文件超限或格式异常保留来源诊断；整体采集、容量或持久化失败不发布部分快照。默认读取限额及配置方法见仓库 README。
- 单设备退出、撤销、到期或切换凭据后撤销该设备读取与在途交付，其他设备的共享任务继续；退出全部设备取消工作台任务，保留已提交结果。工作台、发现与缓存不随设备退出删除，重新提供相同有效 token 可恢复；缓存读取遵循本地会话与周期远端权限检查，旧全局项目缓存不转换成个人授权。

## 长期技术与访问约束

应用采用 Next.js App Router、React 和 Node.js 服务端 API。Git、配置、凭据和索引处理留在服务器，客户端读取展示数据。运行需要 Node.js 24、Git、仓库读取权限和持久磁盘；单 Node 进程、单实例使用一个数据目录，进程锁防止重复写入。

默认监听 loopback，远程访问由受信 HTTPS 反向代理提供。个人访问使用 token 与服务端会话；独立管理员密码仅控制[运维配置](./configuration/spec.md)、上传地址及公开版本撤回，不授予工程读取权限。[个人访问与分享](./access/spec.md)定义会话和协作者访问规则。

工程记录 API 按当前设备会话、工作台、稳定仓库、快照及文档清单检查读取范围，不接收任意本地路径或 Git ref。平台身份在登录时验证；仓库身份和内容权限按同一凭据工作台、同一仓库固定复用 5 分钟，列表与正文共用并合并并发。首次或过期复验，活跃工作台的每分钟后台检查在到期时触发；服务重启后重新检查。私有快照和已发布原型使用同一周期，新增公开原型发布前即时复验。Git 读取失败主动复验，明确拒绝立即失效并阻止在途交付；本地设备状态每次检查。临时网络与限流保留已显示内容，过期复验失败不延长成功授权。文档和流程响应采用 `private, no-store`，刷新接口只接受空请求体。普通响应不包含凭据与完整 Git 错误，主动复制当前 token 的独立接口遵守[个人访问与分享](./access/spec.md)的边界。

原型产物在有权限时准备固定版本，匿名读取只使用已发布文件，不触发 Git 或平台 API。内置静态托管使用专用上传地址，公开文件可按固定版本缓存。托管选择、文件存储与隔离约定见[原型浏览](./prototype-preview/spec.md)。
