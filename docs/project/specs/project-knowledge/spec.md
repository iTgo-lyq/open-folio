# 项目知识工作台

OpenFolio 从已配置中心 Git 仓库的已推送记录提供 [Spec 阅读](./spec-reading/spec.md)、[Change 追踪](./change-tracking/spec.md)与[原型浏览](./prototype-preview/spec.md)。工程文档和流程继续由 SpecTrail 维护，工作台只读展示，不创建或修改工程记录。

## 能力边界

- 主导航包含 Specs、Changes 与原型，默认进入 Specs；提供原型总览和静态预览，没有在线编辑、Agent 调度或工作台流程写入。
- 用户可以切换已配置项目、选择 Specs 来源分支、搜索文档和刷新远端记录。空项目显示真实空状态，不填充演示数据。
- 文档及详情展示来源分支、提交、文件路径和快照读取时间；原型二级预览聚焦目录与画布，来源信息在详情中查看。本地工作区、暂存区及未推送提交不属于采集来源。
- 蓝紫背景、可收起侧栏和内嵌阅读区组成统一外壳。桌面提供详情抽屉，手机提供可返回的阅读区域；键盘与 Escape 支持导航、关闭最上层弹层和恢复焦点。
- 浏览链接保存项目、来源、文档或 Change、视图、筛选和锚点。重新打开链接读取该来源的最新缓存；一次阅读中的正文绑定明确的快照。浏览器存储仅保存显示偏好和阅读位置。

## 中心仓库与来源选择

服务只读取部署者登记的 HTTPS 仓库，地址不包含用户名、密码、查询参数或片段。运行环境的 Git credential helper 提供读取权限，浏览器不接收或录入仓库凭据，也不能指定任意远端地址。

Specs 默认来源取配置的 `specBranch`，未配置时使用远端 HEAD 指向的默认分支，并核对该来源是否为默认分支中 `docs/project/workflow.json` 声明的守护分支。缺失或异常的默认来源给出提示，用户仍可显式选择已推送分支。页面保留所选分支身份，不把其他分支内容冒充默认分支能力。

Change 列表跨已推送分支聚合，主来源按 Change 自身的 `branch` 确定，与 Specs 分支选择独立。主来源判定和冲突处理见 [Change 追踪](./change-tracking/spec.md#状态与主来源)。

原型总览只读取 main 的当前清单与开关，不随 Specs 来源切换，也不从历史 Change 聚合当前版本。未合入的原型通过 Change 页面查看和分享。

## 快照与恢复

服务在私有持久目录维护独立 bare Git 缓存、按 blob 保存的正文和不可变快照，不使用数据库。采集 fetch 已推送分支及原型归档保留标签，不 checkout 来源工作区、运行仓库脚本或初始化子模块；普通文件以固定 commit、tree 和 blob 读取，符号链接和子模块不作为正文。

完整采集后原子发布快照，每份快照固定各分支的提交及对应文档、Change 和关系索引。同一分支的 JSON 与正文不能混用不同提交；不假设多分支具有同时提交的事务语义。

- 首次进入尚无快照的项目时自动读取一次，之后由页面手动刷新；同项目并发刷新合并。
- 刷新失败保留最近成功快照和成功时间，并保存错误提示；没有可用快照时说明读取失败。
- 服务重启恢复已成功保存的快照。保留当前及前两份完整快照；访问已清理版本时明确提示过期，不静默换成新正文。
- 单文件超限或格式异常保留来源诊断；整体采集、容量或持久化失败不发布部分快照。默认读取限额及配置方法见仓库 README。
- 项目移出配置后，其缓存不再通过 API 暴露；仓库地址变化使用隔离缓存。

## 长期技术与访问约束

应用采用 Next.js App Router、React 和 Node.js 服务端 API。Git、配置、凭据和索引处理留在服务器，客户端读取展示数据。运行需要 Node.js 24、Git、仓库读取权限和持久磁盘；单 Node 进程、单实例使用一个数据目录，进程锁防止重复写入。

默认监听 loopback，远程访问由部署环境提供。应用没有内置团队登录；访问控制、配置与含私有仓库内容的缓存由运行环境保护。

API 按已配置项目、快照和文档清单检查读取范围，不接收任意本地路径或 Git ref。文档和流程响应采用 `private, no-store`，原型截图使用私有缓存并强制校验，详见[原型浏览](./prototype-preview/spec.md)；刷新接口只接受空请求体。凭据与完整 Git 错误输出不返回浏览器。
