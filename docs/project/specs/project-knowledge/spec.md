# 项目知识工作台

OpenFolio 使用当前凭据工作台的 token 发现可访问的 SpecTrail 仓库，从中心 Git 的已推送记录提供 [Spec 阅读](./spec-reading/spec.md)、[Change 追踪](./change-tracking/spec.md)与[原型浏览](./prototype-preview/spec.md)。工程文档和流程继续由 SpecTrail 维护，工作台只读展示，不创建或修改工程记录。

## 能力边界

- 平台明确标记归档的仓库不进入常规目录，发现时不执行工作流和 Git 探测；已有仓库在现有元数据复验周期内识别归档后停止采集。用户可在可阅读及需要处理的仓库菜单选择「不再追踪」，并从「已停止追踪」恢复；选择按稳定仓库身份保存在当前 Token 工作台，跨设备、退出重登、服务重启和重新发现保留。目录、仓库选择与后台扫描统一过滤，刷新开始和快照发布前复核最新选择。停止追踪不删除已有快照或公开原型；明确的私有阅读链接仍按权限读取已有内容，采集新快照需恢复追踪。解除平台归档后可重新发现。
- 首次进入自行设置账号密码注册并登录，绑定有效 Token 后自动发现仓库；同账号可在不同浏览器直接选用已绑定 Token，恢复对应工作台。首页展示可阅读仓库、检查异常、加载更多、重新发现及 HTTPS 地址检查。仓库内主导航包含 Specs、Changes 与原型，默认进入 Specs；没有在线编辑、Agent 调度、搜索或快速跳转入口及工作台流程写入。
- 用户在当前 token 工作台选择仓库，阅读集成分支的预发布 Specs 和当前原型、查看 Change 材料和刷新远端记录；账号可绑定多个 Token 并命名、选用或解绑；不同浏览器独立选择，同浏览器标签页同步。未登录、发现中、空仓库、部分失败和失权分别展示真实状态，不填充演示数据。
- 文档正文上方只显示单行文件路径与提交；阅读页顶栏直接展示刷新按钮和当前内容的上次更新时间，点击时间可查看实际分支、提交与异常详情。窄屏保留紧凑时间和刷新入口，Change 详情与原型聚焦页同样可用。时间取自最近成功内容快照，检查未产生新快照或刷新失败时保留；读取中禁用重复刷新。原型来源信息在详情中查看。本地工作区、暂存区及未推送提交不属于采集来源。
- 中性窗口底色、陶土强调、墨色平面标志和圆角阅读区组成统一外壳，未手动选择时跟随系统主题，浅色或深色的手动选择保存在本机。玻璃材质用于浮动顶栏、导航胶囊、菜单与弹层；抽屉贴合窗口边缘，单层玻璃表面与模糊遮罩保留正文可读性。页面内容区保留 Changes 与原型标题，顶栏承载上下文与操作，账号菜单提供主题、Token 切换、账号与 Token 设置及退出。
- 网站侧栏首次默认收起，尊重已保存的展开偏好；点击居中的标志或 Cmd/Ctrl+\\ 切换，收起态以悬浮胶囊显示四个模块，平板默认收起，手机改用底部导航。收起态 Changes 图标展示当前仓库进行中总数，0 隐藏、超过 99 显示 99+，辅助说明保留准确数量。同仓库切换模块持续保留快照与角标，切换仓库或凭据仍即时隔离旧数据。键盘与 Escape 支持导航、关闭最上层弹层和恢复焦点。
- 浏览链接保存稳定仓库身份、来源、文档或 Change、视图、筛选和锚点，不携带访问凭据。重新打开链接读取该来源的最新缓存；一次阅读中的正文绑定明确的快照。同账号选中相同 Token 的设备共享服务端保存的最近仓库、阅读模块及侧栏偏好，明确链接优先；页面阅读位置保留在按工作台隔离的浏览器状态中。随机 HttpOnly Cookie 恢复账号设备会话与当前选择，token 在服务端加密保存，只有用户主动复制当前凭据时读回明文。不同账号或 Token 的工作台保持独立，切换恢复目标偏好并使旧请求失效；同浏览器标签页共享当前选择，其他浏览器独立。

## 仓库发现与来源选择

公开版本只支持 GitHub.com；平台身份、个人仓库枚举、内容探测与 Git 凭据注入通过适配器隔离，内部可扩展其他平台。稳定仓库身份包含平台、实例及平台仓库 id，改名或转移后按此身份重新解析路径。同账号的不同 Token 对应不同工作台；不同账号绑定相同 Token 仍隔离，工作台匹配不依赖 GitHub 登录系统或可变用户名。

候选仓库来自当前 token 可见的个人仓库列表，处理分页、限流和中断续传；不遍历平台全部公开仓库。初次自动发现直接尝试推荐集成分支 develop；用户可通过仓库地址检查指定实际集成分支，按凭据工作台和稳定仓库身份保存选择，后续重新发现、重试与重启沿用。识别依据是所选集成分支中的普通文件 `docs/project/workflow.json`、受支持的 v3 契约、与选择一致的 integrationBranch 及不同的 releaseBranch；发布分支不作为发现文档的来源。有效、需要处理、未接入及检查失败分别呈现；部分扫描不冒充完整空结果。发现只读取必要元数据、配置与明确配置的 refs，工程记录由后续刷新对已接入仓库定向 fetch。HTTPS 地址补充检查使用同一适配器与当前 token，不建立全局项目登记。

私有工作台的平台 API、`ls-remote` 和 `fetch` 只使用当前连接的 token，不读取宿主 Git helper、netrc、SSH agent 或继承鉴权头，也不回退其他连接。单个 Change 的匿名分享从同目标的已接入可读来源选择凭据，规则见[公开只读分享](./access/spec.md#单个-change-的公开只读分享)。仓库地址不含凭据、查询参数或片段，只允许受信平台解析的 HTTPS 目标。

项目当前配置、Specs、原型开关与清单均直接从指定集成分支读取；名称可自定义，develop 只是推荐初值。默认分支配置、HEAD 指向和发布分支是否存在均不影响该来源。页面标明实际集成分支和预发布来源；明确阅读链接的选择优先于已保存的仓库选择。配置缺失、版本不受支持或声明名称不匹配时提示 Setup，不跳转到其他分支或全量扫描。发布分支只定向读取 Git tip 以核实发布交付，读取失败不隐藏已有工程文档。

Change 列表只从集成分支 changes/archive 的集中入口建立，按 change.json.branch 定向读取登记的工作分支；子项优先读取已合入父分支的有效归档，整体集成后读取集中归档；集中旧副本不提供当前执行进度。有效集中归档直接阅读。主来源判定和冲突处理见 [Change 追踪](./change-tracking/spec.md#状态与主来源)。

原型总览只读取集成分支的当前清单与开关，不从其他工作分支或历史 Change 聚合当前版本。未集成的原型通过 Change 页面查看和分享；已准备版本使用独立公开入口。

## 快照与恢复

服务在私有持久目录维护 bare Git 缓存、按 blob 保存的正文和不可变快照，不使用数据库。发现位于 `discovery-v2/<workspaceId>`，仓库位于 `repositories-v2/<workspaceId>/<sourceKey>`，其中 sourceKey 为稳定仓库身份与所选集成分支的摘要，不包含设备会话 ID；同账号选用相同 Token 的设备共享发现与完整快照；不同账号或 Token 不共享私有数据、锁或异步任务。采集定向 fetch 所选集成分支、已登记目标及配置的发布分支，按需获取完整集成历史用于合入索引，不查询或拉取原型归档标签，不 checkout 来源工作区、运行仓库脚本或初始化子模块；普通文件以固定 commit、tree 和 blob 读取，符号链接和子模块不作为正文。

完整采集后原子发布快照，每份快照固定各分支的提交及对应文档、Change、关系和合入索引。同一来源的 JSON 与正文不能混用不同提交；不假设多分支具有同时提交的事务语义。发布前重核所选集成分支配置和路由集合，变化时有界重读，持续变化则保留旧快照并报错；普通工作分支持续推进不阻止本轮固定提交结果发布。

Specs 正文、目录和原型清单均从快照读取。集成分支采集当前工程文档和集中入口，规划及有效归档读取正文；移交后集中旧正文不读取、不占正文预算。工作分支采集分配给它的 Change 目录，已知父分支同时提供所属子项的有效归档；按来源、提交、入口范围和读取规则复用文档与 blob，集成分支未变化时复用有效原型清单。Git 来源未变化时仍读取 PR 状态；文档、交付投影和诊断均未变化时保留原快照和采集时间。最近成功检查及 PR 最近成功时间另行持久化，失败不延长成功时间。PR 元数据更新同样经过发布前权限核实。缓存失效或扫描限额变化重新采集；分支删除、强推和集中入口切换在下一次成功刷新反映。快照语义与缓存身份随来源契约升级，旧全量快照不能当作新模式成功快照；仓库缓存和刷新任务按凭据工作台、稳定仓库身份与集成分支隔离，更换来源不复用其他分支的正文、原型策略、历史快照或在途刷新。旧发现结论重新检查，旧内容缓存不作为当前成功快照；Git 缓存只接受当前定向读取配置。缓存刷新持有写锁，删除 refs/openfolio/archive-v2/\* 专用引用，并在新快照发布后淘汰旧标签快照；未访问缓存随下次刷新重建，不扫描或删除用户持久资料。

- 服务启动即从已有 Token 绑定与发现记录恢复全部已接入仓库的后台扫描，无需打开页面；构建阶段不启动，服务关闭时结束调度。每轮结束一分钟后检查到期目标，全局最多并发两个来源，同一轮不重叠。来源连续两分钟没有私有页面或分享页的刷新请求后，改为扫描完成后至少五分钟再扫描；活动按工作台、仓库和集成分支隔离。单个来源或工作台失败不阻断其他目标，后续周期重试；不额外枚举新仓库。
- 首次进入尚无快照的仓库时自动采集；已有快照先呈现内容，同时检查。可见页面在每轮结束一分钟后、重新打开仓库或回到前台时检查，隐藏页面暂停自身轮询，后台扫描继续。发现新快照后自动更新 Specs、Change 正文及原型总览。手动刷新可立即检查。
- 当前页面会话按读取身份、仓库及分支复用有界内存缓存，覆盖工作台、正文和原型目录；私有内容不写入浏览器持久缓存。阅读模块间切换不重新请求相同工作台或重启刷新，返回已读材料优先展示对应内容版本。更新时先准备当前可见正文与原型目录，再一并替换快照、正文及资源版本；准备期间切换材料会重新核对当前阅读项。已删除材料不继续作为当前材料展示。
- 会话后台检查或仓库目录更新的暂时故障保留已显示内容并提示重试；目录状态和列表独立加载。明确账号、绑定或权限失效时清空对应阅读缓存并取消在途交付，迟到响应不能恢复旧内容。
- 同工作台同仓库同集成分支的并发刷新合并，一分钟内成功检查可复用；每个设备请求仍单独检查本地会话与归属。共享任务归属于工作台，只使用其 token，不借用其他凭据。
- 刷新失败保留最近成功快照、成功时间及错误提示；后台网络、限流或采集临时失败保留已显示内容并提示更新失败，后续检查重试。明确失权清除正文，普通新读取仍需当前 token 授权；没有可用快照时说明读取失败。
- 服务重启恢复已成功保存的快照。保留当前及前两份完整快照；访问已清理版本时明确提示过期，不静默换成新正文。
- 单文件超限或格式异常保留来源诊断；整体采集、容量或持久化失败不发布部分快照。默认读取限额及配置方法见仓库 README。
- 单设备退出、撤销、到期或切换凭据后撤销该设备读取与在途交付，其他设备的共享任务继续；退出全部设备取消该账号当前全部工作台任务，保留已提交结果。只要账号保留 Token 绑定，后台在后续周期继续扫描；解绑移除目标并中止其在途任务。工作台、发现与缓存不随设备退出删除，重新登录账号并选用原绑定可恢复；缓存读取遵循本地会话与周期远端权限检查。

## 长期技术与访问约束

应用采用 Next.js App Router、React 和 Node.js 服务端 API。Git、配置、凭据和索引处理留在服务器，客户端读取展示数据。运行需要 Node.js 24、Git、仓库读取权限和持久磁盘；单 Node 进程、单实例使用一个数据目录，进程锁防止重复写入。

默认监听 loopback，远程访问由受信 HTTPS 反向代理提供。个人访问使用账号密码与服务端会话，Git 权限来自账号选用的 Token；独立管理员密码仅控制[运维配置](./configuration/spec.md)、上传地址及公开版本撤回，不授予工程读取权限。[个人访问与分享](./access/spec.md)定义会话和协作者访问规则。

工程记录 API 按当前设备会话、工作台、稳定仓库、快照及文档清单检查读取范围，不接收任意本地路径或 Git ref。平台身份在绑定及选用 Token 时验证；仓库身份和内容权限按同一凭据工作台、同一仓库固定复用 5 分钟，列表与正文共用并合并并发。首次或过期复验，页面检查与常驻后台扫描均在到期后触发；服务重启后重新检查。私有快照和已发布原型使用同一权限有效期，新增公开原型发布前即时复验。Git 读取失败主动复验，明确拒绝立即失效并阻止在途交付；本地设备状态每次检查。临时网络与限流保留已显示内容，过期复验失败不延长成功授权。文档和流程响应采用 `private, no-store`，刷新接口只接受空请求体。普通响应不包含凭据与完整 Git 错误，主动复制当前 token 的独立接口遵守[个人访问与分享](./access/spec.md)的边界。

原型产物在有权限时准备固定版本，独立公开入口只使用已发布文件，不触发 Git 或平台 API。Change 分享中的原型按当前目标与可读来源提供，和永久公开版本分开。内置静态托管使用专用上传地址，公开文件可按固定版本缓存。托管选择、文件存储与隔离约定见[原型浏览](./prototype-preview/spec.md)。
