# 项目知识工作台

OpenFolio 使用个人连接的 token 发现可访问的 SpecTrail 仓库，从中心 Git 的已推送记录提供 [Spec 阅读](./spec-reading/spec.md)、[Change 追踪](./change-tracking/spec.md)与[原型浏览](./prototype-preview/spec.md)。工程文档和流程继续由 SpecTrail 维护，工作台只读展示，不创建或修改工程记录。

## 能力边界

- 首次进入连接自己的 GitHub 账号，成功后自动发现仓库；首页提供仓库搜索、状态筛选、分页、重新发现及 HTTPS 地址检查。仓库内主导航包含 Specs、Changes 与原型，默认进入 Specs；没有在线编辑、Agent 调度或工作台流程写入。
- 用户明确选择个人连接与仓库，可以选择 Specs 来源分支、搜索文档和刷新远端记录。未连接、发现中、空仓库、部分失败和失权分别展示真实状态，不填充演示数据。
- 文档及详情展示来源分支、提交、文件路径和快照读取时间；原型二级预览聚焦目录与画布，来源信息在详情中查看。本地工作区、暂存区及未推送提交不属于采集来源。
- 蓝紫背景、窄侧轨、玻璃胶囊导航和圆角阅读区组成统一外壳。侧栏可收起，桌面提供详情抽屉，手机提供底部胶囊与可返回的阅读区域；键盘与 Escape 支持导航、关闭最上层弹层和恢复焦点。
- 浏览链接保存稳定仓库身份、来源、文档或 Change、视图、筛选和锚点，不携带访问凭据。重新打开链接读取该来源的最新缓存；一次阅读中的正文绑定明确的快照。浏览器保存显示偏好与阅读位置，通过随机 HttpOnly Cookie 恢复服务端会话，token 只在服务端加密保存。

## 仓库发现与来源选择

公开版本只支持 GitHub.com；平台身份、个人仓库枚举、内容探测与 Git 凭据注入通过适配器隔离，内部可扩展其他平台。稳定仓库身份包含平台、实例及平台仓库 id，改名或转移后按此身份重新解析路径。同一账号的多个 token 可以建立不同连接，由用户明确选择。

候选仓库来自当前 token 可见的个人仓库列表，处理分页、限流和中断续传；不遍历平台全部公开仓库。识别依据是默认分支中的普通文件 `docs/project/workflow.json`、完整受支持契约和声明的守护分支。有效、需要处理、未接入及检查失败分别呈现；部分扫描不冒充完整空结果。发现只读取必要元数据、配置与 refs，进入仓库后才 fetch 工程记录。HTTPS 地址补充检查使用同一适配器与当前 token，不建立全局项目登记。

所有平台 API、`ls-remote` 和 `fetch` 只使用当前连接的 token，不读取宿主 Git helper、netrc、SSH agent 或继承鉴权头，也不回退其他连接。仓库地址不含凭据、查询参数或片段，只允许受信平台解析的 HTTPS 目标。

Specs 默认来源使用远端 HEAD 指向的默认分支，并核对该来源是否为默认分支中 `docs/project/workflow.json` 声明的守护分支。缺失或异常的默认来源给出提示，用户仍可显式选择已推送分支。页面保留所选分支身份，不把其他分支内容冒充默认分支能力。

Change 列表跨已推送分支聚合，主来源按 Change 自身的 `branch` 确定，与 Specs 分支选择独立。主来源判定和冲突处理见 [Change 追踪](./change-tracking/spec.md#状态与主来源)。

原型总览只读取仓库默认分支的当前清单与开关，不随 Specs 来源切换，也不从历史 Change 聚合当前版本。未合入的原型通过 Change 页面查看和分享；已准备版本使用独立公开入口。

## 快照与恢复

服务在私有持久目录维护 bare Git 缓存、按 blob 保存的正文和不可变快照，不使用数据库。私有缓存按会话、连接、凭据 revision 与稳定仓库身份隔离，不跨连接复用授权或快照。采集 fetch 已推送分支及原型归档保留标签，不 checkout 来源工作区、运行仓库脚本或初始化子模块；普通文件以固定 commit、tree 和 blob 读取，符号链接和子模块不作为正文。

完整采集后原子发布快照，每份快照固定各分支的提交及对应文档、Change 和关系索引。同一分支的 JSON 与正文不能混用不同提交；不假设多分支具有同时提交的事务语义。

- 首次进入尚无快照的仓库时自动读取一次，之后由页面手动刷新；同一隔离范围的并发刷新合并，每个请求仍单独检查权限。
- 刷新失败保留最近成功快照、成功时间及错误提示，但只有当前 token 重新通过授权才能读取；权限无法确认时隐藏正文，没有可用快照时说明读取失败。
- 服务重启恢复已成功保存的快照。保留当前及前两份完整快照；访问已清理版本时明确提示过期，不静默换成新正文。
- 单文件超限或格式异常保留来源诊断；整体采集、容量或持久化失败不发布部分快照。默认读取限额及配置方法见仓库 README。
- 移除连接、退出、会话到期和替换 token 后撤销对应读取与在途任务；残留私有缓存不再通过 API 暴露。旧全局项目缓存不转换成个人授权。

## 长期技术与访问约束

应用采用 Next.js App Router、React 和 Node.js 服务端 API。Git、配置、凭据和索引处理留在服务器，客户端读取展示数据。运行需要 Node.js 24、Git、仓库读取权限和持久磁盘；单 Node 进程、单实例使用一个数据目录，进程锁防止重复写入。

默认监听 loopback，远程访问由受信 HTTPS 反向代理提供。个人访问使用 token 与服务端会话；独立管理员密码仅控制[运维配置](./configuration/spec.md)、上传地址及公开版本撤回，不授予工程读取权限。[个人访问与分享](./access/spec.md)定义会话和协作者访问规则。

工程记录 API 按本人连接、稳定仓库、快照及文档清单检查读取范围，不接收任意本地路径或 Git ref。普通读取、HEAD、缓存、历史快照与图片均确认 token 身份、仓库 API 权限及指定 token 的 Git refs；长请求交付或发布快照前再次检查。权限无法确认时不返回旧数据。文档和流程响应采用 `private, no-store`，刷新接口只接受空请求体。凭据与完整 Git 错误输出不返回浏览器。

原型产物在有权限时准备固定版本，匿名读取只使用已发布文件，不触发 Git 或平台 API。内置静态托管使用专用上传地址，公开文件可按固定版本缓存。托管选择、文件存储与隔离约定见[原型浏览](./prototype-preview/spec.md)。
